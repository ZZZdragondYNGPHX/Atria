# 《斗破苍穹》开放沙盒：功能与交互表现

Task ID：`package/doupo-living-world`。本文件与 [离线视觉原型](doupo-visual-direction.html)、[前端设计指导](doupo-frontend-guidelines.md) 一起交付，仅负责游戏表现设计。后端 `0.1.0-be.2` 与 C2 已交付；本原型没有连接后端、模型、Atria Session 或真实存档。正式集成由用户另行选择执行者。

权威入口为 `docs:plans/package/doupo-living-world/index.md`；已确认方向读 `decisions.md`，动作、公开字段和恢复语义读 `frontend-contract.md`，文件与职责边界读 `execution-split.md`。本文把它们映射到页面，不替代规则、闭合 schema 或契约。示例姓名、地理图、金额、计时、物品和未来片段不是小说考据或发布数据。素材参考与原创 NPC 仅用于设计演示，不自动成为发布内容。

## 1. 阅读与覆盖口径

| 标记 | 含义 |
| --- | --- |
| HTML 演示 | 在随附 HTML 中有操作入口或可切换的静态状态；只证明本地交互设计，不能证明真实玩法或模型质量 |

| 设计建议 | 具体布局、组件和反馈方案，可在已确认方向内迭代；不新增世界规则或自动冻结美术 |

页面以国风手绘 2D 场景图片为主体。本轮用户补充的组织方向为：地区图片总览 → 点击设施进入末级场景 → 左侧附近人物入口 → 大立绘人物交互，人物交互期间保留场景背景；返回先关闭人物，再回地区总览。末级设施内部不再套子地图。自动接近、距离条件与贯穿的自由文字继续有效。

借用 Atria 前端审计的三项交付、能力编号、状态映射和覆盖方法，不沿用其 Shell、Dock、活动灵动岛、平台功能表或视觉主题。《觅长生》只作为场所与功能组织的参考，不复制素材。图片沿用用户指定的已有素材参考，不用示意 SVG 代替主视觉。

离线交付由 HTML 与同级 `assets/` 组成，打开时需保留相对目录。`assets/sources.json` 记录 16 张从本项目素材目录原样复制的场景、人物、地图与物品图片；新增乌坦城总览 `assets/wutan-overview.png` 独立记录于 `assets/wutan-overview-source.json`，不计入前述 16 张复制清单。原型无需 CDN 或网络下载；SVG 仅用于缺图时的路径对照，不是正常主视觉。完整来源、版本和使用限制见素材记录及设计指导。

默认打开乌坦城图片总览（`layer: overview`），不会直接把玩家送进人物交互层或创建弹窗。总览提供以下五处设施，热区与左侧设施列表等价；每处都是末级场景，没有内部子地图：

| 设施 | 演示标识 | 附近人物 / 主要入口 |
| --- | --- | --- |
| 回春堂 | `herbal` | 苏晚禾、回春堂柜台；问询与药材交易 |
| 坊市 | `market` | 陈槐、陆青、告示栏与歇脚处；物资和传闻 |
| 歇马客栈 | `inn` | 燕宁；交流、关系与同行提议 |
| 族宅 | `clan` | 住处与家庭往来语境；没有人物时如实显示空场景 |
| 乌坦城门 | `gate` | 跨地区行旅入口；打开世界地图安排旅行，不再进入子场景 |

进入其他设施会展示本地示例的 5 分钟耗时；图片热区、落点、路径和这个计时都不是后端契约，正式界面必须读真实位置与结算。总览和世界地图可保留草稿，但须进入场所、确认对象及交互距离后才能执行文字行动。

| 入口 | 返回与上下文 | HTML 对应 |
| --- | --- | --- |
| 地区图片总览 → 设施 | 点设施进入末级场景，内部不再出现一层子地图；真实进入是否移动和耗时由权威规则决定，查看设施介绍不耗时 | 地区 / 设施层次；实际图片资产以配套设计指导记录为准 |

| 底部人物 / 行囊 / 修炼 / 家庭 / 见闻 / 存档 | 资料抽屉非模态；关闭回到触发器，草稿仍留在主画面。连续切页不清除未提交文字 | 相应抽屉 |

| 见闻全文、家庭成员、历史人物 | 正式界面保存来源页、筛选、页码与滚动位置；返回原列表。引用通过稳定身份定位，不按名字猜人 | HTML 主要为短列表；全文分页和跨页返回仅文档 |
| 右上宿主入口 | 随时有途径回到 Atria 既有控制；原型仅提示未接入，不伪造退出、费用或授权成功 | 宿主菜单 |

正式前端可记住抽屉、镜头、筛选和字号等表现偏好，不能通过偏好存储写入世界时钟、生死、库存或关系。内部页面定位必须带当前 Session / 分支上下文；这里不另定义 URL 或路由 API。

## 4. 关键操作链

### 4.1 人物生活与自由输入

1. 在地区图片总览点击设施，进入末级场景；从左侧附近人物选择苏晚禾，展开大立绘交互，原场景背景保留。看到名称、所在地点、当前可见活动与距离。
2. 自动接近按路径分段移动。已在范围内不重复移动；受阻给路线失败原因；人物离场则保留旧观察并停止接近。
3. 输入第一段文字时绑定对象。之后选中别人，显示“草稿写给 A，当前选中 B”，由玩家明确保持 A 或改为 B；没有确认不能偷偷改发。
4. 提交后显示“处理中”，输入区允许写下一份草稿；新世界行动需等待当前规则允许。已提交文字独立保留，不能与正在编辑的草稿混为一条。
5. 规则成功后先显示已经发生的时间、资源或关系事实，再等待 NPC 回应 / 旁白。回应失败不回滚事实；重试表达不重新交易。
6. NPC 可拒绝邀请、先完成谋生事务或自行离开。当前活动文字来自可见投影，不能读取 NPC 私有日程后包装成全知提示。返回先关闭人物交互，再从设施回地区总览；返回不丢草稿，也不自动替换草稿对象。

HTML 的自由文字仅播放固定交流 / 行动结果，不理解任意输入。按钮与文字在正式前端都应进入既有规则，但原型的一致外观不是实际意图解析能力。

### 4.2 探索与机缘竞争

见闻中读到“赤叶”传闻 → 查看消息来源和时间 → 调查 → 得知竞争者已经采走 → 记录归属变化 → 再尝试采集得到不可执行原因。原传闻仍能回看，标注已经过时；它不会被改写成玩家一直知道真相。世界地图上的路径或地点只取玩家已知范围；听说某地不必然意味着可旅行。

正式流程中普通采集、唯一机缘、救援与战术冲突分别呈现其合法结果；胜负不必回归原著情节。未制作的远方地区有说明与返回，不伪造可玩入口。

### 4.3 家庭、人口与长时活动

相处与协商 → 双方可接受的约定 → 履约 / 失约 → 成年角色的婚姻提议与实际决定 → 共同生活 / 资源安排 → 照护与子女成长。每一步以真实规则与 NPC 意愿为准，文案中的亲近或生成回应不能直接代办婚姻、怀孕或资源转移。

长时活动展示“计划多久、已经多久、为何停下、还剩什么”。收到来信、途中风险、资源耗尽等中断后，先保留已完成事实，允许阅读消息和修改计划，再按 operation 提供继续 / 停止。孩子成长、迁入、继任与死亡要带获知来源；逝者仍可从已知历史查到。没有消息不意味着人物仍然存活，也不意味着已经死亡。

HTML 的家庭未来片段跳转到一份独立静态快照；修炼人口消息同样是固定片段。它们展示信息组织，不能替代 C2 已有家庭规则，也不能作为长期人口模拟或容量证明。

### 4.4 保存后变化再读档

保存当前时点 → 产生交易 / 家庭未来片段 / 探索新见闻 → 留下未提交草稿 → 选择旧档 → 确认恢复整个世界 → 载入 → 重读当前投影。载入后人物位置、库存、关系、子女、机会、历史与当前活动一致回到该分支；未来消息、目标缓存、待处理回应和叙述重试入口清除。

草稿文本可留存为表现状态，但解除旧目标绑定并提示重新确认，不能把未来才认识的人物名称当作当前合法目标。旧分支请求即使迟到也不得覆盖新分支。原型的 epoch 与内存快照只模拟这种界面隔离，正式行为必须由宿主分支和 Bridge 实现。

### 4.5 多步战术与停止

玩家提交“绕到侧面，再施技” → 显示当前执行段 → 第一段已移动 → 第二段因条件变化失败 → 显示已完成动作、耗时与未执行段。继续按钮只继续真实 operation 的下一步；不重新执行整段文本。

“停止生成”“停止计划”“停止本地行走动画”三者必须区分。前两者分别使用宿主任务控制与规则 cancel；停止动画不能冒充世界行动取消。已消耗的时间、补给和伤势始终以已提交结果为准。

## 5. 状态、草稿与恢复协议

这是界面语义表，不要求后端添加同名枚举或新通用调度层。

| 情况 | 界面表达 | 允许的下一步 | 禁止的误导 |
| --- | --- | --- | --- |
| 正在查看 / 输入 | 明确“草稿未提交”和目标；世界时钟不走 | 编辑、查阅、选择、预览 | 现实打字时间自动增加游戏时间 |
| 提交未确认 | 保留提交内容，显示不定等待；只有真实进度才用进度数值 | 继续写草稿、看已知信息、观察状态 | 用 650ms 演示计时器推算真实耗时或百分比 |
| 被规则拒绝 | 就近说明条件已变；保留草稿、对象和当前位置 | 修正输入 / 重新查看条件 / 合法重试 | 显示成功动画后才吞掉错误 |
| 目标移动 / 离场 / 死亡 | 显示已知状态及观察时点；草稿标过期 | 重选合法对象并明确重绑；查看历史 | 按名字匹配给同名新人或当前选中者 |
| 结果不明 / 断线 | “正在确认结果”，先读现有任务 / receipt / screen | 重新观察；仅按既有重试能力复用同次身份 | 当作失败另造 idempotencyKey 重发交易 |
| 规则成功，表达生成中 | 已发生事实与尚待表达分区显示 | 查看结果、编辑草稿、按实际能力停止表达 | 把旁白视为结算凭据 |
| 规则成功，表达失败 | 明确事实有效；只提供适用的表达重试 | 重新读取回应或重试允许的表达步骤 | 再执行原动作、重复扣金币 / 材料 |
| 保存成功，列表刷新失败 | 保留“保存已完成”；刷新按钮写“仅刷新列表” | 重读列表 | 再保存一次以“修复”读取错误 |
| 保存失败 / 保存结果不明 | 失败和未知分别说明；未知先查证 | 确认未写入后才重新保存 | 把未知伪装成无副作用失败 |
| 载入中 | 当前世界行动暂停、目标暂不可提交；显示正在恢复 | 观察宿主结果，保留宿主安全通道 | 允许旧对象继续提交或清空画面后永久锁死 |
| 载入失败 | 明确当前权威世界是否仍有效；重读并保留失败原因 | 再选档 / 重读 / 退出 | 把半份旧缓存和半份新投影拼接 |
| 载入成功 | 新分支画面一次更新；草稿需重新绑定 | 浏览当前已知信息后再提交 | 旧任务、未来消息和旧图片说明重新闪现 |
| 原 revision / epoch 过期 | 告知状态已变化并重读；保留未提交文字 | 在新状态重新确认行动 | 自动把旧请求移植为新分支行动 |
| 空列表 / 读取失败 | 分别显示“暂无所知记录”或“未能读取” | 返回、重读、合法分页 | 用“0 人”替代未知人口或加载失败 |

草稿至少关联提交前的目标、场景与分支语境；这是表现需求，实际字段由正式前端与宿主边界决定。新投影更新期间保留用户当前编辑内容；提交成功只清理该次已提交草稿，不能清掉等待时新写的文字。快捷行动发现已有草稿时避免覆盖，允许先处理已有草稿再执行。

## 6. 知识、家庭与历史边界

- 人物详情分清“在场”“上次见于”“已知死亡”。离屏事件不会自动穿透到旧档案；收到可靠消息才更新已知状态。未知显示“尚不知晓”，不能展示为数值 0 或默认否定。
- 亲见、转述、传闻和个人原著记忆带来源与时点。原著记忆仅对相应角色可见，并明确可能因开放历史而失效；它不自动证明 NPC 活着、机缘仍在或路线可达。
- 家庭页面显示本人获知的婚姻、亲属、承诺、共同资源与照护需要。NPC 私有评价数值、隐藏目标和远方真实位置不送入普通玩家界面；不能先下载全部私有记录再用 CSS 隐藏。
- 家庭成员保有工作、旅行与个人意愿。子女展示出生 / 成长来源；未成年角色只保留照护、教育与亲属互动，亲密婚姻入口依真实成年和资格校验。资格未知时不能仅凭画面外观判断。
- 共同物资与个人库存分别显示归属，分配动作展示来源、接收方、数量和实际结果。婚姻与“关系亲近”的文本标签不隐式赋予操作对方资源的权限。
- 动态 NPC 使用稳定身份；列表分页总数只解释为当前获知档案数量。历史人物仍有名字、亲属和已知经历，不能为了人口预算从玩家历史消失。
- 世界平衡通过玩家获知的迁居、风险、继任等因果事件呈现。不能展示“腾出槽位”“全世界已满”等内部调度文案，也不能承诺所有损失都有提前预警和挽救机会。

## 7. 键盘、IME、缩放与可访问交互

| 场景 | 原型行为与正式设计要求 | 验证边界 |
| --- | --- | --- |
| 输入 | Enter 提交，Shift+Enter 换行；组合输入期间 Enter 只完成候选选择；`compositionstart/end`、`isComposing` 与兼容键值避免误触发 | DOM 事件检查不能替代真实系统中文 IME 手工验收 |
| 快捷键 | C 人物、B 行囊、K 修炼、R 家庭、J 见闻、M 地图、L 存档、? 说明；输入框、选择框、可编辑元素与组合输入时不执行场景快捷键 | 正式集成需核对宿主快捷键冲突 |
| 场景等价路径 | 可聚焦对象列表与图形目标提供相同选择 / 接近入口；场景聚焦后方向键移动一步；地图目的地同样有列表 | 不把鼠标悬停路径预览作为唯一获知条件 |
| 焦点与返回 | Tab 顺序可预测且焦点可见；非模态资料抽屉允许回到输入；模态确认层限制背景交互；关闭后回到触发器，触发器已消失则回到合理主入口 | 完整键盘焦点路径以浏览器验证为准 |
| Esc | 先处理顶层确认，再关闭演示 / 宿主菜单或资料；只有没有覆盖层时才处理移动取消 / 选择清理 | 不能一键同时关闭多层并意外取消世界行动 |
| 200% 缩放 / 小窗口 | 收起侧栏，允许页面与面板滚动；目标、输入、主要行动和宿主入口仍可达；不靠缩小正文挤回三栏，不禁用浏览器缩放 | 真实浏览器缩放与模拟 CSS 视口分别报告 |
| 长内容 | 对话可展开；正文换行，消息来源不截断；列表分页 / 搜索只读已知信息；更新不强行把正在回读的人拉到底部 | HTML 的短示例不证明生产长历史性能 |
| 状态与颜色 | 选中有轮廓与名称，危险有文字；不可执行给原因；等待区域适度播报，避免整页重复播报 | 不将颜色作为唯一信息；屏幕阅读器实测另记 |
| 减少运动 | 保留选中、到达与结算信息，降低装饰运动；输入和焦点不等待动画结束 | 原型开关与系统偏好支持分别核对；不推导真实帧率 |
| 触控 | 无悬停也能选目标和执行主要行动；触点有可点击面积，小窗口使用展开面板 | 本轮电脑优先；模拟小视口不等于真实手机设备验收 |

目标展示尺寸为 1440×900、1920×1080，兼顾 1280×720 与 200% 缩放。它们是本次设计和验证样本，不是限制设备的规则。任何浏览器实测应单独注明实际视口、缩放方式与已走通流程，不能只凭媒体查询声明“已适配”。

## 8. C2 真实绑定与正式接线需求

以下据 `frontend-contract.md` 的 C2 整理，用于正式集成的导航，不建立第二份 schema 权威。实际作者源 `tools/build.mjs`、`tools/schema.mjs` 与容器 `integration/bridge.json`、`integration/screen.schema.json` 仍是接线依据；使用前应核对届时版本。原型中 `S`、`runLocal`、快照和定时器都不是这些绑定。

### 8.1 既有路径

| 真实入口 | 已有语义 | 前端如何消费 |
| --- | --- | --- |
| 安装、generation 授权、SessionCore.create、experience.ready | 既有宿主启动路径 | 使用实际宿主入口，不仿造凭证或费用授权；再调用 `bind0/1/2`，各输入 `{}`，取得原生身份绑定 |
| `screen`，输入 `{}` | 只读 `dw_public`；返回数组项 `{id,value:{screen:JSON字符串}}`，读取 `main` 解码 | 构建玩家公开画面；不能读取全 Domain 或 NPC 个人 view 来补细节 |
| `act` / `choice` / `plan` | 同一规则体系；choice 与 plan 在动作前自动保存并接旁白 | 复用实际 schema 和 typed transaction；choice 的 kind 只限已声明集合，其余合法单步走 act |
| `continue` / `cancel`，输入 `{}` | 确定性后续结算 / 停止，不调用模型 | `operation.kind` 非空时显示对应继续 / 停止；已完成部分保留 |
| `talk` + Native NPC Task + `acknowledge` | 接近后以人物 key 交谈；后台回应完成后 acknowledge 同一 target | 观察真实任务；先展示 `result.text`，再 continue 处理评价，不自动重做 talk |
| `browse` / `clues`，输入 `{qty:0起页码}` | 已知人物 / 消息分页，不耗时 | 保留页码与滚动；人物每页 12、消息每页 8；不是全世界搜索 |
| `recall`，输入 `{target:消息id}` | 获知消息全文写入 `result.text`；未知或越权拒绝 | 摘要打开全文，保留来源与返回位置；不能从摘要补造全文 |
| 原生 SavePoint / Branch | 完整世界与分支恢复 | 真实档案标识、保存与加载结果走宿主；成功后重开 Bridge、清缓存并重新读取 |

规则输入字段全部必填：`{kind,target,item,qty,x,y,detail,text,steps}`；未用字符串为空、数字为 0、`steps=[]`。目标使用人物 key，不能使用显示名字或猜测 actor。购买 `detail` 必须是当前 quote 的整数文本，不能把 HTML 显示价作为报价凭据。

`choice` 的 kind 为 `travel/train/wait/rest/marry/conceive/attack/technique/work`；`plan` 的 kind 为 `plan`，1–4 个顺序步骤，每步 `{kind,target,item,qty,x,y,detail}`。每次推进一个步骤，`result.steps` 与 `partial` 表达部分完成后的失败或取消。不要将原型固定“两段战术”限制为后端能力上限。

提交携带 `epoch/revision/idempotencyKey`。同次允许的重试保留原 key / revision；读档重开 Bridge 后旧 epoch、目标和旧任务结果失效。成功 Bridge Action 返回 receipt，公开 payload 是 `{}`；必须重读 screen，不能假造 Action 直接返回完整世界快照。`time/at/spent` 单位为开局后分钟，不能使用浏览器时间代替世界时间。

### 8.3 需要核对而非虚构的缺口

1. **原生前端载入：** 后续把选定设计编译为实际 `.aui` / Controller / Canvas，引用作者 Bridge 并经原编译器产出；HTML 不能直接当正式作品导入。
2. **视图细节映射：** 场景构件的尺寸、阻挡、遮挡、物品图标和人物半身像要与真实身份和状态对应。若公开 screen 没有某一细节，先采用未知 / 无法操作表达，再核对现有投影；不能读私有域补齐。
3. **操作与可执行原因：** 家庭、照护、传授、交换提议与救援等完整入口需对照现有 schema 和可见规则。本文不新增虚构 HTTP 路径、`exchange` 或 `rescue` 等专用绑定；不支持的表达不能显示成交或获救。

### 9.2 直接设计自查与限制

| Before | After | Why |

| 行走 token 使用 `left/top` 补间，等待条持续绘制背景 | 移除补间和装饰循环，以位置与文字状态即时反馈 | 离线原型无需为常用操作增加等待或持续绘制；不声称已有正式行走动画 |
