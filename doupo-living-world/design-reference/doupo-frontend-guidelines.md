# 《斗破苍穹·众生行》前端设计指导

Task ID：`package/doupo-living-world`。本文件与 [离线视觉原型](doupo-visual-direction.html)、[完整功能与交互表现](doupo-function-presentation.md) 共同构成设计交付。当前范围是游戏前端视觉与交互原型；没有真实后端、模型、世界存档或宿主接线。名称“众生行”、原创人物、场景布局与演示数值均用于说明设计。

既有已确认方向以 `docs:plans/package/doupo-living-world/decisions.md` 为准；本轮用户追加的图片主视觉与导航要求另在下表明确列出，不反写共用决定文件。布局默认方案归 `presentation.md`，功能语义与实际接口归 `frontend-contract.md` 的 C0/C2。本文件只约束表现，不建立第二份游戏规则或字段权威。正式前端集成执行者仍由用户决定。

## 1. 已确认方向与本轮设计建议

| 层级 | 内容 | 本文件如何使用 |
| --- | --- | --- |
| 已确认体验 | 世界地图与 2D 俯视地点；点击地面/对象移动，选择 NPC 自动接近；按钮与自由文字共同操作 | 作为布局与可达性设计的基础，不改成插画翻页或纯对话游戏 |

| 已确认内容重点 | 自创角色、NPC 自主生活、三地深入体验、探索竞争、婚姻家庭、动态人口与完整世界恢复 | 关系、历史、来源、行动后果和读档都必须有可发现入口；不能为了简洁删去 |

| 既有默认方案 | 玄青/深石面板、石白/雾青文字、古金选择、炎赤危险；宋体标题、黑体操作；场景居中，面板按活动展开 | 本轮保留并细化；精确色值、字号、面板宽度没有因此成为用户逐项冻结要求 |
| 本轮设计建议 | “众生行”工作名、图片上的设施热区、附近人物列表、人物大图的版式、记录区、局部状态提示、具体尺寸与状态样式 | 可继续迭代；不以视觉稿新增玩法、重定义后端字段或承诺真实模拟能力 |

参考 Atria 前端审计的做法是“三份产物分工、完整功能映射、状态与恢复、证据分层”。不采用其 Shell、Dock、活动灵动岛、主题系统或全产品导航。

用户提供的《觅长生》相关参考用于地区与人物交互的组织和布局理解。本轮采用本项目已有生成图片，不复制参考游戏的美术、图标、音效或字体，也不把其规则带入本项目。引用另一对话用于读取用户指向的参考，不把其中 AI 的解释升级为新增用户确认。

## 2. 视觉身份：场所是主体，人物有自己的生活

第一眼应看见实际绘制的城镇、道路和建筑。地区总览以图片建立地理与生活感，设施入口叠加在对应区域；进入设施后以实际场景图建立在场环境。界面是贴近场所的观察和操作工具，不把城镇切成一组等大的数据卡片。场景中的药铺、街巷、林道与家宅应能帮助理解“人在哪里、为什么在那里、我能做什么”。

- 乌坦城：木石街巷、屋檐、摊铺和来往人物，突出日常生活与交往。
- 青山镇：行旅、药材和佣兵生活痕迹，突出准备、同行与消息交换。
- 魔兽山脉：可读的路径、林木、岩石、遮挡与线索，突出可达性和已知风险。
- 家庭：具体成员、住处、生活记录和约定构成内容，不用“好感度仪表盘”替代人物意愿。

这些造型是游戏美术推导，不声称小说规定了精确建筑图。远方地区、主线角色储备和未发现地点不因存在素材就成为本局可知、可达或可玩的内容。

界面用深色背板保护阅读，少量古金强调当前选择。场景可以有纸感和笔触，文字背板保持平整；不在正文后叠重纹理、强光晕或持续粒子。危险色集中表达后果，不用于常规装饰。

## 3. 色彩与材质

下表是本轮 HTML 的主要 token。组件优先引用 token；未来调整同一语义时集中修改，不逐个控件换色。

| 名称 | HTML token | 值 | 用途 |
| --- | --- | --- | --- |
| 玄青 | `--xuanqing` | `#172A30` | 应用基底、面板和文字背板 |
| 深石 | `--shenshi` | `#263E44` | 抬高的面板、控件底色、对象详情 |
| 石白 | `--shibai` | `#F1EBDD` | 正文、主要操作和重要数字 |
| 雾青 | `--wuqing` | `#B5C9C8` | 辅助描述、来源、非主要信息 |
| 古金 | `--gujin` | `#CBA568` | 当前选择、重点与主行动边线 |
| 炎赤 | `--yanchi` | `#E77C55` | 伤势、危险、交锋和重要后果 |

补充色用于原型的局部层级：`--shenshi-2:#304C53`、`--line:#3D5A60`、`--wuqing-2:#94ACAB`、`--gujin-2:#E2C58E`、`--yanchi-2:#F29C7B`；成功采用 `--ok:#8FC4A4`，注意采用 `--warn:#E6B566`。宣纸 `--paper:#E8DDC4` 与墨色 `--ink:#2A2824` 只用于图像和局部美术，不创建第二套主题。

使用规则：

- 选中状态同时有轮廓、底色或文字，危险同时有原因；不只靠红绿区分。
- “未知”“未在场”“已知死亡”“旧观察”保留不同文字，不用同一种灰色抹平语义。
- 古金不铺满全屏；同一操作区突出一个主要动作，次要操作保持低调但可发现。
- 正文与背景的设计目标对比度至少为 4.5:1；大字、焦点和关键非文字控件至少为 3:1。叠在场景上的名称需有足够实的背板，并在实际背景上验证。以上是验收目标，不是本文件宣称已完成的测量。
- 边线用于分组、层级与选中；约 6px 的控件圆角延续原型，避免所有内容变成同形浮卡。阴影只给浮层和必要的场景分离。

## 4. 字体与文字密度

原型不分发字体文件，不使用外部字体 CDN。CSS 中写到的字体只有系统已安装时才会使用；字体名称不是授权凭证。

| 角色 | 原型回退顺序 | 使用建议 |
| --- | --- | --- |
| 标题、姓名与地点 | `Noto Serif SC` → `Source Han Serif SC` → `Source Han Serif CN` → `Songti SC` → `STSong` → `SimSun` → `serif` | 用宋体建立古风气质；只用于短标题，不将整屏控件设成装饰字体 |
| 正文、按钮与表单 | `Noto Sans SC` → `Source Han Sans SC` → `Source Han Sans CN` → `PingFang SC` → `Microsoft YaHei` → `Hiragino Sans GB` → `sans-serif` | 中文黑体便于密集信息与连续输入；离线缺少首选字体仍可操作 |

默认根字号为 16px，正文目标为 16–18px，行高约 1.6。姓名与面板标题适度增大；辅助时间、来源和标签可小一级，但不能把必要条件、错误原因或目标身份压成难读小字。正式集成允许随界面缩放，不能用固定像素强行缩小到塞满屏幕。

长对话优先控制在约 35–45 个汉字一行，窄窗口自然换行；不以每行挤满全屏来减少滚动。较长资料分为“当前事实、相关经历、可做的行动”，详情按需展开。数值列对齐，可使用 `font-variant-numeric:tabular-nums`，不要求玩家阅读技术字段。

面板每段先给结论，再给条件和来源。列表一行表达一个对象或记录，不在行内堆全部经历。文字量增加时保留稳定滚动区、分页与全文入口；摘要不能冒充全文，也不能静默截断重要后果。中文标点与真实换行正常呈现，长名称和连续英文需允许折行。

## 5. 场景、人物与可交互对象

### 5.1 图片构图与人物比例

地区总览优先展示完整城镇结构，设施热区使用图片内容坐标随画幅一起缩放，不能因裁切而漂到其他建筑。默认进入总览，提供药铺、坊市、客栈、族宅和城门五处设施入口；此为原型入口编排，不据此冻结后端地点编制。最末级场景优先保留人物互动相关的柜台、道路和环境语境；不能强行拉伸原图来填满窗口。需要裁切时检查关键入口和交互位置，必要时使用完整显示与背景衬底。

人物交互使用足够大的实际人物半身像，与姓名、身份、活动、行动及对话形成主次关系；它是当前对象的近景表现，不是场景内角色的物理比例。人物图与文本之间保留阅读空间，不把面孔裁掉，也不让大图盖住必要操作。缩小时先压缩装饰留白，再将人物图与操作区顺序排列。

本轮选用的既有人物图片包含画面背景，按“有底半身像”展示。可以使用边框或背板将其融入界面，但不能称为透明立绘，也不能用 CSS 混合效果冒充已完成抠图。透明人物、完整行走形象和动画是需要独立制作与验收的资源。

每个人物应先通过骨相、眉眼、年龄、体态与姿势区分，再靠颜色和衣着补充。D28 的差异化要求继续有效，不能用同一脸型换服饰充数。现有素材进入原型只证明表现可以使用，不自动证明时期、身份映射和正式场景接线已完成。

地区图、场景图和人物大图的视觉尺度都不是 C2 世界坐标、碰撞半径或交互距离。正式接线仍需要权威位置与可达性模型；入口和路径不能由装饰画面自行决定。

### 5.2 地区、设施与人物交互层

```text
地区总览（实际城镇图片 + 设施入口）
  └─ 最末级设施场景（实际场景图片；不再进入下级子地图）
       └─ 人物交互层（附近的人 → 人物大图、行动与自由文字）
```

设施内的柜台、采集点或环境对象是当前场景中的交互目标，不通过新子地图继续增加导航层级。人物交互开启后保留该设施场景作为背景，避免看不出交谈发生在哪里；可适度压暗保护文字，但不把背景彻底替换成无上下文页面。

“返回”与 Escape 的层级一致：先关闭最上层普通弹窗；人物交互开启时关闭人物层、回到同一设施并恢复原人物列表焦点；设施层再返回地区总览并恢复设施入口焦点。返回不默认撤销已提交移动、交易或时间，也不等于跨地点旅行的后端提交。

人物图出现不等于已到达交互距离。选择附近 NPC 时应显示接近状态与距离条件，只有规则确认可交互后相应行动才可执行；目标离开、路径受阻和途中取消仍有明确反馈。原型表现的自动接近是本地演示，真实接线需映射 C2 `approach` 等既有动作。

### 5.3 选择与可达性

人物、设施、地面与出口有不同的命中和反馈方式。选择 NPC 后显示姓名、活动、所知信息和当前目标；接近与后续交互分开。路线预览、正在接近、到达、受阻、目标离场和已取消使用明确文字，不能只播放角色位移。

图片上的设施热区、场景按钮和人物列表具有可访问名称；选中可用轮廓和 `aria-pressed` 表达。名称在悬停、焦点和选中时保持可见，避免只对鼠标用户有效。图片不承担唯一的文字入口，等价列表提供足够大的操作区。

**对象列表是必要操作路径。** 地区层提供设施等价入口，设施层左侧提供“附近的人”；列表与图片热区使用同一选择对象。列表可通过键盘聚焦，提供人物、设施、出口、活动和离场信息。不要把选择绑定到姓名字符串；正式接线使用 C2 的稳定人物 key。没有出现在当前场景的已知档案通过人物分页访问，不强制把所有人物同时画在场景上。

美术缺失时保留地点名、对象按钮和列表，明确提示图片未加载；图像失败不能让行动入口一并消失。未知位置显示未知或上次观察，不将角色自动放到当前场景来填补画面。SVG 或简单色块只可作为缺图回退与辅助标记，不继续承担本轮主视觉。

## 6. 桌面布局与缩放

顶部保留地点、世界时间、当前活动及保存/设置入口；中部让地区或设施图片占主要面积；左侧随层级显示设施或带头像的附近人物；人物交互开启时在中央以大幅半身像与行动/对话区组织近景，场景背景保持可辨，右栏仅承担可选详情。底部承载记录、目标明确的自由输入和功能入口。布局随总览、设施、人物三种状态调整，不要求固定三栏。

| 验证样本 | 设计要求 |
| --- | --- |
| `1440×900` | 场景、目标和自由输入同时可见；常见动作不需要先关闭无关面板；短记录能回看 |
| `1920×1080` | 增加场景空间和阅读留白，限制正文行宽；不通过无限拉宽人物与面板放大密度 |
| `1280×720` | 压缩非必要标题留白和记录高度，折叠侧栏；目标、主要行动和输入保持可达，不把按钮藏到不可滚动区 |
| 浏览器 `200%` 缩放 | 按缩放后的有效视口重排；面板可折叠或纵向滚动，弹层内部可滚动；不得裁掉关闭、提交、取消或目标信息 |
| 更窄窗口 | 先保证阅读、目标和行动的顺序，允许主页面纵向滚动；场景列表始终是备用入口 |

上述是验证要求，实际执行的尺寸与结果记录在配套交互文档。手机触摸和真实设备性能不属于本轮全量验收；窄视口模拟不等于已通过真实手机验证。

滚动区有清楚边界；记录、侧栏和弹层可独立滚动，但避免形成多层嵌套滚动陷阱。输入区不要被固定层压住。打开家庭或行囊面板时仍说明当前场所；关闭后回到原来的目标和阅读位置。

## 7. 组件与必要状态

| 组件 | 表现与状态规则 |
| --- | --- |
| 操作按钮 | 文案说清结果，例如“接近”“询价”“载入此档”；具备默认、hover、focus-visible、pressed、disabled、loading、success、error。成功/错误可显示在操作结果区，不强制每个按钮自行闪烁 |
| 不可执行动作 | 显示用户可知的原因；若保留可聚焦按钮读取原因，使用 `aria-disabled` 并阻止执行。不能仅降低透明度，也不能暴露秘密条件 |
| 选择项 | 地图对象、列表和目标卡保持一致；既有选择变化立即可见；选中不等同于提交 |
| 自由输入 | 始终可知“对谁、在何处”；草稿与已提交内容分开；提交中保留可编辑草稿，冲突动作有明确限制；失败不清空原文 |
| 状态提示 | 普通更新不抢焦点；等待显示不定状态，有真实进度才显示百分比；错误贴近受影响操作，并提供可行下一步 |
| 记录与事实 | 已发生事实和生成中的表述分开；来源、时点和过期状态可辨；旧记录不是当前世界实时状态 |
| 弹层与面板 | 名称、关闭按钮与阅读顺序明确；模态层限制背景焦点并支持 Escape，关闭后回到触发器；非模态面板不伪装成全局阻断 |
| 空/缺失状态 | 区分没有已知对象、暂无记录、加载失败与功能未接线；提供查看其他页、重读或返回等合适入口 |
| 保存与载入 | 显示目标档的时间与位置、将恢复整个世界的含义、进行中/失败/完成。保存成功但刷新失败只引导重读；恢复后移除未来信息和失效目标 |

hover 只提供辅助强调，重要内容不能只在悬停时出现。触控使用按下、选择与明确按钮，命中区以约 44px 作为舒适目标；较小场景对象由列表补足。频繁按钮不缩放整段文本；按下可通过即时底色/边框反馈，避免装饰反馈造成布局抖动。

状态文案使用游戏含义：“苏晚禾已离开药铺”“报价已变化，请重新询价”“行动已完成，描述未生成”。事务、CAS、epoch、后台任务路由留在开发诊断与接线资料中，普通玩家不需据此决策。

长期使用后的提示递减是后续建议：熟悉基础操作后可收起非必要说明，并保留随时可开的操作说明入口；目标、失败原因、耗时与读档后果不能随熟悉度消失。本轮未模拟玩家习惯学习。

## 8. 自由文字、知识与长期后果的表现

自由文字不是某个 NPC 弹窗的附属功能。切换地图、家庭、交锋与功能面板时，保留输入入口与可见目标。已有草稿若绑定旧目标，切换后必须明确重新指定或保留原绑定，不能悄悄发送给新对象。

输入使用 Enter 提交、Shift+Enter 换行，并在输入旁说明。中文 IME 组合输入期间 Enter 只用于选词；聚焦可编辑区域时不触发场景快捷键。错误保留输入、目标和原因，重试不自动覆盖新编辑内容。重复按下提交不能产生第二次相同结算。

人物卡只展示玩家获知的经历和状态。对私有意愿用人物回应和行为表达，不输出精确隐藏好感；拒绝是正常分支。家庭成员有活动、约定、需求与已知去向，不能让“家庭”页看起来像控制所有成员的管理台。

人口变化通过出生、迁入、离开、死亡和继任的已知事件进入记录；死亡人物仍能在已知关系和历史中找到。不要显示“释放人口槽位”，也不要把可见人物总数称为世界人口。家庭新成员的出现应能追溯到相应经历，不能只改变一个人数徽章。

见闻区区分亲见、转述、原著记忆与失效线索。传闻不能因重复显示就变成已核实事实；探索争夺后的线索变化由玩家获知范围决定。完整读档恢复后，界面重读人物、资源、家庭、关系、线索与历史，旧分支中的图像标签、弹窗和草稿上下文也必须失效或重新绑定。

这些表现要求不新增后端字段。完整状态链、F01–F12 覆盖与缺口见 [交互文档](doupo-function-presentation.md)。

## 9. 动效、减少运动与性能目标

本轮优先保证选择、输入、切换与状态识别即时。没有必要通过动画说明的变化直接更新；键盘触发的频繁操作不添加装饰动画，不让用户等待展开或淡入后才能输入。

若后续加入行走、受击或场景切换，只用于表达空间连续性和行动后果。世界时间来自规则结果，不能以动画的毫秒计时推进。取消动效不等于取消世界行动；加速或减少运动时结果、位置与文字反馈仍完整。

原型 token 预留的 `--t-fast:120ms`、`--t-mid:200ms` 是候选表现时长，不是后端 SLA，也不说明每个组件已使用动效。本轮原型用静态状态指示等待；正式模型接线不得将固定演示倒计时冒充生成进度。

后续动效建议：

- 优先少量 `transform`、`opacity` 变化；不做持续背景漂移、循环呼吸边框或全屏火焰粒子。
- 频繁 hover/焦点/列表选择立即反馈；hover 特效只在 `hover:hover` 且 `pointer:fine` 时启用。
- 避免 `transition:all`，不按帧修改大量布局和继承变量；长列表按既有分页显示，避免每次读屏重绘完整历史。
- 系统 `prefers-reduced-motion:reduce` 和原型减少运动设置都能关闭位移与装饰动画。减动后保留文字、轮廓、状态和焦点，不以去掉反馈代替减少运动。
- 图片解码、长文本和异步结果不能抢输入焦点；模型等待期间草稿与已知资料继续可用。

常规反馈约 100ms、基础画面朝 60fps 优化仅是目标。本轮没有据此声称帧率、模型延迟、最大人口或真实宿主负载已验证。正式集成需要在实际素材、目标设备与真实宿主上测量，出现卡顿时再定位布局、绘制、脚本和资源成本。

## 10. 无障碍与操作一致性

- 所有图形操作提供名称和键盘路径；Tab 顺序跟随阅读顺序，focus-visible 清晰且不被固定层遮挡。
- 模态弹层具有标题和正确语义，初始焦点落在合适控件；关闭后恢复触发器焦点。原触发器已消失时选择同一区域的稳定入口。
- 对象列表与场景同步，但更新普通记录不自动抢走焦点；可用 `aria-live` 温和播报必要结果，避免播报整页。
- 隐藏面板不留下可聚焦控件；展开/折叠状态通过语义属性暴露，不只改变箭头。
- 在强制颜色模式下保留边框、名称、选择轮廓和焦点，不依赖背景图与阴影解释状态。
- 不用色相、声音或动画作为唯一信息；对话可回看，重要结果不以短暂 toast 作为唯一记录。
- 200% 缩放下保留完成操作的能力；长文与长名称可读，焦点移动到的控件会进入可视范围。
- 触控替代路径不要求 hover、右键或精确双击；本轮只定义方向，真实设备操作以实际验证为准。

## 11. 原型素材与 D28 正式资产

本轮使用项目已有实际图片作为场景、人物及相关物品的视觉资源。已有素材来源为 `package:doupo-living-world/media/v1/images/` 中的 `scene`、`character`、`item`、`map` 分类；选中的场景和人物 WebP 无损原样复制到本设计目录的 `assets/`，不改写来源文件，不压缩重绘，也不以参考游戏截图替代项目素材。地区全城总览单独生成，交付文件为 `assets/wutan-overview.png`；它是本轮原型新增图片，不冒充既有素材或真实可行走地图。

HTML 与 `assets/` 一起交付，使用相对本地路径离线加载；不再宣称 HTML 单文件自包含。没有外部网络图片、字体 CDN、远程脚本或模型请求。移动 HTML 时需一并保留素材目录。原型没有播放或生成正式音乐。

既有资源来源记录见 [assets/sources.json](assets/sources.json)，包含原始路径、SHA-256 和 provenance；新增全城总览的生成来源见 [assets/wutan-overview-source.json](assets/wutan-overview-source.json)。使用限制与已有资源的生成信息仍以素材任务原始记录为准。人物半身像有背景，在画幅内直接展示；未制作的透明人物、遮挡层、碰撞对齐和行走动画不得标成完成。

本轮原样选取 16 张既有 WebP：6 张场景（坊市、药铺、客栈、族宅、城门、山谷）、4 张人物（`local-su`、`local-chen`、`local-lu`、`local-yan`）、1 张首批三地氛围图和 5 张物品（药材、红叶草、药物、干粮、功法册）。复制文件共 `30,758,246` 字节，逐文件 SHA-256 与来源一致；该检查证明编码字节未改变，不证明场景规则接线。来源文件在复制时仍未跟踪，元数据明确记录其工作树角色与 HEAD，同时以文件哈希标识真实版本，不能只用 HEAD 声称这些素材已在提交中。

苏晚禾和药铺沿用原始参考素材，其提示词从 `media/references/v1/prompts.json` 对应条目读取，并核对参考 PNG 哈希与 provenance 的 `sourceSha256` 一致；其余条目保留生产 `catalog.json` 中的提示词。已有 provenance 未逐项记录提示词哈希，因此复制清单不将“保存了提示词”夸大成独立证明生成请求与输出逐项一致。

D28 对真实批量美术的授权和要求已经存在，无需为本轮重新询问。本轮选用其中代表性资源作离线表现，不接管素材任务，也不代表全部储备人物、地图与音乐已纳入游戏。正式资产的状态、稳定 ID、人物年龄/时期、生成提示词、文件格式、尺寸、用途与限制由素材制作模块和实际文件记录证明。

正式接入前应做到：

1. 场景底图、遮挡层、互动标记与权威坐标/阻挡模型对齐；画面能走的地方与规则一致。
2. 人物行走形象、朝向和对话半身像对应稳定身份，年龄与时期明确；储备角色不自动出现在开局已知列表。
3. 图片丢失有名称和列表回退；加载失败不隐去已有操作，图像按需加载，不一次装载全大陆储备。
4. 分发字体核对具体字库授权和体积；图像及音频保留来源记录。音频以可播放文件、试听、循环、音量和加载验证为准，提示词或曲目清单不算生成完成。

这些是后续素材与集成要求。本轮交付视觉原型、其本地引用素材与资料，不修改正式素材任务、发布包或后端规则。

## 12. 接线与验证记录的边界

C2 的 `screen` 公开投影、人物 key、既有分页、动作 schema、receipt 与后续重读是正式映射依据。HTML 的对象名、字段、计时器、内存快照和事件函数仅用于演示，不升级成新 HTTP API、Host Bridge 方法或第二套世界状态。

正式前端沿原生 `.aui`、Controller、Canvas 与 Host Bridge 能力实施；不因 HTML 使用 DOM/CSS 就换栈，不把客户端样例状态写成生死、资源、关系、时钟或存档权威。真实后端已经提供部分能力，不代表本原型已经接通；当前接线缺口由 [交互文档](doupo-function-presentation.md) 统一维护。

验证由执行代理直接完成，专门测试脚本、fixture、日志和截图仅本地保留。文档中的设计目标不自动成为通过结论。交付记录应分别写清：

| 证据层级 | 可以证明 | 不能据此证明 |
| --- | --- | --- |
| 静态检查 | 文件结构、本地素材引用、无外部网络依赖、标注和设计映射 | 浏览器实际布局、真实模型、宿主行为 |

本轮实际执行的浏览器尺寸、流程及结果集中记录在交互文档，避免在多份设计资料中形成互相漂移的验证结论。未验证项保留明确边界，不引入独立审查流程或逐阶段审批。
