## 1. 设计立场与方案来源区分

### 1.1 核心设计立场：「苍青卷轴 · 烟火乌坦」

本作为承载于 Atria 宿主之上的《斗破苍穹》开放沙盒 RPG。不同于泛用数据仪表盘、卡牌对战界面或霓虹电竞风，亦不照搬 Atria 平台壳层的「中庭 Atrium / 磁吸 Dock / 活动灵动岛」，本游戏的界面围绕**国风手绘 2D 俯视场景**与**贯穿始终的自由文字交互**构建：

1. **2D 俯视场景为第一视觉主体**：城镇街巷、药铺室内、佣兵集结点与山脉探索地始终占据核心视野。面板围绕当前活动按需展开或收起，不把鲜活世界切割成固定死板的三栏后台表单。
2. **自由文字是一等公民，且目标永远显式绑定**：输入框常驻舞台底部，始终标明「对谁 · 在何处 · 做什么」及当前绑定对象与距离。文字意图与快捷动作按钮进入同一套权威规则结算，不把自由输入藏在某个人物对话弹窗里。
3. **时间、事实与认知严格诚实**：
   - 思考、打字、查阅面板与离线期间**世界时间暂停**（D07），界面显著区分「预览耗时」与「已提交消耗」。
   - 严格区分**亲见事实**、**坊间传闻**、**穿越者原著记忆（不等于本局事实）**与**未知信息（绝不画成 `0`）**。
   - 严格区分**规则已结算（带回执印记）**与**模型叙事生成中**，表达失败只允许重试叙事，绝不诱导重复扣费或重复交易。
4. **作品接管舞台，宿主永远留门**：游戏全屏接管会话舞台时，顶部右侧常驻低打扰的「宿主门（Host Door）」，确保保存、读档、停止请求、诊断与退出作品在任何状态下可达。

### 1.2 已确认方向、D4 默认方案与本轮设计建议的边界

为便于后续用户审阅与前端集成者接线，本文档将所有规范明确划分为三类状态：

| 类别 | 定义与约束 | 代表内容 |
| --- | --- | --- |
| **已确认决定（D01–D26）** | 用户已明确拍板，前端原型与后续集成必须严格遵守，不重开询问 | 世界地图 + 2D 俯视场景（D13）、点击移动与选 NPC 自动接近（D14）、自由文字贯穿与按钮同规则（D01/D12）、思考/输入暂停时间（D07）、本土/穿越可选与多出身（D11/D15）、深度成长（D17）、自由存档与完整世界恢复（D18）、首批三地与婚姻家庭（D20/D21）、电脑为主质量优先（D22）、动态 NPC 与人口事件平衡（D24） |

## 2. 视觉语言与语义 Token

组件样式只引用语义 Token（`--surface-*`、`--text-*`、`--tone-*`），不硬编码裸色值。以下 Token 已在 [`doupo-visual-direction.html`](doupo-visual-direction.html) 的「设计系统与对比度自检」抽屉中提供实时渲染与 WCAG 对比度验算。

### 2.1 表面与背景层级（Surface & Elevation）

采用青石与松烟墨的国风矿物色阶，依靠明度差与克制的古金/青灰细边区分层级，避免滥用大面积毛玻璃遮挡手绘场景：

| Token | 色值 | 来源状态 | 用途与约束 |
| --- | --- | --- | --- |
| `--surface-void` | `#0B1519` | 本轮深化 | 窗口外缘底色、死亡结局/全屏模态遮罩基底 |
| `--surface-canvas` | `#112026` | 本轮深化 | 2D 俯视场景画布默认底色（素材未加载或灰盒态下的保底地形底色） |
| `--surface-panel` | `#172A30` | **D4 默认（玄青）** | 主面板基底、顶部状态栏、底部自由输入与交流记录背板 |
| `--surface-raised` | `#1E343B` | 本轮深化 | 列表卡片、场景对象等价列表行、折叠抽屉内层容器 |
| `--surface-control` | `#263E44` | **D4 默认（深石）** | 按钮、输入框底色、选中区域、分段控制器与悬浮构件 |
| `--surface-hover` | `#2F4C53` | 本轮深化 | 交互控件悬停与键盘聚焦抬升态 |

## 3. 字体、排版与素材规范

### 3.1 字体栈与授权说明（Offline-First Typography）

原型与默认前端**零外部 CDN 依赖**，断网环境直接可用。针对桌面端中文字重渲染设置分级回落：

| 类别 | CSS Token | 字体回落栈 | 字号与行高规范 | 授权与随包说明 |
| --- | --- | --- | --- | --- |
| **标题与章回（宋体）** | `--font-display` | `"Noto Serif SC"`, `"Source Han Serif SC"`, `"Songti SC"`, `"STSong"`, `"HYSong"`, `"SimSun"`, serif | 场所主标题 `20–24px`、面板标题 `16–18px`，行高 `1.35`，字距 `0.04em` | 优先调用系统自带宋体；后续正式整包若内置子集化字体，推荐采用 **思源宋体（Source Han Serif SC，SIL Open Font License 1.1）**，可在 `.atria` 包内合法分发 |
| **正文与控件（黑体）** | `--font-ui` | `"PingFang SC"`, `"HarmonyOS Sans SC"`, `"MiSans"`, `"Microsoft YaHei UI"`, `"Noto Sans SC"`, `"Source Han Sans SC"`, system-ui, sans-serif | **交流叙事正文 `16–18px`、行高 `1.65`**；操作面板正文 `14–15px`、辅助标签 `12–13px`（严禁小于 12px 以防汉字笔画粘连） | 优先使用系统黑体；正式包若需统一跨平台字形，推荐 **思源黑体（Source Han Sans SC，OFL 1.1）** |
| **数值与坐标（等宽）** | `--font-mono` | `"JetBrains Mono"`, `"Cascadia Code"`, `"Consolas"`, `"Noto Sans Mono CJK SC"`, monospace | `12.5–14px`，全局开启 `font-variant-numeric: tabular-nums` | 用于游戏时间、距离丈数、银两数量、存档 Revision 标识（如 `exact rev·r18`）与帧率/耗时指标，保证数字列纵向对齐 |

### 3.2 文字密度与行宽控制

- **交流与叙事记录区**：单行最大阅读宽度控制在 `38em–44em`（约 680–760px），段间距 `0.85em`，长篇对话与事件回顾支持按「全部 / 当面交谈 / 行动结算 / 世情传闻」过滤与关键字检索，**严禁用固定高度 `overflow: hidden` 截断必要结果**。
- **两档界面密度（本轮建议）**：
  - `舒适（默认）`：正文 `16.5px`，列表行高 `40px`，适合日常沉浸对话与探索。
  - `紧凑（桌面宽屏可选）`：面板内距收紧约 `18%`，列表行高 `34px`，适合对比多条见闻、行囊盘点与家庭账目，**不隐藏任何状态标签或操作入口**。

### 3.3 美术素材来源与灰盒保底原则

- **零外部网络图片依赖**：[`doupo-visual-direction.html`](doupo-visual-direction.html) 中的世界地图、2D 俯视街巷/药谷、建筑屋脊、道路网格、遮挡树冠、人物小比例行走棋子（Sprite）与重点人物半身像（Portrait）全部采用**内联原创 SVG 与语义化 CSS 图层**绘制，可完全离线打开、缩放不失真。
- **素材失效保底（Graceful Fallback）**：所有场景对象、地块与人物均带有语义化 DOM 容器、坐标标签、轮廓边框与文字名牌；即便在未来真实集成时某张贴图未加载，玩家依然能通过**网格坐标 + 文字名牌 + 左侧「场景对象等价列表」**完成选中、移动与交互。
- **设定真实性标注**：乌坦城木石坊市、青山镇佣兵集结坪与幽涧药谷的具体建筑布局、以及韩石（掌柜）、林青（学徒）、柳狰（采药客）、苏婉（伴侣）、石猛（向导）等人物造型，均明确标注为**「游戏美术推导与原创生活角色演示」**，不伪称小说原著给出了精确建筑图纸或固定剧情。

### 4.2 2D 俯视场景与人物尺度规范

| 视觉层级 | 尺度与透视规范 | 交互与无障碍要求 |
| --- | --- | --- |
| **场所底图与建筑构件** | 采用顶视偏约 `25°–30°` 斜向俯视（Oblique Top-Down），展现屋檐、门楣、药柜、摊位与山石立面；基础逻辑网格按 `1 格 ≈ 0.5 丈` 换算距离 | 可进入建筑标明门廊入口与开放条件（如家族内院按身份开放）；不可通行区有清晰石墙/山崖边界 |
| **遮挡层（屋顶/树冠/迷雾）** | 位于人物上层的林木树冠或屋檐，在玩家或选中目标进入其下方、或开启「遮挡淡化（`Alt+V`）」时自动降至 `opacity: 0.28` 并带虚线轮廓 | 确保被树林或岩石半遮挡的药材点、伏击者与路径始终可辨认、可点击 |
| **人物行走棋子（Sprite）** | 场景内采用约 `44×56px`（100% 缩放下）的小比例国风立绘棋子，通过服饰主色、发髻/佩剑轮廓与底部阵营底座区分身份 | 鼠标悬停或键盘聚焦显示完整姓名、当前活动状态片（如 `正在盘点药材`、`准备入山`）；选中态增加 `#CBA568` 双圈高亮环 |
| **路线预览与交互距离圈** | 选中地面或 NPC 时，绘制古金色虚线路径与步点，终点标注预计耗时（如 `预计 +1 刻`）；NPC 周围绘制 `2.0 丈` 交互距离浅圈 | 区分「仅选中预览（0 耗时）」、「移动接近中」、「已抵达交互距离」、「路径受阻（炎赤叉号）」与「目标改道重算」 |
| **重点人物对话半身像** | 在右侧详情面板或展开式对话层中，展示 `120×140px` 国风手绘风格半身像，反映当前神态（常态、戒备、负伤、关切） | 辅助表达人物身份与当前处境，不遮挡场景中的位置关系 |

### 4.3 桌面分辨率与 200% 缩放适配规则

电脑为已确认的主要运行目标（D22）。布局针对四档关键视口进行验证：

| 视口 / 缩放档位 | 布局响应策略 | 必须保留的核心可操作项 |
| --- | --- | --- |

## 5. 核心游戏组件规范

### 5.1 账本与认识论印记系统（Epistemic & State Seals）

开放沙盒中「玩家知道什么」与「世界实际发生了什么」必须严格分离。所有信息条目、见闻、人物关系与存档状态统一采用**「外框形状 + 前缀图标 + 文本标签」三重编码**：

| 印记类型 | 视觉编码（形状 + 色调 + 前缀） | 适用场景与设计铁律 |
| --- | --- | --- |
| **亲见事实（Verified Fact）** | 实线方角框 + 玉髓色（`#68BD96`）+ `[亲见]` | 玩家当面目睹、亲自交易或已结算的权威状态（如「韩石已收下 15 金币押金」） |
| **坊间传闻（Rumor）** | 虚线圆角框 + 琥珀色（`#DFA052`）+ `[传闻·待核]` | 茶肆听闻、路人转述或隔日消息，注明来源与听闻时点（如「传闻幽涧药谷有凝血草，三日前采药客言」），**可能过时或有误** |
| **原著记忆（Canon Memory）** | 点划线框 + 绛紫色（`#B788C9`）+ `[原著记忆]` | 仅穿越者可见的个人初始记忆，**必须配注「本局历史可变，不保证按原著发生」**；当本局事实已偏离时并列提示差异 |
| **未知信息（Unknown）** | 点线暗框 + 雾青色（`#B5C9C8`）+ `[未知]` | 尚未探明的修为、未发现的机缘归属、NPC 私有心事。**严禁将未知画成 `0`、空进度条或默认友好的假数值** |
| **权威回执（Settled Receipt）** | 双线印章框 + 玉髓实心章 `[印·已结算]` | 交易已成交、移动已抵达、丹药已服下、存档已写入。**一旦出现回执印章，即便后续叙事生成或列表刷新失败，也绝不再显示重复提交按钮** |
| **阻塞/不可执行（Blocked）** | 斜纹底衬 + 炎赤色（`#E77C55`）+ `[条件不足]` | 境界不够、缺少火种/药材、目标已离开、非可进入区域。就近写明**具体缺失条件与合法出路** |

### 5.2 贯穿式自由输入栏与「目标漂移防误发护栏」

自由输入栏（`Pervasive Action Composer`）是玩家与世界交互的中枢组件，包含四个强制子区：

1. **当前绑定目标胶囊（Bound Target Pill）**：
   - 实时显示：`对谁/何处：[掌柜·韩石] · 所在：百草堂柜台 · 距离：1.4 丈（可当面交谈）`。
   - 提供 `[切换为场景环境行动]` 与 `[重绑至当前选中对象]` 快捷按钮。
2. **目标漂移防误发护栏（Target Drift Guard）**：
   - **触发条件**：当玩家输入框内已有非空草稿（编辑时绑定目标为 `Target A`），此时玩家在画布上点击了另一个人物 `Target B`，或 `Target A` 因自主日程离开了当前场所。
   - **表现规则**：**严禁静默把针对 `Target A` 的草稿改发给 `Target B`**！输入栏上方立即弹出琥珀色护栏，并锁定「直接发送」，要求玩家显式选择：`[追上原目标 (韩石) 后发送]`、`[显式改绑至新目标 (柳狰)]` 或 `[暂存草稿，先查看新目标]`。
3. **多行自适应输入框与 IME 保护**：
   - 支持单行简短指令至多行复杂战术/长篇交涉（最大增高至视口 `32%` 后内部滚动）。
   - 监听 `compositionstart` / `compositionend`：中文拼音/五笔选词期间按 `Enter` 仅完成上屏，不触发提交；非组合状态下 `Enter` 提交行动，`Shift + Enter` 换行。
   - 提交失败、条件不足或被拒绝时，**100% 保留原输入文本与光标选区**，绝不吞稿。
4. **双阶段等待状态条（Rule vs. Narrative Progress）**：
   - 阶段一 `规则校验与结算中`：显示不定式水墨脉冲条（无真实百分比时不伪造 `73%`），锁定会产生世界冲突的并发行动按钮，但允许继续修改下一条草稿或查阅已知面板。
   - 阶段二 `世界结果已生效 [印] · 正在生成人物回应`：立即在记录流顶部展示已生效的结构化事实（如「耗时 1 刻 · 银两 -20 · 获得回气散 ×1」），若模型生成超时或失败，仅提供 `[重试叙事生成（不重扣银两）]`。

### 5.3 关系、婚姻与家庭面板组件（F08）

- **非对称关系卡片**：摒弃单条 `好感度：85/100` 的数值条，改为展示：
  - **已发生事实与契约**：婚姻/婚约状态、亲属血缘、欠债/承诺期限、共同居所。
  - **已知经历驱动的印象标签**：`信任：深厚`、`亲近：相知`、`敬意：认可`、`紧张：担忧`，每项必须附带玩家可知的具体事件来源（如 `因「东坊垫付药资」与「按期归家」`）。
  - **隐私边界声明**：明确标注 `NPC 私有真实盘算与未公开秘密由其独立视角持有，界面不提供全知窥探`。
- **家庭共同生活与协商卡**：
  - 区分**个人行囊**与**家庭共同物资（居所银箱、存粮、药材储备）**。
  - 展示伴侣（如苏婉）与子女（如幼子萧宁远）的**今日自主目标与作息**，伴侣对玩家的提议（如长期入山、动用共同积蓄、携子迁居）可呈现 `[同意]`、`[提出折中条件]` 或 `[因照看幼子/自身生计而婉拒]`。

### 5.4 完整世界读档与分支恢复对比卡（F10）

- 读档对话框不只有「载入」按钮，必须并列展示**「当前分支状态（将被留在原分支）」**与**「目标存档快照（exact revision 将恢复的完整世界）」**的差异摘要：
  - 游戏时间与所在场所变化；
  - 关键机缘归属与库存回退（如已被夺走的凝血草恢复为未采状态）；
  - 人物伤势、生死、关系与记忆回退范围；
  - 动态人口计数与在途计划重绑说明；
  - 明确提示：**「载入后将从历史 Revision 派生新分支，当前分支未完成的后台模型请求将被隔离丢弃，不会写回恢复后的世界。」**

## 6. 动效、减动与性能目标

### 6.1 动效与过渡 Token

| Token | 建议值 | 用途与因果语义 |
| --- | --- | --- |
| `--dur-fast` | `100ms` | 场景对象选中高亮、按钮按压、面板标签切换（对齐 `presentation.md` 普通反馈 `~100ms` 候选目标） |
| `--dur-normal` | `200ms` | 侧栏折叠/展开、详情抽屉滑入、路线预览浮现 |
| `--dur-scene` | `360ms` | 角色沿路径移动步进、战术分段位移演示、场所切换淡入 |
| `--ease-out-ink` | `cubic-bezier(0.22, 1, 0.36, 1)` | 面板展开与棋子落定，干脆不拖沓 |

### 6.2 动效铁律与减少动态效果（Reduced Motion）

1. **动画时长绝不等于世界时间**：浏览器中棋子走路动画播放 `360ms` 或 `0ms`，世界时钟都严格按权威路线结算（如 `+1 刻`）推进；输入与操作**永远不等待装饰动画播完才允许下一步**。
2. **减少动态效果（`prefers-reduced-motion: reduce` 或原型内「减动模式」开关）**：
   - 关闭所有位移动画、呼吸光效与脉冲循环；
   - 场景移动直接跳至目标终点或中断点，并用文字气泡与路径实线标明结果；
   - 面板抽屉与模态框瞬间显隐，不损失任何状态信息。
3. **性能候选目标与诚实边界**：
   - 普通选中与面板反馈朝 `≤ 100ms` 优化，基础 2D 画面朝 `60fps` 优化（当前 Canvas 约束为单边 `2048px`、每批 `2048` 条绘制命令）。
   - **诚实声明**：上述数值为设计目标；真实模型等待耗时、大步长世界追赶延迟与接近上限时的动态人口结算开销，必须由后端在真实负载下实测，绝不由前端原型的本地 `setTimeout` 演示计时器推导。

## 7. 键盘、IME 与无障碍规范（Accessibility）

1. **全功能语义化控件**：所有可交互元素必须使用原生 `<button>`、`<input>`、`<textarea>` 或带完整 `role` / `tabindex="0"` 及键盘事件处理的语义节点，禁止仅绑定鼠标 `onclick` 的裸 `<div>`。
2. **2D 场景的键盘等价路径**：
   - 2D 画布内的所有人物、设施、采集点与出入口，均同步映射至左侧**「场景对象与可达列表」**。
   - 玩家完全不触碰鼠标，仅凭 `Tab` 键进入对象列表、`↑/↓` 选择目标、`Enter` 预览或接近、再按 `/` 聚焦底部自由输入框，即可完成全部移动、对话、争夺与战斗操作。
3. **快捷键与输入框/IME 隔离**：
   - 全局快捷键（如 `[` 折叠左栏、`]` 折叠右栏、`1–8` 切换功能工作区、`Escape` 关闭顶层抽屉）在焦点位于 `<input>` / `<textarea>` 或 `isComposing === true` 时**自动静默禁用**，防止打字误触。
4. **焦点管理与层栈（Layer Stack）**：
   - 所有浮层（角色创建、世界地图、战术交锋详情、读档确认、宿主门诊断）共用单一层栈；按 `Escape` 每次仅关闭最顶层，并将键盘焦点精准归还给触发按钮。
   - 焦点环采用双层高对比描边（`2px #0B1519` 内衬 + `2px #CBA568` 古金外环），在深浅背景与 `forced-colors` 模式下均清晰可见。
   - 状态变化（如「目标已改道」「交易已结算，叙事生成失败」「世界已恢复至第 11 日」）通过 `aria-live="polite"` / `"assertive"` 区域向读屏软件播报。
