# 原生前端：众生行体验重构

当前版本 `0.1.0-combat.2`，规则继承 `0.1.0-combat.1`，Task ID `package/doupo-living-world`。2026-10-24 起前端按方案 `docs:plans/package/doupo-living-world/frontend-redesign.md` 重写：规则、screen 字段、Bridge 绑定与宿主控制不变，只重做玩家看到和操作的部分。下文“C4表现与操作”及其后各节保留为既有能力与验证历史；与本节冲突处以本节为准。

## 界面层级（重构后）

三层：**场景**常驻（全幅场景图、Q版人物、物件铭签、点地面行走）→ **情境**占据场景但不替换它（相处、交易、交锋、光阴流转）→ **四卷**从右侧展开、半掩场景（己身：修为/法门/身体/行囊；人间：人物/家/约定/关系；江湖录：委托/此地活动/见闻/书信/往事；山河：地区/大陆）。Esc 由内向外逐层关闭，最后回到城中总览；C/R/J/M 开卷。存档、字号与宿主控制在“歇息”。

视觉为“墨框纸卷”：玄青外框，宣纸资料面，朱砂“落印”只用于会推进世界的动作，并写明耗时；信息条目带出处印（亲、闻、信、忆、谈、告）。只有重大动作（远行或长时安排、发起交锋、提亲成家分离、冲关、换修、读档、退出）弹出二次落印，其余动作落印即行。

## 文件与状态预算

- `Game.aui`：唯一模板。`state.mjs`：唯一状态声明。Native 编译器把整份组件状态 schema 限制在 256 节点、每个记录 128 键，因此可见性全部由一个 `stage` class 串控制（CSS 决定显示什么），互斥的层共用四个通用列表 `rowsA–D`，每个列表项都是同一个 10 字段行（k/t/s/x/p/v/b/c/d/m）。当前约 212 节点。
- `view.js`：公开 screen + 本地表现状态 → 各区域视图（纯函数，不写世界、不读私有域）。`pack.js`：把区域视图压进扁平状态与共享列表。
- `main.js`：读取、串行写入、revision/key、自动续行与停手、草稿防误发、恢复重挂载（语义沿用旧控制器），外加层级、按钮令牌分派和光阴流转记录。键盘由根节点统一接收。
- `game.css`：token、组件、可见性规则与生成的格位类。`client.js` 不变。
- 战斗与行走沿用 20×14 网格按钮；两步内可达格只是显示提示，结算以规则为准。人物立绘与 Q 版、物品图仍走 `media` 绑定（CSS 资源会在启动时整批加载，不用于人像）。
- 不确定的提交在重读后若世界 revision 未动、且没有进行中的表达，判定为未落成并释放，保留草稿；revision 已变则仍按旧规则保持待核对。

## C4表现与操作

- 新局按构建导出的BINDINGS（content.1为bind0至bind5）、create、initialize/appraise/refresh执行，零耗时居民准入与公开刷新结束后进入可操作状态。用户不必逐次点击初始化。区域名称来自同一公开REGIONS；三十二场所均由地理池声明场景图片；黑岩城、石漠城、塔戈尔外缘各有专属总览。
- 地图仅消费独立markers及主角appearance，人物列表消费people；地图上限12，截断提示明确。Q版与详情画像取同一appearance的chibiAsset/portraitAsset，不按姓名猜图、不重抽外观。无图明确回退文本。
- 选人调用零耗时focus；不自动接近。标记位于另一人物页时，经当前附近分页找到合法详情再选中。失去感知、换地点与恢复清理失效选择。附近与已知旧档案可切换，旧档案不能用于实时定位/交互。
- 人物/修行展示实际arts，区分已学、持有秘籍、当前修习、资格、收益与斗技消耗；换修传art id，研习传秘籍item id。身体展示已知伤处、缺失、能力限制、器物耐久/余量和治疗/装备/维修操作。
- 人间保留交往、约定、家庭、赠礼与传授，并展示本人关系认识、寄信与释放入口；读口不泄露NPC私人目标。见闻提供来源、时点、书信和事件分页详情，行程包含实际本地生产信息。
- 自由文字沿宿主composer接口进入真实解析路线，保留目标/地点/分支；Ctrl/Cmd+Enter提交，Enter换行，组合输入不误送。失败保稿，未知提交用同revision/key核对，不自动重做交易。
- 保存/恢复使用Native SavePoint与Branch/Epoch；恢复后重挂载，清除旧选择、草稿和叙述。生成停止与规则活动停止分开。

## 构建与美术

`tools/frontend.mjs`复用`tools/interfaces.mjs`生成C4绑定，宿主schema从当前core读取。静态catalog仅传公共地点、路线、出身与物品，不含CAST私有动机。

交付107张图片：60张池配对图，加47张场景/物品/总览与占位引用；未使用的旧人物画像不进入运行资源图。作者原图与来源仍保存在原目录；前端交付以已安装的Apache-2.0 jsquash工具编码WebP，quality90/method6，保留像素尺寸。Native安装资产与前端图像使用同一交付字节及稳定asset id。`media/pools/manifest.json`记录原图，`frontend/media-delivery.json`记录原始hash/尺寸/编码后体积，安装manifest记录交付hash/体积，三者用途不同。

可选`ATRIA_MEDIA_CACHE`指定仓库外的作者图片编码缓存，key包含原始hash和编码参数；不进入包、不包含世界或用户数据。构建采用所选core的媒体预算（当前单媒体16MiB、媒体库256MiB）；结构预算与运行缓存分开，详细规范见产品`docs/development/native-media-capacity.md`。重要人物18对与普通NPC12对仍是静态姿态，不包含方向行走动画。场景图装饰人物不代表运行时NPC；网格/坐标依规则，建筑画面未逐像素标定为碰撞图。

## C6 战斗、功法与现场遗留

正式字段与动作只以 docs 的 frontend-contract C6 和包内 integration/screen.schema.json 为准。交锋控件直接发送同一 Authority 动作，普通战中动作使用 act(kind=battle)，轮号在qty中；初次危险接触走choice。锁定、结算和世界清算时禁用主要行动；同伴下拉只显示本页实际同方活跃者。全库可选，分页只影响参战者／法门／尸身展示。

隐藏battleStep只推进已锁定的收集／执行／战后步骤；死亡登记、个人评价和世界钟继续走普通continue。菜单暂停不撤销决定，继续从保存的队列游标推进。Controller仍负责CAS、重复操作和epoch隔离；输入与选技不增加补间或键盘等待。

现场遗留页每页三具可见尸身，只有近身查验后才显示原库存。取用复用通用数量输入；投降金币使用独立草稿，不能污染书信。原器物保留实例身份、损耗和余量。与原布局同用焦点环、按压／禁用状态、滚动与reduced-motion规则；没有添加依赖或独立设计系统。
