# Native 素材容量与运行缓存

Task ID：feat/native-media-capacity。Primary Workspace：main。状态：已完成，2026-10-23。起点 main@4470cffb，交付 main@16aa49f1。用户在斗破 atlas.1 完成后授权调整框架容量与加载机制，允许依据游戏需求优化框架。实际证据见[Record](../../records/feat/native-media-capacity.md)。

## 目标与取舍

将大型素材库的存储预算与代码/界面复杂度、活跃缓存分离，消除32MiB总图谱对现有游戏高画质资源的阻挡。保留哈希、资源声明、权限、结构与执行预算。当前容器仍整包加密/解密，HTTP旧接口还使用base64；不能把一个常量改到1GiB就宣称完成GB级流式资源系统。本轮按当前架构落实可验证的过渡容量：媒体库256MiB，结构源/IR仍32MiB、单结构2MiB；单本地媒体16MiB；媒体4096条、结构清单维持256条；容器512MiB、解压1GiB。1GiB作品是后续流式容器/传输目标，不在未压测时承诺舒适运行。

## 实现

1. 前端共享契约按资源类型分开预算，作者编译、安装验证和浏览器加载使用同一限额；不放大命令、DOM、脚本内存或关系状态预算。
2. 本地精确媒体使用引用计数与闲置LRU，编码字节缓存64MiB。展示中资源不淘汰；读完生成Blob后释放重复字节缓存；切图、显式隐藏图片、卸载及迟到结果释放租约，CSS静态资源随界面生命周期持有。并发加载预留预算，失败释放，重新进入可重载并重新验hash。该预算不是解码像素/GPU内存上限。服务端解析缓存独立256MiB/8条，每次仍验原包并隔离返回数据。
3. 安装包及用户导入入口统一容量，保持压缩比/条目数/路径/权限检查。HTTP大型输入避免无条件扩大所有请求；只调整作品上传路径及对应客户端预检。MCP专属临时上传保留独立预算并明确边界。
4. 斗破重新以quality90生成新版本，旧atlas.1兼容包保留。验证框架后按治理集成main，游戏按新main重包验收。
5. 实际高画质回归发现规则缓存键对所有图片作UTF-8/JSON转换；改为直接哈希原始字节，保留全文件身份、模块变更失效与执行预算，避免大素材库引发无用文本分配。
6. 收尾诊断捕获新局precondition在输入freeze阶段触发QuickJS interrupted，证实服务端事务沿用浏览器40ms限额不足。将服务端单阶段时间预算从浏览器常量分离，设100ms，浏览器仍40ms；输入冻结减少原始值递归，保持深层不可变、8MiB堆、输出及事务总工作预算。以无限循环中断、嵌套冻结及真实新局验收；这是本轮发现后的明确方案调整，替代前文“不扩大执行预算”对服务端单阶段时间的约束。

## 验证

边界：大于旧32MiB的真实媒体集合、单媒体超过旧2MiB、媒体数超过256；结构/媒体超限、哈希破坏、资源类型伪造仍拒绝。缓存验证并发去重、预算预留、LRU淘汰、使用中保护、失败重试、迟到结果、卸载释放。实际Native安装、浏览器切图和斗破游戏回归。测试脚本/大样本只放仓库外。根据实际打包路径检查容量与内存，不把声明上限当作1GiB性能证据。完成后记录结果、提交/本地集成main/同步已提交产品结果，保护其他工作树与dirty文件。
