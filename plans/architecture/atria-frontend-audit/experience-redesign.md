# Atria 前端体验重构蓝图（重新评估稿）

> **性质：方案（建议）**。本文在实施前重新评估整个前端体验：信息架构、功能组织、导航、交互与首次使用。依据优先级固定为：
>
> 1. **主依据**：[`design-proposal/`](design-proposal/) 三份文件——[设计指导](design-proposal/atria-frontend-guidelines.md)、[功能表现](design-proposal/atria-function-presentation.md)、[HTML 原型](design-proposal/atria-visual-direction.html)。
> 2. **次依据**：Apple 的设计取向（清晰、顺从内容、直接操作、渐进披露、一致性、细节），只用来补足和打磨主依据，不推翻它。
> 3. **现有前端**：只作功能清单与问题来源，不作设计标准。现有实现的布局、控件与流程不因「已经存在」而保留。
>
> 产品能力边界、状态词与写入顺序仍以审计清单与实施输入为准；本文不扩大 P-01～P-11 的范围，凡偏离主依据之处都在 §10 单独列出理由。

## 0. 一句话结论

现在的前端「看起来像 Atrium」，但**用起来不像**：它把内部对象模型（Connection / Secret / Model / Program / Generation / Route、Program / Module / Stage / Anchor、Package 原件 / exact revision）原样摆给用户，让用户先理解架构才能做事。重构的核心不是换皮，而是**按用户的任务重排每一屏**：先让人完成事情，再在需要时把精确性（账本语法）展开给他看。

### 1.6 根因

1. **按存储对象而非用户任务组织页面**（P3、R4、W3）。
2. **缺少「默认路径」**：每个能力都只给了全功能专家表单，没有一条「推荐、可一步完成」的路径（R3、P1、P5）。
3. **账本语法用错了位置**：精确性信息（exact、revision、原件）被铺在首屏，而真正需要诚实的地方（就绪链、Memory 开关）却画了假状态（R1、N6）。
4. **组件层没有收敛**：头部、列表-详情、空状态、导入、返回在每个域各写一套（N8、P4、W1）。
5. **遗留 ST 外壳仍在运行时生效**（F1、N7）。

## 2. 设计北极星

保留主依据的**三种语域**（舞台 / 工作台 / 账本）和**六条原则**不变，再加四条从 Apple 借来、用于约束实现的工作规则：

| 规则 | 含义 | 对应主依据 |
| --- | --- | --- |
| **A1 先做事，再解释** | 每屏有一条推荐路径，可在不理解内部对象的情况下完成；精确信息在用户问「为什么」时展开 | §5.2 按需披露 |
| **A2 一个地方，一种做法** | 同一种操作（新建、导入、返回、删除、选择资源）在全产品只有一个组件、一个位置、一套文案 | §4.1 组件分层 |
| **A3 直接操作** | 能在原地编辑就不跳页；能在列表行内新建就不要求先去别处建好 | §3.6、Q05 |
| **A4 克制的仪式** | 动效只在空间转换时出现；启动、加载不为氛围让用户等待 | §8 |

**判断一个屏幕是否合格的四问**：用户来这里要做什么？推荐路径是否一眼可见、≤3 步？出错时是否在原位说清原因和出路？这屏是否只有一个金色主按钮？

## 3. 信息架构

### 3.1 五域不变，域内按任务重排

五域（故事 / 书库 / 工坊 / 智能体 / 运行）与 utility 的划分沿用功能表现 §1.1。调整只发生在域内：

```text
故事 Play
├─ 首页：继续阅读（大卡）· 最近故事 · 空时「开始的三件事」(§4.1)
└─ 会话：舞台 · Composer · Inspector（默认关）· 宿主门

书库 Library            —— 统一「列表-详情」骨架（§5.2）
├─ 作品  ├─ 我的故事  ├─ 世界与知识  ├─ 提示词  ├─ 角色(Persona)  └─ 图像
│   （「Prompt 预设」改称「提示词」，「Image studio」改称「图像」；英文副标签保留）

工坊 Studio             —— 编辑器-Inspector 骨架
├─ 项目列表（卡片）
└─ 项目：资源树 · 编辑区 · Inspector/AI · Activity · 顶栏「审阅变更 N」

智能体 Agents           —— 图-Inspector 骨架
├─ Memory（默认）├─ 目标与反馈 ├─ 运行与编排（V3）└─ 诊断与回放

运行 Runtime            —— 新增「概览」作为默认子页
├─ 概览：就绪状态（按任务，而非按对象）+「连接模型」向导入口
├─ 连接 ├─ 模型 ├─ 路由 ├─ 检索 └─ 诊断（编译预览）
```

### 3.2 两个关键的重新切分

1. **运行域的心智模型从「六种对象」改为「任务 → 用哪个模型」**。用户看到的是「主叙事：用 Claude Sonnet（Anthropic）」「线索整理：未设置」；Connection、Secret、Program、Generation 作为该行的展开细节存在，而不是六张独立的配置页作为入口。六种对象的完整编辑页仍保留（专家路径，不删能力）。
2. **提示词的心智模型从「四种资源」改为「一份可写的提示词」**。打开一个预设，看到的是它的大纲（Stage → 条目）和正在编辑的正文；Program / Module / Generation / Regex 是大纲里的节点类型与侧栏分区，而不是四张入口卡片。

### 3.3 深链

统一为可读路径：`#/{domain}/{child}/{id}?rev={exact}`（功能表现 §1.2）。资源引用用稳定 ID，不在 URL 里序列化 JSON。所有子页、预设详情、扩展子标签可深链（P-05，建议采纳）。整页加载时直接进入深链目标，不播放启动封面。

## 4. 首次使用与关键流程

### 4.1 首次启动

- **冷启动且无任何故事**：直接进入「故事」首页的空状态，标题「开始之前」，三张真实入口卡片，按顺序编号：
  1. **连接一个模型**（主按钮，金色）→ 打开 §4.2 向导。完成后此卡变为「已连接 · Claude Sonnet」并带「更换」链接。
  2. **获取一部作品**：「安装 .atria」「导入存档」。不生成样例作品（G05）。
  3. **自己写一部**：→ 工坊「新建项目」，或学习中心「从零开始」。
- **有故事的冷启动**：直接回到上次阅读的 Session，启动封面只作为 ≤600ms 的淡出过渡；从未阅读过或通过深链进入时完全不显示。
- **遗留 ST 初始化**（角色、聊天、`active character` 检查）在原生 Shell 下不得产生任何弹窗；若需报告，进诊断。

### 4.2 「连接模型」向导（替代首次配置 6 种对象）

全屏层（D 为 560px 居中对话框，M 为全屏层），三步，每步一屏：

1. **选择服务**：卡片网格——Anthropic、OpenAI、Google、OpenRouter、DeepSeek、本机（Ollama / LM Studio）、其他 OpenAI 兼容服务、NovelAI（图像）。卡片只写名字和一行说明（「需要 API Key」「无需密钥 · 本机运行」）。adapter、transport、tool schema 由所选服务决定，用户看不到。
2. **填写凭证**：只出现该服务需要的字段（API Key；自定义服务额外显示 Endpoint）。Key 字段旁写明「只保存为引用，界面不再显示原文」。下方是**凭证目的地审查**（R04）的内联形态：展示目的地主机与指纹，一个**未预选**的复选框「允许把这个密钥发送到 api.anthropic.com」。不能跳过、不能预选，但它是这一步的一部分，而不是事后在另一页冒出的琥珀卡片。
3. **选择模型**：自动「获取模型」，列表按推荐排序，可搜索；获取失败时允许手填 ID（标 override 印记）。点「测试并完成」→ 发送一次最小测试请求（明确写「将发送 1 次测试请求，可能产生少量费用」）→ 回执。

**完成时**宿主在原服务上依次创建 Connection、Secret 引用、Model，并用官方基础 Program/Generation 为「主叙事」建立 Route，显示一张回执列出创建了什么（每项可打开）。任一步失败：保留已创建的对象并说明到哪一步、如何继续，不回滚、不重建（§2.3）。高级用户可在任何一步点「改用完整设置」进入原 Connections 编辑器，草稿带过去。

### 4.3 就绪状态（替代全绿就绪链）

运行 › 概览按**任务**列出，而不是按对象：

| 行 | 内容 |
| --- | --- |
| 主叙事（必需） | `已就绪 · Claude Sonnet · Anthropic` 或 `未设置 · [设置]` |
| 线索整理 / 插图提示 …（作品声明的槽位） | 仅当已安装作品声明时出现；可选项写「可选」 |
| Memory、搜索、编排等系统角色 | 折叠在「其他功能使用的模型」里；未设置时写明「这些功能会使用主叙事模型」或「此功能不可用」，取决于真实回退规则 |

就绪判断只认真实证据：**placeholder 连接、未测试的连接、端口不可达都不得显示为就绪**（显示 `未验证` 点线印记 + 「测试」）。每行展开才显示六环就绪链，缺的环节是虚线 +「修复」。

### 4.4 开始一个故事

作品详情 ›「开始新故事」时如需任务槽位（L07）：

- 只有一个可用 Route 且满足能力要求时，**预选并显示为建议**（标注「建议」而非静默绑定），用户一次确认即可开始。
- 缺 Route 时对话框内直接提供「连接模型」向导（§4.2），完成后回到此对话框并重新 preflight——不再跳到运行域再「完成并返回」。跳运行域的修复横幅（R14）仍保留给复杂情况。

### 4.5 第一次写提示词

书库 › 提示词 ›「新建」打开模板选择（对话框，卡片）：

| 模板 | 结果 |
| --- | --- |
| 空白 | 一个 Stage、一个空正文条目，光标在正文里 |
| 通用叙事骨架 | 预置「角色与职责 / 世界 / 记忆 / 历史 / 当前输入 / 输出要求」条目，每条有示例正文 |
| 角色扮演 · 文学创作 · Agent 任务 | 同上，内容不同 |
| 从文件导入 | 拖放区；预检后创建（导入身份映射见 Q09） |

创建即保存为草稿修订并出现在列表中（解决 P2）。随后进入 §6.4 的提示词编辑器，第一屏就能打字。

## 5. Shell 与通用骨架

### 5.1 Shell

- **Dock**：桌面默认「始终显示」，带文字标签（图标 20px + 标签 11.5px，或悬停展开标签——由 §11 决定）；「阅读时隐藏」只在 Play 会话内生效，且首次使用时先完整展示 Dock 再淡出，并在边缘留 4px 可见把手 + 键盘焦点可唤出。四边吸附、鱼眼保留为可选项（主依据 §3.4），默认不开鱼眼。
- **Workspace Header（统一）**：所有域共用一个头部组件，结构固定：
  `[返回/面包屑] [对象标题] [印记/状态片] ……… [域工具：带文字的按钮 ≤3 个 + 溢出菜单] [主按钮] | [搜索] [全局菜单] [账户]`
  - 域工具默认**图标 + 文字**；只有在窄宽度时折叠为图标，并保留 tooltip（桌面）/ 长按标签（手机）。
  - 域「更多」用 `more-horizontal`，全局菜单用 `grid`，两者图标不同、分组之间有分隔。
- **灵动岛**：保持主依据 §3.5；无活动时不渲染。
- **返回**：每屏只有一个返回入口（面包屑上一级或左上返回），遵循层栈。去掉「Back to presets / Back to preset / Back to resources」这类就地多返回。

### 5.2 列表-详情骨架（书库、Persona、运行各子页、扩展）

```text
┌ 工具栏：搜索 · 过滤分段 ……………… [导入…] [新建]（主按钮）┐
├ 列表（可选中行/卡片，整行可点）  │ 详情（标题区 · 印记 · 主动作 · 分区）   │
│  ─ 我的                          │                                        │
│  ─ 来自作品（只读原件）          │                                        │
└──────────────────────────────────┴────────────────────────────────────────┘
```

- **新建**统一是工具栏右侧主按钮；需要名字时在对话框里问，不在列表顶部常驻输入框（W4）。
- **导入**统一是一个按钮 → 拖放区对话框（文件选择、大小上限、预检、结果），不出现原生 `<input type=file>` + 第二个「导入所选」按钮（P1）。
- **分组**：「我的」与「来自作品（只读）」是同一列表里的两个分组；空状态只在**所有分组都为空**时出现（W1）。
- **详情未选中**：显示该类资源的简短说明 + 主按钮，而不是一句灰字。
- **行/卡片整行可点**，次要动作放溢出菜单（W2）。

### 5.3 编辑器-Inspector 骨架（工坊、提示词、World/Knowledge 编辑）

左：大纲/资源树（可收起）；中：正文或结构化表单；右：Inspector（依赖、修订、Used By、来源，按需打开）；底：Activity（按需）。头部固定显示「草稿 · 基于 rev x」印记和唯一主按钮（「审阅变更 N」或「保存修订」）。所有编辑器支持「字段 / 原文」分段编辑同一草稿（主依据 §5.1）。

### 5.4 状态、空、错误

统一一个 `StateView` 组件承载空 / 加载 / 部分失败 / 错误 / 无权限，文案遵循「发生了什么 + 为什么 + 怎么办」。开关依赖总开关时，子开关在总开关关闭时**显示为禁用且保留其值**，并在组顶部给出横幅（N6）。

### 6.4 提示词编辑器（书库独立创作与工坊 Prompt 编排共用）


- **大纲即 Program**：Stage 与条目按实际有效顺序显示（唯一顺序权威是 Host，主依据 Q05）。作者条目（实心点）与来源贡献（`⌁`，只读展开）字形不同。继承自父版本的条目显示继承印记，替换/禁用/新增各有标记。
- **就地新建**：在任意 Stage 下「添加条目」直接创建 Module 并打开正文；Stage 有可编辑的显示名，ID 自动生成并只在 Inspector 中显示（P5）。

- **生成参数、Regex** 是大纲底部的两个固定节点，打开后在编辑区显示对应表单（Q06/Q07 的「默认/显式」标记）。
- **预览 ▾**：Authored / Effective / Provider Wire / 与某修订对比，作为编辑区上方的分段视图按需打开（主依据 Q12）；未接通的层显示 `BLOCKED` 印记，不伪造。
- **保存语义**：头部主按钮文案随入口变化——书库里「保存修订」，工坊里「加入 ChangeSet」；分享、发布、采用是溢出菜单里的独立动作（Q08）。

保持原型（Memory 默认，图/列表，控制栏 + 实体 Inspector）。修正 N6：Memory 关闭时，控制栏顶部横幅「Memory 已关闭 · 故事不会记住新事实 · [开启]」，子开关禁用并保留其值；统计显示「—」而不是 0（未知≠0）。分段控件留足宽度。V3 运行与编排按主依据保持「设计目标」诚实标注。

### 6.6 运行 Runtime

- 默认子页「概览」（§4.3），顶部是「连接模型」次要按钮（已连接时）或主按钮（未连接时）。
- 连接编辑器分两层：**基本**（服务、名称、Endpoint、密钥、测试）默认展开；**高级**（transport、tool schema、gateway mode、超时）折叠，写明「大多数服务不需要修改」。

## 7. 视觉与图标

### 7.1 图标体系

- **唯一来源**：`atria-shell/icons.js` 的 24 网格 1.6px 线描集。所有原生页面、对话框、菜单只用它；Font Awesome、Unicode 字形（✦ ▸ ↑）、原生 `<details>` 三角在原生 Shell 内一律替换。保留的 FA 只允许出现在尚未清退的遗留 ST 页面中。
- **三档尺寸**：16（行内、按钮小）/ 18（按钮、列表）/ 20（Dock、空状态标记），线宽在 16px 时视觉补偿为 1.7，避免细线发灰。
- **语义唯一**：一个含义一个图标，一个图标一个含义。建立对照表并在 `icons.js` 里用语义名导出（`action.review`、`panel.inspector`、`domain.runtime`），禁止在业务代码中按形状名引用。示例修正：
  - 三个面板开关：`sidebar-left` / `sidebar-right` / `panel-bottom`，形状必须一眼可分。
  - 「运行」域当前是芯片图标，与「模型」概念冲突且在 20px 下细节糊——改为路由/节点类（`route`）或仪表（`gauge`），由 §11 决定。
  - 「设置」当前是滑杆，与 Play「选项」同形——设置改用齿轮线描，选项保留滑杆。
- **光学对齐**：图标与文字基线对齐（按钮内 `translateY(.5px)` 校正），图标按钮命中区 ≥ 32px（D）/ 44px（M）。
- **按钮内图标**统一在文字左侧；仅图标按钮必须有 tooltip（D）与长按标签（M）。

## 8. 动效

- 采用主依据 §8 的 token。Sheet、Dock 换边、灵动岛展开使用可中断的弹簧（`--ease-snap`），时长 280–460ms。
- 页面/标签切换：内容区 120ms 交叉淡入 + 4px 位移，不移动 Shell。
- 启动封面：仅冷启动且有上次阅读时使用，≤600ms，可点击跳过，深链与 reduced-motion 下不出现。
- 禁止：加载时的装饰动画、等待用户看完的过场。

## 10. 与主依据不同的判断

| 主依据 | 本文 | 理由 |
| --- | --- | --- |
| Dock 默认「智能：阅读时隐藏」（§3.4、原型默认左边） | 默认「始终显示」；只在 Play 会话内阅读时隐藏，且首次先展示 | 实测首次用户看不到 Dock（N1）；主依据同时要求「隐藏后可发现」 |
| 就绪链横向六环作为运行域首屏（R02） | 首屏按任务列出，六环在行内展开 | 六环要求用户理解六种对象；能力与证据不变，只改呈现层级 |
| 修复往返：跳运行域 + 横幅 + 完成并返回（R14/L07） | 常见情况在槽位对话框内直接调用连接向导，复杂情况才跳转 | 减少一次上下文切换；R14 能力保留 |
| Prompt 预设详情：Program/Modules/Generation/Regex 标签页（Q02） | 大纲统一承载四类，Generation/Regex 为大纲固定节点 | 主依据 §5.1/§3.2 已要求「大纲 + 编辑 + Inspector、默认聚焦原文」，标签页形态与之冲突，取后者 |
