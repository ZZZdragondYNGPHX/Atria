# Atria 前端设计指导（建议稿）

> **性质：讨论输入**。本文给出统一的视觉语言、布局、组件、表单与数据密度、响应式、中英文、主题与自定义、动效与一致性规则，供用户和开发 AI 多轮讨论。用户确认之前，这里的任何审美、布局或组件形态都**不冻结**，也不构成实施授权或技术栈决定。
>
> 配套材料：[`atria-visual-direction.html`](atria-visual-direction.html)（「04 设计系统」可以实时查看 token）、[`atria-function-presentation.md`](atria-function-presentation.md)（189 项功能的位置与交互）。产品能力的依据仍然是 [前端审计](../index.md) 和原有的正式合同。

本轮原型修订保留 Atrium、Nocturne/Folio、暖金色、Stage/Workbench/Ledger 与语义状态系统，在原 HTML 上细化导航、活动和工作区，不从零重建。当前 HTML 是用户重新提供的修订稿；本文描述其视觉与交互方向，产品接线与采用范围归[实施输入](../claude-code-frontend-prompt.md)。原型不代表这些能力已经接入应用。

## 1. 设计立场

### 1.1 一座「中庭」，三种语域

Atria 要同时做三件差别很大的事：舒适的长篇阅读、精密的创作与运维、可信的版本／权限／恢复。方向名「中庭 Atrium」的意思是：结构安静克制，光只落在故事上。

| 语域 | 用在哪里 | 气质 | 主要手段 |
| --- | --- | --- | --- |
| **舞台 Stage** | 故事会话、作品界面、插图 | 沉浸、温暖、少打扰 | 衬线长文、36em 版心、作品氛围光、大圆角、低对比的宿主控件 |
| **工作台 Workbench** | 书库、工坊、运行、智能体、设置、存储 | 精确、可扫描、密度可调 | 无衬线 + 等宽、发丝线、登记角标、小圆角、两档密度 |
| **账本 Ledger** | 贯穿两者：修订、引用、回执、审批、冲突、未知 | 可信、不含糊 | 形状 + 图标 + 文字三重编码的印记、状态片、回执、横幅 |

舞台和工作台可以在同一屏共存（故事页右侧的 Inspector 就属于工作台语域），账本语法则在两者中保持完全一致。

### 1.2 六条原则

1. **光只给故事**：金色（Lumen）只用于故事之光和每屏唯一的主意图。
2. **真相有形状**：每种版本或可信度状态都有独立的形状，灰度、色盲和 forced-colors 下仍可辨认。
3. **同等能力，不同姿态**：手机不是只读版；布局可以不同，能做的事必须相同。
4. **作品接管舞台，宿主永远留门**：Work 可以重写舞台，但退出、停止、保存、Persona、诊断、重载永远可达。
5. **按后果命名操作**：按钮文字说它真正改变了什么，不用笼统的「确定」或「撤销」。
6. **不画假的绿灯**：NOT_RUN、UNKNOWN、source_unready、BLOCKED 是一等视觉公民；没有证据就不显示成功，没有来源就不显示数值。

## 2. 视觉语言

### 2.1 色彩：语义 token

组件**只**引用语义 token，主题只替换 token 的值。原色值（`--raw-*`）只出现在主题定义里。

| 类别 | Token | 用途 |
| --- | --- | --- |
| 表面 | `--surface-void` `app` `stage` `paper` `panel` `raised` `hover` `press` `input` `scrim` | 层级靠明度区分，不靠阴影堆叠；`stage` 和 `paper` 只给舞台语域 |
| 线 | `--line-1` `2` `3` `strong` | 发丝线分隔；`strong` 用于登记角标和只读虚线 |
| 文字 | `--text-1` `2` `3` `4` `inverse` | 1 是正文，2 是次要，3 是说明，4 只用于占位和装饰（不承载信息） |
| 语义色 | `--tone-lumen` `lapis` `jade` `amber` `vermilion` `umber` `dai` | 见下表 |
| 柔和底 | `--soft-*` | 语义色约 10% 的底色，用于印记、横幅、选中行 |
| 作品氛围 | `--mood-a` `--mood-b`（RGB 三元组） | 只影响舞台的天光和渐变，作品可以设置 |

**七个语义色**取名自「金 青 玉 琥 朱 赭 黛」，每个只承担一种含义：

| 色 | Token | 含义 | 不要用于 |
| --- | --- | --- | --- |
| 金 Lumen | `--tone-lumen` | 品牌、每屏唯一的主意图、故事之光、当前选中项的标记 | 成功、警告、装饰性高亮 |
| 青 Lapis | `--tone-lapis` | 草稿、信息、选区、焦点环、链接式按钮 | 已提交的状态 |
| 玉 Jade | `--tone-jade` | 已提交、就绪、在线、实时 | 「建议」或「推荐」 |
| 琥 Amber | `--tone-amber` | 注意、待处理、预算、过期 | 错误 |
| 朱 Vermilion | `--tone-vermilion` | 危险、拒绝、错误、缺失 | 停止按钮（停止用中性色） |
| 赭 Umber | `--tone-umber` | 历史、只读、归档 | 禁用态 |
| 黛 Dai | `--tone-dai` || 「信息」 |

**规则**：

- 语义色永远和形状、图标或文字一起出现，不能单独靠颜色传递状态。
- 一屏最多一个金色主按钮。
- 承载文字的语义色在其背景（`panel` 和 `app`）上的对比度要 ≥ 4.5:1；正文 `text-1` 和 `text-2` 要 ≥ 7:1。HTML「04.1」会实时计算并标出 AA/AAA。本稿已据此把昼 Folio 的玉色从 `#2c8660` 调到 `#226f4e`，琥色从 `#b26a17` 调到 `#935509`（原值 4.12 和 3.88，低于 AA）。
- `text-4` 低于 3:1，只能用于占位符和纯装饰。

### 2.2 两套主题

| 主题 | 气质 | 主按钮 |
| --- | --- | --- |
| **夜 Nocturne**（默认） | 墨底、暖象牙字、金色是唯一的暖光 | 金色渐变 + 深色字 |
| **昼 Folio** | 宣纸底、墨字、金退成赭金 | 墨色实心 + 象牙字（在浅底上，金色主按钮对比不足） |

两套主题共享全部组件，只换 token 值。用户自定义主题（T03）是在这两套之上派生副本。「跟随系统」按 `prefers-color-scheme` 选择。

### 2.3 字体

默认**只用系统字体**：离线可用、不发外部请求、三端都有合理的回落。设计字体（Inter、Newsreader、Fraunces、Noto Serif SC、JetBrains Mono）作为可选项；如果要内置，应该随应用打包，不从 CDN 加载。

| 家族 | Token | 用途 | 回落顺序（节选） |
| --- | --- | --- | --- |
| 阅读 | `--font-read` | 故事正文、作者长文预览 | Newsreader → Iowan → Palatino → Noto Serif SC / 思源宋体 → 宋体 |
| 展示 | `--font-display` | 章节标题、空状态标题、封面 | Fraunces → Newsreader → … → 思源宋体 |
| 界面 | `--font-ui` | 全部控件和工作台正文 | Inter → Segoe UI Variable → PingFang SC → HarmonyOS Sans → MiSans → 微软雅黑 → Noto Sans SC |
| 等宽 | `--font-mono` || JetBrains Mono → Cascadia Code → SF Mono → Consolas → Noto Sans Mono CJK |

**字号阶梯**（界面）：10.5 / 11.5 / 12.5 / **13.5（基准）** / 15 / 18 / 22 / 28 / 38 / 56 / 84 px。

**阅读排版**：18px，行高 1.92，版心 36em，段距 1.05em，中文首行缩进 2em；手机 16px、行高 1.9。用户的界面大小设置（T05）会整体缩放，阅读字号另有作品氛围的微调空间。

**中英混排**：

- 不手动在中英文之间插空格，交给排版引擎；如果 `text-autospace` 可用就启用它。
- 中文用全角标点和直角引号「」；英文用弯引号。
- 数字、版本号、revision 在界面里用等宽或 `tabular-nums`。

### 2.4 材质与造型

- **颗粒**：全屏一层很淡的胶片颗粒（opacity ≤ 0.07，overlay），不拦截输入，forced-colors 下关闭。给墨色界面一点纸感，是可选项。
- **发丝线**：工作台用 1px 的 `line-1`/`line-2` 分隔，不用厚边框。
- **登记角标**（`.ticks`）：只用于工作台的关键容器（如 Review 区），像制图的定位角，提示「这里是精确的」。
- **圆角**：结构件小（4–9px：按钮、字段、印记），舞台件大（13–26px：卡片、对话框、Composer）。
- **阴影**：三层。shadow-1 给按钮和卡片，shadow-2 给浮条和菜单，shadow-3 给对话框和 Sheet。
- **玻璃材质分工**：导航 Dock 用轻透的悬浮材质，活动灵动岛用更凝练、可读的表面；正文、编辑器和长列表保持稳定纸面。按主题调整底色、边线与透明度，不把所有容器都做成玻璃卡片。关闭模糊时用实心表面保留层级与对比度。

### 2.5 图标

- 1.6px 线描，24 网格，圆头圆角，无填充，颜色跟随文字。
- 图标永远配文字或 `aria-label`；纯装饰图标加 `aria-hidden`。
- 现有约 98 个图标（HTML「04.8」），覆盖五个域、版本状态（exact、fork、lock、unlink、unknown、hourglass）和媒体动作。新增图标遵循同样的线宽和网格。
- 不使用品牌 logo 作功能图标。

## 3. 页面布局

### 3.1 自适应 Shell

```text
┌─────────────────────────────────────────────────────────────┐
│ 顶栏：面包屑 · 域工具     活动灵动岛     搜索 · 更多 · 账户      │
│─────────────────────────────────────────────────────────────│
│ [可收起资源/控制面板]     阅读 / 编辑主区     [按需 Inspector/AI] │
│                         [可收起 Activity]                    │
│  浮动导航 Dock：左 / 右 / 上 / 下，阅读时可自动隐藏             │
└─────────────────────────────────────────────────────────────┘
```

| 断点 | 范围 | 导航 | Inspector | 对话框 |
| --- | --- | --- | --- | --- |
| Compact | ≤ 719 | 底部悬浮五域 Dock；全局工具在顶栏 | 按需三档 Sheet | 全屏层 |
| Medium | 720–1179 | 悬浮 Dock；空间不足按内容调整 | 默认收起，按需覆盖主区 | 居中对话框 |
| Expanded | ≥ 1180 | 四边磁吸 Dock | 用户打开后可调宽；不强制常驻 | 居中对话框 |

表中数值沿用现有 `atria-shell/constants.js`，用于产品阅读对照，不冻结原型 CSS。当前 HTML 的 Dock 在 ≤720px 使用底边常驻形态，禁用换边拖动与鱼眼；Studio 侧栏、资源树与 Memory 控制栏分别按可用宽度收起。实现时沿原组件断点协调，不把 72px 导航轨、368px Inspector 或固定三栏继续当作布局要求。存储中心 760px 的抽屉轴向切换是既有行为。

### 3.2 五种页面原型

| 原型 | 用在哪里 | 结构 |
| --- | --- | --- |
| **舞台** | 故事会话 | 全宽舞台 + 浮动 Composer；Inspector 默认关闭，由历史/上下文/选项/健康入口打开；作品 HUD 和全局活动灵动岛各自独立 |
| **书架 / 列表-详情** | 书库、Persona、Prompt 预设、视觉资源、运行的各子页、扩展 | 工具栏 + 列表或网格 + 右侧详情抽屉（M 上变成全屏页）；Library 里独立创建 Prompt/Visual 资源无需先建游戏，预设来源可辨别官方基础、作者共享、私人/项目派生，不把来源分组升级为权限标签；导入详情可审查依赖/本地身份映射与升级 Diff |
| **编辑器-Inspector** | 工坊、Library 独立 Prompt/Visual 创作、World/Knowledge 与 Media Studio | 原生资源/Stage/Module 大纲、Inspector/AI 与底部 Activity 可收起、可调尺寸，主区优先完整正文或结构化编辑，支持专注编辑；大纲只展示唯一原生编排与实际有效顺序，不另建排序表；继承的 exact 父版本、子级替换/禁用/配置/新增需可辨识，升级父版本与插入冲突要进入明确 Diff/Review；语义 Anchor 作为已选的 Program/Stage 内受控有序条目，在后端合同接通后才出现；当前来源 Contribution 只能在有 Host 脱敏投影时作为只读展开节点，不能伪造已实现 |
| **图-Inspector** | Memory、V3 编排 | 图/列表主区 + 可收起、可调宽的控制面板和 Inspector；图永远有列表等价视图，不要求三栏同时打开 |
| **全页 utility** | 设置、账户与备份、存储中心、诊断 | 左侧分区 + 主区；没有 Inspector |

### 3.3 留白与对齐

- 4px 基础栅格，间距阶梯 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 56 / 72。
- 工作台页面的外边距：expanded 24px，medium 16px，compact 12–16px。
- 舞台的外边距更大，版心居中。
- 表单标签与字段左对齐；数字列右对齐；印记和状态片在行末对齐。

### 3.4 磁吸导航 Dock

- Dock 只承担 Play、Library、Studio、Agents、Runtime 的主工作域导航。搜索、全局工具和账户独立放在顶栏，不混入 Dock，也不把 Inspector 称为导航 Dock。
- 宽屏可拖动把手或空白处，在左、右、上、下四边吸附；停靠菜单与把手方向键提供等价换边入口。自动隐藏提供「阅读时隐藏 / 始终显示 / 自动隐藏」；隐藏后可由边缘提示、点击或键盘焦点唤出。菜单或焦点仍在 Dock 内时保持展开。
- 鼠标邻近图标可平滑鱼眼放大，以静止命中布局为基准，换边或拖动时复位；触屏、窄屏和 reduced-motion 不依赖鱼眼。图标配名称和当前域标记，基础触控目标 ≥44px。
- 原型的窄屏形态见 §3.1；手机仍须能进入全部五域与顶栏工具。产品需沿原软键盘机制保证输入和 Stop 可达，拖动不能成为唯一入口。
- 拖动取消、失焦和重复操作须沿原手势机制收束，不丢当前编辑内容；换边不重新挂载业务页。自动隐藏与始终显示时的空间预留可以不同，不能把每次唤出变成正文反复重排。

### 3.5 活动灵动岛 Dynamic Island

- 汇总 Agent 任务、已知进度、待审批、阻塞和错误；收起态呈现当前重点与数量，点击或键盘展开任务列表，临时通知结束后回到摘要，需要处理的任务继续可找。无活动时不显示假任务。
- 默认顶部居中，检测顶栏、Dock、作品 HUD 和历史预览条；优先在空隙中移动或缩为图标/计数，再退到下方。窄屏原型使用顶部独立状态带；用户主动展开的是临时层，不将长任务列表常驻压在正文上。
- 与 Play 作品内状态组件分开；故事生成与 Stop 继续在 Composer 附近，作品 HUD 继续表达世界内状态。灵动岛不替代 Studio Activity、Agents Run Timeline 或完整审批页。
- 任务动作跳回对应 Task/Run/ChangeSet 的真实详情、审批或错误处理；汇总只读取原任务投影与回执，不创建第二套调度状态，也不因点击摘要批准、重发或重试未知派发。
- 进度未知时显示不定进度与文字；错误、审批、阻塞分别使用原账本语义。状态变化适量读屏播报，不抢编辑焦点；展开层纳入原层栈，Escape/Back 收起后归还焦点。
- 当前 HTML 的任务、进度与活动事件是本地演示；其 `localStorage` 只保存原型布局偏好，不证明产品任务、账户或跨设备持久化已经接通。

### 3.6 可调工作区

Studio 的资源树、Inspector/Project Agent、Activity 和 Agents 的控制栏/Inspector 保持入口可见，允许收起与调尺寸。专注模式临时收起辅助面板，退出时恢复进入前的布局；收起不丢选中对象、草稿、选区或滚动位置。窄屏切为覆盖层、Sheet 或分段，不把三栏挤到不可编辑。

分隔条可聚焦，标明方向、名称和尺寸范围；方向键调整，Home/End 到边界，Enter 收起，提供恢复默认尺寸的入口。范围随主区最小可用空间约束。原型的像素默认值仅是演示起点，产品复用原编辑器和面板状态，不另建一套业务草稿。

## 4. 组件体系

### 4.1 分层

```text
Token（色、字、距、圆角、阴影、动效、层级）
  └─ 原子：按钮 · 字段 · 分段 · 开关 · 复选 · 滑块 · 菜单 · 标签 · 头像 · 图标
       └─ 账本：印记 seal · 状态片 chip · 横幅 banner · 回执 receipt · 预算条 · 进度
            └─ 模式：列表行 · 卡片 · 对话框 · Sheet · Inspector · Toast · 空状态 · diff · 代码
                 └─ 业务组件：资源详情 · 修订时间线 · Used By · 就绪链 · Review 对话框 · 审批层 · 宿主门
```

**技术事实**：当前前端是原生 ES modules、DOM、CSS，加上既有的 jQuery 和模板，以及 Node Host、HTTP、流式事件和 Host Bridge，**不是** React 组件库。本稿的组件都可以用「CSS 自定义属性 + 语义 class + 少量行为脚本」实现（HTML 就是这样写的），不预设框架。是否换栈要另行讨论。

### 4.2 账本组件

| 组件 | 回答的问题 | 形状 | 规则 |
| --- | --- | --- | --- |
| **印记 seal** | 「这是什么？」 | 小方角标签，等宽字 | 当前（实线 + 实心方点）· 草稿（虚线 + 空心圆）· 历史（斜纹）· 原件（锁）· 副本（分叉）· exact（准星）· 过期（时钟）· 缺失（虚线 + 断链）· 未知（点线）· 阻塞（斜纹 + 沙漏） |
| **状态片 chip** | 「正在发生什么？」 | 胶囊 + 点 | 实时（呼吸点）· 生成中（旋转环）· 待处理 · 失败 · 已结束 · 未确认 · 待你审阅；减动时点不动 |
| **横幅 banner** | 「为什么，以及能做什么？」 | 圆角块 + 图标 | 必须有「原因 + 合法出路」；没有出路时写「需要谁做什么」 |
| **回执 receipt** | 「已经发生了什么？」 | 带「印」字的倾斜方章 | 刷新失败也保留；只给「重读」「打开」，不给再提交 |
| **预算条** | 「还剩多少，为什么？」 | 分段条 + 图例 | 已用、必需保留（斜纹）、可选分开；没有来源时不显示数字 |

### 4.3 交互组件的合同

| 组件 | 必须满足 |
| --- | --- |
| 按钮 | busy 时 `aria-busy` 加旋转指示，文字隐藏但宽度不变；disabled 时就近写明原因 |
| 字段 | label 与 `for` 绑定；错误用 `aria-invalid` + `aria-describedby`；草稿竖线 + 未保存印记 |
| 对话框 | `role=dialog`、`aria-modal`、Tab 圈定、Escape 关闭这一层、焦点归还；危险对话框的背景点击不关闭（`data-modal-strict`） |
| Sheet | 三档；grip 是 `role=slider`，带 `aria-valuetext`；拖动、点击、方向键等价；`pointercancel` 回到最近档位；内部滚动 `overscroll-behavior: contain` |
| 菜单 | `role=menu`，Arrow/Home/End 导航，点外部关闭，打开时聚焦第一项 |
| 命令面板 | 结果按来源分组；IME 组合中不选择；部分来源失败只在该组提示 |
| Toast | `role=status`（错误用 `alert`），4.6 秒自动消失，可手动关闭；不承载需要操作的错误 |
| 层栈 | 菜单、对话框、Sheet、命令面板、抽屉共用一个栈；Escape 和 Back 一次只关一层 |

导航 Dock、灵动岛与面板分隔条的交互合同见 §3.4–§3.6；层栈也覆盖灵动岛的展开层。

## 5. 表单与数据密度

### 5.1 表单

- 一列为主；expanded 下相关的短字段可以两列。
- 标签在上；说明在下（`text-3`）；错误在下（朱色 + 图标 + 原因）。
- 「字段 / Source」分段编辑**同一份草稿**；结构化编辑不能静默改写作者的原文。**独立作者与游戏内入口共用同一编辑器、原生精确资源和版本/权限状态**，界面要清楚显示 Library 独立编辑、Project ChangeSet 派生编辑、Package 原件只读三种保存语义；游戏作者应能选现有预设后再按需 Fork/Derive，不能因为没有自制 Prompt 就被阻塞。视觉提示词与文本提示词共享这些创作组件与版本导航，而不共享编译器/付费任务权威。Prompt 的 Stage/Module 有序大纲、正文内联变量和独立来源贡献须清楚区别：大纲是原 Program 的可视投影，独立贡献可解释来源/纳入原因，变量仍属于宿主正文；跨 target 不可因拖动改变可信 Role/Grant，不推定已实现新 Anchor/Contribution Schema；父级未钉版本与插入点缺失不得隐式追加或自动采用最新，需保留草稿并给出处理入口；Stage/Module 条件与来源授权是两套语义，不允许由 UI 条件编辑器创造新 Source/Grant；Anchor 的来源类别/必要性声明不能变更 Provider Role，重复/未纳入原因和顺序只读原 Host 证据。
- **作者自由文本**（角色描述、Prompt 正文、World 描述）：全宽、可增高、原文保留、不自动格式化；字数提示是建议值，不截断。
- 默认值和显式值分开标示（Q06 那种「默认 / 显式」标记）。
- Prompt 新建应有**空白 / 通用原生骨架 / RP 叙事 / 文学创作 / Agent Task** 等适量入口，不按每个模型厂商堆出大量预设；工作区内保留自由原文和可编辑 Native Module/Stage/Anchor。视觉模板在 Rendering/Target/ImagePromptIR 的独立入口，不和文本 Provider Lowering 混淆。默认不启动 Tool/Judge/付费模型生成。
- 多模型能力面板只说明真实 Provider Capability/Role/Tools/Schema/Token 与当前 exact 模板适配结果。必需能力无法合法转换应阻断或请作者选择，不能暗改正文和权限，也不把官方来源展示成已跨模型质量认证。
- 提示词资源界面应分开表示**保存修订、导出分享、正式发布/绑定、消费者采用/升级**；每个操作显示独立状态、影响消费者、exact 版本与真实回执。游戏创作者可直接选择已有基础/共享资源，无需自制 Prompt，派生后不回写原共享资源；升级须先看 Diff/能力/冲突。可编辑预设包和游戏运行时 `.atria` 冻结快照区分；手动再次导入新版只创建可比较候选，找不到可靠原始身份映射或存在本地派生冲突时保留两份并列资源，不自动应用更新。
- “官方/作者/私人”“作者试读/开发案例”“来源受审的独立评价”分别是资源出处与证据状态：官方不自动认证，未知质量写 `unknown/source_unready`，不把未认证误写成禁止作者导出分享。Preview/付费试读仍由原 Native Host/Visual Job 严格授权，不因分享或导入触发隐式执行。
- 提交顺序遵守功能文档 §2.3：编辑 → 审查 → 提交 → 回执 → 刷新 → 冲突。

### 5.2 数据密度

| 档位 | 用途 | 差异 |
| --- | --- | --- |
| **舒适**（默认） | 触屏、阅读、首次使用 | 行高 38px，间距按标准阶梯 |
| **紧凑** | 专业编辑、长列表、宽屏 | 间距缩小约 20%，顶栏 46px，基准字号 13px |

密度**只改间距和字号**，不隐藏任何控件或信息（P-10 提案）。Prompt 工作台额外遵循**按需披露**：默认聚焦创作原文与必要状态；激活条件、来源、Token、Diff、Trace 在对应操作或问题出现时再展开，隐藏面板不等于删除能力。完整 Diff/Token 计算不因键入而常驻触发。Prompt 专业工作台按需进入 Authored/Effective/Provider Wire、来源 Trace、精确版本 Diff；保留用户返回原文的路径与草稿状态。上下文身份不一致的比较标记“环境变化”，不把非同源差异算作作者修改；受限来源显示 restricted/unknown 而不泄露存在性。

### 5.3 列表和表格

- 列表行最低 38px（舒适）；触屏上命中区 ≥ 44px。
- 选中行：抬高的底色 + 左侧金色竖线（同时设置 `aria-selected` 或 `aria-current`）。
- 长列表保留已有的窗口和分页机制（对话 64 条窗口、历史 25 个分支每页、存储 50 项、Gallery 12 张）。全量加载的列表先实测，再决定是否虚拟化。
- 截断要写明：「显示 250 / 共 1,204」；「未显示」不等于不存在。

### 5.4 数字与 ID

- 数字用 `tabular-nums`；字节用 KB/MB/GB；时间用相对时间 + 悬停或长按显示绝对时间。
- 未知数值写「未知」或 UNKNOWN，不写 0，也不写「—」以外的猜测值。

## 6. 状态、反馈与文案

### 6.1 状态协议

18 种状态的画法见 HTML「03 状态协议」，各功能落点见功能文档 §4。核心规则：

- 空 ≠ 读取失败；部分失败 ≠ 全部失败；缺数据 ≠ 0。
- 已提交但刷新失败时显示回执，不再提供提交。
- 冲突时保留草稿，显示新的 revision，对比后重审。
- 只读要说明原因并给出合法出路。
- 审批写明审什么、发给谁、花多少（或「未知」），同意项不预选。
- 未知派发要查回执，不能直接重发。
- 部分完成要列出已完成、失败和剩余。

### 6.2 文案规范

- **按后果命名**：「切换到此分支…」而不是「确定」；「移入回收站」和「永久删除…」分开；「停止」不是「撤销」。
- 会弹出进一步确认的按钮，结尾加省略号「…」。
- 错误 = 发生了什么 + 为什么 + 怎么办。例：「无法删除『雾港城 1926』：3 个对象仍在使用它。逐个打开处理，或先 Fork 出新身份。」
- 不写「出错了，请重试」这种万能话。
- 能写对象名就写对象名（「柳絮」「rev 8b21」），不写「该项」。
- 演示数据和真实数据要分开；未接通的能力写「设计目标」「未接通」，不写「即将推出」。

### 6.3 术语表（中英对照）

界面文案用中文，括号里是英文原名或内部名。英文界面直接用英文列。

| 中文 | English | 说明 |
| --- | --- | --- |
| 故事 / 会话 | Story / Session | 首页和列表叫「故事」，技术语境叫 Session |
| 作品 | Work | 安装后的 `.atria` |
| 项目 | Project | 工坊里的可编辑源 |
| 存档 | Save / SavePoint | 故事内的保存点，不等于账户备份 |
| 分支 | Branch | |
| 修订 | Revision | 不可变 |
| 精确引用 | Exact reference | 印记写 `exact r4` |
| 原件 | Package original | 包内只读资源 |
| 副本 / Fork | Copy / Fork | 独立的新身份 |
| 审阅变更 | Review changes | 不提交 |
| 应用 ChangeSet | Apply ChangeSet | 写新修订 |
| 回执 | Receipt | |
| 任务槽位 | Task slot | 作品声明的模型用途 |

### 6.4 语言切换

- 语言设置保存在浏览器本地，切换后重新加载（T06）；不承诺跨设备同步。
- 中文文本比英文短，英文比中文长约 30–60%：按钮和标签按英文长度留余量，过长时折行，而不是截断。
- 搜索支持中英别名（设置、命令面板）。

## 7. 主题与自定义

| 层 | 谁能改 | 能改什么 | 不能改什么 |
| --- | --- | --- | --- |
| 内置主题 | 产品 | 全部 token 的值 | 组件结构 |
| 用户主题（T03） | 用户 | 颜色和强调色（显示实时对比度） | 账本语法的形状 |
| 主题 CSS（T04） | 用户 | 任意 CSS | 只有用户自己承担后果；`Ctrl+Alt+Shift+R` 或 `atriaNoThemeCss=1` 可以临时抑制，原文不删 |
| 作品氛围 | Work | `--mood-a` `--mood-b`、舞台背景、舞台内的 surface | 宿主门、导航、审批和凭证对话框、系统偏好 |
| 作品界面（hybrid/full） | Work | 整个舞台（通过 Host Bridge 的受控能力） | raw Host 写权限、宿主门 |
| 可信插件（X06/X07） | 用户安装 | 页面执行 JS | 与 Work 沙箱是不同的信任级，安装时单独说明 |

**规则**：宿主的安全关键 UI（审批、凭证、费用、外发、永久删除、宿主门）放在一个作品样式和用户 CSS 不应覆盖的层上，并在自定义 CSS 生效时仍然保持可读。如果做不到完全隔离，至少要保证恢复快捷键始终有效。

## 8. 动效与减动

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ease-settle` | `cubic-bezier(.2,.8,.2,1)` | 进入：浮起 6px 后落定 |
| `--ease-exit` | `cubic-bezier(.4,0,1,1)` | 退出，比进入更快 |
| `--ease-spring` | `cubic-bezier(.34,1.36,.64,1)` | 只给手势回弹和开关 |
| `--dur-1…5` | 110 / 180 / 280 / 460 / 900ms | 900 只用于封面和氛围 |

- 动效只表达因果和层级（东西从哪来、到哪去）；不做装饰性循环。
- 实时状态片的呼吸点、流式光标和旋转指示是仅有的循环动画。
- **减少动态效果**（T07 或系统 `prefers-reduced-motion`）：所有过渡变成即时，流式光标不闪，呼吸点静止，Sheet 直接跳档。
- **减少模糊**：去掉 `backdrop-filter`，改用实心底；低端设备建议默认开启。
- 舞台氛围光的漂移（若有）在减动时停止。
- Dock 跟手、吸附、鱼眼和灵动岛展开只为反馈与空间连续性服务，保持可中断；避免泛化仪表盘、装饰性循环和大面积玻璃。优先复用原 CSS/WAAPI，位移与透明度用合成属性；必要的容器尺寸过渡限制影响范围，不在键入时逐帧重排编辑正文。reduced-motion 下取消鱼眼、吸附位移与形变过渡，操作结果仍即时可见。

## 9. 沉浸与专业如何协调

- **同一个 Shell**：故事页和工坊用同一套导航、命令面板和 Inspector。区别只在主区的语域，不会切换成「另一个应用」。
- **Inspector 是桥**：故事页的 Inspector（历史、上下文、选项、健康）用工作台语域，默认关闭，按需打开；编辑与图工作区同样不要求辅助面板常驻。
- **活动有自己的层级**：导航 Dock 负责去哪里，灵动岛汇总 Agent 活动，作品 HUD 表达世界内状态，Composer 表达当前故事生成；具体规则见 §3.4–§3.5。
- **宿主控件低调**：舞台上的宿主控件（顶栏、宿主门）用低对比的墨色和小尺寸；生成状态只是 Composer 上方的一行字。
- **从故事到工作台只有一步**：故事页的「上下文」可以跳到运行的诊断；「健康」可以跳到任务槽位；作品详情可以跳到工坊（对作者）。修复往返都带返回横幅。Library 预设作者可独立进入专业创作视图，Studio 通过同一资源的 exact 深链引用/派生后返回原项目；选择基础/共享预设是正常游戏创作流程。视觉作者也可独立进入视觉资源编辑，但无 Session 的试生成与 Gallery 归属仍需原视觉服务实现支持。
- **作者的预览就是玩家的舞台**：工坊的「预览」用同一个舞台组件和作品氛围，作者看到的就是玩家看到的。Prompt 的 Authored/Effective/Wire 则是另一种**受信编译诊断预览**，只在原 Host 支持、具备来源/权限证明时显示，不等同于运行作品、发送模型或即时文学试读。Library 独立作者用 Host 受权测试 fixture，而非虚构的游戏 Session；手动付费试读需要额外 Route/预算/费用许可与显式发送，视觉生成使用单独 ImagePromptIR/Visual Job/Asset 合同。

## 10. 作品 UI、插件与错误恢复

- **作品 UI**（text / component / hybrid / full）通过 slot 或整体接管舞台。宿主保证：宿主门固定在舞台角落，44px 触控区，作品层之上；作品 UI 崩溃或无响应时，宿主门依然可用，「重载表现」只重新挂载作品界面。
- **作品的无障碍**：作品 UI 要声明自己的无障碍替代（键盘、读屏标签）。宿主不能代替作品做到这一点，但能保证宿主门和 Composer 本身是可访问的。
- **插件 UI**（可信 JS）：在宿主的组件 token 上渲染，建议只使用公开的语义 token；插件面板放在 Inspector 或独立的扩展页里，不覆盖宿主门和审批层。
- **错误恢复的统一入口**：故事页「健康」标签、宿主门「诊断」、全局菜单「诊断」指向同一套诊断，并带上当前 Session 的上下文。
- **恢复不是一个按钮**：分支切换、存档载入、回收站恢复、ZIP 回滚、Mask 撤销、LAN 撤销（仅本机）各有自己的文案和确认（HTML 03.2）。

## 11. 防止「手机只能看」

1. 只能看不能做就算未完成。
2. **替代手势**：拖拽有按钮（上移 / 下移）；精确绘制有坐标表单；悬停提示有长按或信息按钮；图有列表。
3. **全屏层优先**：手机上的审批、Review、二次确认都用全屏层，主按钮在拇指区，内容可以滚动。
4. **常驻待办**：未审变更、待审批、生成中这三种状态在手机上常驻在底部或顶部，不藏在菜单里。
5. **软键盘**：输入和主动作在键盘上方；旋转不丢稿。

## 12. 无障碍

- 语义控件（button 或 link），不用可点击的 div。
- 焦点环：两层阴影（底色 2px + 青色 2px），任何主题下都可见。
- 对比度：正文 ≥ 7:1，承载信息的语义色 ≥ 4.5:1，大字和图标 ≥ 3:1。
- 不只靠颜色：印记形状、图标、文字三重编码。
- `forced-colors`：印记、状态片、按钮回落为 CanvasText 边框；关闭颗粒。
- 读屏：busy、成功、错误、冲突、partial、审批用 live region；流式生成只在开始、结束、失败时播报。
- 触控目标 ≥ 44×44px。
- 缩放到 200% 时功能不丢；界面大小设置（T05）整体生效。

## 14. 留给讨论

- **本轮保留项**：Atrium、Nocturne/Folio、暖金色、三种语域和语义状态系统继续沿用；细化时先调整留白、字体层级和按需披露，不以通用仪表盘重做视觉身份。
- **两套主题**：夜和昼是否足够，是否需要高对比主题作为内置选项。
- **设计字体**：是否内置打包，还是只用系统字体。
- **密度**：是否把紧凑档位做成用户设置（P-10）。
- **产品／IA 提案** P-01 到 P-11：见功能文档 §8.4。
