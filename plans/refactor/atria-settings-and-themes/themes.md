# Atria 设置与主题 — 主题契约

- 状态：已实施；
- 本文件定义主题、明暗模式、CSS 和临时预览的行为权威。
- 设置页面构图与控件归属见 [settings-ui.md](settings-ui.md)。
- 升级与导入规则见 [migration.md](migration.md)。
- 现状证据与外部资料见 [audit-and-research.md](audit-and-research.md)。

## 1. 目标与范围

将旧主题的配色意图适配到完整 Atria 原生界面，保留现有名称和用户资产。
主题切换需要在各域、公共组件与兼容设置中产生一致且可理解的效果。
本文件规定目标行为，不将源码中保留的导入入口视为该目标已经完成。

本轮包含：

- 原生配色主题和浅色、深色、跟随系统模式。
- 日间与夜间主题分别选择。
- 随主题保存的高级 Custom CSS。
- 跨应用预览、确认保存、取消恢复和编辑草稿保护。
- 旧主题转换及用户自定义副本，具体兼容规则链接至迁移模块。

本轮不提供背景图或透明度调节控件。
保留必要的材料与状态颜色，不把它们扩张为一套任意换肤参数编辑器。
不恢复旧聊天外观、布局和交互开关作为默认设置。
主题不承载字号、语言、输入、滚动、减动等个人偏好。

## 2. 内置主题及配色意图

下表依据默认 JSON 盘点；
5 个旧主题原本均为深色，不存在可直接恢复的对应浅色版本。

| 主题 | 明暗归属 | 应保留的气质 |
| --- | --- | --- |
| Serene Canvas | 浅色 | 当前纸白、墨色和橙色强调的产品视觉 |
| Azure | 深色 | 蓝黑底、冷蓝文字、蓝紫强调的清冷蓝色气质 |
| Cappuccino | 深色 | 暖炭灰底、奶油色文字和咖啡棕强调 |
| Celestial Macaron | 深色 | 深海军蓝底、桃粉文字和薄荷绿点缀 |
| Dark Lite | 深色 | 中性近黑底、米白文字和橙色强调 |
| Dark V 1.0 | 深色 | 冷蓝灰底、米白文字和低饱和黄绿强调 |

保留名称不要求复制旧界面的逐像素视觉。
旧色彩在原界面中承担的角色应解释为新界面的语义角色。
不得把原来用于引文的颜色直接复用于所有链接、错误或焦点状态。
需要避免因旧透明色与新不透明底色组合而降低文字和边界对比度。

本轮不为每个主题家族补造浅深双变体。
浅色与深色各自选择现有对应主题；日夜可以采用不同色彩气质。
后续增加新的浅色主题不改变本文件的日夜独立选择模型。

## 3. 模式与日夜主题

模式、日间主题、夜间主题是独立选择。
模式有 light、dark、system 三种语义；具体持久字段名称由实施决定。

| 模式 | 当前使用的主题 |
| --- | --- |
| 浅色 | 已保存的日间主题 |
| 深色 | 已保存的夜间主题 |
| 跟随系统 | 根据当前系统偏好，使用日间或夜间主题 |

用户切换模式不得覆盖两个主题槽的选择。
用户编辑某一槽不得暗中将模式改为该槽的明暗。
界面需要同时解释已保存模式、正在使用的主题和当前预览对象。
名称中的 Dark 不替代明暗元数据，也不用名称字符串推断主题可用槽位。

系统偏好变化时，system 模式应解析到相应槽位。
显式 light 或 dark 模式保持用户选择，不随系统变化。
主题资源缺失或不可用时应有可理解的降级结果与修复入口。
降级不得删除原选择，也不能静默把坏资源另存成有效主题。

## 4. 原生语义颜色契约

应用组件继续消费已有 Atria tokens，不另建平行组件配色系统。
主题解析后产生完整的有效颜色集合，缺失角色按确定的基础主题补全。
补全过程不得依赖当前页面恰巧存在的元素或其计算样式。

至少覆盖以下角色组：

- 画布、普通表面、次级表面、浮层与材料的替代底色。
- 主文字、次级文字、弱化文字和强调底上的文字。
- 强调、强调悬停、强调按下和弱强调背景。
- 普通边界、较强边界、分隔线和焦点环。
- 普通填充、悬停、按下、选择和禁用状态。
- 成功、警告、危险及其背景。
- 遮罩、阴影以及依赖明暗的装饰颜色。

role 字典的实际键名复用现有 token 命名及组件需求。
不要求为了格式统一引入完整 DTCG 编译层、转换工具链或任意引用图。
最小主题描述应能表达版本、身份、明暗、颜色角色、CSS 及兼容原文信息。
字段拼写和底层组织属于实施细节，不在方案中提前冻结。

普通入口提供主题与强调色选择；进阶配色编辑使用上述语义角色，
由完整解析结果补齐关联状态，不要求用户逐项填写所有 token。
关键文字、表面与控件颜色配对不足以清楚辨识时，显示对比度提示及恢复建议值。
自定义配色允许高级用户保留选择，不把提示升级为禁止保存。

完整覆盖包括：

- Play、Library、Build、Runtime、Agents 及全局设置。
- 导航、菜单、弹窗、提示、表单、选择器和空白、错误、加载状态。
- 仍需保留的旧控制器、插件设置等兼容岛。
- 页面 color-scheme、浏览器主题栏颜色及相应平台栏桥接。

旧 SmartTheme 只作为兼容投影，不继续作为原生界面颜色权威。
不能只更换主背景和文字，同时留下硬编码白色材料、阅读预览或菜单。
减少模糊等辅助偏好启用时，其替代材料仍需符合当前主题。
作品自定义呈现边界由现有 Host 合同决定，不强行改写作品内容。

## 5. 内置、自定义与 CSS

内置主题作为只读起点。
修改内置主题时创建用户自定义副本，不直接覆盖产品提供的原件。
用户应能理解正在查看内置主题、已有副本还是未保存副本草稿。
重命名、保存和删除只作用于有明确身份的用户资产。

Custom CSS 属于单个主题，随该主题保存、切换及导出。
同一主题的附带 CSS 只有一个生效来源。
本轮不增加独立的全局个人 CSS 覆盖层，也不把一段 CSS 同时注入两次。
内置主题需要编辑 CSS 时同样先进入自定义副本流程。

高级编辑器应说明它使用 Atria tokens，且旧 DOM 选择器可能不再适用。
CSS 开关及文本都属于主题草稿，并随确认保存或取消处理。
关闭 CSS 不删除原文。
主题配色正常工作不应以用户手写 CSS 为前提。
CSS 出错时应保持可达的取消与恢复入口，不能让预览永久锁住设置。

## 6. 预览状态与真实保存

外观预览为全应用的一次临时覆盖。
应用可以暂时使用候选配色和该主题 CSS，但此时不写真实用户选择。
预览状态与既有设置权威协作，不成为另一套持久主题状态。
当前预览对象、未保存状态和恢复操作必须可见。

预览仅隔离本次正在编辑的外观字段。
字号、输入方式、语言、滚动和减动等独立偏好的正常保存不受影响。
取消外观预览不得把这些独立偏好恢复到较早快照。
临时配色通过同一 tokens 作用于当前 Shell、真实组件及其弹层。
退出预览的导航边界按第 8 节执行，不在离开外观页后遗留临时覆盖。

顶部操作行承载当前对象、保存或确认、取消等动作。
不设置固定底部操作栏；整体构图与窄屏处理见设置界面模块。

## 7. 模式、槽位与明暗预览

| 操作 | 临时显示 | 确认后的变化 |
| --- | --- | --- |
| 简单选择模式并预览 | 按候选模式解析 | 仅保存显式选择的模式及本次明确选择的主题 |
| 查看日间槽候选 | 临时展示该浅色主题 | 仅保存日间槽及本次显式修改的模式 |
| 查看夜间槽候选 | 临时展示该深色主题 | 仅保存夜间槽及本次显式修改的模式 |
| 预览中切换查看明暗 | 展示当前查看的槽 | 查看动作本身不产生持久变化 |
| 取消 | 撤销本次外观临时覆盖 | 不保存本次外观候选与编辑 |

若模式始终为 system，确认夜间主题后应退出强制夜间预览。
退出时根据当时系统偏好解析，可能立即回到日间主题。
取消时同样按结束时系统偏好解析，不能恢复一个已过时的明暗快照。

简单 system 模式预览可以响应系统偏好变化。
显式槽位预览以用户正在查看的日间或夜间槽为准，不被系统切换打断。
两者都只是显示规则，不能把系统变化或查看动作写成用户模式选择。
不得通过“保存夜间主题”暗中持久化 dark。

## 8. 浏览、编辑及离开保护

仅浏览主题候选产生临时预览，不产生内容草稿。
纯浏览离开外观页时自动取消临时预览，恢复当前已保存外观。
此边界包括返回分类、切换分类、关闭设置与导航到其他工作区。
已编辑配色、CSS 或自定义主题信息则形成未保存草稿。
草稿离开保护接入既有 WorkspaceLeaveGuard，具体入口行为见设置界面模块。

在未保存编辑与纯浏览之间需要有一致区分。
不能每次浏览主题都弹出未保存对话框，也不能静默丢弃编辑内容。
保存成功后才清理草稿状态并更新主题资产与选择。
保存失败时保留草稿、已保存状态和可理解的重试或取消入口。
失败不能被“预览看起来已变化”掩盖。

确认保存进入真实写入后，防止重复提交；不能将此时的取消描述为撤回已发送写入。
保存进行中的离开交由既有离开保护与请求结果处理，不能提前显示“已取消保存”。

若主题资产保存成功，而日夜槽或模式保存失败，应分别报告两步结果：
“主题资产已保存，外观选择未保存”，并保留已成功的资产。
重试只处理尚未完成的步骤，不重复创建主题副本，不误报整个操作已成功。
当前已引用主题的编辑同样按实际持久结果说明，不能把已写入内容宣称为未保存或已撤销。
取消临时显示只能清理预览，不能伪装成回滚已经成功的资产或偏好写入。
