# 设置界面与偏好交互

本模块是设置页构图、分类、搜索定位、普通偏好保存反馈及旧条目归属的唯一详细权威。
方案入口见 [index.md](index.md)；
审计参考源码提交为 `60aca69572`，实施时以真实 Git 和本方案冻结范围为准。

## 1. 目标与职责

- 设置页使用 Atria 的现有 ES modules、DOM、CSS、Shell 与 WorkspaceHost，形成完整的原生设置体验。
- 保留现有状态、配置、持久化与能力权威；呈现描述不成为第二套配置数据源。
- 本模块不定义主题数据格式、预览事务、应用/取消、导入合并或升级规则。
- 主题状态流与编辑动作见 [themes.md](themes.md)，升级和导入见 [migration.md](migration.md)。
- Account、备份、Extensions、Diagnostics 保留各自完整工作区；设置提供相关入口。
- 模型连接、生成参数、提示词程序与作品内容继续由 Runtime、Library、Studio 等所属工作区管理。

## 2. 当前基线与问题

- `main:public/scripts/atria-shell/utility-workspaces.js` 构建四组设置，并搬入三个旧外观 DOM 区块。
- `main:public/scripts/atria-shell/preference-controls.js` 只提供七个原生控件，覆盖尚不完整。
- `main:public/index.html` 的旧 User Settings 保留大量聊天、角色管理、脚本及设备条目。
- 旧搜索仍只查找隐藏的 `#user-settings-block-content`，不能定位新的原生设置。
- 普通控件同步更新内存后调用 debounced save；真实网络失败没有回传到对应设置行。
- `font_scale` 是现有全局界面偏好，当前原生控件将其称为 Reading size，作用范围表达不准确。
- 旧沉浸、通知、保活、媒体条目存在消费者，但消费者可能只服务兼容聊天或部分生成路径。
- 上述条目是否进入新设置，以其产品归属和真实 Native 消费链为依据，不按旧 DOM 是否存在决定。

## 3. 桌面构图

桌面采用一张设置工作纸内的两列结构：左列是稳定的分类导航，右列是当前分类内容。
两列位于现有 Shell 工作区内部，不增加另一套全局导航或悬浮设置窗口。
分类侧栏保持可见；内容纸限制可读宽度，宽屏增加留白，不把设置行无限拉宽。
页面标题、设置搜索、当前分类标题和返回来源保持清晰层级。

```text
┌────────────────────── Atria Shell ───────────────────────┐
│ 设置                         [ 搜索设置                 ] │
├────────────────┬────────────────────────────────────────┤
│ 外观与主题     │ 外观与主题                             │
│ 阅读与输入     │ [顶部预览操作行：动作按 themes.md]       │
│ 通用与语言     │                                        │
│ 通知与声音     │ 主题图库                               │
│ 辅助与性能     │ [主题卡] [主题卡] [主题卡]              │
│ 隐私与媒体     │                                        │
│                │ 当前预览                               │
│ 账户与备份 ↗  │ [真实组件与内容状态，纵向排列]           │
│ 扩展 / 诊断 ↗ │ [当前分类的设置行与必要说明]             │
└────────────────┴────────────────────────────────────────┘
```

- 主题图库位于预览上方，二者在右侧工作纸内上下排列，不把预览固定成第三列。
- 主题预览操作位于内容顶部，状态与动作命名完全复用 [themes.md](themes.md)。
- 普通分类使用一致的设置行：名称、必要说明、控件、保存或错误反馈。
- 高级内容只在确有需要时按需展开，避免把旧抽屉嵌套层级带入新页面。
- 主题选择、配色和 CSS 编辑使用原生呈现；当前三个旧主题 DOM 区块不再原样嵌入新设置。
- 相关入口与设置分类有视觉区别；跳转到其他工作区不伪装成开关。
- 配色编辑区在宽屏可让字段和局部样例并排，手机上下排列；不形成页面级第三栏。

## 4. 手机构图与返回

手机首先展示分类列表，进入分类后显示独立子页，不堆成一个超长设置表单。
分类标题、返回和搜索沿用现有 Shell 返回及焦点规则，浏览器返回能够回到合理来源。

```text
分类列表                       分类子页
┌────────────────────┐        ┌────────────────────┐
│ 设置      [搜索]   │        │ ‹ 设置  外观与主题 │
│ 外观与主题       › │        │ [预览状态与动作行] │
│ 阅读与输入       › │        │ 主题图库           │
│ 通用与语言       › │   →    │ [主题卡] [主题卡]  │
│ 通知与声音       › │        │ 当前预览           │
│ 辅助与性能       › │        │ [预览内容]         │
│ 隐私与媒体       › │        │ [设置行与说明]     │
│ 账户 / 扩展 / 诊断 │        │ [保存状态或错误]   │
└────────────────────┘        └────────────────────┘
```

- 窄屏预览动作允许换行，不挤压主题名称或隐藏取消/恢复等关键动作。
- 预览操作行仅在预览或编辑时出现；顶部保持可达，并为内容及焦点定位预留其占用空间。
- 子页返回保留分类列表位置；搜索进入设置后返回搜索时保留查询与结果位置。
- 不新增手势返回要求；点击、键盘与已有返回入口均可完成导航。
- 断点沿用现有 Shell 环境与设计 token，具体排版按内容可用空间调整。

## 5. 分类与条目边界

| 分类 | 本分类职责 | 条目范围与限制 |
| --- | --- | --- |
| 外观与主题 | 界面外观与现有主题资产 | 主题图库、模式及预览入口；主题编辑和持久化规则归 themes.md。 |
| 阅读与输入 | 已存在且能正确接入当前前端的阅读、输入偏好 | 界面字号、Enter 发送行为、现有跟随偏好；|
| 通用与语言 | 通用交互和语言 |需要重载的行为应明示。|
| 通知与声音 | 已有生成通知与提示音能力 | 对照 Native 生命周期、权限与平台能力后迁移；不承诺所有路径已经覆盖。 |
| 辅助与性能 | 系统偏好与已有减负功能 ||
| 隐私与媒体 | 已有外部内容与媒体策略的用户入口 | 必须对接 Native 媒体/权限权威；不能用旧聊天布尔值代替作品权限。 |

- 分类先表达稳定职责，不能为了填满六组而新增偏好或保留无效开关。
- Account 与备份、Extensions、Diagnostics 是相关入口，不复制其完整设置到上述分类。
- 设置不是所有旧参数的总表；任务现场选项继续留在所属工作区。
- 没有等价 Native 项的旧值保留为兼容数据，不在主设置中制作无法生效的控件。
- 有效但仅特定设备支持的后台能力在相关辅助/性能分类按能力呈现，解释可用性、当前状态和失败恢复。

## 6. 界面字号与范围约束

- 现有 `power_user.font_scale` 准确命名为“界面字号”，说明其全局作用范围。
- 修复当前 Shell 与原生设置的消费链，使显示值、实际界面及预览保持一致。
- 不把旧全局字号暗中迁成只控制正文的偏好，也不让字号行为依赖主题偶然覆盖。
- 本任务没有授权新增独立阅读字号、阅读宽度及其持久化键。
- 旧 `chat_width_slider` 的存在不构成新增 Native 阅读宽度功能的依据。
- 预览使用真实生效链；单独放大示例段落不能作为界面字号已经生效的证明。

## 7. 设置搜索与定位

- 搜索覆盖六组实际提供的设置、当前语言名称及必要的中英文别名。
- 搜索描述可以包含说明文本与旧名称别名，不能索引用户私有内容或远端资源来补结果。
- 结果展示设置名称、所属分类及必要的作用范围，点击后进入分类并定位对应设置行。
- 折叠区域中的目标应展开；滚动后焦点落在可理解的标题或目标控件上。
- 定位提示不只依赖颜色，并尊重减少动画与键盘操作。
- 桌面与手机使用同一结果语义；手机从结果进入分类子页。
- 查询为空显示清晰初始状态；无结果提供改写查询的提示，不显示虚构设置。
- 键盘可搜索、遍历结果、进入设置、返回结果，并保留合理焦点。
- 分类与单项定位复用现有 Navigation Authority，不建立独立路由或历史栈。
- 设置描述注册仅保存标签、分类、别名和定位信息，不复制偏好值、默认值或持久化逻辑。

## 8. 普通偏好的保存反馈

普通偏好延续即时生效与现有持久化；主题草稿和预览不使用本节状态流。

| 状态 | 用户看到的行为 | 实现要求 |
| --- | --- | --- |
| 已同步 | 控件与权威值一致 | 不持续显示干扰性的成功提示。 |
| 待保存 / 保存中 | 变化已应用，状态可理解 | 等待真实写入结果，不能将调用 debounce 当作保存成功。 |
| 已保存 | 轻量、可被辅助技术感知的确认 | 只有当前变更获得成功回执后才能显示。 |
| 保存失败 | 保留用户意图，说明失败并提供重试 | 不伪造回滚或成功；反馈关联具体设置或当前保存批次。 |

- 复用现有保存排队和持久化服务，通过适配层暴露真实成功/失败结果。
- 不从每个设置行新增独立 settings endpoint 写入，避免绕过合并、顺序与配置兼容约束。
- 连续调整以最后一次有效用户意图为准，较旧回执不能覆盖较新的控件状态。
- 导航离开、组件卸载和重开后仍由真实保存状态决定呈现，不遗失失败提示所指的变更。
- 受影响控件可以按实际依赖禁用并解释原因。
- 重试沿既有保存权威执行，成功后清除对应错误，不要求用户重复输入。
- 反馈使用现有本地化、status/alert、焦点与按钮组件，不依靠全局 toast 承担全部恢复路径。

## 9. 旧设置归属与消费者核查

| 旧条目族 | 新归属或处理 | 必须避免的等价假设 |
| --- | --- | --- |
| 主题 CRUD、十个颜色槽、Custom CSS | 外观与主题；具体映射归 themes.md / migration.md | 旧颜色槽和旧 CSS 选择器不等于新语义 token。 |
| 语言、字号、Enter、离页确认、减少动画/模糊 | 对应全局分类，复用当前权威 | 旧标签、当前 UI 状态和实际作用范围可能不一致。 |
| 沉浸记忆、故事聚焦、视觉模式、HUD、扩展组件 | 阅读相关候选；| 对旧 #chat / .mes 生效不等于对新阅读器生效。 |
| 通知、提示音、正文预览、移动后台保活 | 通知与声音或设备能力入口 | 有浏览器/Android 函数不等于所有 Native 生成路径已接通。 |
| 外部媒体、媒体懒加载与展示方式 | 对照 Native 媒体和隐私权威处理 | 旧聊天媒体允许值不等于作品声明、权限或远程媒体授权。 |
| 采样界面、角色提示覆盖、示例策略、自动 swipe / continue | Runtime / Prompt 既有能力或兼容数据 | 旧生成拼装、重试和续写语义不能直接套到 Native Turn。 |
| 角色列表、标签文件夹、导入对话、图片裁剪等 | Library / Studio 的现有对应操作或兼容数据 | 不能借设置重构恢复整套旧角色管理产品。 |
| STscript、宏、自动补全、解析 flags | 当前 Extensions 能力核查后归所属入口 | 旧脚本字段不自动成为通用 Atria 功能。 |
| 日志、Android 录制、Self-Profiling、提示词日志 | Diagnostics 既有能力 | 技术观察项不混入普通阅读外观。 |
| 账户、备份、退出、清理、版本与帮助 | Account / 备份 / 相关入口 | 当前上下文操作不包装成全局偏好。 |

旧聊天专属项退出主设置，只保留兼容数据：MovingUI 与其预设、旧气泡/文档布局、Waifu Mode、旧消息动作和 swipe 显示、旧群聊队列与 trim、旧消息编辑行为、名字前缀与标签格式化、首条消息样式固定等。
保留数据不表示继续公开入口，不自动承诺新的同名 Native 功能，也不在本任务中擅自删除旧数据。

## 11. 响应式、可访问性与实现边界

- 复用现有组件、颜色/字体/间距 token、图标、反馈样式、工作区加载和错误模式。
- 原生 label、button、select、details 等优先；开关、只读状态与导航行的语义清楚区分。
- 系统减少动画开启时保持有效状态与说明，不通过应用开关覆盖系统要求。
- 键盘焦点可见、顺序合理；固定操作行和底部区域不完全遮挡聚焦控件。
- 320 CSS px 下普通设置不产生页面级横向滚动；放大文字不裁掉标签、状态或关键操作。
- 不新增前端框架、第二套组件系统、偏好数据库、设置路由或与现有 authority 并行的服务。
- 不借清理旧 DOM 删除尚未分类的配置数据，不修改无关 Shell 导航或其他工作区产品设计。
