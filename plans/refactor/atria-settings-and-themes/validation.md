# 设置与主题：验收目标

## 1. 使用方式与边界

- 先读 [index.md](index.md)，再按本次改动读取对应设计模块。
- 设置构图、分类与普通偏好语义归 [settings-ui.md](settings-ui.md)。
- 配色、日夜配对、预览与主题编辑语义归 [themes.md](themes.md)。
- 首次升级、旧主题导入、字段归属与兼容范围归 [migration.md](migration.md)。
- 原始问题、已执行旧检查与来源归 [audit-and-research.md](audit-and-research.md)。
- 执行、Record、环境及测试限制只归 [Governance](../../../README.md)。
- 本模块定义可观察的完成证据，不增加逐阶段审批或新的 API 调用要求。
- 按实际变更先做最小相关检查；有新改动、失败或明确风险才扩大或重复。
- 不要求全量 lint/test/build，也不要求全部主题、页面、设备的笛卡尔积矩阵。
- 既有 `2686aa40` 测试和复现不能记作后续实施 HEAD 的通过结果。

## 2. 检查层次与记录

1. 源码/合同：核对旧消费者、schema、保存回执和 CSS token 的实际连接。
2. 针对性单元/集成：验证选择、迁移、取消、失败与持久化边界。
3. 真实浏览器：验证布局、跨域颜色、交互和刷新恢复。
4. 只在具体问题需要时增加性能 trace 或额外平台检查。

每次记录 start/tested HEAD、执行目标、实际结果与未验证限制。
测试名、selector 和数据样例可随新实现调整；用户行为与 authority 合同不能丢失。
现有测试过度绑定旧 DOM 时，应改为验证同一语义，不能用删除断言掩盖功能退化。
不能把“控件可见”“选择器值已改变”当作颜色、功能或保存成功的证据。
临时数据与故障注入应隔离真实用户配置、主题和账户资料。

## 3. 设置工作纸与分类

对应 [settings-ui.md](settings-ui.md)，检查用户已确定的桌面/手机构图。

- 桌面是一张工作纸内的窄分类侧栏与单一内容列。
- 不再把正文拆成主题图库与大预览两列而造成三栏拥挤。
- 中宽缩减分类栏与卡片列数，内容和动作仍可完整访问。
- 手机先显示分类列表，进入后是有清楚返回入口的分类子页。
- 外观页依次容纳模式、当前日夜组合、主题卡片与真实组件预览。
- 高级 CSS 按已确定方式展开，不压过常用操作。
- 主题目标切换与实际运行模式可辨；不出现两套含糊的日/夜开关。
- 账户、备份、扩展、诊断等相关入口进入已有权威页面。
- 进入相关页面再返回，不能丢失必要的设置分类与原场景导航。
- 不改已集成的边缘 Dock，不建立设置专属的全局导航体系。
- 分类空/不可用状态说明实际原因，不展示无效的空白表单。
- 长中文、英文、长主题名称与错误回执能换行，主要动作仍可见。

## 4. 设置搜索与定位

- 搜索覆盖本次真实支持的设置，名称、说明与必要别名可匹配。
- 结果显示所属分类，点击打开原设置项并正确滚动/聚焦。
- 若目标藏在高级 Disclosure 内，先展开再定位。
- 不复制第二份控件或绑定第二套保存 handler。
- 清除查询后恢复正常分类浏览，返回结果不会丢失必要查询上下文。
- 无结果有清楚反馈；不存在的旧设置不能被搜索伪装成可用能力。
- 搜索和焦点定位不横向推动页面，也不把目标藏在固定页头后。

## 5. 普通偏好与真实保存

- 保留现有设置 authority、用户配置与持久层，不新增平行 store。
- 普通偏好即时反映其既定行为；“已保存”以实际持久回执为依据。
- 保存中、成功、失败和重试状态与请求实际结果一致。
- 失败保留可理解的当前值/草稿，或恢复已保存值并解释结果。
- 快速连续修改时，迟到响应不能覆盖更新的选择或错误状态。
- 页面卸载后，旧异步结果不能替换新分类或修改下一位账户的控件。
- 中文 IME 期间 Enter/快捷键语义保持；字号仍沿既有释放后应用规则。
- 主题选择、编辑、导入、取消与恢复默认均不顺带修改字号。
- 回归复现：先设 `font_scale=1.25`，再换主题，实际值、正文与滑条持续一致。
- 滚动跟随、输入提交、离开保护、减动与减少模糊按实际消费者检查。
- 通知/声音需检查 Native 生成完成及前后台路径，不能只切换布尔值。
- 媒体偏好不得绕过 Native Work/Session 权限；旧 chat 消费与 Native 路径分开验证。

## 6. 模式、日夜配对与有效主题

对应 [themes.md](themes.md)，至少覆盖关键分支而非只看模式标签。

- 浅色、深色、跟随系统三种模式能恢复真实保存值。
- 日间与夜间分别保存主题身份；刷新后配对、模式与实际颜色一致。
- 固定浅色时改夜间槽，确认只保存候选配对和显式模式，完成后回到浅色。
- 固定深色时改日间槽同理，不把查看目标偷偷写成运行模式。
- 跟随系统时，系统明暗变化切到对应槽的主题。
- 手动浅/深模式不被系统变更覆盖。
- 样例区查看日/夜只改变查看目标，不自动改变已选择的模式。
- 缺失/无效主题身份按设计回退并有解释，不留下半套未定义 tokens。
- theme identity、mode、effective appearance 与查看目标保持职责清晰。
- 浏览器控件/滚动条的 `color-scheme` 与当前有效主题一致。
- `meta[name=theme-color]` 等现有 browser chrome 投影随有效主题更新。
- 首屏恢复在可行的首次绘制前应用有效模式，避免明显的浅/深闪烁。
- 启动前脚本、恢复路径与正式安装器不能各维护一套相互漂移的默认值。

## 7. 临时预览、确认与取消

- 点选主题开启一次临时预览；无需依次进入局部和全局两个预览页面。
- 预览明确标识目标槽和候选名，例如“预览夜间 · Azure”。
- 未确认预览不写用户选中主题、模式或主题资产。
- 使用确认后，保存配对与显式模式；根据该模式重新计算最终显示。
- 取消恢复原选择与模式，再依当前系统状态计算，不回放旧颜色快照。
- system 模式预览响应系统变化；显式日/夜槽位预览保持查看目标，不写模式。
- 系统变更、快速换候选和关闭中重开不产生迟到覆盖或残留 style。
- 纯浏览预览离开按设计取消，不弹无意义的二次放弃确认。
- 主题编辑的有输入草稿沿既有离开保护，不把它与无输入的浏览预览混为一谈。
- 保存中防重复提交；已发出写入不能被“取消”伪装成已撤回。
- 写入失败时明确未保存，保留可重试候选或安全恢复已保存状态。
- 预览失败不能破坏当前主题；刷新后的状态必须来自已保存权威。
- 取消只处理本轮主题草稿，不回滚同时发生的字号、语言等普通偏好。

## 8. 主题编辑、资产与部分写入

- 五个旧主题名称和主要配色特征按已确定适配保留，新内置资产只读。
- 基于内置修改时创建用户副本，不原地覆盖或删除产品原件。
- 用户主题编辑/另存/命名冲突/删除引用按设计返回明确反馈。
- 编辑保存成功前保留原资产可恢复，失败不清空用户草稿。
- 资产保存与用户偏好选择分两次写入时，检查每个请求的独立失败。
- 资产成功但偏好失败时，不显示整体成功，也不产生指向不存在资产的选择。
- 偏好只能引用已经可读取的资产；重试不重复创建无意义副本。
- 若采用已有事务能力，验证其真实回滚/提交结果，不由 UI 推测原子性。
- 删除当前/日间/夜间引用资产时处理配对一致性，不留下悬空身份。
- 成功回执、实际资产、当前偏好和刷新结果应相互印证。

## 9. 首次升级与旧主题导入

对应 [migration.md](migration.md)，按其决定的默认与回退规则验证。

- 首次升级只执行规定的一次迁移；再次启动不反复改写已保存选择。
- 已有用户的旧选择为 Dark Lite、系统当前为深色时，首次升级仍保持当前浅色与原有有效 CSS。
- 新用户按 system 默认解析；浏览器本地状态丢失不把已有账户误判为新用户。
- 当前有效 CSS 保留原文和启用状态，并只从迁移主题副本注入一次；全局深色 CSS 不被初始 light 模式主动关掉。
- 同名被修改的主题及未存入主题的当前颜色调整均保留，不能被新版内置原件覆盖。
- 迁移失败可恢复，不靠删除旧主题/旧配置使新入口可用。
- 旧主题原件保留，映射结果与原始文件可区分。
- 导入先解析/校验；取消或坏文件不改变当前选择和资产。
- 旧颜色可映射到新语义，旧布局、字号与消息外观字段不再盲目回放。
- 携带旧 Custom CSS 的导入默认关闭 CSS，查看说明后才能显式启用。
- 被忽略或无法映射字段得到清楚摘要，不宣称百分百还原旧界面。
- 同名文件、无效颜色、缺字段、空名称与未知版本有可恢复结果。
- 导入新 Atria 格式后再导出/重入，配色和必要元信息保持一致。
- 旧保留字段/原件的数据兼容性不等于继续暴露全部旧控件。

## 10. 高级 CSS 与恢复

- CSS 编辑、暂时预览、启停和持久保存职责可辨。
- 默认关闭的导入 CSS 不会在解析、预览列表或刷新时意外执行。
- 无效 CSS、请求失败或过度覆盖界面后仍可禁用用户 CSS 并回到可用设置。
- 恢复入口不依赖被该 CSS 隐藏的唯一按钮，复用现有可诊断恢复能力。
- 禁用 CSS 不删除原始用户文本，重新启用与取消遵循同一保存语义。
- 原生主题、兼容桥、用户 CSS 的实际优先级与设计一致。
- 编辑/预览卸载后不残留 style、listener、observer 或重复绑定。

## 11. 浏览器视觉与可达性

本任务参照 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 中适用的 AA 要求检查新界面，
不据此宣称已完成全产品合规认证。普通文字对比度目标为 4.5:1，大字为 3:1，
识别必要控件/状态的非文字信息为 3:1；键盘焦点可见且不被自建内容完全遮挡。
目标尺寸按 24×24 CSS px 及标准规定的间距等例外检查；约 44px 的手机设置行是工程建议，
不是将 AAA 增强目标误作 AA 的一律门槛。自定义配色的提示与保留规则仍按主题契约执行。

- 代表尺寸选择 1440、一个 medium、390 与 320px；按实际改动增加边界点。
- 大字号、长文案、safe-area、横屏或软键盘只在受影响场景补测。
- 无页面级横向溢出；末尾操作可滚达，顶部预览栏不遮挡搜索定位目标。
- 手机无长期大型底部保存栏；键盘出现后编辑器与动作仍可操作。
- 检查 hover、focus、pressed、disabled、loading、error、success 的真实表面。
- 内置主题的文字与必要非文字状态达到对应对比目标，语义不能只靠颜色区分。
- 自定义配色对比不足时提示并建议恢复值；高级用户可保留，不以此禁止保存。
- Tab 可达、标签关联、状态通知、焦点归还与隐藏内容 inert/焦点隔离正确。
- Escape/Back 尊重既有 modal、sheet、命令与工作区顺序，不覆盖 IME。
- 系统/应用减动与减少模糊使用现有 Environment 和偏好入口。
- 作品自有内容保持独立，只验证应用 chrome 与声明的共享组件边界。

## 12. 最小测试选择与完成证据

- 可复用 `tests/atria-shell/appearance.test.js`、`preference-controls.test.js`、
  `utility-workspaces.test.js`、`structure.test.js`，按实际变更选择或更新。
- 新增测试重点为迁移、日夜/模式、取消、请求失败和部分写入合同。
- 浏览器从设置切换到受主题影响的代表领域，读取真实 `getComputedStyle` 与截图。
- 代表表面至少包含 Shell、阅读内容、配置表单及 Popup/Toast；兼容岛受影响时加入。
- 对全部主题检查语义 token 完整性；实际浏览器用能揭示不同问题的代表配色。
- 不用保存值、HTML dataset 或缩略图替代跨域计算颜色证据。
- 旧 E2E 的 dark 假设应按最终合同更新；是否运行及结果必须如实记录。
- 完成证据包括相关检查结果、保存/刷新一致性、代表视觉和明确环境限制。
- 发现失败后诊断、修复并做相关复测；一次实验结束不等于目标完成。
- 产品实际执行的检查、失败修复和环境限制见 [Record](../../../records/refactor/atria-settings-and-themes.md)，本模块继续定义验收目标。
