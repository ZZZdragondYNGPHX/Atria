# 存储中心：页面结构与操作流程

本模块定义用户可见的信息架构、清理预览、批量操作和状态反馈。
计划唯一入口为 [index.md](index.md)。
资源分类、数据量与配额口径见 [resources-and-accounting.md](resources-and-accounting.md)；
删除、依赖保护、回收站和恢复契约见 [lifecycle-and-recovery.md](lifecycle-and-recovery.md)。
实现职责见 [architecture.md](architecture.md)，验收场景见 [acceptance.md](acceptance.md)。
本模块不另建存储算法、业务删除通路或恢复策略。

## 1. 容器与交互基础

本次 UI 实装以 [已确认 HTML 草稿](../../../previews/atria-storage-center/index.html) 的视觉方向为参考：紧凑五区导航、集中用量摘要、资源行列表、详情抽屉、整页固定预览及手机底部导航。草稿示例数据与模拟服务行为不进入产品；本模块的真实范围、计量、保护与执行规则继续有效。设计取舍及审查见 [草稿说明](../../../previews/atria-storage-center/review.html)。

- 保留现有设置中的存储管理入口，进入应用内独立的宽版管理面板。
- 桌面使用充分的可用宽度；移动端采用全屏布局，并保留明确的返回路径。
- 面板内完成范围切换、导航、筛选、资源详情、预览和结果查看。
- 最终执行确认可使用既有弹窗组件；复杂清理预览使用完整页面。
- 复用现有设计系统、组件、排版、颜色、间距和焦点规则，不另建视觉体系。
- 视口缩小时调整信息顺序和操作布局，不依赖横向挤压才能完成管理任务。
- 列表、选择、确认、取消、详情和恢复可通过键盘操作。
- 状态、危险性和选中状态除颜色外，还应有文字或可访问名称表达。
- 长任务更新应可被辅助技术理解，同时避免每条内部进度都打断用户。
- 加载、空列表、搜索无结果、局部失败、权限不足和离线状态均有明确反馈。
- 有可用数据时保留它与统计时间；刷新失败不得把旧数据伪装成刚完成的结果。

## 2. 管理范围

面板顶部持续显示当前范围，范围标签不会在资源详情或操作预览中消失。

| 范围 | 显示标签与边界 |
|---|---|
| 服务器 | 当前账户 · 服务器；使用账户权限与业务资源边界 |
| 浏览器 | 本设备 · 当前站点；涵盖该设备上当前 origin 可访问的数据 |

- 切换范围同时切换汇总数字、分类、筛选结果与可执行操作。
- 浏览器数据不得标成当前账户独占；无法确认所属账户的数据明确说明范围。
- 每批操作只针对一个范围，不提供混合服务器与浏览器对象的统一删除批次。
- 已生成的任务保留原范围；后续切换页面范围不会改变它的执行对象。
- 浏览器端只呈现已实现并可验证的能力，不以服务器能力推定本地可恢复性。
- 权限变化后重新检查可见性和操作资格，不通过缓存详情暴露已无权查看的内容。

## 3. 五区导航

| 区域 | 职责 |
|---|---|
| 总览 | 当前范围占用、配额、分类入口、统计覆盖状态 |
| 清理建议 | 安全清理项、需人工检查的候选及其依据 |
| 备份与回收站 | 备份管理、恢复预检查、保留状态与永久删除入口 |
| 操作记录 | 活跃任务、执行结果、失败重试及可恢复对象入口 |
| 高级工具 | 旧版兼容数据、未识别数据和底层存储检查 |

- 五区共享同一套范围、资源标识和操作状态，不维护独立的资源副本。
- 总览的“备份与回收站”分类进入同一个备份与回收站页面。
- 清理建议、详情与操作记录中的同一对象链接回同一资源详情和生命周期入口。
- 主界面移除旧版分类；高级工具中的旧数据入口仍按实际存在的数据呈现。
- 高级工具不绕过权限、引用保护和恢复检查，底层技术名称只在此处按需展示。

## 4. 总览

总览由上到下显示以下内容：

1. 资源数据量与配额，包含范围、统计时间和统计完成程度。
2. 可安全清理数据与回收站占用摘要，以及进入相应流程的操作。
3. 九类服务器资源的名称、业务对象数量和数据量。
4. 高级工具数据对账说明，进入旧版与未识别数据详情。
5. 可展开的实际占用说明，解释可测量范围和与主数字的差异。

九类服务器入口依次为会话与存档、作品与项目、世界与知识、媒体与附件、
个人身份、Agent 资料、设置与集成、备份与回收站、缓存与临时数据。
分类定义与汇总依据由 [resources-and-accounting.md](resources-and-accounting.md) 统一规定。

- 资源数据量为主数字与配额判断依据；辅助实际占用不替代主数字。
- 回收站摘要明确其已计入总量；不能让用户误以为需要再相加。
- 移入回收站后的状态表达为保留占用，不显示“已释放空间”。
- 高级工具数据参与对账，不能因主界面不展示旧分类而从总量中消失。
- 未完成扫描显示已统计范围与待检查状态；未知、不可测量和失败不显示为零。
- 图表仅表达有依据的数据；统计不完整时不绘制看似完整的占比。
- 浏览器总量注明估算及来源；分项无法完整对账时直接说明差异。
- 浏览器分类按实际能力展示缓存、离线内容或本地模型、设备偏好等入口，
  不强行套入服务器九类，也不将技术容器名称作为主要用户分类。
- 业务对象数量应有明确单位；共享素材引用数量与素材本体数量分别表达。

## 5. 资源明细与详情

- 分类明细支持搜索、排序、分页与批量选择，默认按数据量排序。
- 不以固定前若干条代替完整枚举；浏览器大列表也必须能够继续查看后续结果。
- 列表显示名称、对象类型、数据量、必要时间和影响操作的状态。
- 查询、统计和加载失败各自反馈；一页失败不清空已有选择或伪称全部已加载。
- 筛选条件、当前页和选择范围有清楚的可见说明。
- 资源详情显示占用构成、所属对象、引用关系、适用操作与限制原因。
- 同一素材在不同资源详情中展示引用贡献，不重复宣称拥有整份可释放空间。
- 对可访问的关联对象提供跳转；对无权查看的对象仅展示必要的阻止原因。
- 列表和详情不展示凭据、原始消息、全文附件或其他无关敏感内容。
- 需要编辑业务内容时进入现有业务编辑器；管理中心不内嵌第二套业务编辑器。
- 原始文件、JSON、localStorage 和 IndexedDB 结构检查放在高级工具。
- 不可执行操作可说明禁用原因；可解决的限制提供对应处理入口。
- 受保护资源的限制应真实、具体，不能以笼统“暂不支持”掩盖未完成能力。

## 6. 清理建议

- 安全清理项与需要人工检查的业务候选在视觉和选择语义上明确区分。
- 默认只勾选符合既定安全清理依据的项目，具体资格由资源与生命周期契约决定。
- 暂无引用的作品、用户素材、存档和手动备份不因无引用而默认选中。
- 每项建议可查看原因、适用范围、重建或恢复方式及估算可信度。
- 扫描建议本身不执行删除；执行前仍须生成预览并重新检查资格。
- 重新扫描后保留仍有效的用户选择，失效项明确标记，不偷偷补选新增匹配项。
- 无清理建议时显示正常空状态，不制造必须清理的紧迫感。

## 7. 批量选择与固定清单

- “选择当前页”与“选择全部筛选结果”是不同操作，分别显示准确数量与范围。
- 全部筛选结果的选择必须能枚举完整对象，不依赖已渲染的行数。
- 父对象与其所属子项去重；预览说明哪些子项将随完整对象一并处理。
- 生成预览时固定对象标识、资源版本或等效变更依据、动作与范围。
- 后来新增的匹配资源不加入已生成清单；筛选变化不会扩大本次选择。
- 新增对象或改变动作需要重新预览，不能沿用旧确认。
- 引用保护、运行状态、权限和版本变化在执行时再次核验。
- 相互依赖的资源形成完整处理单元或受约束的组，独立对象才允许独立推进。

## 8. 清理预览与确认

预览使用完整页面，分为本次范围、处理结果预估和恢复说明三个部分。

| 区域 | 必须表达的信息 |
|---|---|
| 本次范围 | 固定对象清单、动作、对象数量、关联影响、阻止项与原因 |
| 处理结果预估 | 处理数据量、预计立即释放量、保留占用和无法估算的原因 |
| 恢复说明 | 是否可恢复、适用恢复入口与期限、永久删除的不可恢复性 |

- 处理数据量与预计释放空间使用不同字段和文案，不用同一个数字代替两者。
- 共享引用、数据库回收等影响直接体现在估算说明中，不承诺无法保证的释放量。
- 被阻止项单列；允许执行其余项时按钮明确标注实际可处理范围。
- “移入回收站”“清理缓存”“彻底删除”使用明确动作名称。
- 永久删除作为独立批次确认，不与可恢复动作混为一次含糊的“清理”。
- 确认提交后生成可追踪的任务标识；重复提交不能产生重复处理。
- 恢复也先展示预检查结果和恢复范围，具体检查由生命周期模块定义。
- 可恢复对象的依赖缺口、同 ID 冲突与不再有效的操作分别说明并阻止相关执行。

## 9. 执行、停止与故障

- 任务进度显示等待、处理中、成功、失败、待重新检查等状态。
- 一个完整业务对象是处理单元，详情中可查看其关联处理范围。
- 操作按钮在提交与处理中反馈状态，防止重复点击造成重复任务。
- 取消按钮使用“停止后续处理”，说明已成功部分仍然生效。
- 收到停止请求后，在当前完整对象的安全边界结束处理，不留下半个已删除对象。
- 单项引用冲突、版本变化等领域问题记录结果，并继续其余独立对象。
- 存储不可用、无法保存恢复记录等整体故障停止后续处理并保留已完成事实。
- 前置条件失效的对象不得自动降低保护或切换成永久删除来完成任务。
- 预览、任务列表和资源详情使用一致的任务状态，避免多个页面各报一套结果。
- 服务器任务应持久化，离开页面后可从操作记录重新查看执行状态。
- 浏览器任务说明需要页面保持打开；关闭、刷新或中断不能假称仍在后台执行。
- 浏览器重新进入后核对已完成事实与待处理对象，不从旧进度条直接推定结果。

## 10. 结果、重试与历史

- 结果页分别展示成功、失败、未处理和需要重新检查的对象及原因。
- 执行后重新统计受影响范围，展示实测变化和仍待确认的释放情况。
- 提供适用的恢复、详情、重新预览和失败项重试入口。
- 重试只针对仍需处理的对象，重新核验当前条件，不重复处理已成功项。
- 失败不改写成成功；部分完成不能用“全部完成”概括。
- 操作记录仅保存追踪和恢复所需的最小元数据，包括范围、动作、时间、状态和原因。
- 不在历史中复制凭据、消息正文、素材内容、原始请求响应或完整数据库记录。
- 日志与记录中的名称、标识和原因同样遵守账户隔离与最小可见性。
- 历史任务链接不恢复已经失效的执行资格，也不绕过当前权限检查。

## 11. 与业务页面同步

- 删除、恢复和清理完成后，更新业务列表、资源索引、占用和相关详情状态。
- 打开的编辑器、会话和缓存接收资源状态变化，失效对象不能继续写入。
- 旧内存状态、延迟自动保存和离线待提交数据不得把已删除对象重新创建回来。
- 受影响页面给出可理解的状态与下一步入口，不让用户在失效界面继续操作。
- 恢复后更新业务可见性和引用状态；是否续跑遵循生命周期契约。
- 同步与失效控制依赖统一资源事实和业务写入校验，不能只靠当前面板刷新。

## 12. 本模块验收映射

页面结构、状态、范围、无障碍、大列表和端到端流程以 [acceptance.md](acceptance.md) 验收。
实施验证应覆盖完整选择、预览、执行、停止、结果、恢复和业务状态同步，
并证明浏览器中断与服务器离页两种行为符合各自真实能力。
