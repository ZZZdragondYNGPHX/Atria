# 验收场景与验证路由

本模块将冻结设计转为可验证的行为。详细产品规则以对应模块为准；实际执行、失败、环境限制和 Tested HEAD 记录在 [Record](../../../records/refactor/atria-storage-center.md)。

验证按 [Governance §12](../../../README.md#12-execution-adapters) 选择最小相关检查，不用固定用例数量或全量测试代替行为证据。

## 统计、分类与配额

权威：[Accounting](resources-and-accounting.md)。

| ID | 场景与预期结果 |
| --- | --- |
| A01 | 混合创建当前 Native kind、版本化资源、项目源码及 Git 历史、素材、备份、旧版与未知文件；所有数据进入九类或高级工具对账，无静默遗漏。新增类型有兜底统计。 |
| A02 | 多个会话、作品和身份共享素材；总量只计一次，引用详情不再次加到分类总量，删除单个引用不会宣称释放整个素材。 |
| A03 | 在九类之间移入回收站和恢复原对象，总量与配额用量没有重复增长或提前减少；九类加高级工具数据与主数字一致。 |
| A04 | 同一资源内容在 FS、SQLite、MySQL、Postgres 上使用一致逻辑计量；数据库页、WAL、索引等不混入逻辑分类，无法按账户归属的物理量明确不可得。 |
| A05 | 扫描进行中、超时、权限或读取失败、部分后端暂不可用时展示已统计范围及时间，未知值不变成零，也不绘制虚假的完整占比。 |
| A06 | 在配额临界值测试 Native 创建、导入、修改、恢复、项目文件和素材写入；页面计量与写入准入使用同一权威，覆盖请求大小与实际净增长不一致的情况。 |
| A07 | 并发写入和恢复不会因为独立预检查通过而共同超占预留；失败后释放预留，已有配额值及无限制语义正确保留。 |
| A08 | 空间不足时原有未到期恢复记录保持可用，失败操作不继续提交删除；支持可解释的导出、清空或取消选择。 |
| A09 | 浏览器聚合估算不与分项重复相加；本地缓存、离线内容、偏好及未知技术结构的范围明确，读取失败与空数据可区分。 |

## 清理、回收站与恢复

权威：[Lifecycle](lifecycle-and-recovery.md)、[Architecture](architecture.md)。

| ID | 场景与预期结果 |
| --- | --- |
| A10 | 安全清理默认候选符合明确白名单；未引用的用户作品、原始素材、手动存档和备份仍不会自动勾选。每个候选有可解释依据和影响。 |
| A11 | 删除仍被引用或运行中的作品、身份、知识、素材等对象时受到领域保护；只能看到有权限的关联详情，跨账户引用不泄露他人名称或内容。 |
| A12 | 普通会话处理覆盖所属分支、消息、存档、记忆与任务结果；项目处理覆盖源码、Git 历史及项目直接拥有的 Agent 数据，不连带删除仅有来源引用的独立资料；每种对象按能力矩阵验证闭包。 |
| A13 | 回收记录创建、依赖保留、领域删除或恢复提交各处注入失败或进程中断；重启后可识别状态，已删除资源有有效恢复来源，未提交目标不会以半完成状态可见。 |
| A14 | 回收站到期和手动彻底删除均重新检查引用、运行状态及素材保留；尚在保留期内的素材不会被既有会话维护、媒体 GC 或 blob GC 清掉。 |
| A15 | 30 天保留按持久到期时间执行，页面显示删除和到期时间；重启、重新扫描或重试不会静默改变到期记录，空间压力不提前逐出记录。 |
| A16 | 恢复前制造同 ID 冲突、缺失精确作品版本、闭包损坏或空间不足；预检查说明缺口，提交时再次检查，目标和当前默认身份不被静默覆盖。 |
| A17 | 恢复成功后从原业务页面打开资源，版本、素材、关联和项目历史完整；后台任务保持暂停，历史外部请求及模型调用不自动重发。 |
| A18 | 特殊运行模式继续服从领域生命周期；铁人终结状态不能通过回收站、导入新 ID 或另存副本恢复为可继续运行。 |
| A19 | 账户备份与恢复、引擎迁移包含新管理元数据、回收站闭包和保留素材；原有 Native metadata、project sources、blobs 的精确闭包保持完整；导入的历史待执行管理任务先暂停核对，不能自动重放旧删除意图。 |

| A20 | 当前页选择、全部筛选结果选择及父子去重产生明确固定清单；预览后新增匹配项不被加入，切换筛选不会改变正在执行的任务。 |
| A21 | 预览后变更版本、引用或运行状态；受影响对象重新预览或被阻止，其余独立对象继续。恢复记录写入失败、存储不可用等整体故障停止后续处理。 |
| A22 | 重复确认、刷新、断网重连和失败重试不重复处理成功对象；“停止后续处理”保留当前完整对象安全边界并准确标出未开始项。 |
| A23 | 服务器任务离开页面后可查询持久进度；浏览器页面中断后标明已完成与待核对项。结果分别展示处理数据量、释放量估算或实测依据、失败和未处理原因。 |

## 验证组织

- 单元与契约检查优先覆盖计量、类别映射、配额预留、引用与恢复协议、选择去重及任务状态转换。
- 集成检查使用真实 Engine 和隔离临时数据验证各受支持后端、文件与数据库交界、备份迁移以及中断恢复；缺少证据的后端不能标成已验证。
- 浏览器检查复用既有 E2E 基础和当前面板组件，补齐原生资源、浏览器记录、移动及键盘流程。
- 空间变化有并发写入时，区分任务自身已处理量与全局重新统计差值；无法可靠归因的物理释放量不标成精确实测。
- 对破坏性路径使用合成资源与临时存储。既有真实业务数据只用于授权范围内的兼容检查。

## 既有验证资产与缺口

优先复用产品源码中的以下测试族，再针对实际变更补充：

- `tests/storage-inspector/*`、`tests/storage-management/service.test.js`：旧检查器与通用服务。
- `tests/native/storage-*.test.js`、`tests/native/storage-*.contract.test.js`：原生基础、引用、GC、提交和往返。
- `tests/storage/endpoints/native-backup-roundtrip.test.js`：修复样本构造后实际验证当前原生资源备份闭包。
- `tests/e2e/storage-inspector/*`、`tests/e2e/browser-storage-inspector/*`：既有浏览器流程，补充原生中心与未覆盖失败情形。

先前审计的实际通过、失败与环境限制归 Record；本模块不将历史测试结果当作新实现已经验收。

## 交付判定

九类资源具有真实统计与适用操作，普通可恢复对象具备完整恢复契约，受保护对象能解释限制，所有适用验收项有实际证据。页面占位、仅接入旧目录、仅修复测试启动或仅通过旧 UI 测试不能代表本任务完成。完成状态与集成流程按 Governance 执行，实际结果更新同一 Record。
