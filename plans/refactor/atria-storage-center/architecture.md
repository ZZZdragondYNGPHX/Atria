## 管理层的责任

管理层组织五类能力：

1. 资源目录与统计快照：枚举业务对象，提供完整性、归属、更新时间和统一计量结果。
2. 业务对象检查：读取明细、引用、操作能力及原因，构建带版本依据的预览。
3. 受控操作：将固定对象清单路由至相应领域服务，执行配额预留、回收记录、领域变更及持久任务更新。
4. 恢复与清理：提供回收站协议和清理协调，具体可达性、运行检查、原 ID 恢复由领域权威负责。
5. 浏览器适配：按已识别数据用途提供能力，未知结构通过高级工具检查。

统计层可以使用只读的 Engine 原语高效聚合；结构化变更必须通过业务服务和 Repository。通用文件编辑不能直接改写原生状态，通用文件删除不能代替业务删除。

管理层需要的对象适配器用于桥接现有业务服务，不另建一套会话、素材、身份或项目持久层。所有适配器都服从同一统计、操作和恢复契约。

## 统一契约

以下为实现必须表达的语义；字段命名、路由后缀和类名属于工程选择。

### 资源身份与能力

资源条目必须能表达：

- 服务端派生的稳定业务身份、类型、所属类别和账户或设备范围。
- 可见名称、归属对象、数量和数据量；统计完整性与时间依据。
- 当前版本、完整性标识或足以检测变化的领域依据。
- 查看、导出、清理、移入回收站、恢复、彻底删除等实际能力及限制原因。
- 可恢复性及其约束，不能把“有导出按钮”等同于“可撤销删除”。

客户端提交的是明确业务身份与预期版本，不由客户端提供任意路径决定目标。资源类型、保护状态和能力由服务端重建；不能依赖客户端 `kind` 字段保护角色、设置或其他身份资源。

### 统计与预览

统计响应须携带范围、快照时间、完整性、已知和未知量、分项与对账信息。计量定义归 Accounting。

预览须绑定操作者、范围、固定对象集合、操作类型、版本和引用检查依据、恢复要求、空间需求及估算。确认和执行时重新认证并核对；不把旧预览视为绕过最新领域约束的许可。

### 操作与结果

操作请求需要稳定的操作身份，使重复提交、刷新和失败重试可以识别已完成工作。执行结果区分业务对象成功、失败、未开始及需重新预览，保存最小必要的状态与原因。

领域对象闭包是处理单元。跨对象批次不承诺单个全局事务；单对象内部完整性和可恢复性由生命周期协议保障。具体继续、停止和取消行为归 Interface。

### 恢复

恢复记录必须能验证来源、版本、完整闭包、依赖、保留素材及到期状态。恢复前预检查与提交时复核使用同一业务身份约束。格式、备份选择和原 ID 恢复边界归 Lifecycle。

## 持久状态与故障恢复

原生回收站、服务器任务进度、操作去重依据、配额预留等需要跨请求和进程恢复的状态，应接入既有 Engine、资源命名与事务体系。可复用已有版本化资源机制，或按现有约定增加必要资源种类；实现需明确其统计、迁移、备份和清理归属。

文件闭包保留到既有用户文件存储中，素材沿用内容寻址。跨数据库与文件操作使用可恢复的操作记录和安全发布顺序；不能将内存 Map 或浏览器页面状态作为删除成功、素材保留或可恢复性的唯一证据。

核心故障不变量：

- 需要可恢复的删除，在可验证恢复记录及必要保留依赖就绪之前不能提交业务删除。
- 中断后可以识别已提交、未开始和待修复对象；重试不会重复删除或重复生成已完成对象的恢复副本。
- 恢复中的目标不能以半完成状态被业务使用；提交前失败保留可重试来源。
- 错误不能被转换成“无数据”或虚假的操作成功。

沿用已有锁、写入门禁、事务、HEAD 冲突和领域租约机制。锁序、并发度、游标和缓存策略依据实际实现选择，不能用全局长期停写掩盖不完整的对象协议。

## 接口接入与兼容

建议在现有 `/api/users/storage/*` 命名空间内组织统计、资源明细、预览、执行、任务结果和回收站接口；具体路由由实施时结合既有调用者确定。新增接口在实现前不得当作现有能力引用。

- 现有高级检查调用者保留必要兼容路径；主面板改用原生资源契约。
- 用户身份从认证会话取得；账户总量和原生对象默认只在授权范围内读取。
- 浏览器总量和操作在本设备执行，不把其他设备的本地数据伪装成服务器账户数据。
- 原生写入、导入、恢复、项目文件、素材和管理操作统一接入新的配额计量权威；已有配额配置值和无限制语义保留。
- 配额拒绝、引用冲突、版本变化、存储故障和恢复不足提供可区分的错误原因，界面按能力处理。
- 写入、删除和恢复后刷新受影响的业务状态与索引；保留领域冲突检查，防止旧内存随后覆盖新状态。

## 高级工具边界修复

现有通用管理器需要同时修复，而不是仅通过隐藏入口规避：

- 分类路径到允许目标的映射使用明确白名单；主设置分组不能定位到任意用户根目录子项。
- 身份资源、密钥、数据库及引擎备份内部文件的保护由真实目标和业务身份决定。
- 路径解析检查实际落点、链接和目录边界，内容大小、格式及并发变化遵守适用限制。
- 原生数据检查保持业务权威；高级操作具有同样的权限、引用、事务和生命周期约束。
- 浏览器操作不假定整个 origin 属于当前账户，技术级编辑和删除说明范围、覆盖行为及不可恢复性。

## 扩展与兼容验证

新增资源类型应有分类或高级工具兜底、操作能力、配额、备份和 GC 归属。对当前全部 Native kind 及版本化 resourceType 建立完整盘点，避免又出现“引擎存了数据但管理中心完全看不到”。

账户备份必须保留管理状态依赖及素材保留闭包，引擎迁移必须保持对应状态；对于未完成操作，恢复或迁移后的协调逻辑依据持久状态安全接续，不能直接重新发送历史外部请求。

原地进程崩溃续接与导入账户备份是不同场景。账户备份恢复、merge 导入或引擎转换带入的历史待执行管理任务，先处于暂停核对状态；重新验证目标身份、当前版本、配额预留和保留根后才能继续。快照中的旧操作身份不能自动成为再次删除当前资源的执行依据。

实施先以真实源码核对上述入口；同期新增的业务对象与现有 UI 变化按本模块的权威边界接入。相关可验证结果见 [Acceptance](acceptance.md)。
