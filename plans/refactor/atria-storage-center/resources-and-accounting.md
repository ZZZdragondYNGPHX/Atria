# 资源分类与计量

本模块定义资源归属、占用数字和配额口径。入口见 [index.md](index.md)；删除与恢复规则见 [lifecycle-and-recovery.md](lifecycle-and-recovery.md)，界面与操作呈现见 [interface-and-workflows.md](interface-and-workflows.md)。

## 1. 状态与边界

- 本模块是实施方案，不表示相关能力已经实现。
- §2—§5 是确定的产品规则；§6—§8 是实现这些规则的工程设计，具体接口、索引、序列化与事务方案应根据实际持久层选择。
- 分类面向业务资源，文件目录、SQL 表、浏览器存储结构只是底层来源。
- 服务器与浏览器一起规划，各自核算；不得把两处数字相加当作账户配额用量。
- 主界面移除 SillyTavern 旧分类；旧数据和未识别数据仍参与对账，在高级工具查看与管理。

## 2. 九类资源

| 分类 | 归属内容 | 归属边界 |
|---|---|---|
| 会话与存档 | 会话、分支、消息与变体、状态、历史版本、存档、所属记忆与任务结果、游戏进度 | 会话拥有的内容跟随会话；作品级连续进度不因引用作品而重复计量 |
| 作品与项目 | 已安装作品及版本、作品状态、Studio 源码、项目创作历史、项目任务与结果 | 项目 `.git` 属于项目；发布包不能代替项目源码和历史 |
| 世界与知识 | 世界、知识库、条目、绑定及版本 | 独立资料库资源计入本类；内嵌在作品或存档内的快照随容器计量 |
| 媒体与附件 | 图片、音频、文档、头像及素材引用元数据 | 共享素材本体统一计一次，引用方展示关联占用而不再累加本体 |
| 个人身份 | Persona、身份版本、默认身份与迁移资料 | 身份头像本体归媒体；会话内已冻结身份快照随会话 |
| Agent 资料 | 独立经验、证据、目标、演化资料及其保留记录 | 会话或项目直接拥有的执行状态、记忆和任务结果仍随所属对象 |
| 设置与集成 | 模型、连接、路由、提示词、检索、扩展与设备配置等 | 配置与用户内容分开；敏感内容只计量，不因此开放读取或导出 |
| 备份与回收站 | 本地备份、恢复记录、待彻底删除资源及恢复所需数据 | 移入回收站只是归属变化；已被纳入的保留数据不可重复计量 |
| 缓存与临时数据 | 经识别可重建的缓存、缩略图、临时数据、适用的内部维护资料 | 位于临时目录、超过时间或没有引用都不能独立证明可安全清理 |

统计项归属与操作能力分开。能统计不代表能直接删除；九类都覆盖实际存在的数据和适用管理能力，受保护内容说明原因。

同一持久化单元只能有一个计量归属。业务详情可同时展示“自身数据”“引用素材”，但只有自身计费数据与素材唯一归属参与分类合计。

## 3. 统一数字定义

| 数字 | 含义与规则 |
|---|---|
| 资源数据量 | 当前范围内实际保存的资源内容总量，是服务器主数字和账户配额依据 |
| 回收站占用 | 资源数据量的子集，已经包含在“备份与回收站”中 |
| 可安全清理数据 | 当前检查确认符合清理规则的数据量，不等同于保证立即释放的物理空间 |
| 处理数据量 | 这批操作实际处理的对象及所属数据量；移入回收站也有处理量 |
| 预计释放空间 | 按共享依赖、保留状态、后端回收特征估计的空间变化；无法可靠估算时说明原因 |
| 实际占用 | 可测量的文件、数据库与存储系统物理占用，作为辅助信息独立展示 |

服务器主数字满足：

`资源数据量 = 九类资源计量合计 + 高级工具数据计量合计`

其中回收站已经属于九类。旧版与未识别数据属于高级工具数据，不另外产生第十类主界面业务分类。

- 分类条目数按业务对象计数；版本、子记录、引用数量可展开，不与对象数混称。
- 无配额显示“无限制”，配额信息不可用显示不可用，不猜测成无限制。
- 物理数据库页、索引、日志、压缩、分配空洞与延迟回收会使实际占用不同于资源数据量；不能把整个数据库文件作为“其他资源”再次相加。
- 执行完清理后重新测量，分别报告资源数据量变化和可获得的实际占用变化。
- 删除引用、移动到回收站、数据库行删除都不能直接承诺立即释放同等磁盘空间。

## 4. 共享、保留与重复计量

1. 按当前账户实际拥有的素材存储身份识别本体；同一 blob 被多个 assetRef、会话或作品引用时只计一次。
2. 当前 AssetStore 的内容哈希与账户素材边界是主要证据，不能仅靠文件名或 URL 推测去重。
3. 引用仍活跃的共享素材继续归“媒体与附件”；只有回收站保留的独占数据转入“备份与回收站”。引用关系仍需在恢复预检查与 GC 中保留。
4. 多条回收站记录共享的同一本体只计一次；每条记录可展示关联大小，但不得把关联大小直接求和作为回收站占用。
5. 原位标记、迁移保留和独立恢复副本采用各自真实存储清单核算；同一实体不能因同时出现在原分类与回收站清单而重复计量。
6. 真正保存的独立备份副本占用仍应计入，不能因内容与在线资源相同就凭空扣除。
7. 移入回收站后，原资源保留占用不释放；新增的真实恢复元数据或必要副本也应计量，不以分类转换虚增原资源本体。
8. 彻底删除后的释放估算考虑剩余活跃引用和其他回收站保留引用，最后一个可保留引用消失前不得释放本体。

依赖保护、30 天保留、到期与空间不足处理的详细规则只归 [lifecycle-and-recovery.md](lifecycle-and-recovery.md)。

## 5. 统计状态与浏览器范围

每份结果说明当前范围、统计开始与完成时间、数据版本或可用的一致性标记，以及完整性状态。

- 扫描中显示已统计的部分和仍在检查的范围；分页完成一个列表不表示全账户扫描完成。
- 未识别且已测得的字节归高级工具；无法读取或无法测量的范围显示“暂不可估算”及原因，不能填 `0 B`。
- 部分失败保留已知小计和失败范围，不把小计渲染为完整总量，也不绘制暗示完整的比例图。
- 业务写入发生在扫描期间时，通过一致快照、版本校验或重新检查保证结果语义；不声称多个时刻拼接的结果是精确瞬时快照。
- 刷新、删除、恢复、导入和后台写入会使快照过期；失效后的旧数字不能继续作为精确配额判断依据。

浏览器范围固定说明“本设备 · 当前站点”，不能声称整个 origin 的内容都属于当前账户。

| 浏览器主视图 | 内容 |
|---|---|
| 缓存 | 已识别且可以说明用途与重建方式的缓存 |
| 离线内容／本地模型 | 已识别的离线资源、模型及其关联元数据 |
| 设备偏好 | 当前设备保存的偏好和本地设置 |
| 高级工具 | localStorage、sessionStorage、IndexedDB、Cache Storage 等原始结构与未识别记录 |

浏览器不强行填满服务器九类。它使用相同的预览、结果与能力表达，只显示实际支持的分类和操作。

- `navigator.storage.estimate()` 返回站点估算，和逐项估算是不同维度；两者不可相加，也不能相减后把差额当成精确的未识别记录大小。
- 浏览器“主数字”明确标注估算或已统计小计；站点配额是浏览器提供的能力，与服务器账户配额分开。
- 分项来源、计量方法、缺失范围均可查看；localStorage 字符数估算不能冒充文件磁盘字节数。
- 浏览器大数据集必须完整分页或游标遍历，不能把前若干条记录当作全部。
- 已识别记录可以按语义展示；未识别结构保留高级工具入口，不默认视为可清理缓存。

## 6. 当前 Native 数据覆盖清单

以下符号对应 `main:src/native/contracts.js` 的 `NATIVE_RESOURCE_KINDS`。实施以当时真实注册表为准；本清单防止只统计常见资源，不要求永久复制一份注册权威。

| kinds（符号名） | 计量归属／细分规则 |
|---|---|
| `session`, `runControl`, `branch`, `timelineEntry`, `timelineVariant`, `sessionState`, `sessionRevision`, `savePoint`, `commitReceipt` | 会话与存档；包含状态命名空间中的消息、记忆、任务和快照数据 |
| `sharedAccess`, `sharedAccessRevision` | 会话与存档；按 sessionId 归属，不因共享访问复制计量 |
| `realm`, `realmRevision`, `playerContinuity`, `playerContinuityRevision` | 会话与存档中的持续游戏进度；它们以 packageId 定位，不能当成可随作品任意删除的静态配置 |
| `package`, `packageVersion`, `packageState` | 作品与项目；版本内内嵌资源随作品计，外部共享 blob 单列 |
| `projectAgentTask` | 作品与项目，按 projectId 归属并展示项目任务构成 |
| `world`, `worldRevision`, `knowledgeBase`, `knowledgeRevision`, `knowledgeEntry`, `knowledgeBinding` | 世界与知识；绑定只计自身记录，不重复展开计量被引用资料 |
| `persona`, `personaRevision`, `personaDefault`, `personaMigration` | 个人身份；头像本体按共享素材规则处理 |
| `agentExperience`, `agentEvidence`, `agentGoal`, `agentEvolution`, `agentEvolutionOwner` | 独立对象归 Agent 资料；由业务权威确认随项目或会话直接拥有、一起处理的资料归其所有者。来源引用或 scope 标签本身不改变所有权，不重复计量 |
| `assetRef` | 媒体与附件中的引用元数据；本体由 AssetStore 的 blob 清单补齐 |
| `connectionProfile`, `credentialTargetPermit`, `modelProfile`, `runtimeRoute`, `retrievalProfile` | 设置与集成；保留版本、权限与敏感信息边界 |
| `runtimeCheckpoint` | 按执行归属展示的临时续跑数据；只有失效且不被运行使用后才可能成为缓存清理候选 |
| `maintenance` | 按 scope 归属会话／素材等维护开销；无法证明业务归属时列高级工具，不凭名字自动清理 |
| `versionedJsonResource`, `versionedJsonResourceRevision` | 必须继续按 resourceType、资源身份与所属对象细分，见下表 |

通用 versioned 存储除 Runtime Library 外还承载其他业务数据，不能只枚举五种模型／提示词资源后就宣称完整。

| 已存在的 resourceType | 归属与要求 |
|---|---|
| `core.prompt-module`, `core.prompt-program`, `core.generation-profile` | 设置与集成；包括根、精确版本、预设所持资源与引用 |
| `core.image-target`, `core.image-rendering` | 设置与集成中的图像生成配置；实际图片本体归媒体 |
| `atri.extensions.official`, `atri.extensions.settings`, `atri.extensions.plugin` | 设置与集成；插件安装资料及删除标记按实际记录计量 |
| `atri.visual.budget`, `atri.visual.planner` | 分别识别账户视觉预算配置和规划运行记录；配置归设置，运行记录按有效期／所属对象细分 |
| `atri.visual.prepared`, `atri.visual.job`, `atri.visual.commit` | 按所属会话或任务归属；预备请求、任务和发布记录不能整体当缓存删除 |
| `atri.visual.scene`, `atri.visual.shot`, `atri.visual.state-change`, `atri.visual.director-scan` | 按所属会话与分支归属的视觉连续性及导演资料 |
| `atri.visual.draft`, `atri.visual.mask`, `atri.visual.gallery` | 区分会话编辑草稿、遮罩、画廊元数据与素材本体；记录与引用各计自身 |
| `atri.visual.gc` | 素材回收状态记录，按素材维护开销归属；存在记录不等于素材已经可以删除 |
| 其他实际存在的 resourceType | 保留已知字节、身份、来源与不可识别原因，列高级工具；不可静默忽略 |

上述细分是建议的工程映射。具体所有权从持久化键、文档的已验证 scope 和业务仓库取得；缺失、冲突或损坏的资料进入待核对状态，不能猜测所属对象。

## 7. 持久层与文件覆盖

复用现有 engine、repository 和 ProjectStore 的读取权威，补齐统一只读统计能力；管理中心不另建一份资源内容库。

| 来源 | 覆盖要求 |
|---|---|
| FS Native | 通过完整 Native kinds、有效记录及维护候选扫描覆盖 `atria-native/`，不只遍历旧目录 |
| SQLite／MySQL／Postgres | 通过账户绑定的 engine 获取结构化资源；数据库主体不再当“其他文件”计入资源总量 |
| Studio 项目 | 覆盖 `projects/` 源码、清单、项目内部资料和 `.git`；构建导出排除项不代表统计也可排除 |
| 素材 | 结合 assetRef 与实际 blob 清单识别共享本体、孤立文件和保留引用；扩展名或 `assets/` 目录不足以决定归属 |
| 备份与回收站 | 纳入归属当前范围的实际备份、恢复元数据和独占保留内容，不重新展开重复计量 |
| 旧版结构化数据 | 通过现有 legacy repositories／engine 读取；SQL 中旧聊天、世界书、预设等也需计量并归高级工具 |
| 原始 legacy 文件及 unknown | 通过边界内文件清单补齐；扣除已由 Native、项目、素材等认领的实体，保留来源以便对账 |
| 引擎容器与全局设施 | 物理数据库、WAL、全局共享服务等作为可取得的实际占用信息，不能猜测分摊成账户资源内容 |

建议为每个计量单元保存来源身份、所属业务对象、分类、测量值与方法、保留状态和扫描版本。稳定身份应使用业务键、内容身份或受控文件身份，避免仅按显示路径去重。

资源 JSON、文件、备份的具体字节算法须统一实现并用于配额；例如选择规范化内容字节或持久化内容字节时，应说明元数据边界，并证明跨 engine 的语义一致。不能把 SQL 引擎分配页与 FS 文档字节拼成同一“资源数据量”。

统计扫描为只读操作。遍历中的恢复、GC、修复或目录整理必须由已有生命周期负责，不作为查看占用的隐式副作用。

## 8. 配额写入闭环

账户配额必须消费同一资源数据量权威。现有请求路径拦截、用户根目录大小缓存和 HTTP `content-length` 不能独立承担原生写入后的真实判断。

- 覆盖普通新增／更新、版本提交、消息与后台任务、素材上传与生成结果、项目文件与 Git 历史、导入、恢复、迁移及备份落盘。
- 恢复或导入不能绕开配额；原地恢复保留对象与真正新增副本按真实增量区别处理。
- 增量以实际净变化为基础：替换扣除旧内容，去重素材仅为新增本体与引用计量，失败操作不永久占用虚构增量。
- 并发写入需通过现有事务／串行权威配合预留和结算，避免多个请求同时看到剩余空间后共同越限。
- HTTP 头与预计产物大小可用于提前预估，实际提交前后仍需校验和结算；不能用猜测的固定常数代替资源大小。
- 预留记录区分资源占用和在途预留，界面说明可用额度受何影响，不把同一批数据的预留与已保存数据同时累加。
- 回收站转换没有释放原资源额度；需要额外恢复副本但空间不足时，按生命周期规则提供导出、彻底删除或取消选择。
- 空间不足不能挤掉尚未到期的回收站记录；恢复元数据无法可靠保存时，不先删除业务原件。
- 持久化失败、进程中断和重试后，预留与计量必须可对账，不能仅刷新页面数字来掩盖配额漂移。
- 已超额账户仍应能够检查、导出和执行能够减少占用的合法清理；具体写入提交与保留机制应避免为回收操作制造死锁。

建议在实施早期形成“实际写入口 → 资源权威 → 计量与配额入口”的覆盖清单，并用针对性验证证明其完整性。索引、增量账目、失效广播与全量校正可组合使用，选择依据是实际 engine 能力和可验证的一致性，不新增平行业务持久层。
