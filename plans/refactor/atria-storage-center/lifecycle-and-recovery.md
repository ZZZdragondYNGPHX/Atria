# 生命周期、安全清理与恢复

本模块是安全清理范围、原生回收站、删除与恢复语义的详细权威。
分类和空间口径见 [资源与核算](resources-and-accounting.md)，服务边界见 [架构](architecture.md)。
预览、批量任务、取消和结果交互见 [页面与流程](interface-and-workflows.md)，验证见 [验收](acceptance.md)。

## 1. 生命周期操作

| 操作 | 数据语义 | 空间和恢复 |
|---|---|---|
| 归档 | 按业务规则降低可见性或停止被新业务选择，原对象仍存在 | 仍归原资源，不释放占用；取消归档走业务入口 |
| 安全清理 | 删除能够证明可重建或已无业务保留义务的数据 | 通常不可撤销；清楚说明重新生成条件 |
| 移入回收站 | 保留完整恢复闭包，将对象从活跃业务命名空间移出 | 默认保留 30 天；保留期间仍占用空间和配额 |
| 恢复 | 按原身份和依赖恢复完整业务对象 | 不覆盖冲突，不自动续跑后台任务 |
| 彻底删除 | 永久解除对象及恢复闭包的保留责任 | 不可恢复；实际释放还取决于共享引用和后端回收 |

归档不是回收站，业务状态中的 `archived`、视觉素材的隐藏标记也不能直接解释为可永久删除。
默认删除入口对适用的普通业务资源使用回收站；永久删除必须是独立且明确的操作。
任何入口都不能将“暂不展示”冒充“已删除”，也不能将“进入回收站”报告为已经释放空间。

## 2. 安全清理白名单

默认只勾选已经通过当前检查的下列对象：

- 可以从仍可用的权威数据重新生成，且没有独立创作价值的缓存和派生文件。
- 确认已过期、不属于运行中或可恢复操作的临时数据。
- 满足既有隔离期、引用、读者租约等规则的内部垃圾，例如完成回收核验的孤立 Blob。

白名单依据必须来自服务端资源类型和生命周期；文件扩展名、目录名称或客户端标签都不足以证明安全。
每种清理项必须说明来源、可重建依据、引用检查、运行限制和执行前复核条件。
缓存来源已丢失、无法重建或不清楚其业务归属时，移入手动检查候选，不能默认选择。
临时路径中的数据若参与尚未提交的恢复、导入、生成或迁移，仍然受到操作保留责任保护。

以下内容不得因“暂时未引用”而默认勾选：

- 用户上传素材、已安装作品、Studio 项目、Persona、世界与知识、独立 Agent 资料。
- 手动存档、仍可达历史、当前版本、被绑定的版本和有恢复义务的快照。
- 手动备份、设置与集成配置、未到期回收站数据、旧版及未识别数据。

到期回收站由第 5 节的到期回收流程处理，不以缓存白名单绕过其状态检查。
手动检查候选必须给出检查理由，用户选择后仍执行同等引用、权限与一致性检查。

## 3. 完整对象与删除边界

清理或删除以完整业务对象为原子处理单元，不按统计列表中的零散文件直接操作。
对象闭包包含其身份、根记录、所需不可变版本、子对象、状态及专属附属资料。
共享依赖按精确引用保留，不能因删除一个所有者而直接连带删除整个共享资源。
外部引用必须与“属于该对象的子项”区分：前者通常阻止删除，后者在预览中明确随对象处理。

| 对象 | 必须识别的闭包或保护边界 |
|---|---|
| 普通会话 | 分支、消息与变体、修订、状态、存档、所属记忆、维护资料、任务和结果；保留关联素材及精确作品依赖 |
| 已安装作品 | 根、已保留版本、作品状态及专属资源；仍被会话使用时阻止删除，不连带删会话 |
| Studio 项目 | 项目清单、全部源码、隐藏业务文件、完整 `.git` 历史、由项目直接拥有的任务与经验资料；独立 Agent 资料的来源引用或 scope 标签不等于项目所有权 |
| 世界与知识 | 根、修订、条目和绑定；保留精确版本引用，不删除其他对象持有的共享绑定 |
| Persona | 根、发布版本、头像、相关默认选择和迁移/会话引用；不能删除其他账户的引用对象 |
| 媒体与附件 | 逻辑引用、内容哈希与 Blob；回收站、历史版本和正在读取的消费者同样构成保护 |
| Agent 资料 | 独立资料的根和版本；附属于会话或项目的资料跟随所有者，不能重复处理 |

项目源码列表和发布产物不是完整项目备份：既有 `listFiles` 跳过 `.git`，恢复闭包必须另行覆盖。
项目目录与任务/经验的删除路径必须统一到同一业务生命周期，不保留两个范围不同的删除实现。
会话导出能力可复用闭包构造，但必须补齐回收站所需资料及精确作品依赖的保留契约。
共享世界、连续性、Realm 等外部业务根不能为了凑齐会话闭包整库复制或整库删除。

## 4. 执行前校验

预览是操作计划，不是长期有效的删除授权凭证；执行前必须再次校验当前真实状态。

- 从当前身份和服务端对象标识确定账户、资源类型和能力；不能信任客户端传入的种类或路径。
- 校验当前权限、对象是否仍存在、预览版本或 HEAD/指纹是否匹配。
- 在对应业务锁与事务边界内检查引用、运行状态、未完成转移和其他生命周期约束。
- 对象、闭包或引用变化后，将该项退回重新预览；不静默扩大原确认范围。
- 正在使用的资源先通过业务入口结束使用；管理中心不得暗中终止模型任务或外部请求。
- 被引用的资源给出可处理的阻止原因，只链接当前用户可以访问的关联对象。

Persona 的删除检查必须保留跨账户精确快照引用能力，不能为简化本账户扫描而漏检。
跨账户阻止信息只给出必要的存在性或汇总原因，不泄露对方的身份、会话 ID、标题和内容。
当前版本、手动存档、仍可达历史及被引用的快照不能作为通用历史清理目标。
历史清理必须遵守现有业务可达性和保护规则，不引入只按年龄或文件大小判断的旁路。

## 5. 原生回收站与保留期

本次新增原生业务回收站；现有文件路径恢复点不具备等价能力，不能直接包装后宣称支持。
保留期默认 30 天，记录成功移入回收站的时间及确定的到期时间，界面据此展示剩余期限。
成功移入回收站后，活跃业务根不再接受普通读写；通过回收站入口检查和恢复。
回收站项需要可辨认的业务名称、种类、原身份、闭包摘要、删除时间、到期时间和恢复状态。
记录格式、索引布局、分片大小等由实现选择，不将本模块中的工程建议当作已冻结字段协议。

尚未到期的记录不得因为空间不足、数量过多或新删除请求而被自动淘汰。
无法保障新对象的恢复闭包时，保留原对象并拒绝本次可恢复删除。
向用户提供取消、导出后自行处理、明确永久删除或主动清空可选记录的操作；不能暗中降级为永久删除。
恢复与删除所需的空间预留、配额和临时副本核算统一遵守 [资源与核算](resources-and-accounting.md)。

到期后可按原生生命周期自动彻底删除；实际执行仍需验证状态、引用和恢复/操作锁。
到期时间不能使正在恢复或尚未完成的删除记录变成可任意清除的文件。
用户可以提前永久删除自己的回收站项，但必须重新检查共享依赖，并明确不可恢复。
到期或主动删除失败时保留可诊断状态和必要保留根，继续重试；不能先标成功再遗失数据。
回收站项的最终释放只有在永久删除提交后才能解除素材保留责任。

## 6. 持久协议与故障保障

复用现有 Storage Engine、事务、Native Repo、业务锁、文件持久化日志及 AssetStore。
新增恢复清单和生命周期编排不构成另一套业务持久引擎；各业务对象仍由既有权威负责解释。
可以为不同种类提供闭包构造、保留、移除、校验和恢复适配器；名称及内部接口属于工程选择。

一次可恢复删除必须形成可在进程重启后辨认的持久操作，按以下不变量推进：

1. 先锁定/核对目标，构造闭包并检查容量；此时不得丢弃活跃数据。
2. 将恢复内容、精确依赖和素材保留根可靠持久化，校验它们足以完成恢复。
3. 在业务事务和文件日志边界内移除活跃根及所属数据，记录可重放的完成状态。
4. 原对象全部脱离活跃状态后，才发布为成功的回收站项并报告操作成功。

数据库和文件无法以单个事务提交时，使用已有机制配合可重放的操作日志与补偿。
正常失败必须保留完整活跃对象，或完整可恢复对象；中间态不得供普通业务当作完整对象读写。
崩溃后根据持久阶段完成或回退该对象，不靠请求内存、前端页面或成功响应是否送达判断。
若某后端发生部分失败而尚待修复，明确报告待核对/待恢复状态并继续修复，不能报告删除成功。
恢复记录持久化失败、空间耗尽和存储不可用属于整体故障，停止后续对象处理。
重复请求、重启续接和重试必须幂等，不复制回收站项、不再删除已经成功处理的原对象。

GC 的根集合必须覆盖活跃资源、回收站恢复闭包、精确依赖，以及准备/恢复中的持久保留根。
现有 `AssetStore` 的引用/作品版本根和 `retainHashes` 能力是接入基础，不能假定它已经扫描回收站。
清理候选生成与实际删除都核对保留根；回收站保护不能只靠一次扫描时临时传入的内存列表。
恢复和 GC 并发时，使用现有 Blob 租约/读者保护及业务锁，防止恢复中素材先被回收。
删除恢复清单、解除保留根和实际垃圾回收必须按可重试顺序完成，避免悬空恢复承诺。

## 7. 恢复契约

恢复前检查账户、权限、闭包完整性、模式兼容、原 ID、精确版本依赖、素材和可用空间。
缺失依赖时明确列出可见缺口；允许先补齐精确依赖再重试，不用当前最新版代替历史版本。
恢复闭包持有的共享依赖不等于允许覆盖或回退现有共享业务根。
默认按原 ID 恢复；任一需要发布的原 ID 已被占用时拒绝冲突，不自动覆盖或分配新 ID。
资源内容看起来相同也不能凭此忽略身份冲突；幂等续接只能依据当前操作自身的持久状态判定。
导入为副本属于独立操作，不能作为原 ID 恢复的替代，也不能标记为撤销删除成功。

恢复先构造并验证暂存闭包，再通过业务权威发布完整对象；失败不留下可见的半个对象。
恢复失败时原回收站记录和素材保留责任继续存在，当前活跃对象不得被删除或覆盖。
恢复成功后将对象从回收站占用归回原分类；暂存清理和共享素材核算遵守统一核算规则。
发布与回收站收尾发生故障时按持久操作续接，不能同时计为两个完整业务对象。

恢复后保持暂停，不自动续跑 Agent、重发外部请求、执行定时任务或产生模型费用。
复用已有 `effectPolicy: 'no-background-model'` 等恢复约束，并补齐各对象后台入口的校验。
会话/项目恢复要同步既有运行时与界面状态，旧缓存、旧任务不能随后把已删除或旧版本数据重新写回。
Persona 默认选择不随恢复暗中替换：恢复的身份可重新选择为默认，当前有效选择保持受保护。

### Ironman 与终结状态

Ironman 的死亡、终结与删除控制属于业务权威，回收站不能回滚这些控制记录。
已有删除会使 Ironman 终结，恢复不能将其改回可继续游玩的活跃状态或规避防回溯约束。
允许的历史恢复保持只读/终结语义；可恢复的历史范围由原业务闭包和控制规则决定。
现有 head-only resume 导出不等于任意完整历史恢复能力，不能用它承诺普通会话同等撤销体验。
界面在删除前说明这些具体后果，不统一承诺所有会话恢复后均可继续游玩。

## 8. 必须完成的种类能力

矩阵表示本次交付目标，不表示现有代码已经具备这些能力。
普通资源必须具备统计、明细、适用的导出/管理、可恢复删除和完整恢复；不能以“暂不支持”占位验收。
有业务保护的对象仍进入统计和明细，操作状态给出具体约束与对应处理入口。

| 种类 | 本次恢复和删除要求 |
|---|---|
| 普通会话及所属资料 | 完整闭包移入回收站并按原 ID 恢复；所属存档/历史的独立操作沿现有业务可达规则 |
| Ironman 会话 | 遵守第 7 节终结语义，具体验证历史可恢复范围，不承诺复活 |
| 已安装作品及保留版本 | 无外部引用时可恢复删除；被会话持有的精确版本阻止删除或由回收站继续保留 |
| Studio 项目 | 源码、完整 `.git`、由项目直接拥有的任务与经验一起恢复；独立关联资料保持引用保护，发布包导入不算项目恢复 |
| 世界、知识库、条目与绑定 | 保持根/修订/绑定身份和精确依赖；资源副本导入不能替代撤销 |
| Persona 及头像 | 原身份与发布版本完整恢复，跨账户引用保护有效，默认选择显式处理 |
| 媒体与附件 | 无引用逻辑资源可恢复删除，恢复相同 AssetRef 和内容；共享 Blob 继续只存一份 |
| 独立 Agent 资料 | 按资料种类补齐身份、版本及引用闭包；附属资料不另建并行所有权 |
| 设置与集成 | 使用既有设置权威处理可重置/删除单元及恢复；恢复不自动启用外部任务或替换冲突配置 |
| 备份 | 支持明细、导出和适用删除；被恢复任务持有时保护；自身删除若进回收站仍计保留空间 |
| 回收站项 | 预检查、原 ID 恢复、30 天保留、到期/手动永久删除、失败后可续接 |
| 缓存与临时数据 | 按白名单清理和解释重建条件；不伪造持久恢复能力 |

实施时按真实 Native resource kind 补齐映射和覆盖检查，避免一类页面可见而其子 kind 被遗漏。
只对受明确业务规则保护的操作显示禁止；既有缺少删除/恢复 API 是需要补齐的工作。

## 9. 备份、浏览器和高级工具

账户备份是独立灾难恢复/迁移机制；回收站恢复不调用整账户 replace 来找回单个对象。
已有备份覆盖 Native 数据、项目和 Blob 的能力可以复用，但备份恢复记录不自动转成普通回收站项。
已有资源 bundle 导入会重写部分 Library ID，不能冒充本模块要求的原 ID 恢复。
备份恢复、单对象恢复和导入为副本必须有清楚的能力边界和各自一致性保证。

浏览器处理范围是本设备当前站点，包含多个账户时不把全部站点数据称为当前账户资料。
已识别的缓存可直接清理；离线内容、本地模型和设备偏好按其真实所有权及重建/恢复能力处理。
浏览器业务资产不能因为存于 IndexedDB 或 `localStorage` 就默认被当作缓存。
不将整个浏览器数据库当作单个可随意恢复的对象；分页、主键变更和清理中断遵守浏览器资源契约。
仅在恢复内容已可靠保留时提供恢复承诺，无法保证的永久清除必须明确说明后再执行。

旧版兼容数据和未识别数据只在高级工具展示明细，但仍计入总量。
高级工具不得绕过账户/路径边界、引用保护和运行约束，不能直接编辑原生数据库或 Native 目录代替业务操作。
现有按原路径复制、先删目标再覆盖的恢复实现只能用于明确隔离且经过冲突保护的旧文件场景。
旧文件恢复不能覆盖原生对象、数据库文件、运行中资源或其他分类的受保护路径。
原始 JSON、文件、浏览器键值入口不得生成比主界面更宽的删除权限。

## 10. 实施验证连接

删除/恢复的单元、集成、故障注入和真实浏览器验证统一由 [验收](acceptance.md) 定义。
本模块的关键证明是完整对象能恢复到业务页面、故障不丢失恢复义务、GC 不破坏保留闭包。
文件复制测试、旧目录管理测试或导入成功均不足以单独证明原生回收站完成。
