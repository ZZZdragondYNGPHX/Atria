# 资产、包和宿主工作

## 交付

- 使用同一已打开文件描述符取得 stamp/size 并交付。不可变 Blob 首次读取验证，未变 stamp 后续读取复用准入；文件变化必须重新验证，错误不缓存成功。
- HEAD/ETag/Range 使用实际元数据；热资产不再完整读取后才返回 304 或小片段。缓存不取代 AssetRef、账号权限或删除租约。
- 冷校验按流执行且共享同一文件身份的进行中工作；保持有界缓存和可回收文件句柄。
- 精确媒体引用可经现有认证服务取得会话限定的 GET 资源地址；只允许固定包已声明媒体，不暴露任意路径。视频/音频使用浏览器原生 Range 加载，预览字节加载路径保持可用。

## 大包与内存

- 资产总量、单资源大小、解码内存和缓存容量分别管理。允许总量超过内存缓存，通过按需加载和淘汰控制驻留。
- 同步 Blob 读取改异步；包冷处理和图像编解码不得长时间阻塞服务事件循环。保留内容寻址和导入完整性验证，使用已接纳摘要消除写入过程的重复计算。
- 现有全 Buffer 容器格式的上限不能仅调成数十 GB。大型资产通过可流式文件/分卷设计进入既有资产权威；明确受支持格式与旧格式边界后实现，不做虚假的无限容量配置。
- 不使用更大的常量掩盖全包物化。仍需整体 Buffer 的导出/导入边界必须单独记录峰值与容量，后续架构工作保持未完成状态直到真实路径实现。

## 宿主 CPU

- 图像验证/转码/掩码编码使用有界工作线程池；同步 API 的真实调用方随之改为异步。独立 CPU 工作不占用通用网络调度器的执行线程。
- 线程返回 transferable 数据时明确所有权；不能 detach 调用方仍在使用的 Buffer。

## 证据

冷/热 HEAD、304、1 KiB Range 统计实际读取字节；损坏/替换文件不能命中旧准入。图像处理测宿主事件循环延迟。大媒体播放/seek 验证 Range、取消和资源释放；大文件测试使用临时合成资产，不触碰用户资产。
