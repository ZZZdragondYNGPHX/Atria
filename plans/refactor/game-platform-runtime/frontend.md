# 前端数据与绘制

- 保持现有组件、token、布局与输入语义。本阶段为底层执行优化，不以视觉重设计扩大范围。
- Controller snapshot 使用明确版本信号；同一版本的重复 settle 不重新传完整快照。Worker 内维持已接纳快照，仅在版本变化时更新；事件与能力结果分别传输。
- Canvas 只在实际尺寸变化时调整 backing store；每帧明确重置绘图状态，保持旧语义，不依赖尺寸重置隐式清屏。绘图命令预算与解码纹理预算独立。
- 虚拟列表复用未变数组的键索引；对可变数组必须有明确更新信号，不因引用相同跳过必要变化。更新范围逐步缩小至脏组件，不能丢掉 bridge、locale、环境更新。
- 高频重计算通过后端计算协议；OffscreenCanvas/渲染 Worker 若引入需满足图片传输、取消、错误诊断和不支持平台的明确处理。不能仅增加接口就声称主线程绘制已迁移。
- 媒体消费使用 assets 模块定义的流式入口，图片与字体继续按需要持有租约。

## 证据

必要的真实浏览器检查包含列表滚动、连续输入、Controller 往返和媒体播放。JS 微基准不能作为浏览器 FPS；无物理设备证据时不声明手机性能通过。若实际修改运动/视觉交互，才加载适用的 UI/动画 Skill。
