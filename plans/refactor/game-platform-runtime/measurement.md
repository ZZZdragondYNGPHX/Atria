# 性能与正确性证据

## 基线

审查基线 `519642ad`，本地 Node v24.18.0，16 logical processors：4 个各 8,000 万次整数循环，串行 996 ms、并行 280 ms；32 MiB 文件热 HEAD/304 仍读全文件；2048² PNG normalize 阻塞事件循环约 64 ms。这些是合成微基准，不是完整游戏帧率。

## 测量方式

- 测试/脚本/合成资产只在本地临时空间；Record 保存命令类别、环境、输入规模、结果和限制，不上传测试代码。
- 每个相关改动选择能暴露根因的最小场景。记录输入规模、耗时、实际读取/传输字节，必要时记录 RSS 和事件循环 delay。
- 目标是改变增长关系：热资产小 Range 的读量与 Range 大小相关，单 ID 读取热路径与记录总量无关，单逻辑任务可在多核分片加速，计算期间其他会话能完成存储工作。
- 大世界样本按 5k/50k/100k 实体递增；大型资产按 32 MiB/256 MiB/1 GiB 的相关路径递增。超出当前接口支持时先定位和修改对应边界，不能将失败样本从报告删除。
- 1/4 Worker 对比使用相同工作量与输出，区分冷启动和热运行；CI/机器负载波动不伪装成确定的产品加速倍数。
- 正确性覆盖必要边界：不可信输入、跨账号资源、损坏文件、取消/超时、CAS 冲突、基底不变、确定性结果。没有相关修改的不反复运行。
- P6 集成真实调用方，不以单独工具函数跑分快宣布完成。若存在剩余容量/全量路径，写入 Record 并继续工程工作。
