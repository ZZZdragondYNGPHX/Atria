# 计算与调度

## 现状

现有 isolated-vm 子进程池能并行独立调用，但每阶段创建上下文、重复传输 JSON；没有游戏内显式分片接口。64 项 FIFO 不携带取消信号，复杂度与输出大小限制不一致。

## 实施

- 复用现有池与不可信程序进程隔离。程序身份在已接纳包内固定，按程序调度以复用编译缓存。
- 引入显式分片协议：程序 `partition(input)` 返回有序分片，多个 `compute` 在池中并行，`reduce` 按原分片次序汇总。原单任务模式仍为无分片程序的直接执行形式；不是两套提交系统。
- partition、compute、reduce 都在沙箱运行。每个分片带确定性索引、种子派生信息；完成顺序不影响汇总顺序。任何分片失败不得提交部分世界状态。
- 队列计量直接使用边界得到的传输字节；避免重复 JSON stringify。单批任务共享可复用只读输入，尽可能合并不产生宿主副作用的相邻阶段。
- 输入与输出的内存/节点预算分开于 UI 消息预算。分片数量、待处理字节、活跃进程与任务 deadline 均显式有界；用户配置可扩展，不能删除背压。
- 支持 AbortSignal；排队取消移除任务，运行取消终止对应可丢弃进程，迟到消息不恢复结果。错误保留可诊断的 code。
- 二进制高吞吐后端作为同一计算入口的扩展方向，不能把普通 IPC 宣称为零拷贝；先证明当前 JS 分片实际加速。WASM/原生/GPU 需要具体数值内核与平台证据后才宣称支持。

## 证据

测试单个逻辑运算的 1/4 分片结果相同与吞吐；取消排队/执行任务及超时后下一任务能运行；记录 wall time、宿主事件循环延迟、消息字节和内存。没有依赖隔离证明的事务或模拟步骤保持串行。

## P8 — 按真实调用链占比继续改造

起点 `main@486cd1f1`。未改游戏规则/预算的 53 人物三天推进基线约 5,998 ms。初始采样显示脚本计算约 378 ms；首批准入/借用修改后的第二轮诊断中发布约 2,819 ms（含 journal 提交 1,447 ms），首次模块编译约 477 ms。函数时间有包含关系，不相加为总耗时。

1. JSON 准入为每个已拥有、深冻结子树保留复杂度与精确字节元数据；沙箱返回 JSON 解析后原地准入，避免重复复制。外部对象仍检查描述符、原型、密度与键，较小预算继续拒绝。
2. 持久化的内部只读比较借用现有不可变记录接口，保留公开副本。FS journal 预编码每份资源一次，并行压缩，日志和目标文件共用同一编码结果；兼容既有日志恢复，不撤销耐久屏障。
3. 首次运行时编译移入既有计算子进程池，主线程只收集有界静态依赖；构建入口仍复用同一编译权威。独立编译/计算使用多核，取消和失败回收保持统一。
4. 在同一事务内，若前后不变量的完整只读输入相等，复用已成功的判定和证据；若输入变化仍重新运行。不并行有因果依赖的世界事务。
5. 完整真实游戏重复对照、固定 Revision 的状态/回执精确比较、沙箱取消隔离、JSON 较小预算与 Unicode、日志故障恢复，以及真实游戏并发会话的事件循环/吞吐验证。局部收益不得代替端到端数字。

## P9：冷编译与并发冷启动

- 世界程序转译使用固定版本 `esbuild@0.28.2` 原生服务，在原计算子进程池内执行；宿主原有 TypeScript AST 的源码/产物准入保留。世界构建与运行时同权威，UI Controller 编译不变。
- 按捕获的完整可达源字节合并并发首次编译；各调用方独立取消，仅最后一个离开才终止共享任务。保留队列背压、进程 deadline、fresh guest context 与源字节固定。
- 编译器改变会改变新执行证据的 artifact hash，不伪装旧 hash；原历史回执不改写。固定 Revision 比较真实四种操作，仅 execution.resourceHash 改变，状态和其他回执字段相同。
- 首次等待准备 869 ms → 390–426 ms；四真实会话编译 job 从 5–6 次降至 2 个实际不同程序。详细完整流程及剩余宿主开销见 Record。
