## 架构原则

1. 接纳外部数据时验证一次；内部不可变声明复用身份。修改的数据在写入边界校验，权限、跨账号隔离、沙箱、CAS 与耐久提交保留。
2. 计算与提交分离。独立分片并行，冲突写入仍由现有 SessionCore 顺序提交。禁止把 Promise 并发宣称为 CPU 并行。
3. 控制消息与大量计算数据分开；以批次、共享只读程序及显式数据分片降低序列化和调度成本。
4. 世界运行按实体/集合索引与实际变更处理；历史展示与完整导出保留无损原始数据，不能以截断历史换性能。
5. 大资产按需读取、流式交付；容量上限必须与文件格式、设备内存和实际算法相关，不能用缓存大小限制已安装资产总量。
6. UI 脚本负责交互与编排；持续重计算通过服务计算通道。渲染保留已有组件和交互语义。
7. 当前实施以 JS/V8 多核为主。WASM/原生/GPU 后端必须复用同一作业协议；本任务不凭接口占位宣称已有 GPU 加速，也不默认加载任意本机代码。
