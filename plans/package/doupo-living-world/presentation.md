# 空间表现与场所移动

状态：沿用 v0.7 的布局、移动和美术默认设计，供 v0.9 前端原型迭代；正式制作已授权，前端集成执行者由用户在后端完成后选择。分工与前端委托见 [execution-split.md](execution-split.md)、[frontend-ai-brief.md](frontend-ai-brief.md)；已确认决定以 [decisions.md](decisions.md) 为准。

## 产品目标

空间表现服务已确认的地图、场所、人物和功能界面，以及自由文字贯穿交互的方向。人物位置、可接触对象、距离和环境需要足够清楚，让玩家理解能做什么，以及行动为何产生对应后果。

《觅长生》作为整体玩法参考，具体镜头、场所结构与美术结合已确认方向、Atria 前端能力和世界模拟优先级设计。

## 世界地图与地点场景

空间方向以 [D13](decisions.md#d13--世界与场所的空间表现) 为准，候选展开为：

| 层次 | 玩家所见与操作 | 主要制作内容 |
| --- | --- | --- |
| 世界地图 | 选择旅行目的地，理解地区与路线关系 | 已知地点、通路、旅途条件与信息可见性 |
| 2D 俯视地点 | 在城镇、室内或探索场所中接触人物、设施和环境对象 | 场景、人物、对象位置、移动、可达性与交互条件 |
| 功能界面 | 在同一世界上下文中操作物品、角色、成长和战斗 | 当前对象、资源状态、按钮与文字意图的配合 |

地点位置与战术交锋的位置表达需要一致；场景中的人物与对象要对应真实状态。场所编制见 [内容模块](content-and-runtime.md#首批场所与人物编制)，场景操作与美术的 D4 建议见下文，精确尺度与渲染开销通过原型确定。

## 场所移动的候选细则

移动方向以 [D14](decisions.md#d14--点击移动与自动接近) 为准。自由输入可候选表达接近、观察、绕行或离开的意图，执行需要与同一位置和路径模型一致。

移动、交互和战斗的耗时需遵循同一世界时间原则，不能把输入速度或动画播放时间直接计作世界时间。路径选择、途中事件、目标移动、不可达情况和取消边界仍需设计；自动接近应有可理解的结果与失败反馈。

## D4 设计覆盖与待验证项

- 美术方向、场景密度、人物动画、地图尺度与镜头切换。
- 视野、遮挡、可达性、距离与战斗范围。
- 键盘、触控、焦点、文本输入和对象选择的配合。
- 长时赶路与场所内移动的衔接、过程事件与中断。
- 桌面屏幕布局与实际渲染性能验证；电脑为主要运行目标已经确认。

以下 D4 小节保留默认设计；实际原型按前端委托推进，原生界面和资产在后续集成时验证。当前尚无本任务界面或浏览器实测，不把方案目标写成完成结论。

## 空间与交互原则候选

应用 frontend-design 与 emil-design-eng 的相关方法组织空间与操作，不提前冻结调色板、字体或动画参数。

- 让场所本身、人物与可交互对象构成主体；功能界面围绕当前活动组织，不把世界切碎为互不关联的状态卡片。
- 当前选中对象与文字输入对象应清楚可见。切换地图、人物或功能时，需要明确文字意图针对谁或什么，避免上下文变化后误发行动。
- 常见对象选择、面板查看和输入应即时响应，不被装饰动画或模型等待阻塞。已提交行动与尚在编辑的意图区分显示；等待、失败或不可执行时提供可理解的状态反馈。
- 镜头与场景转换用于帮助理解位置，动作表现用于说明后果；浏览器动画时长不决定世界时钟。频繁键盘操作不依赖动画才能完成。
- 美术应从斗气世界的地理、建筑、材料和人物身份中形成一致方向；参考游戏提供组织启发，具体素材、字体授权与美术制作后续另行落实。

这些是界面候选原则，不能据此声称已完成 UI、动画或真实性能验证。

## D4 桌面界面默认方案

以场景为主，文字和功能面板围绕当前活动展开；拟先适配 1440×900 与 1920×1080，兼顾 1280×720 和界面缩放。尺寸是验证样本，不限制用户设备。小窗口折叠侧栏，保留对象、行动和输入；移动端不作为首轮主要验收目标。

```text
┌────────────────────────────────────────────────────────┐
│ 地点与游戏时间       当前活动/同行           保存 · 设置 │
├─────────┬──────────────────────────────┬───────────────┤
│ 已知地点│                              │ 当前对象      │
│ 与联系  │   2D 场景：人物、道路、对象    │ 可见资料/行动 │
│ 可折叠  │                              │ 可折叠        │
├─────────┴──────────────────────────────┴───────────────┤
│ 当前交流/行动结果与可回看记录                          │
│ 对谁/在何处：[对象]   [自由输入……]       [执行]         │
│ 人物 · 行囊 · 功法修炼 · 关系家庭 · 见闻 · 世界地图     │
└────────────────────────────────────────────────────────┘
```

对话时扩展文字区域并显示对话对象和可见表情/动作，场景仍保留位置上下文；战斗时突出距离、可用行动、斗气、伤势与最近结算，不堆满所有面板。家庭界面从人物关系进入，展示共同生活、已知亲属、约定和来往记录，不暴露 NPC 私有评价的精确数值。

所有已知信息可用功能列表查找；地图和 Canvas 对象提供对应的可聚焦列表，不能只靠鼠标命中小图标。按钮有名称和键盘焦点，弹窗关闭后返回原焦点；文字输入获得焦点时不触发场景快捷键，Enter 提交与换行规则清楚，提交后保留失败输入。

选中、预览路线、提交与完成分开反馈。点击 NPC 拟自动沿可达路线接近至交互距离，接近不自动承诺交易、战斗或透露秘密。目标改道则重检路径，目标离开或不可达时说明原因；取消保留已完成行动。镜头可平移缩放，人物和可交互对象有明确选中轮廓与名称辅助，遮挡区域可淡化以便判断位置。

模型等待显示正在交流/判断及可理解状态；规则已提交则显示已发生结果，生成失败可重试表达，不重复扣费或重做交易。开发诊断只在开发工具中，不把事务、内部预算或模型路由作为游戏叙事。可编辑草稿和查看资料不推进时间；会冲突的新行动在当前提交完成后再执行。

## D4 美术默认方向

建议采用国风手绘的 2D 俯视场景，轻微倾斜便于看到建筑与人物，人物小比例行走形象配对话半身像。乌坦城以街巷、坊市、木石建筑与商贸痕迹建立生活感；青山镇更突出行旅、药材与佣兵用具；山脉以林地、山石、路径和可辨识线索组织风险。具体造型是游戏美术推导，不宣称小说给出精确建筑图。

面板拟采用深青灰、石白文字和克制的金属边线，火焰色留给斗气/危险与重要动作；地图作为有地形与路线的手绘地理图。视觉重点在人物、环境和斗技后果，避免把世界界面做成同形卡片列表或泛用霓虹电竞风。

| 候选视觉 token | 值/用途 |
| --- | --- |
| 玄青 | `#172A30`，面板基底与文字背板 |
| 深石 | `#263E44`，层次、选中区域与控件 |
| 石白 | `#F1EBDD`，正文与重要数字 |
| 雾青 | `#B5C9C8`，辅助文字与中性信息 |
| 古金 | `#CBA568`，选中轮廓、标题与重点 |
| 炎赤 | `#E77C55`，危险/斗气效果，配图标或文本说明 |

标题候选用思源宋体一类中文宋体，正文与操作用思源黑体一类中文黑体；是否随包分发需在素材选择时核对具体授权与体积。正文默认约 16–18px、行高 1.6，可缩放；长篇对话控制行宽，数字列对齐，不能只靠色相区分状态。最终对比度与字号在真实场景背景上验证。

动画优先表达行走、受击、施技与状态改变，拟先做待机/行走、朝向、少量交锋动作；重要 NPC 用不同轮廓、衣着和半身像辨识。可加速/减少运动，暂停与输入不依赖动画结束。渲染目标和反馈目标见 [运行模块](content-and-runtime.md#制作负载与性能目标)。

## 资产与实现次序

先完成可操作的灰盒场景、路径、对象、UI 和统一比例，再制作一套城镇/室内/林地/洞窟复用构件和重点人物样板，经场景内验证后扩展。首轮实际制作资产包括世界/路线图、场所底图与遮挡层、可交互对象、人物行走形象与重点半身像、物品/技能图标、必要动作与音效反馈。数量由场所编制与可辨识度决定，不以补齐百科配图为目标。

批量美术应在身份、状态和存档验证成立后展开，避免规则结构改变导致返工；前端设计可先以少量代表性素材迭代，最终资产由集成任务制作和接线。素材来源、授权和版本在制作时随资产记录。

本版使用 frontend-design 的主体、字体与材料方法，以及 ui-ux-pro-max 的焦点和反馈指导。其通用设计系统检索两次均偏向宣传网站或 3D 电竞展示，未获得适配本项目的整套方案，故没有采用其默认布局/配色；上述视觉 token 为本项目的设计建议。
