本文是任务实例、目标与条款、动态编排、任务结算和长期后果的唯一详细设计。内容种子、作者编制与丰富度覆盖归 [quest-content.md](quest-content.md)；通用池目录、资格筛选、抽样和版本规则仍归 [content-pools.md](content-pools.md)。已确认方向只归 [decisions.md](decisions.md)，外部依据与调查边界归 [research.md](research.md)。

人物意愿与规划引用 [npc-agency.md](npc-agency.md)，资源、生产、组织和经济事实引用 [world-systems.md](world-systems.md)，个人所知与关系传播引用 [social-graphs.md](social-graphs.md)，时间、离屏推进和调度引用 [world-simulation.md](world-simulation.md)。任务只组织参与这些事实的目标、承诺与可见进度，不建立第二套库存、关系、时间或世界模拟。

## 六类来源与共同体验

| 来源 | 主要作用 | 产生与结束的依据 |
| --- | --- | --- |
| 日常与职业委托 | 稳定赚钱、积累本地联系、使用不同职业能力 | 实际工作/采购/运输需求，完成本次工作即可结束；需求再次出现才可再发布 |
| 人物情境任务 | 普通居民和动态 NPC 也能形成连续经历 | 伤病、缺粮、家庭、失物、关系与修炼准备等当时可成立的困难 |
| 随机事件任务链 | 玩家在流动世界中介入事件 | 合法情境、真实参与者与可发生的行动，胜负、错过和改策导向不同后续 |
| 固定人物专属任务 | 重点人物的情感、秘密与长期关系 | 手写骨架与当前人物状态；原著姓名不锁定本局未来和结局 |
| 固定活动任务 | 提供有辨识度的地方活动和阶段目标 | 拍卖、公会考核、家族活动等作者规则与实际举行条件；场所存在不等于活动已实现 |
| 探索与玩家主动目标 | 支持追查线索、争取成长和自主介入 | 玩家合法已知线索与主动意图，可以没有委托人或预设报酬 |

来源可以重叠。同一人物的短采购单可以连接活动筹备，但不能因此强制转成长链。任务的真实玩法由目标结构、障碍、解法和后果决定，不能用来源标签代替行动差异。

任务可经交谈、公告、公会渠道、书信、传闻、现场发现或玩家主动提出进入视野。公告只是信息入口，不是全大陆实时订单表；接取与完成按实际沟通、权限和交付条件结算。玩家没有发现或接取时，相关世界问题仍随游戏时间发展。

## 世界问题、任务与承诺分层

1. 世界问题是既有事实或正在发展的局势，例如病人未治疗、组织缺料、商队失联；它可以被本人、NPC、组织或玩家改变。
2. 任务是某个参与者围绕问题提出或自己建立的可追踪目标。多个参与者可以有不同立场与目标，不能各生成一份病人或赃物。
3. 合同/承诺表达实际同意的义务、报酬和期限。听到传闻、查看公告、口头设想或 AI 提案本身不等于双方已经订约。
4. 活动是实际占用时间与物资的执行过程。接任务不自动赶路、消费、获得情报或使 NPC 同意同行。

探索目标可以先调查后形成正式委托；已有的行为证据也可被后续知情者认可。每项合同须说明哪些既有事实可计入、哪些要求接约后的特定服务，避免无意义重做与事后重复领取报酬。

## 模板、实例与目标语义

手写模板保存稳定 ID/版本、来源与原创边界、适用条件、角色槽、目标与可选分支、实际能力依赖、报酬类型及后果钩子。重点人物使用专属角色约束；普通事件按职业、关系、所知、位置和意愿选角。

实例在正式成立时固定抽样结果与条款，保存稳定身份、来源事实、当时版本和阶段；刷新菜单、地图切换或模型重试不重抽。AI 临时编排形成经过检查的本局实例，不自动成为永久作者模板，也不往通用池写入未经制作的新物品或动作。

| 实例信息（设计语义，非最终字段名） | 作用 |
| --- | --- |
| 身份、模板版本或编排来源、成立修订 | 区分本次任务、历史相似任务与重试；关联正确世界分支 |
| 问题/事件引用、真实参与者与角色 | 引用同一病人、组织、物品、地点、活动和事实，保留动机依据 |
| 已同意条款、期限、独占或并行性质 | 明确承诺什么、谁可以参与、何时需要复议及怎样认定违约 |
| 主目标、可选目标、依赖与替代路径 | 区分基本完成、额外成果、分阶段与互斥结果 |
| 合法证据与已确认进度 | 记录已提交行为及其来源，不由文字“成功”增加完成度 |
| 报酬承诺、预留/支付/退还依据 | 防止双重占用、重复领奖和无来源报酬 |
| 已知信息、最后核实时点、追踪状态 | 区分世界真实进展与玩家所知，保留传闻不确定性 |
| 终态、实际结算与后果引用 | 任务结束后仍可追溯人情、债务、损失与后续事件 |

目标优先描述要达成的状态，而不是唯一按钮顺序。采购若无来源限制，已有合格库存可以直接交付；需要药材来自特定生境时，必须有实际来源依据。治疗要求合法处置和病情状态，交出药物不自动等于治好。调查要求取得或提交证据，不以模型猜中幕后者代替调查。

顺序、并行、任选其一、可选加分和阶段条件只在已有动作可结算时开放。长链按当前阶段展开，不预先编出所有未来事实；后续目标引用前一阶段结果并重新检查条件。

## 普通委托协商与条款生效

D52确定：普通委托可协商报酬、期限和替代成果，NPC按实际条件接受或拒绝；公开悬赏维持公告条款。协商是可选路径，已有明确报价且双方愿意时可以直接接单，不把每个短差事都变成多轮讨价还价。

以下是已确认方向下的拟定执行语义，具体判断权重、同意操作与数据结构尚未冻结：

| 情境 | 拟定规则与实际依据 |
| --- | --- |
| 报酬与期限提议 | 以原提议为起点，玩家可以提出金额/物品/服务或游戏期限变化；NPC依据可支配资源、需求紧迫性、替代人选、对承接人的了解、性格和已有义务决定接受、拒绝或反提议，不因玩家反复输入便凭空增加预算 |
| 替代成果 | 明确替换哪个目标、合格标准及对报酬/时间的影响；替代物、替代服务或证明目标已被解决须实际可用并获对方同意。提供不同药物不自动视为同效，递交旧成品也不自动替代必须本人实操的考核 |
| 尚未接单 | 提议、反提议、拒绝和双方接受分开；未达成时不因协商本身自动接单、占普通委托独占名额、扣押金或产生托付责任；另有已接受托付的财物仍按其约定处理，也不保证协商期间名额永远保留 |
| 接单后的改约 | 展示拟变更部分及已完成/已支付/已投入的影响，双方同意后才产生新条款；尚未同意时原约继续有效，改约本身不自动暂停期限或改变助手合同。不能单方降低已完成工作应得报酬或抹除既有清算义务 |
| 公开悬赏 | 成果标准、分配、期限和报酬按公告约定，对参与者一致适用；不私下提高一人报酬、降低其验收条件或更改已认定贡献。原公告已经允许的选择仍依其执行，局势变化、主动撤回与已有工作按原有复议/清算规则处理 |

候选条款保留原提议、当前有效版本、双方同意及生效时点；接受、改约与资源检查在同一合法提交中确认。资金不足、世界条件或独占名额变化时不能让过期同意直接生效，需给本人可知的原因和可继续选择。对话中的客套、假设和模型建议不替代接受依据；具体交互沿同一按钮/自由文字规则设计。

按条款实际完成、证据认定和物资流转仍使用原领域权威；不得只把任务文案改成“接受替代”而不更新验收条件。重大改约涉及第三方财物、代理预算或协助安排时，不能越过已有权限。协商未成、拒绝提议与恶意失约分别表达，不统一扣信用。

## 承接独占与公开竞争

D42确定：普通付费委托接单后独占，公开悬赏和机缘争夺允许多人竞争。任务来源与承接性质分开：NPC私人求助或固定活动中的普通有偿差事同样可以独占，不能因为来自随机事件就自动变成竞速单。

| 承接性质 | 成立后的约束 | 世界仍可发生的变化 |
| --- | --- | --- |
| 普通付费委托 | 同一委托的同一有偿工作只由已接受的承接者履约结算，不能重复派单、换ID复制同一工作或事后降为公开竞争 | NPC仍可自行解决需求，第三方仍可自然介入；条款失去意义时复议或结束，委托人主动撤单按D43补偿 |
| 公开悬赏 | 允许多个符合条件的参与者竞争，不因一人加入就关闭其他人的参与；胜出依据与报酬分配须有明确条款 | 目标变化、对手行动和真实先后顺序继续影响结果；知情范围不因竞争而变成全知 |
| 机缘争夺 | 多人可以追求同一真实机会；没有事先合同的探索不强行附加雇主或报酬 | 按实际物品归属、人物能力、交易和消耗决定结果，不为失败者刷新第二份唯一资源 |

以下为拟定承载：普通委托的接受与名额确认在同一权威提交中完成，并发接单只有一个有效承接结果；其他人再次查看该已知委托时得到合法的“已有人承接”反馈。谁承接及其位置是否公开，仍由信息权限决定。终止、改约和再发布须有真实原因与清算状态，不能借重发规避原承接者权利。

独占针对本次有偿服务的履约和结算资格，不授予承接者整个地区的资源垄断，也不禁止别人自由采集、救援或交易。多人接不同任务时仍可能争用相同资源。NPC协助与整单转包按D46处理；邀请助手不为每人再生成一份完整报酬。

公开竞争允许多人参与；公开悬赏按D44在参与前分别约定结算，不能统一按“最先按按钮提交”判断。机缘归属仍由实际取得、交易和物品规则决定，不等同悬赏报酬；自然落败、主动撤单与违约分别记因，不能互相替代。

### 公开悬赏的成果与贡献结算

D44确定：单一目标由提交有效成果者获酬，可拆分目标按贡献结算。目标及报酬规则在参与前可查，不能在看到谁完成后再改变类型或分配办法。

| 目标性质 | 已确认原则 | 仍拟定的任务细则 |
| --- | --- | --- |
| 单一目标 | 提交有效成果者获酬 | 什么是合格成果、怎样核实提交人与成果关系、允许何种取得方式、多个合格提交的优先及争议处理；不把最先看到线索、造成一次伤害或只声称完成当成有效成果 |
| 可拆分目标 | 按实际贡献结算 | 划分可验收的数量、阶段、服务或成果单位及各自价值，明确总目标、预算与计量方式；是否分批支付及多人重叠工作怎样处理仍待任务细则收敛 |

以下为拟定结算约束：成果/贡献引用已提交的合法行为和验收依据，同一证据不能换一个提交者或多次点击重复领奖，同一批物资/同一服务不能重复计量。调查核实、治疗、护送等不同成果采用各自实际规则，不能用统一“进度分”替代。

贡献须能对应有限目标与真实报酬来源；总已结贡献和支付不能无因超出任务已接受的工作量及预算。部分完成保留各人已认定成果，后续改约、撤回和清算引用同一记录；不能为了按贡献结算复制一份唯一机缘或给每人全额报酬。

规则实际先后次序提供结算证据，不把某一种合格提交的优先序当作已确认默认。有效成果的认定、冒领/重复申领与真实争议需要可解释反馈；玩家只获知获准披露的提交与结果，不因此读取对手私有行程或全部贡献明细。

### NPC协助、分工与整单转包

D46确定：允许邀请NPC协助，须满足其意愿、能力、时间和报酬条件；原承接人负责履约，整单转包须委托人同意。协助安排与原合同关联，不能用“请求帮忙”的对白替代对方接受，也不能用协助名义绕过普通委托独占。

以下为拟定执行与清算语义，具体数据结构、人数和分成尚未冻结：

| 安排 | 拟定承载与边界 |
| --- | --- |
| 邀请与接受 | 提出可执行工作、时间与报酬条件，NPC按自身所知、当前目标和已有义务决定；被拒、尚未回复与已接受分别表达，不能自动解除其原工作或家庭安排 |
| 分工与实际执行 | 说明谁负责准备、采集、加工、运输或交付，使用真实人物活动、位置、能力及物资权限；同一时间不能同时为两项工作贡献完整工时，异地协助仍有旅行/消息和交付条件 |
| 成果与报酬 | 助手实际贡献引用既有成果证据，报酬有已同意来源，预付、分成、固定工钱或无偿互助均需明确约定；助手贡献可成为原委托完成依据，原委托支付与内部协助报酬分别记账并关联，同一合同内不重复计量，不复制多份完整任务报酬 |
| 履约责任 | 对委托人仍由原承接人履约；助手接受工作不代表原承接人免责。助手失能、退出或失约后的继续、换人、改约和损失处理依实际原因，具体责任分担仍待细则收敛 |
| 整单转包 | 在委托人同意前原承接关系不变；拟保留委托人、原承接人及新承接人的实际同意、条款和交接依据，不能仅改一个名字就宣布转包。新接手者仍须有能力、时间、意愿和资源 |
| 交接与收尾 | 已完成工作、已付/应付款、托付财物、助手安排及未清责任分别交接/结算；是否解除原承接人的哪些后续责任以同意范围为准，不能追溯抹去转包前的损失 |

公开悬赏中自行参与的竞争者、原承接人邀请的助手和得到同意的新承接者是不同角色。公开参与者按D44领取成果/贡献报酬，助手按协助约定清算；若某人兼有两种角色，要说明工作范围和已结依据，不能同一成果两头全额领取。

协助可以是生产、信息或局部服务，不强制所有助手始终跟在玩家身后。实际行动与信息传播继续引用npc-agency、world-simulation和world-systems，任务模块不另建无条件NPC控制、瞬移或第二套生活模拟。

### 信使、代理异地代交与本人目标

D55确定：条款允许时可以委托信使或代理异地代交，实际承担运输时间、费用和风险；本人完成要求仍由本人执行。以下为拟定交付语义，不代表现有书信或同行动作已经支持通用物流：

| 环节 | 拟定约束与证据 |
| --- | --- |
| 约定与承运 | 原委托明确是否允许代交、可收件人/代理、目的地或联系办法、验收和期限依据；承运者按D46实际同意工作、报酬、时间与所能承担的条件。货主授权、承运工作与整单承接关系分别保存 |
| 交出与在途 | 原物品/器物/成果凭据实际进入承运者或获准运输活动的保管，同一货物不能仍由发件人出售、装备或交付另一单。保管转移不自动改变所有权，承运者实际使用旅行、补给、身体能力和路线时间 |
| 接收与验收 | 到达后核对收件身份与代收权限、实际数量/状态和成果来源，记录交接；签收、目标验收、付款和原承接人获知分别推进。最后核实地址可能过时，发出一封信或一项运输指令不算已经履约 |
| 费用与报酬 | 承运费用、原委托报酬、代收款及托管释放分别认定其来源/归属和已付/未付，按实际交接一次结算；运输费用不自动从别人托付的购买预算扣除 |
| 期限与变更 | 发件时限、送达时限和验收时限按已同意条款区分；寄出本身不自动停止期限。收件人迁移、路线阻断或额外费用需实际联系、改约或止损，具体通知窗口和可授权调整幅度仍拟定 |
| 受阻、损坏、丢失或人员失能 | 保留真实货物所在/损耗和工作进度，不自动补货或把未知延误判为恶意。按损失、保管过程、责任与各方所知处理续运、返还、改约或清算，承运者失约与原承接人对委托人的履约分别关联 |

本人操作要求与交付动作分别检查。采购者可以在允许范围内让代理交付已取得的物资；本人考核或亲历见证不能靠代理提交他人的操作/经历变成本人完成。代理提交本人已合法完成的证据，也只有在原目标和机构规则允许时才被认定，不把代交当作更换成果作者。

原承接人仍按D46负责履约，整单转包另需委托人同意。物资在途、委托已撤回或玩家主动放弃时，托付财物与承运工作不能一键消失；召回需要实际通知和可执行返程。货物抵达、事故和回执只有经合法消息渠道获知才更新精确详情，日志可显示“已交承运、尚无新消息”，不泄露远方实时位置。

## 生命周期、改约与世界变化

拟区分已知线索/可洽谈、已接受、执行中、受阻/待复议、目标已达成待清算，以及已结算、未达成、放弃、撤回或被外部解决等结束原因。是否需要独立阶段状态由实际实现收敛，避免用一个“失败”标签混合玩家违约、委托人变卦和目标自然消失。

| 变化 | 候选处理 |
| --- | --- |
| NPC 自行买到粮食、另一人治好病人 | 原问题被外部解决，不能要求再次制造问题；若委托人主动撤回已接受委托，按D43补偿已完成工作与实际投入，其余自然失效的处理待定 |
| 人物迁走、失联、被限制或死亡 | 任务真实状态与玩家获知分开推进；迁走可以追查或改交付处，死亡可能终止或依法已有约定转接，不自动换一个 NPC |
| 目标物售罄、被盗、被毁或唯一机缘易主 | 更新可行途径与归属；允许追索、协商、替代或结束，不能为保任务凭空补一份 |
| 期限临近、路线阻断、活动延期 | 按原条款延期/部分履约/失约；重大条款变更需要双方实际沟通，不能静默改单 |
| 玩家未接、拒绝、放弃或来晚 | 问题按世界条件继续变化；没听说过的合同不会产生玩家违约；主动放弃按D45归还未使用托付财物并按实际损失与责任收尾，逾期的具体判责仍拟定 |
| 多人参与同一目标 | 按D42区分独占与竞争，公开悬赏按D44采用有效成果或可拆贡献结算；具体证据、计量与争议规则仍拟定，竞争进度只通过可观察渠道获知 |
| 委托人主动撤单 | 记录撤回原因，保留已完成工作与实际投入的补偿义务，按下述撤单清算处理；不能记成承接者失约 |
| 基本目标达成但额外目标未达成 | 保留基本成功与对应报酬；额外损失独立解释，不把整单全部重置 |

期限使用游戏时间；思考、输入、读菜单和现实离线不会使任务过期。长时活动只按已有世界中断语义提示本人可获知的新情况，不能因内部任务状态变更弹出全知预警。

## 短任务与偶发成长链

日常以一次明确差事为主，有可辨认的完成点和结算。允许就地处理、顺路合单、使用已有材料和主动拒绝；不设置现实每日必须清完的列表。短不等于零游戏耗时，跨城运输仍支付真实旅行和占用成本。

短任务后有三类同等有效结果：本次结清、关系/资源留下局部影响、满足新条件时出现可选后续。后续可以在更晚的游戏时间经同一人物、亲属或组织再次联系，玩家可以不继续；不能扣住短单应得报酬逼迫接下一段。

成长链需要新的因果与可行动者，例如发现供货缺口并非偶然、持续合作形成引荐、一次照护结识病人亲友。单纯把交付数量从三份改成六份不算长链；不让每个普通差事都升级成阴谋或全城危机。

后续的频率、跨度和具体并发容量保留拟定；D56–D57已确认长期合作与多单管理方向，具体提醒方式按下节及实玩体验校准。投放只从当时合法候选中选取，不为了刺激程度制造不成立的灾难，既有因果也不会为了玩家安静而停止。

## 长期合作、期次与暂停终止

D56确定：重复短单可以发展为定期供货、固定服务等长期合作，分期验收结算，允许暂停或终止并清算已发生义务。职业上的稳定合作不要求产生剧情反转或成长链；单次短单和人物新经历也不会自动变为持续合同。

以下为拟定执行语义，周期、续期方式、通知窗口和清算计算尚未冻结：

| 环节 | 拟定规则与持续依据 |
| --- | --- |
| 成立与续期 | 根据实际供需、能力、意愿和资源提出长期安排，双方同意周期、每期成果/服务、验收支付、期限及暂停/终止条件。已同意周期协议内按条款形成期次，超出范围的续约或重大变更重新协商；不因做满若干短单便自动强加未来义务 |
| 各期履行 | 关联合作协议版本、本期期限/范围、实际工作/投入、验收及已付/未付；每期使用当时真实物资、能力、工时和付款来源。固定服务确实占用时间，交出一批供货不能重复计入两期的同一消耗性需求 |
| 分期结算 | 已验收各期按条款结算，其他期未完成不自动抹去应得报酬；预付、跨期材料、托管保障及欠款各有去向。部分完成仍保留其成果和清算依据，不能为下一期重置未付款项 |
| 暂停与恢复 | 区分请求暂停、按既有条款生效和双方另行同意；明确暂停覆盖哪些未来工作、通知/生效时点与已有在途工作安排。暂停合作不暂停世界，已到期或已发生义务不自动豁免；恢复需仍有真实条件，并按约确认起期与期限，不把暂停期无条件堆成待补单 |
| 终止 | 根据提出方、条款及原因停止后续安排，清点已做工作、实际投入、未用托付物、应付未付与承运/助手事项；委托人主动撤回适用D43，承接人退出依D45和实际责任处理。终止不等于已全部清偿，也不默认赔付所有尚未发生的未来利润 |
| 条件变化 | 需求消失、原料短缺、价格/路线变化、人物失能或组织变化影响本期及后续可行性，需要履约、沟通、改约或收尾；不为保住周期凭空补资源、替换人物，亦不静默更改已生效价格和成果标准 |

合作中一次失误、延期或缺资可以影响之后的信任和安排，但不预写必定解约、每期加价或永远接续。稳定收入来自实际交付和支付，长期合作不等于点击签约后自动生产、运输或无限领款；已获同意的NPC分工仍依真实活动执行。

协议、当前/近期必要期次和下一需处理时点采用有界承载，不预生成无限未来订单；历史摘要保留各期已认定成果、支付及未清义务的必要依据。不能用期次列表滚动删除欠款，或以缓存重建重新派发已结束的同一期工作。

## 多项委托、顺路交付与期限冲突

D57确定多项委托可并行，允许顺路交付；长途旅行或闭关前提示本人已知的期限冲突，由玩家选择改约、安排代交或继续行动。并行是同时承担多项目标，不使人物同时完成彼此冲突的工时或跨地动作；接单继续重检独占名额和真实条件，具体技术容量按宿主实测确定。

拟按任务、人物、地区和期限整理本人已知的工作，可将同一次实际出行中相容的采购、调查和交付顺路安排。各合同的成果标准、权限、物资交接、验收和支付仍独立；实物只能按真实数量分配，不因多单同目的地而重复交出同一份。非消耗性的报告/经历能否复用依来源权限、保密及各任务条款分别判断，不禁止不同合同合法认可同一段真实观察。

顺路整理不自动替玩家接单、改道或交货，实际行动仍有路径、游戏耗时、费用与各自结果。同一段旅行可以服务多个相容目标，但不能把同一实际成本伪称为多次独立投入申领，也不把一项失败直接改成所有同行任务均失败。

候选提示依据为：本人当前有效且已知的单次/本期时限、已知交付/本人到场要求、计划行动耗时，以及本人有权获知的路径和承运安排。发件截止、送达截止、验收截止依原约分别估计；未知位置、未核实路况或尚无回执时说明不确定性，不读取远方隐藏真相来计算必然成败。

在正式提交长途旅行/闭关等长时行动前，拟给出受影响的已知委托和依据，区分按计划已难兼顾、时间紧张与信息不足。玩家可返回安排、请求改约、寻找愿意且能承担的代交者，或知情后继续；点选处理方向不代表NPC已同意改约或承运。提示不强制锁住行动、自动延期、取消任务或提供免责，继续后的后果仍按实际行为与所知处理。

行动计划或有效条款变化后重检提示，确认过的旧计划不覆盖新条件；普通查看、思考和现实等待不使游戏时限流逝。途中获知变化依既有世界中断与消息规则处理，未预警不保证安全，也不因隐藏事件发生立即全知报警。提示可合并相关事项，避免每个界面刷新重复打断，具体阈值与呈现留后续实现校准。

## AI 混合编排与规则检查

重点故事由作者明确人物矛盾、必要信息、可用行动、选择和后果边界，模型负责贴合当前状态的表达与已允许路径内的适配。动态委托由模型在获准世界片段和可执行动作目录中提出结构化候选，规则决定是否正式成立。

候选输入区分发布者本人所知、玩家已知和规则私有检查数据。模型不读取所有 NPC 私有目标或真实远方位置；规则可以检查身份、库存等事实，但不能将秘密以拒绝理由、地图标记或任务说明泄露给玩家。

拟采用以下接纳流程，不引入每项 AI 委托都要玩家额外审批的流程：

1. 从实际需求、事件或人物意图提取有来源的候选，并标明发布意愿与可用资源。
2. 模型在现有角色/地点/物品/能力目录内编排目标、角色、条款、可选阶段和表达；重要固定故事沿作者边界。
3. 规则检查结构、引用、来源、资格、参与意愿、资源占用、可执行路径、可发现线索、时限与报酬条件，以及重复和并发情况；按D53区分有依据的陈述偏差和无来源的虚构。
4. 合法候选才成为可发布的提议；协商与实际接受时再次检查最新修订、双方同意、条款、名额和资源，并登记必要预留。玩家主动目标可不形成对外合同。
5. 执行和结算继续检查当时事实；旁白只能表达已接纳提议和已提交结果。

规则检查不是只验证 JSON。没有护送行动、合法治疗手段或已制作考核规则的候选不得作为可执行任务发布；不能靠叙事补足。检查有限近期路径和必要条件，不承诺未来必定成功，也不运行无界规划证明整个长链。

误信、欺骗和隐瞒按D53及下节接纳：须有可表达的动机、所知或误解依据和真实行动，不把模型幻觉事后解释为NPC撒谎。规则知道存在隐瞒，不等于将真相告诉玩家；检查通过只证明内容有规则承载，不表示世界内各方认可其正当性。

失效或不合法候选返回有界修正依据或放弃本次编排；不循环调用直到凭空造出可接任务。模型不可用时保留已有已成立任务和确定性日常候选，不伪造新委托。等待现实服务不推进世界，取消、读档、分支切换后的迟到结果按原有修订与 epoch 隔离。

## 误报、隐瞒、灰色委托与立场变化

D53确定少量纳入有真实动机和信息差依据的误报、隐瞒及灰色委托，允许核实、拒绝、揭发或改变立场；后果按实际行为和各方所知产生。这不是普通任务一律不可信，也不要求每个故事反转。具体频率和题材分布归内容编制与后续体验校准。

拟将世界事实、发布者所知/动机、对外陈述、双方接受的条款及玩家已知证据分别关联。下列偏差可能重叠，但不共用一个“说谎”标签：

| 情境 | 必要依据与拟定处理 |
| --- | --- |
| 误报或过时消息 | 有实际消息来源、观察偏差或信息延迟，发布者可能自己相信；新证据可以更正认识，不因事实有误自动判成恶意 |
| 蓄意隐瞒或欺骗 | 已有真实利益、顾虑或冲突动机，保留其实际知道什么、隐去/歪曲了什么及陈述出处；不能到揭发时才随机补一个幕后原因 |
| 灰色或利益冲突 | 当事人目标、所有权/承诺、组织约定或当地规则存在可表达的冲突；不强制所有人共享善恶评价，不用一个任务颜色替代真实责任 |

规则对陈述偏差的接纳不制造不存在的人物、物品、受害者或行为。误认失物位置可以指向可调查的消息和真实场所，“某人偷了货”仍只是有来源的指控，不能直接写成所有权或盗窃事实；查无此事允许进入受阻、澄清或结束。若设定本就没有目标物，也不能为保证任务可完成临时生成它。可执行要求是当前调查、交谈、提交证据等步骤确有承载，不承诺委托人所述结果必定存在或目标必可达成。

候选发现与选择路径如下，不是固定剧情顺序或自动解锁菜单：

- 核实：访问合法可达现场、询问愿意回应的人、检查可用物证或交接记录，依实际结果增补/更正所知。选择“怀疑”或模型猜中真相本身不产生证据。
- 拒绝或暂停参与：未接单可直接拒绝；已接单可以提议改约、查证后再履行或主动退出，原有期限、托付财物和清算按已生效条款及D45处理，不因勾选“发现隐瞒”自动免责或全额没收。
- 揭发或澄清：玩家选择向实际可联系的对象提交自己有权使用的证据或陈述，接收者按其所知、立场和可信判断回应；转述可能被质疑，不能一键向全世界广播正确结论。若存在保密或第三方权益冲突，后果须有真实行为和约定依据。
- 改变立场：通过实际交涉、交还托付物、终止/改约或另行接受工作表现选择；不自动替另一方接单、转移财物或消除已承担责任。同一物品/成果不能同时用于互斥承诺并重复获酬。

事实责任、双方争议与NPC评价分别处理。查明隐瞒可能改变履约基础、损失归因或合作意愿，但是否解除义务、部分工作如何计酬及争议怎样解决仍按具体条款和证据设计；不以全局“正义选项”替代清算。玩家帮助一方可能失去另一方合作，也可能因他人尚未知情而暂未受到反应。

后续传播沿既有见闻、书信、观察和社交关系，消息有发生/获知时点与来源，知情者可能只知道片段、误信指控或拒绝相信。纠正、道歉、赔付和新证据可以形成后续经历，不自动抹去旧行为、恢复所有关系或同步全城认识。模型仅表达人物当时有依据的说法与反应，不直接发奖、改账、判责或解密隐藏真相。

## 报酬、信用与清算

金钱和物品报酬有真实出资人和可追溯的支付来源；D54允许机构托管单与私人信用单并存，接单前展示本人可知的付款/担保情况，缺资或拒付保留欠款及追偿途径。实际预留和有风险的信用承诺分别认定，不能将同一份托管或预留钱物重复保障多单。预付款、材料托付、押金、部分成果与取消退款分别记录实际流转，不能混成一次领奖。

情报、引荐、传授与服务优惠同样需要给予者确实知道、拥有资格且愿意提供。声望或贡献只在实际支持的组织规则存在时使用；通用修为奖励不作为所有跑腿的默认产物，成长优先来自实际练习与取得学习机会。

完成认定引用具体行为与结果；每次实际交付或支付及对应状态/凭据在同一权威提交中保持一致，不要求异地运输、验收和延期付款在同一时点完成。重复点击、并发交付或模型重试不能再次收费、消耗材料或领奖。真实争议、拒付、缺资和违约需有可解释状态，不用第二次生成旁白覆盖已完成事实。

主动探索、救人或收集线索可以没有事先承诺报酬；世界后续答谢若发生，是基于实际意愿和资源的新行为，不自动无限追认所有已做之事为有偿合同。

### 机构托管、私人信用与欠款追偿

以下为D54下的拟定操作与清算细则，机构资格、费用、保障范围和处理时限未冻结：

| 付款安排 | 拟定真实承载与边界 |
| --- | --- |
| 机构托管 | 由实际具备权限和保管能力的机构接受托管，钱物确已转入或被合法占用后才显示已托管；记录付款方、受益方、用途/保障额度、释放与退回条件。发布在公会告示栏不自动等于公会担保，尚未交存或只覆盖部分时不能标成全额保障 |
| 私人信用 | 保存付款人的承诺、已同意支付时点/条件和已知担保，接单前允许按可知经历判断风险；没有托管不自动判为骗局，也不保证付款人未来始终有足够财物。未到应付条件的承诺不能直接算逾期欠款 |
| 可知信息 | 展示获准知道的付款方式、已核实托管/担保及其来源/核实时点、预付和后付条件；未核实之处明确待确认。不公开NPC秘密余额、隐藏赖账计划或系统推算的必然结果，D53陈述和事实区分继续生效 |
| 验收与付款 | 依据当前有效条款认定成果和应付，再从实际可用来源支付或按托管条件释放；部分验收、部分付款、应付未付和有争议部分分别记录。托管退回、撤单补偿、预付抵扣不能对同一钱物重复执行 |

欠款关联实际债权人/付款人、所依据的工作/条款/清算及应付/已付证据。缺资、拖延、明确拒付与验收争议分别保留来源和时间，不仅改变“已完成”标签；信用评价仍依各方所知。尚未付清的任务可以离开日常活跃工作列表，但欠款和未清义务仍可查询、继续处理，不能随普通历史摘要删除。

拟提供实际可执行的追偿路径：联系付款人并提交成果/对账依据，协商支付、分期或其他可接受清偿；涉及托管/担保时，可向具有相应权限的机构申请核验、按已接受条件释放或处理争议。每条路径须有真实可联系对象、其权限/意愿、证据、行动和可能结果，不将“申请追偿”视作已经收回财物。未获同意的分期不单方改原约，机构也不凭空补足未承诺覆盖的差额。

缺资或拒付后可能继续欠款、部分清偿、达成和解或争议未决；不预写必定追偿成功或自动从全世界其他人钱包扣钱。具体调解权限、担保人履约、机构失能、债务人死亡/失联及追偿费用等需按现有组织/继任能力收敛，不由本节默认建立完整司法、保险或继承系统。长期后果与后续消息继续引用同一事实和所知。

### 委托人主动撤单的补偿

D43确定的底线是同时补偿已完成工作与实际投入。仅退回托付材料而忽略已做劳动，或仅支付阶段工资却不认实际成本，都不能作为默认清算。普通委托被委托人自行解决需求后撤回，也不能用“外部已解决”清空补偿责任。公开悬赏由发布者主动撤回时，同样遵循这项原则；多人各自成果和投入如何认定仍需结合公开条款讨论。

以下结算安排均为候选设计，不是已确认计算公式：

| 清算部分 | 拟定依据与仍需讨论的边界 |
| --- | --- |
| 已完成工作 | 用真实阶段成果、服务记录和已提交行为确认，按事先条款或可核实工作量估值；不要求先完成整单才承认劳动，也不把未发生的剩余利润自动视作已完成工作 |
| 实际投入 | 保存与本委托有因果关联的材料、采购、交通、服务费用及实际损耗；通用生活开支、机会成本、风险损失、仍留在承接者手中的可用物如何认定与折价，尚未决定 |
| 托付物与剩余财物 | 按真实所有权清点、退还或经同意移交，不复制财物；与投入补偿分别对账，避免同一笔已退财物又计入全额赔付 |
| 预付与已结部分 | 区分已付工资、材料预付、押金与尚欠款，按用途抵扣；同一工作或同一成本只结算一次，不因撤单再重复领取 |
| 撤回与通知时点 | 分别保留提出撤回、本人合法收到消息及停止工作的时点；在途工作、合理通知延迟和仍继续发生的必要投入怎样计入，由后续条款确定，不用现实等待时间计费 |
| 缺资与争议 | 已有补偿义务不能因委托人缺钱、拒付或隐藏任务而消失；拟保留可追溯的应补未付状态与证据，不凭空发钱，也不显示为已清偿 |

“任务已停止”与“补偿已付清”分开表达；部分款已付时保留剩余清算，相关凭据不能按普通终态摘要直接丢弃。金额、财物归属、已付/未付与结算凭据沿同一权威提交保持一致；并发交付和撤单按实际提交先后处理，具体同刻裁定与证据要求待实现前收敛。

撤单后怎样影响人物信用、后续合作与争议传播，继续依据本人所知和实际履约情况。按约补偿的撤单不应直接等同恶意赖账；其具体评价幅度仍为候选。玩家主动放弃、双方协商变更、委托人死亡等非主动撤单情形，以及公开竞争自然落败，不自动沿用本项补偿算法。

### 玩家主动放弃、归还与责任

D45确定：玩家可以主动放弃，退回未使用的托付财物，赔偿与信用按实际损失和责任处理，并区分恶意失约、能力不足和不可控变故。主动退出不是世界回滚，已经发生的工作、消耗、财物归属与他人损失继续存在。

以下为拟定收尾路径：登记退出及其合法时点和原因 → 清点未使用托付财物并实际归还 → 核对已完成/已付款/应付款与损失依据 → 按责任形成清算及相关人物可知的评价。退出、归还和清算分别可追踪；发出“我放弃”不自动搬回远方财物或宣布债务清零。

| 收尾事项 | 拟定处理与限制 |
| --- | --- |
| 未使用的托付财物 | 按真实所有权、数量和所在地归还并留下回执；托付材料/专用资金与玩家自有物、已挣得报酬分开。已经合法消耗、损坏或丢失的部分进入事实和责任判断，不能凭空复制一份退回 |
| 已完成工作与已付部分 | 保留实际成果和支付记录，按原有条款清算，具体部分报酬/预付款抵扣方法仍待定；不能将全部已付金额直接当成未使用托付物，也不能重复计算赔偿和退款 |
| 实际损失 | 核对对方实际承担且与本次行为有因果关联的缺料、额外费用、财物损失或已约定服务损失；未发生利润、全部时间和所有生活开支是否可计入，不作统一假定 |
| 责任与可预见性 | 区分主动原因、承诺时已知条件、是否如实说明能力、途中是否合理告知/止损，以及不可控变化；没有完成目标本身不足以证明恶意 |
| 赔偿、信用与争议 | 财物清算与主观评价分开，记录已归还/已付/待付/待确认内容。金额、责任比例、信用幅度及争议处理为候选；不能仅减少一个全局信用数字而不处理真实财物，也不能用任务隐藏删除未清义务 |

责任情境分别编制，不把下列例子当作固定结局或赔付比例：

- 恶意失约：有实际依据表明故意侵占托付物、伪造成果或明知不能履行仍以欺骗获利；相关损失和知情者反应与善意失败区分。
- 能力不足：确实尝试但估计失准，结合是否隐瞒资格、接约时可知风险、及时求助/告知和已做工作判断责任；既不自动全免，也不自动视为恶意。
- 不可控变故：非本人造成且不能合理控制的事件，核对实际影响、可行替代和告知条件后处理；不默认与主动反悔同责，也不把所有困难都直接归为免责理由。

合同认定的事实和NPC当时所知保持区分。对方可能尚未收到退出消息，或对失败原因产生误解；不得把私有后台原因直接写进其即时评价。后续说明、合法证据与清偿可以改变认识，数值及传播仍引用既有关系/信息规则。

未接受的机会没有托付合同责任，无偿探索也不凭空产生雇佣赔偿；公开悬赏自然落败、玩家主动退出已承担的义务和委托人主动撤回分别处理。助手/转包采用D46原则，具体分工/退出责任、逾期认定及无法立即归还时的安排仍为拟定。

## 长期后果与个人所知

| 后果层 | 持续改变什么 | 传播和限制 |
| --- | --- | --- |
| 物质 | 库存、伤势、器物、货物归属、生态压力与路线活动 | 使用原领域权威；任务结束不恢复原料、复活人物或刷新唯一物 |
| 人物 | 守信印象、感激、顾虑、债务、复仇或合作动机 | 依据本人所知与性格形成，不能把任务分数广播成全世界好感 |
| 社会 | 引荐、雇佣倾向、组织资格、合同纠纷、家庭的实际变化 | 亲属或组织需实际获知；帮助某人不自动让其所有亲友产生同样评价 |
| 地方 | 供给稳定性、运输准备、服务可用性与竞争格局 | 通过真实生产、消费、成员活动逐步作用，不因一次小单立刻改变整个地区 |
| 历史 | 重要选择、伤亡、物品流转、冲突结果和后续来源 | 原因可追溯；有界保存、摘要和冷查询不能改变已发生事实 |

同一目标可以形成不同后果：花钱买回赃物、公开揭发熟人、秘密和解和强夺，即使最终物品归属相同，也留下不同支出、知情者和关系。只对规则确实支持的解法作出差异承诺。

短单可以只改善眼前生活，不要求每单留下重大永久事件。多次合作可按实际经历逐步形成可靠供货或引荐，避免固定增信任数值被刷单无限放大；重复收益、相同行为的边际评价与后续机会按实际关系规则校准。

任务终态与后果持续期分开。合同已结清，其造成的伤势、所有权、债务、关系和 NPC 新目标仍由各领域继续维护；后续不要求旧任务一直占据活跃列表。

具体池、行动结构、作者种子及候选覆盖目标只在 [quest-content.md](quest-content.md) 维护。通用 poolId/entryId/版本和资格筛选不另建随机表；任务专属投放需要在同一入口上提供已授权情境与必要的重复签名。

D59将QC01–QC27全部列为首批可玩目标，QC28–QC30按D33后续安排；各自操作、选择、结算与后果的可执行要求唯一见内容模块。投放依当时世界、资格和所知，不因27个制作目标已确定便在每个开局全部显示或强行制造需求；底层依赖未完成的首批目标保留未完成状态，不自动降为本轮范围之外。

重复签名至少能区分主要目标结构、核心行为、委托人/角色组合、地区和主要障碍。不同条目仍可能是同一种体验；理论组合数不作为丰富度验收。近期经历只影响合法候选排序，不能为了新鲜把不合资格的内容强行塞入。

未见内容和冷却采用游戏时间与已提交经历。刷新菜单不重抽，稀缺候选不足时可以明确无新单、复用合理短单或推荐现有机会，不突破资格、不掩盖重复。已接受任务不为了改善分布被自动换掉。

## 任务日志与追踪体验

D47确定：正式委托明确目标、报酬、期限与已确认进度；调查探索展示已知线索与最后核实位置，允许手动追踪。下面的布局、筛选、追踪数量与提醒方式仍为候选，不能当作当前C4已有任务界面。

候选界面复用现有四主入口和人物详情：见闻承载委托/目标、线索与已结事件，人物显示与自己实际有关的约定；不在本轮冻结新主入口或最终布局。

### 附近已知机会与发现入口

D58确定提供“附近已知机会”汇总，整理公告、来信、交谈或亲历获知的委托，保留来源、时点和最后核实地点；未获知的人物线和随机事件通过交谈、现场发现或主动调查进入视野。下列聚合、陈旧处理与筛选细节为拟定设计，不表示当前界面已经具备该能力。

| 信息环节 | 拟定依据与展示边界 |
| --- | --- |
| 获知 | 公告须已实际读取或经合法转达，来信须实际送达并获知内容，交谈和亲历须有已提交结果；某地存在公开告示不等于玩家已读取，更不把NPC私有意图直接放进列表 |
| 来源和时点 | 关联可知的告示/来信/说话者/亲历记录，区分事件或发布时点、本人获知时点和最后核实时点；不知道的日期明确未知，不用收到传闻的时点冒充刚刚核实 |
| 附近与地点 | 按本人当前所在地和已知关联地点整理，地点可为场所、区域或最后核实范围；不以后台实时人物坐标排序，不将旧地址标成当前必定在场。具体距离、地区划分与排序仍拟定，远方已知机会仍可在已有记录中查询 |
| 多来源与矛盾 | 同一已知委托的公告、来信和口述关联到同一机会及各自证据，保留矛盾与更正；不能因多渠道获知复制订单，也不能只凭同名人物或相似描述合并两项不同工作 |
| 陈旧与失效 | 已知过期、撤回或被解决的消息可更新展示；尚未获知的死亡、目标被取走或后台终态不能偷偷删除/改排列表来泄露结果。只有旧说法时保留来源和待核实提示，不保证仍可承接 |
| 未发现内容 | 不显示未获知人物线/随机事件的名称、隐藏目标、准确入口、剩余数量或完成率；实际接触与合法线索才能让对应内容进入视野，不为补齐列表强制发生事件 |

“机会”可以是可洽谈委托、公开悬赏消息或尚待核实线索，分别标明已知性质；听说有一批失物不自动创造正式合同或确认指控。查看、筛选、整理和手动追踪不接单、不预留名额、不与远方人物自动交涉，也不因刷新触发重抽或推进世界时间。实际承接仍需沟通、权限与条件检查，沿D42/D47办理。

汇总读取同一分支的合法所知和任务引用，按相关新消息/核实变化更新，不另建一份可自行改变履约或世界状态的任务目录。缓存、排序与分页可重建；存档恢复后只使用当时来源和已知地点，未来线索、撤单通知与人物位置不得串回。

### 可跳过的开局轻引导

D60确认依据出身和所在地，通过最初交谈、公告或亲历逐步带出少量不同玩法的短机会，玩家自由选择且可跳过；其余内容依世界条件和探索出现。具体样本、提示次序与数量仍拟定，不要求每种出身进入相同人物、相同差事或固定结局。

拟从当前确实成立、可合法获知且具备相应行动条件的短机会组织引导，介绍发现机会、查看条款、协商/承接及实际完成和收尾。它们仍使用正式世界规则、NPC意愿、真实钱物和游戏时间，不另建可以忽略资格/资源的教学任务状态；玩家可以只阅读提示、不接单、换一个机会或自行探索，不将引导完成度设为正常任务与活动的额外准入条件。

跳过仅停止引导提示，不自动完成、接取、取消或重置任何真实工作；已经同意的合同、已收到托付物和世界正在发生的变化照常处理。地点、人物、需求或能力改变时，按当前条件调整或不再提供相应提示，不为凑齐样本生成假需求、复活人物或泄露未发现的故事。

引导的已展示/已跳过状态与任务/所知事实分别维护，随当前世界分支恢复；重新查看操作说明不重复发奖、交物或回填未来线索。提示轻量、可关闭，沿既有按钮/自由文字与帮助入口呈现；具体界面布局、是否提供再次查看说明及提示频率在实现时细化，不能把本段视为当前C4已有功能。

### 已知条款、进度与追踪

| 信息类别 | 已确认表达方向 | 拟定细化与限制 |
| --- | --- | --- |
| 附近已知机会 | 汇总已获知委托并保留来源、时点和最后核实地点 | 以合法所知组织可洽谈/悬赏消息/待核实线索，不展示隐藏任务清单；多来源去重与陈旧说明按上节，查看不等于接单 |
| 正式委托 | 明确目标、报酬、期限、已确认进度 | 显示当前有效条款，协商提议/对方回应/待双方确认与已经生效分开；没有固定期限时明示未约定固定期限，不编倒计时。已同意“寻找某人所说的失物”不表示已核实其失窃指控，陈述与事实区分 |
| 付款、代交与未清事项 | 展示本人可知的付款/担保、代交与已确认进展 | 接单前可查托管/信用与付款条件；交承运、已获签收、已验收、已付和应付未付分别显示。未知在途情况不冒充实时追踪，代交与追偿均不自动宣告完成 |
| 长期合作与多单安排 | 展示已同意合作、本期期限/工作和分期验收支付，以及已知期限冲突 | 暂停请求/已生效暂停/终止/未清事项分开，未来未承诺期次不冒充已接单；顺路整理和冲突提示不改变合同、时间或代交安排 |
| 已确认进展 | 展示有合法依据的本人已知进度 | 区分已发生、已提交和对方已验收，待核实成果不直接显示已获酬；NPC远方自行完成但玩家未获知时不提前更新准确终态 |
| 调查探索 | 展示已知线索与最后核实位置 | 关联来源、发生/获知或核实时点及可信状态，位置可以是场所或已知范围；未知线索不填假精确坐标，旧位置不跟随远方人物实时移动 |
| 手动追踪 | 玩家主动选择关注的任务/线索 | 跟踪与取消不接单、不代办接近/旅行或推进目标；拟零耗游戏时间，不重抽内容、不付费，具体数量与地图表现待实现时校准 |

区分“已知机会”“我的承诺”“本人主动目标”“历史结果”，避免把传闻全部变成必做清单。可追踪、取消追踪和按地区/人物筛选；追踪不接约，也不冻结世界。

地图只标记合法已知地点或最后获知范围；未知目标先提示打听/查证方向，不展示远方 NPC 的实时坐标。消息发生时点和收到时点分别保留；世界实际已被解决但玩家还未获知时，不提前显示准确结束原因。

已知进度、需要确认、部分完成、延期、目标变化、报酬待清算和终态均有自然语言反馈。协助关系、整单转包的同意状态与最后已知助手进展只在本人有权获知时展示，不把帮助请求标成已在执行。

误报/隐瞒任务不会预先显示“真相”“恶意委托”或系统风险标签；界面按玩家实际所知标注谁的说法、可核实线索、矛盾和已确认更正，不泄露NPC私有动机。协商拒绝或规则校验失败的说明同样受此限制，不能以无权读取的真实库存、幕后目的或完整调查答案作为提示。

手动追踪的选择与缓存随对应世界分支保存/恢复；取消追踪不删除任务、来源或义务，读档后不能保留未来目标位置或未来任务进度。自由文字与按钮走同一规则，草稿、重复操作、异步取消、恢复重绑、键盘/IME、窄视口与 reduced-motion 沿用现有前端要求；后续实作再更新真实 C 契约。

## 保存、历史增长与运行成本

任务身份、提议/同意及有效条款版本、合作协议/期次/暂停终止/下次处理依据、目标进度、陈述与动机/所知来源、已提交证据、传播/更正、托管/担保/应付未付及追偿处理、承运授权/实物保管/交接/验收、实际结算、资源预留、近期投放历史、种子/已选结果与合法所知进入同一 Session/SavePoint。恢复后从对应事实继续，未来编排、奖励和信息不可串回；幂等依据随分支快照恢复，不用外部全局已领奖表破坏完整世界读档。多单整理与期限提示从同一分支已知事实派生，恢复后重算，不保留未来计划或真相。

活跃任务保留完整可执行数据，终态任务转为有界历史摘要与必要详情引用；未清算、争议、未来依赖与被引用证据不能因“已结束”丢弃。优先复用既有 Domain、History、Information 与来源存储，避免增加平行存档服务。

迁移/归档方式和具体容量须在实现时按实际持久层验证。若预算不足，优先减少新投放、分页/定向读取和整理可安全冷却的已结记录；不能静默删除未履约合同、重抽任务或把有上限历史宣称为无限世代。

唤醒依赖目标相关的行为、期限、消息、人物状态和关键资源变化，不在每次 continue 扫全世界任务并调用模型。模型只用于受益于编排的少量决策；常规进度、日常委托检查和支付保持确定性。成本与 NPC/W5 同时评估，不能用纯规则长时样本代替完整宿主性能。

当前 package 版本标识、计划容量与产品正在进行的容量工作不是兼容证明；正式实施先核对真实 Git 与当前约束，再决定是否需要具体产品修补。没有先验要求扩大所有框架限额，也不承诺无迁移旧档兼容。

## quests.1 实际规则承载（2026-10-23）

本次已按D39–D60正式实施。上文保留方向与设计理由；实际操作/错误/状态字段只以[当前C5契约](frontend-contract.md#c5--quests1-活动接口2026-10-23)和源码为准。当前参数属于工程默认值，不新增用户确认项。

`source/rules/quests.js` 管理已知提议、协商、承接独占、结算、协作、代交与周期；`quest-operations.js` 只生成真实操作成果；`quest-public.js`按NPC实际缺口发布有资金托管的单目标或贡献悬赏；`quest-discovery.js`复用原有消息账和送达调度寄邀约。完整27种子及故事事实见quest-content，活动见quest-activities。

- 普通委托接单即独占；重复输入不得重复扣料或付款。托管来自真实付款人，私人信用不足形成可追偿欠款。成果工资按具体操作决定，部分履约不会在通用提交或异地验收时升级为全额。
- 当地公告、实际交谈、亲历观察和已送达来信分别保留来源。以人物为对象的现场观察必须实际看见当事人，不因远方人物缺粮便在旧地点投放；本人探索和无雇主机缘按当前所在地、已知路线及实际生境核验，不要求旧竞争者在场。信件仅为寄信时提议，接单时重新核实；未送达不泄露机会。模型不直接创建合同或改变世界。
- 协作支付真实工料，沿NPC原调度执行；原物保管不并入协作者自有库存。一个阶段的工作工时只推进一次，生活活动调度不另加同一份工时。已承接任务的协作者退出玩家同行名单，任务运输不再被普通同行旅行带走。可当面接回尚在的协作及财物，不凭空找回在途物。
- 多段勘察按实际工作地点依次推进：完整勘路由哨棚到外缘营地，第一段完成不提前回报；已协商的半程成果仅查哨棚并按半额验收。协助者回报后由玩家向委托人提交验收；整单转包者完成后先实际返委托地点、沿既有场景寻路走到可交流距离，再接受付款，之后回报。重复提交不再增加工资或勘察证据。
- 异地代交把实际抵达、授权签收、委托人验收和回执返程分开。承运者到达场所后仍须沿既有寻路逐格接近收件人或验收人，进入可见且曼哈顿距离不超过两格的范围才交接；人物未到、离开或路线受阻时保留托付与待办，不远程发货或造出收款。每格移动耗一分钟，等待与旅行继续走统一时间。
- 风险大于零的实际路段到达时，玩家、实际同行者、NPC自主旅行者和任务承运者按同一装备权威，对已装备手持和身上器物各产生一点耐久损耗。安全路段不磨损，尚未抵达的取消旅行不记本段到达损耗；重复继续不重复计入同一次到达。维修恢复原装备实例，不通过任务投放制造损坏；该规则是当前旅行消耗，不冻结D33未来战斗机制。
- 任务操作产生工时后须完成或续做；也可退出并按实际完成工时清算，不把取消主操作解释为全额完成。期限用于知情提示和接单复核；现有具体工作可协商变更，未增加全任务统一逾期罚款公式。
- 已结清可重复工作可约七日周期，未来期可暂停/终止；当前真实需求和资金不足时拒绝新一期，原协议仍保留。短单冷却七日，避免重复点击即时刷收益。引导可跳过，不跳过合同义务。
- 任务明细与汇总有界；只有无欠款、无托付、无协作者和无有效协议的终态可压缩。原物、库存、装备、身体、关系、NPC所知及世界时间继续使用既有权威。

当前未实现完整玩家战斗、未来战斗公式、QC28–QC30；不把原有简单交锋/NPC后台冲突当作替代。模型服务与全自然地域长旅程的验收范围必须看Record，不用合法状态夹具替代。
