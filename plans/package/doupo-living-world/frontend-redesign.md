# 前端体验重构方案 — 从“功能面板集合”到一部修行人生

状态：第 11 节六项决定已获用户确认（2026-10-24，“go on”），R1–R5 的主体已在 `package:doupo-living-world/frontend` 一次实现。实现偏离：地方活动暂作为江湖录“此地活动”签页，而非独立情境；§9 的子组件拆分改为单组件 + stage class + 共享列表（原因见 §9 补记）。未做：R6 的完整键盘/读屏/200% 缩放审查与真实模型下的自由文字验收。适用 `0.1.0-combat.1`（C6）及其后续版本；不改规则、screen 字段或 Bridge 绑定。已确认方向以 [decisions.md](decisions.md) 为准，字段与动作以 [frontend-contract.md](frontend-contract.md) C4–C6 和包内 `integration/screen.schema.json` 为准。概念原型位于任务工作区 `tasks/doupo-living-world/design/redesign-concept/`（本地，不入仓库）。

本方案把现行 `package:doupo-living-world/frontend` 视为待质询的实现，只作功能清单使用；[presentation.md](presentation.md) 与 `design-reference/` 中的布局、色值与面板编排属于“设计建议”，本方案在不违背已确认决定的前提下替换它们。

## 1. 诊断：为什么现在“能玩但不好玩”

| 问题 | 现行表现 | 对体验的伤害 |
| --- | --- | --- |
| 所有系统长成同一种表格 | 13 种面板模式共用一套 `panelRows`（标题/正文/元信息/两个按钮）；功法、伤势、委托、拍卖、家庭、尸身都是同样的行卡 | 系统之间没有辨识度，玩家感受不到“修炼”“交易”“办事”是不同的活动 |
| 功能抽屉遮住世界 | 抽屉从右侧盖住场景，标题“返回场景”；场景在大多数时间是背景装饰 | 世界成为菜单的背景，失去“我在某处”的存在感 |
| 交锋是一张表单 | 14 个动作按钮、目标/斗技/同伴下拉、手填 x 0–19 / y 0–13 落点、短令下拉 | 战斗变成填表，空间战术（D61、D73）完全不可见 |
| 行走靠坐标输入 | “行走”工具展开坐标输入框与隐形网格 | 违背 D14 点击移动的初衷 |
| 对话不是对话 | 选人后弹出人物卡，交谈＝把焦点移到底部草稿框，回应在卡片里一段文字，另有“听取回应”按钮 | 与 NPC 交往（D19 首要体验）没有“交谈”的形状 |
| 动作全部平铺 | 人间页一次列出“表达心意/商议婚约/建立家庭/商议养育/结束共同生活”等十个按钮，赠礼下拉列出未持有物品 | 关系没有进展感，界面替玩家暴露全部可能性又不说明哪个现在有意义 |
| 每件事都要确认 | 绝大多数操作先进入“确认这项安排 → 确认提交” | 节奏被打断；真正重大的决定反而不突出 |
| 系统内部语言外露 | “核对当前结果”“核对原提交”“停止生成”“读取当地悬赏/整理已送达邀约/留意当地情境”“境界 3”“开局后 0 日 8 时 10 分” | 不断提醒玩家这是软件 |
| 时间没有分量 | 时间是标题旁一行小字；长行动是一条“继续行动/停止后续行动”的状态栏 | D07“行动推进时间”是本作核心张力，却没有被感知 |
| 视觉材质冷硬 | 冷玄青平面卡片、细边线，与暖金调手绘场景和宣纸底人物像脱节 | 美术投资被 UI 削弱 |

结论：问题不在单个控件，而在于没有“玩家此刻在做什么”的模型。现行界面按数据结构组织，本方案按玩家的活动组织。

## 2. 设计支柱

1. **一处一景**：当前场所永远是画面主体。功能以“卷”从侧面展开、半掩场景，不替换场景；关闭即回到原地。
2. **人在其中**：人物是内容。场景里能看到人（Q版），底部“在场”列出人，选中即进入与此人相处的情境，而不是打开资料卡。
3. **光阴有价**：每个会推进世界的动作都标出耗时；时间以时辰、日、季呈现；长行动进入“光阴流转”，世界事件在途中浮现、可随时停手。
4. **所知即所见**：每条信息带出处印记——亲见、听闻、来信、原著记忆、旧观察；未知就写未知，传闻不画成事实。
5. **落印为定**：查看、选择、写草稿不留痕；把意图交给世界时盖上一方朱印。印是本作唯一张扬的视觉元素，用来区分“想”与“做”。

## 3. 核心循环与界面承载

```text
身处一地 ──看见──▶ 在场的人、此地的事、手中的物
   ▲                         │
   │                      投身其中（交谈 / 交易 / 办事 / 交锋 / 修行）
世界自行运转                  │  落印：耗时、耗物、承担后果
（来信、传闻、他人的选择）◀──光阴流转───┘
   │
成长与羁绊：境界、法门、伤病、关系、家庭、名声与委托记录
```

界面因此只有三层：**场景（常驻）→ 情境（对话、交易、交锋、光阴流转等，占据场景但保留场景）→ 卷（己身、人间、江湖录、山河，半掩场景的资料与长线经营）**。旧的 13 种面板模式全部归入这三层，见第 8 节。

## 4. 信息架构

### 4.1 主画面

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ▣ 乌坦城·回春堂        ◐ 第三日 巳时 · 晴           [己身像] 气血 ▬▬▬ │
│   （场所铭牌，点击回到城中）  （时辰盘）               斗气 ▬▬▭  金 23 │
│                                                                ┌──┐ │
│                    全幅场景（手绘俯视图）                       │己│ │
│        Q版人物、可交互物件（柜台、告示、药柜）                  │身│ │
│        点地面行走；点人物选中；点物件出现物件动作                │人│ │
│                                                                │间│ │
│                                                                │江│ │
│                                                                │湖│ │
│                                                                │山│ │
│                                                                │河│ │
│                                                                └──┘ │
│ ┌在场────────────────┐  ┌最近之事─────────────────────────────────┐ │
│ │[苏][陈][陆] +2  旧识│  │ 苏晚禾抬头看了你一眼，继续碾药。  ·亲见 │ │
│ └────────────────────┘  └──────────────────────────────────────────┘ │
│  对 [此地]：[ 写下你想做的事……                        ] [落印·行事] │
└──────────────────────────────────────────────────────────────────────┘
```

- **场所铭牌**（左上）：地点名，点击回到所在地区总览；地区总览上点设施即“前往”（显示步行耗时）。
- **时辰盘**（中上）：第几日、时辰、天色。世界时间推进时指针转动一格，这是时间的唯一常驻表达。
- **己身像**（右上）：主角Q版小像、气血/斗气墨条、金币；伤势与受控以小印标在像旁。点击打开“己身”卷。
- **四卷签**（右缘竖排）：己身、人间、江湖录、山河。快捷键 C / R / J / M。
- **在场**（左下）：当前可感知人物的立绘小像，最多 6 个，溢出折叠为“+N”；“旧识”切换到已知旧档案。与场景中的Q版是同一选择。
- **最近之事**（下中）：最近一条结果与旁白，带出处印；点击展开为“行记”全部回看。
- **行事栏**（底部）：自由文字常驻，明确写出“对谁”。没有选中人时对象为“此地”。

去掉的常驻元素：独立“菜单”按钮之外的宿主按钮、状态栏、坐标工具、6 个底部页签。存档、字号、宿主控制收进 Esc 唤出的“歇息”菜单。

### 4.2 情境

| 情境 | 进入 | 画面 | 退出 |
| --- | --- | --- | --- |
| 相处（对话） | 点在场人物 / Q版 | 场景压暗留形，人物半身像占左侧 2/5，右侧为对话卷：此前往来、当前回应、可行之事；底部输入自动绑定此人 | Esc / 点空处；回到场景并保留选中 |
| 交易 | 相处中的“看看货”，或点柜台物件 | 商人像 + 货架（物品画 + 价 + 存量）与行囊并列，拖量或点击加减，结账时落印 | 同上 |
| 交锋 | 相处中“动手/切磋”，或被卷入 | 场景本身变为战场：网格浮现，两步内可达格高亮，敌我小像有血/气墨条与阵营色；底部为本轮行动栏 | 交锋结束后进入“战后”结算页 |
| 光阴流转 | 旅行、闭关、做工、等候、休养、换修等长行动 | 场景转为水墨长卷，时辰盘快转；途中事件以纸条落下；“停手”随时可按 | 抵达 / 完成 / 被事件打断时回到场景并给出摘要 |
| 地方活动 | 在拍卖场、公会等处点相应物件 | 专属版面：拍卖为“拍品台 + 叫价”，考核为“四阶段炉火进度” | 结束后回到场景 |

卷从右侧展开，宽约 62%，左侧仍露出场景与在场人物；卷内用横向签页，不嵌套抽屉。

| 卷 | 签页 | 内容 |
| --- | --- | --- |
| 己身 | 修为 · 法门 · 身体 · 行囊 | 境界与积累、斗气容量/质量；法门书架（主修、辅助、斗技、丹方、秘籍）与快捷栏；人形伤处图；物品格与器物位 |
| 人间 | 在场 · 旧识 · 家 · 约定 | 人物志（立绘、已知身份、上次见于、出处、往来记录、关系认识）；家庭与家用；约定与期限 |

| 山河 | 地区 · 大陆 | 地区总览图与已知场所、路线、耗时与补给、期限提醒；大陆图与未解锁区域 |

## 5. 各系统的体验设计

### 5.1 场景与行走（F02）

- 点地面即行走：点击可走格，人物沿路径走过去，`move` 结算。网格只在悬停或键盘移动时以淡金点阵显现，障碍格不可点。坐标输入框取消；键盘用户用方向键在场景内移动光标、Enter 行走（与 D14 和可达性要求一致）。
- 场所物件（`place.objects`）在画面上有铭签：柜台→交易，告示→江湖录·委托并触发公告发现，资源点→采集/调查。
- 选中人物（`focus`，零耗时）在Q版脚下加金色圈；选中不等于接近。人物卡的“接近”合并进相处情境：距离不足时主动作写作“走近说话 · 约一刻”，一键完成接近再开口。
- 地图人物超过上限时在在场条里写“此处还有 N 人”，不再显示调试式说明。

### 5.2 相处与对话（F03、F08）

对话是本作的核心体验，单独成为情境：

- 左：人物半身像（`portraitAsset`），下方铭牌写姓名、身份、此刻在做什么（`activity`）、可见体征（`signs`）。
- 右上：往来记录——本次以前从书信、事件中已知的与此人有关的条目（只取公开投影）。
- 右中：对话流。玩家说的话、NPC 回应（`reply` / 完成后的 `acknowledge` 结果）、旁白按说话人排版；等待回应时显示“苏晚禾在想……”与停止按钮，取代“听取回应”按钮——回应到达后自动呈现并确认。
- 右下：**可行之事**按语境分组，只显示 `actions` 允许且此人语境相关的项：
  - 常用：交谈（输入框）、询问近况（任务发现 talk）、看看货（有报价时）、赠礼（只列持有物）。
  - 情谊（折叠）：邀请同行、回应所需（有 `needItem` 时）、履约（有待履行约定时）、照护、表达心意、商议婚约、建立家庭、商议养育、结束共同生活、传授。按当前关系与家庭事实排序，无效项不显示而是在折叠页底写明“尚未到这一步”的原因。
  - 动手（折叠，炎赤）：切磋、发起交锋、看守。
- 草稿在离开对话后保留，并显示“写给苏晚禾的草稿”；回到场景若改对象，必须显式改绑（保持现有防误发规则）。

### 5.3 交易（F06）

- 报价 `quotes` 画成货架：物品图、名称、单价、店中存量；行囊在旁边。点物品放入“篮中”，加减数量，底部显示合计金币与落印“成交”。报价变化时在篮中条目上标“价已变，请重看”，不提交旧 quote。
- 出售、赠与、家用存取同一版式：左边来源、右边去处。

### 5.4 江湖录·委托与地方活动（C5，D39–D60）

- **委托**做成“办事簿”：左列已知机会（来源印：公告/交谈/亲历/来信；最后核实地点；追踪星标），右侧为选中条目的“契书”——委托人、条款、报酬、期限、已确认进度、可行操作。协商（报酬、期限、成果方案）只在点“议价”后出现，不常驻表单。
- “查看当地公告 / 读取当地悬赏 / 整理已送达邀约 / 留意当地情境”改为语境入口：告示物件（公告与悬赏）、书信签（整理来信）、在场景空处“四下看看”（witness），对话中“询问近况”（talk）。办事簿空时直接提示这些入口。
- 轻引导（D60）做成卷首一条可关闭的纸笺，不占表单位置。
- **拍卖**：拍品台（物品图、当前价、轮次、你的角色：竞买/寄售/代拍），出价用加价档（+1/+5/+10/自填）而非空白数字框；授权代拍时从在场人物像中点选委托人。**考核**：四阶段进度轴（材料处理→控火提炼→融合成丹→验收），每阶段显示材料、已耗、评分与可选操作。试炼与市井交流沿用同一“活动版面”骨架。
- 期限冲突提示（D57）在旅行/闭关的落印处显示，不再是确认框里的一段文字。

### 5.5 交锋（C6，D61–D80）

把战斗还给空间：

```text
┌ 第 3 轮 · 选择行动 ─────────── 敌：青鳞狼 ×2   我方：你、陆青 ┐
│                                                              │
│     场景 + 20×14 网格；两步内可达格淡金；斗技范围以炎赤描出    │
│     参战者小像：头顶血/气墨条（对手只显示可观察体况）         │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ [移动 ✓ 已选落点 6,8]  主要行动：[碎石掌 12气][疾风步][…书架] │
│ [防守] [调息] [服药] [救援] [撤离] [投降…] [停战…]   [落印·本轮] │
│ 同伴：[陆青像] → 短令：牵制所选 / 对所选施技 / 撤离            │
└──────────────────────────────────────────────────────────────┘
```

- 先选移动落点（点格；可跳过），再选主要行动与目标（点对手小像），最后“落印·本轮”。这是 D63“基础移动加一个主要行动”的直接画面。
- 快捷栏 `hotbar` 直接成为行动栏，完整斗技库从“书架”展开（D66）。需蓄势的斗技显示蓄势状态。
- 群体技悬停/选中时在网格上描出覆盖范围，并写出“范围内：陆青（同伴）”（D74 误伤）。
- 锁定后（collecting / resolving / cleanup）行动栏变为结算回放：日志逐条落下，`battleStep` 自动推进，“暂停”只停后续推进（与现行控制器相同）。
- 投降、停战、短令为行动栏上的二级面板，投降可附金币。
- 交锋结束进入“战后”：胜负与目标结果、伤势变化、可查验的遗留（尸身分页、查验、取用、继承）、看守，代替现行“现场遗留”面板。

### 5.6 己身：修为、法门、身体、行囊（F05、C4 身体）

- **修为**：大字境界名（`realm`）与积累进度（`xp/growthNeed`）；斗气以“容量、质量、恢复”三项分开表达（D69）；突破按钮只在 `actions` 含 `breakthrough` 时出现。不再出现“境界 3”。
- **法门**：书架式，主修/辅助/斗技/丹方/秘籍分格；每本书脊写品阶和掌握程度。已学与仅持有秘籍明显不同（后者书封未拆）。主修换修、辅助启停、研习、演练与快捷栏增删都在书的详情页，并标出耗时耗物（“一日 · 干粮一份 · 十五斗气”）。换修进行中在主修书上标“换修至 X，第几日完成”。
- **身体**：正背人形图，伤处以墨点标在对应部位（`part`），颜色与形状区分创伤/骨折/缺失/未确诊；点伤处看症状、诊断、是否处置，“求医”入口在此。能力限制列在人形旁（“左臂不能持握”）。
- **行囊**：物品格（物品图 + 数量），器物四位（兵刃、衣甲、工具、护符）显示耐久与余量，装备/卸下/维修在器物详情；可服用、可研习的物品直接带动作。
- 闭关、休养、做工、等候四种长行动不放在表单里，而是“修为”签页底部的“安排时日”：选活动、选天数（1/3/7/自定），落印后进入光阴流转。

### 5.7 人间：人物、家庭、约定（F08，D21、D31）

- 人物志：立绘网格，每人一张“名帖”——姓名、身份、在场/上次见于何时何地/已知离世（三种明确不同的样式）、出处印。点开为人物页：往来记录、关系认识（本人所知/听闻/存疑/已否定）、约定、寄信。私有好感不显示数值。
- 家：家庭成员像与关系线、住处、家用金币与干粮、子女与其出生来源；照护与家用存取在此。
- 约定：以期限排序的契约列表，到期与失约有朱印标记。

### 5.8 江湖录·见闻、书信、往事（F09、F11）

- 见闻：线索做成纸条，左上角出处印（传闻、原著记忆、机缘线索、交谈……）与获知时点；机缘有状态（线索所述/已取得/被夺）；“全文”在纸条翻面显示。
- 书信：信笺列表与读信版式；寄信从人物页或这里写，邮资在落印处写明。
- 往事：已知事件按时间排列，详情分页沿用 `event` 绑定。
- 行程：最近一次行动的分步结果（`result.steps`）与当地生产（`workshops`）。

### 5.9 山河与旅行（F04）

- 地区签：地区总览图（现有乌坦城、黑岩城、石漠城、塔戈尔总览）上标出已知场所；点场所显示描述、路线、耗时、所需干粮、期限提醒，落印“启程”。没有直达路线时写“需先经 X”，并提供“先去 X”。
- 大陆签：大陆图与六大分区；未解锁区域写“尚未踏足”，不可点。
- 设施间的移动（同城）与跨地区旅行在玩家眼里是同一件事：都从山河或地区总览发起，区别只在耗时。

### 5.10 光阴流转（长行动、F11）

- 旅行、闭关、做工、等候、休养、研习、换修进入此情境。画面：场景淡出为水墨长卷，中央时辰盘快转，下方“预计至第五日辰时”；自动续行（现有 autoAdvance）推进时，每次结算的事件以纸条落下（亲见、来信、传闻）。
- “停手”立即排队停止（现有 stopAdvance）；被事件打断时停在该纸条，给出“继续上路 / 先处理此事”。
- 结束页：耗时、消耗、所得、身体变化、收到的消息，一页总结后回到场景。

### 5.11 开局（F01）

保持“入世”一屏：地区总览为底，左侧一卷“生平”：姓名、出身（四张带插图的出身卡，写清起点、钱粮、境界）、来处（本土 / 穿越者）、性别。落印“入世”。绑定与初始化的等待显示为“世界正在苏醒……”，不出现绑定编号。

### 5.12 歇息菜单、存档与异常（F10、F12）

- Esc 唤出“歇息”：存档（命册：存档列表、为此刻题名、读档）、字号、宿主（停止表达、重新载入、恢复、退出）。读档确认写明“整个世界回到那时”。
- 死亡：画面褪为墨色，“此身已逝”，直接给出命册入口。
- 异常文案改为游戏语言，并就近显示：“此事尚无定论，稍候再看”（结果未确认）、“情势已变，请重新斟酌”（revision 过期）、“世界已换了一条时间线”（epoch 过期）。“核对原提交”保留为异常提示里的按钮“看看结果”，平时不出现。

## 6. 视觉语言

### 6.1 材质与色彩

美术是暖金调手绘与宣纸底立绘，界面改为“墨框纸卷”：深色只做外框与夜色，资料内容上纸。

| 名称 | 值 | 用途 |
| --- | --- | --- |
| 玄青 | `#172A30` | 外框、场景上的浮层底、夜色（沿用） |
| 宣纸 | `#E8DDC4` | 卷与名帖、信笺、契书的纸面 |
| 墨 | `#2A2824` | 纸面正文 |
| 古金 | `#CBA568` | 选中、时辰盘、铭牌边 |
| 朱砂 | `#A8322A` | 印：落印按钮、承诺与重大结果、出处印 |
| 炎赤 | `#E77C55` | 斗气、危险、交锋（沿用） |

辅色：雾青 `#B5C9C8`（墨框上的次要字）、纸面次要字 `#6B5E4A`。纸面与墨字对比约 11:1；场景上的浮层文字一律有实底。

### 6.2 印

- 落印按钮：朱砂方印形，按下时有一次 120ms 的压印缩放；印文是动作本身（“启程”“成交”“行事”“本轮”），旁注耗时。
- 出处印：小方印标在信息条目角上——亲、闻、信、忆、旧。
- 状态印：约定“已履”“失约”，委托“已结”。
- 只有落印按钮使用实心朱砂；其他按钮是墨框或纸面上的线框，保证全屏同时最多一个朱印主动作。

### 6.3 字体与排版

不分发字体。宋体（Noto Serif SC → Source Han Serif → Songti → SimSun）用于地名、人名、卷名、境界；黑体用于正文与操作。纸面正文 16px / 1.7，对话 17px，行宽 36–42 字。数字使用 `tabular-nums`。不用全大写标签、不用点号串联元信息，元信息分行或用印。

### 6.4 图标

一套自绘 SVG 线性图标（1.5px，圆头），约 24 个：四卷、时辰、气血、斗气、金币、干粮、行走、交谈、交易、赠礼、交锋、调息、防守、撤离、书信、告示、星标、印、存档、停手。全部放在一个 `defs` 中按 `use` 引用，不用表情符号或字体图标。

### 6.5 动效

- 只有三个“有意的时刻”：落印、时辰盘转动、卷展开（220ms，transform）。其余选中、悬停即时。
- 光阴流转的纸条落下使用 opacity + translateY，`prefers-reduced-motion` 下改为直接出现。
- 不做持续粒子、呼吸边框和背景漂移（沿用 guidelines §9）。

## 7. 交互规则

- **确认分级**：零耗时（选中、查看、翻页、快捷栏）无确认；短时普通动作（交谈、接近、采集、调查、买卖小额）落印即提交，结果可在“最近之事”回看；重大动作（旅行与长行动带期限冲突、发起交锋、婚约/成家/分离、投降、读档、退出）在落印处展开一次“此事当真？”二次印，写明后果。
- **返回栈**：Esc 依次关闭：二级面板 → 情境 → 卷 → 回到地区总览；从不一次关多层。关闭后焦点回到触发处（沿用）。
- **文字行事**：Enter 换行、Ctrl/Cmd+Enter 落印（沿用现有防 IME 误发），对象标签常驻；对话情境中对象自动为该人。
- **键盘**：C/R/J/M 开卷，Esc 歇息，方向键场景光标；输入框聚焦时不触发。
- **等待**：提交后落印处变为“行事中”，其他查看照常；表达生成中在对话里显示，停止表达在对话和歇息菜单中。

## 9. Native 实现架构

- **组件拆分**：现行单一 `Main` 组件的状态已逼近 128 顶层属性上限（`questUi` 是为此打的补丁）。改为一个 `Game` 根组件加按情境/卷拆分的子组件（Scene、Talk、Trade、Battle、Passage、Self、People、Journal、Atlas、Rest），各自声明状态；根控制器仍独占读取、串行写入、CAS、epoch 与草稿（`main.js` 的这些部分保持语义不变，只拆渲染）。需先用 compiler 验证多组件与子组件 props 通道；若受限，退路是单组件内按情境分组的嵌套状态对象。
- **渲染层**：`scene.js`/`panels.js` 的“screen → 行卡”替换为每个情境/卷的投影函数，输出结构化视图模型（书架、人形伤处、货架、契书、战场格），而非通用 row。
- **战场与行走**：沿用 20×14 网格按钮作为命中层（已能通过编译），默认透明；两步可达格由前端根据 `PLACES[].blocks` 做显示提示，结算以规则为准。
- **图形**：场景图仍用 `media`；纸纹、印框用 CSS（不引入纹理大图）；图标用内联 SVG `use`。
- **样式**：`theme.css` 重写为 token 层 + 组件层；去掉按尺寸累积的覆盖式媒体查询，改用容器查询按场景区域尺寸适配。
- **不变**：Bridge 绑定、动作参数、自动续行/停止、恢复后重挂载、草稿防误发、IME 规则、素材交付流程。

**补记（实现时确认的 Native 约束）**：编译器把整份组件状态 schema 限制在 256 个节点（旧前端已用 233），绑定只接受 media/text/prose/value/checked/disabled/hidden/class/title/aria-label/aria-current/data-value，脚本禁止 `self` 等标识符，CSS `url(resource:…)` 会在启动时整批加载并常驻。据此：可见性改由单个 stage class 串控制，互斥层共用 `rowsA–D` 通用列表（统一 10 字段行），人像与物品图继续用 `media` 绑定。

## 11. 需要用户确认的决定

1. **视觉材质**：由“冷玄青面板”改为“墨框纸卷 + 朱印”，玄青保留为外框与夜色。
2. **主画面结构**：底部六页签改为右缘四卷签（己身、人间、江湖录、山河），委托与活动并入江湖录与地方活动情境。
3. **情境化**：相处、交易、交锋、光阴流转、地方活动成为占据场景的情境，而非抽屉面板。
4. **交锋改为网格点选**，取消坐标输入。
5. **确认分级**：去掉普通动作的确认框，只对重大动作二次落印。
6. **实施方式**：按 R1–R6 分阶段在 `package` 工作区直接替换现行前端，每阶段一版构建。
