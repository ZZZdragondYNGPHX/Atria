# 任务内容编制与丰富度

状态：2026-10-23，`0.1.0-quests.2` 自然流程修正与补验已完成归档；`quests.1` 为上一轮实现基线。沿用 v0.34 与 D33、D39–D60，QC01–QC27 已编入统一任务池并接入真实规则、工时与结算；QC28–QC30 保留 D33 依赖，不投放。六组人物故事均有作者材料与对应操作，公开募集使用真实人物需求与有限托管预算。下文同一 QC 主表记录实际承载；剧情延展仍按真实条件出现，不把所有候选后续视为已发生故事。具体范围见 [decisions.md](decisions.md)，系统与活动细则分别见 [quest-system.md](quest-system.md)、[quest-activities.md](quest-activities.md)。参数属于工程实现值，不追加为用户确认要求；真实宿主、前端与模型验证范围以 [Record](../../../records/package/doupo-living-world.md) 为准。

## 职责与能力边界

本文只负责内容编制、机制差异、丰富度目标与作者示例。任务领域的身份、条件、履约证据、投放和长期后果统一见 [quest-system.md](quest-system.md)；混合 AI 的提案与规则接纳也以该模块为准，不由本文另立协议。通用池目录、注册、就绪资格、抽样、重复控制与保存恢复仍唯一归 [content-pools.md](content-pools.md)。本文提出用于衡量任务体验的内容标签和样本，不复制通用池算法。

固定活动的竞价、资金与物品、考核及活动运行等领域细则唯一归 [quest-activities.md](quest-activities.md)。本文给出故事与活动作者选题、关联任务和内容依赖；活动内的通用承接/清算仍引用任务系统，不复制两者的详细规则。下文作者候选仍保留扩展方向，当前实际操作以 QC 主表的实现列和实际契约为准；D33 储备不进入可玩池。

编制基线为六地区、三十二场所、四十八位作者 NPC 与既有动态居民；实际数目及来源见 [content-expansion.md](content-expansion.md)。任务层复用已有买卖、赠予、工作、旅行/同行、调查/线索、采集、基础炼药、治疗、维修、人物活动、信息与关系。任务实例保存条款、托付和证据，实际库存、伤势、器物、活动和时间仍归原权威。

以下边界适用于所有示例：

- D33 的完整玩家战斗后续独立实施。已有简单交锋不能承诺潜行处决、目标部位打击、多敌协同、完整护送战、战术竞技或复杂魔兽 AI 已可用；依赖这些能力的内容保留为储备。
- 本次新增拍卖、四阶段考核、非完整战斗试炼与市井交流规则；具体角色、操作和验证归固定活动模块。飞行候场不因此获得未实现的飞行购票能力。
- 药材鉴定、品质分级、配方替代、批次保质、伪造/盗取、信贷、劳动合同、营地工程、动态封路等若进入任务，必须先补对应底层能力。模型描述不能代替新增规则或凭空改变库存、伤势、关系和道路。
- 小说姓名、身份和已发生关系沿用包内来源；本文涉及这些人物的新情节均标为原创候选。不会预设萧炎未来机缘、人物固定死亡、异火归属、宗门结局或其他原著未来一定发生。

## 六来源与动作结构矩阵

来源描述任务因何出现；动作结构描述玩家实际做什么，两者可以交叉。一件缺药事件可以同时关联普通人物求助和地区随机事件，但不能重复发布两份奖励或把它计作两个独立内容种子。具体身份与归并以任务系统模块为准。

| 来源 | 资源取得/配送 | 调查/信息核实 | 制作/修复 | 照护/救援 | 交涉/取舍 | 探索/路线 | 对抗/竞赛 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 日常与职业委托 | 药铺补料、商队当班配给 | 核货、查找漏记订单 | 基础制药、现有器物维修 | 帮医者补齐本次接诊条件 | 协商交付时段和报酬 | 核实本次行程的补给条件 | 有能力基础后再开放定期巡护/演练，不将普通短工默认改成战斗 |
| 人物情境任务 | 居民缺粮、失物归还 | 查找消息来源、确认亲人最后所见 | 修复其实际损坏器物 | 临时照护、求医接送 | 家庭借物、债务与邻里矛盾 | 陪伴迁居或寻找安全返程 | 真实受威胁者求援；完整玩家冲突依 D33 |
| 随机事件任务链 | 真实货损引起急缺 | 现场异常、失联线索 | 事故后处理 | 途中伤者、失散者 | 多方争用补给 | 查明险路、选择绕行 | 真实冲突的介入或逃离；不每次旅行必刷战斗 |
| 固定人物专属任务 | 与其个人目标相关的特定取得 | 秘密、误会与过去承诺 | 围绕手艺/成长的专属工作 | 关系中的实际照护 | 信任、利益与原则冲突 | 共同寻访且不预写结果 | 角色立场冲突可有非战斗路径；战斗分支依 D33 |
| 固定活动任务 | 活动筹备物资 | 报名信息、规则和资格核验 | 活动用品维护 | 活动期间医疗支持 | 名额、担保和交易取舍 | 场地勘察、赴约规划 | 演武/考核/拍卖等各自有新机制依赖，不能因活动名称直接开放 |
| 探索与玩家主动目标 | 自定采购、资源或藏书目标 | 自行调查传闻、人物和旧线索 | 自定修复与制作目标 | 主动救助、照护自己选定的人 | 主动提出交换或解决矛盾 | 寻访已获知地点、规划路线 | 自定挑战依真实可执行能力；禁止把未知目标位置全知公开 |

同一动作不能机械铺满六行。职业委托强调有限报酬与日常循环，人物情境强调这个人的当下困境，专属任务强调无法任意换人的经历，活动强调共同时间与规则，探索目标强调玩家自己选择动机。随机事件是世界情况进入玩家感知的机会，不是无因生成奖品的入口。

### 发现渠道与可知材料

D58确认附近已知机会汇总。作者为各类内容准备实际获知渠道、来源和可核实范围，不把整个内容池直接展示给玩家；汇总、时点、陈旧/矛盾与手动追踪的详细规则唯一见 [quest-system.md](quest-system.md)。以下仅为已有种子的发现编制示例，不另计数量：

| 渠道 | 既有内容的入口候选 | 应准备的可知材料 |
| --- | --- | --- |
| 公告 | QC01/19的补料或有限订单、活动报名/筹备工作 | 实际发布者、公告内容与地点、发布时间及获知/核实来源；公告公开不代表玩家已读取，机构发布不自动增加担保 |
| 来信 | QC03的送达需求、既有合作中的下一次邀约 | 实际发件者、发出与收到时点、信中所指的地点和条件；收到旧邀约不保证对方仍在原地或已重新订约 |
| 交谈 | QC04/05的说法核实、六组人物故事的有限起始工作 | 说话者、其可表达的需求/说法和已获线索，未透露的秘密仍保留；不因专属人物姓名显示全部后续目标 |
| 亲历/主动调查 | QC12的实际救援情境、QC16/24的观察与见证 | 可感知事件、现场观察/调查结果及来源时点；事件是否发生由真实世界决定，不因打开机会汇总必定触发 |

同一内容可由多渠道获知，作者将各条说法指向同一真实问题及任务引用；渠道不同不复制成果或奖励。普通短单、人物线和随机事件都需能说明玩家如何进入视野，暂未发现时不泄露隐藏数量或剧情标题。D59已确认QC01–QC27全部为首批可玩目标，但各条仍依真实世界、本人所知与可执行资格出现，不要求所有开局或同一时刻同时投放27种。

本次来信入口已接入 `quest-discovery.js` 和既有真实信件调度：已完成合作的可重复种子，在作者人物当前仍有需求、知道玩家通讯地址且有邮资时，可实际寄出下一次邀约；每位发件人七日节流，沿原有 16 封信件容量与实际旅途送达。只有发给玩家、已经送达且存在签收依据的规则邀约，才能经“读取已送达来信”进入已知任务。普通自由文字信件即使写出类似 JSON 也不产生合同。收到的是寄信时提议及旧地点；发件人随后迁移、死亡或需求改变不会偷偷更新信中文字，承接仍须实际联系并重检当下条件。此实现先覆盖既有合作邀约，不把任意未认识人物线自动投送给玩家。

### 开局轻引导的内容编制

D60确认可跳过的开局轻引导。按出身、所在地、已有能力和当时可成立的机会，准备最初交谈、读公告或亲历发现的少量短入口；玩家可以不接、换选或直接探索，详细跳过/履约/恢复规则唯一归 [quest-system.md](quest-system.md)。具体引导样本与数量仍拟定，不新增首批种子数。

候选内容可从附近能完成的物资准备、信息核实、有限加工/维修等不同玩法中选择，例如条件允许时复用QC01、QC04、QC07/08；不要求每局相同，也不把尚未掌握的炼药能力或未核实的远方地点预先开放。每个入口提供真实动因、可知条款、可执行选择和独立结束点，沿该种子的正式结算与后果编制，不用额外大奖或强制长链诱导接单。

引导介绍可以结束，相关人物与世界仍继续活动；被跳过的机会按实际条件保留、被他人解决或改变。其余人物线、随机事件与活动由合法发现和世界条件逐步接入，不能为了“完成教学”提前公开全部27个首批目标或把活人固定在原地等待玩家。

## 委托性质与内容标注

来源与动作之外，作者还要明确任务是否有偿、是否属于公开悬赏/机缘竞争，以及玩家是在承接一份工作还是自行追求目标。普通有偿委托按已确认的接单后独占口径编制；公开悬赏按任务标明单一有效成果或可拆贡献等具体条款。D52 允许普通委托协商报酬、期限与替代成果，由 NPC 根据实际条件接受或拒绝；公开悬赏维持公告条款。D54–D55 下的付款保障、信用风险和代交条件也要进入内容条目，不能看到机构名就默认全额保底。独占、竞争、协商、付款保障、代交、长期合作、多单安排、退出清算、协助/转包与提示追踪的唯一规则源为 [quest-system.md](quest-system.md)，对应决定见 [decisions.md](decisions.md) 的 D42–D47、D52–D57；本文只编制例子，不另定补偿范围、估值、贡献权重、同刻合格提交优先序、信用数值、分成、助手退出责任或同意形式。

以下是 30 个种子的**拟定编制属性**，不是新增一套任务类型。属性应在实际作者条目中明确，不能看到他人抢先的情节才临时将普通有偿短单改成公开竞争。

| 种子 | 拟定内容属性 | 编制要点 |
| --- | --- | --- |
| QC01、QC03、QC04、QC07–QC09、QC16、QC19、QC22–QC24、QC27 | 普通有偿短单候选 | 接单后的困难来自实际物资、工时、证据、行程或合作条件；不安排第二承接者用同一单的先交先得抢走报酬。 |
| QC02、QC05、QC06、QC10–QC15、QC17、QC25 | 人物情境/互助候选；有偿版本归普通委托 | 多人同时有困难不等于多人承接同一有偿工作。借物、互惠或无偿帮忙应说明自身关系；形成有偿版本时采用已确认独占口径。 |
| QC18 | 探索与玩家主动目标 | 当前例子没有委托人或预先工资；自行发现的线索与资源仍在共同世界中，不因玩家记录目标而保留。 |
| QC20、QC21 | 固定活动及其子任务 | 活动可以有多名参与者，各人的普通有偿筹备工作与公开竞赛机会分别标明；多人参加活动不自动把每份工作变为竞单。 |
| QC26 | 公开机缘争夺候选 | 明示多人竞争属性；竞争者、物品与先后结果都来自实际世界，不用此例说明普通有偿短单的接单关系。若另写公开悬赏版本，发布时即标明其性质与规则。 |
| QC28–QC30 | D33 储备，按将来具体内容分别标注 | 受雇护人、主动援助、公开悬赏与演武参赛的参与性质分别编制，不因有战斗或多名角色就一概视为公开抢单；底层未就绪时不投放。 |

独占工作不会冻结其涉及的物理世界。NPC 仍可能自行解决需求、目标可能迁移、物资也可能发生真实变化；作者需要让这类变化进入任务系统的复评与收尾，不能安排“另一人交了同一普通付费单，所以已完成的工作作废”。涉及委托人主动撤单的候选，应提供可引用的已做工作、实际投入和已付记录，补偿处理只引用任务系统。未付事项不应被作者的“故事结束”文案遮住。

以下是与现有种子关联的**拟定变体和收尾情境**，不额外计为新种子，也不将普通有偿版本自动改成公开悬赏。内容条目须说明具体成果/贡献对象和可产生的事实；履行、退还、责任与结算仍调用任务系统的同一规则。

| 关联种子与拟定变体 | 作者需编清的区别 | 证据与退出情境 |
| --- | --- | --- |
| QC26：公开悬赏寻回一份指定札记 | 单一目标版本围绕一份可核实成果编制，报酬对应提交有效成果者；不写成任意探索行为都分到同一奖金。自主机缘版本若无出资人与悬赏，不产生预设报酬。 | 指定实物/合法来源、提交有效性与领取依据需有规则承载；同刻多人合格的优先序继续拟定，不由故事一句“先到”决定。 |
| QC02：公开募集普通药草的变体 | 可拆目标版本声明可以分别交付的真实缺口，按有效贡献结算；它与原先两位居民各自的普通求助分开编制。 | 每次实际收到的物资、贡献者、已计部分和剩余目标可追溯；重复提交同一批材料不增加贡献或总报酬。具体折算与权重留任务规则后续细化。 |
| QC16：分段路况勘察的公开版本 | 可拆目标对应具体已走路段的近期观察，部分报告可以独立成立；不是每位参与者都复制一份全程奖金。 | 报告覆盖范围、时点和可核实来源需有承载；重叠报告怎样认可和折算为后续规则候选，不预设平均分配。 |
| QC03、QC07、QC19：有托付财物的普通短单 | 主动放弃分支要显示未使用包裹/材料/资金的实际去向和归还过程；已交成果、已耗投入与剩余财物分别编制。 | 保留托付、使用和归还凭据，以及仍待处理的损失/责任；不能写成点“放弃”就销毁包裹或自动抹账。 |
| QC08、QC09、QC17：能力或条件改变后的放弃 | 可因诚实发现能力不足而停止，也可因身体失能、路线或供应真实变化无法继续；与故意占单、挪用财物等恶意行为区分。 | 原因与责任依据只能来自实际行为和合法所知，是否恶意不能由一次失败反推；赔偿、信用及尚未结清事项按任务系统处理，不设固定扣分。 |

### 协商与信息差的内容示例

D52–D53 确认方向，以下仅在已有种子中准备可适配的情境，不额外计数。普通委托的协商应体现真实预算、急迫程度、所需成果与双方能力，NPC 可以拒绝；不让每单都必须讨价还价。少量误报、隐瞒或灰色安排必须有已存在的动机、事实和知识差依据，不能为了反转把接单前的真实历史改写。误报可能来自误会或过时消息，保密也不自动等于欺诈；默认日常仍应保留可直接履约的清楚工作。

| 关联内容与拟定情境 | 作者需准备的取舍与材料 | 边界与后续 |
| --- | --- | --- |
| QC01/07：当班缺料但预算有限 | 玩家可提出不同报酬、交付期限或可执行的替代成果；作者写清药工当次实际缺口、预算和延后代价，允许接受、拒绝或维持原条件。 | 替代成果必须经同意且有真实效用，不能等同于任意替换配方或凭旁白完成炼药；谈成与否及既有义务按任务系统记录。 |
| QC08/16：有限维修或路段报告 | 准备“先修关键器物、其余另约”或“先核实某段、其余暂不承诺”等可谈方案，体现行程压力和有效成果的实际差别。 | 普通委托可以协商；若是已公告的公开悬赏，不将玩家私下建议写成全体自动改条款，也不把未完成部分标为已交付。 |
| QC04/05、谷茗作者包：说法与可查事实不符 | 分开编制当事人的实际经历、其当时获知内容和对外说法；准备核实、回报暂不能证实、拒绝继续或在有依据时揭发等路线。 | 不能因玩家起疑才生成幕后罪行；各方后续反应取决于实际收到的证据与说法，不全城同步知道真相。 |
| QC03/19、雅妃作者包：被省略的交易条件 | 少量适配情境可围绕真实货源或对他方的既有承诺发生隐瞒，让玩家决定查证、要求澄清、拒绝、揭发或改变合作立场；不预设委托人必然恶意。 | 揭发不自动保证得到相信，改立场不自动解除旧义务；托付财物、未付报酬与实际损失继续按任务系统处理，灰色标签不直接赋予全局信用或阵营判决。 |

## 按玩法区分的短任务种子

下列 `QC01`–`QC27` 已作为统一 `quests.templates` 池的稳定条目 ID，运行时操作位于 `source/rules/quest-operations.js`；`QC28`–`QC30` 仅在 `QUEST_RESERVES` 保存依赖。**标题与情节是游戏原创编制；实际能力见末列，前两列仍保留可继续扩展的作者取舍**，范围确认不等于冻结文案与参数。每项列出与相邻种子的决策差异；换人、换物、换地区、增加交付数量或换一段叙事不另计独立种子。可重复变体只能引用真实已存在、允许使用的对象；所列“待补”能力完成并接入前不能标记就绪。

所有首批种子共用已实现的任务层；末列区分本次可执行动作、真实前提与仍未实现的作者扩展，不以旁白补齐缺失操作。

| 索引与主动作 | 短任务种子、真实动因和决策差异 | 可选结果/后续影响候选 | 实际操作与投放边界（quests.1） |
| --- | --- | --- | --- |
| QC01 取得 | **缺一份的当班**：药工已有一炉真实投入需求但欠普通药草；玩家在就近购买、自有物资交付、去采集之间选择。核心是获取成本与工时。 | 当次生产得以继续，或药工改排工作；不能保证必有存货。 | 已实现按实际药草缺口交付、部分交付与比例报酬，材料实扣并归药工；购买/采集沿原动作，不替代配方。 |
| QC02 分配 | **两处同时缺药**：两个可接诊处争用有限的现成药草，玩家只能承担一部分。核心是有限资源分配，不是加倍收集数量。 | 两方各得部分、优先一方、寻找新增供应；留下真实缺口与可知评价。 | 已实现宁素优先或宁素/唐汀分段分配，前段交付不抹除另一方缺口；另有真实 needitem/needqty 的公开单份成果与按量贡献变体，实际托管且 NPC 可用真实库存竞争。 |

## 短任务偶发成长链的原创示例

短任务应有自身可交付的结果；后续链由尚未解决的真实原因和人物选择产生。下面的箭头表示可能的关联，不表示必然接续。链的出现、发现、停顿、结束与长期后果沿用任务系统，不在本文复制生命周期。

| 原创候选 | 第一次可以独立结束的短事 | 满足真实条件后才可能出现的后续 | 关键分歧与依赖 |
| --- | --- | --- | --- |
| **药柜空了一格** | 为一次当班实际缺口找到普通药草，或说明无法取得。 | 若短缺确实继续，药工请求核实采购/采收情况；若原因是生境耗竭，再协调替代来源或生产安排；若只是一次晚到则到此为止。 | 不预写幕后坏人。路线、生态、账目各有可查证据；后续可能改善生产，也可能因预算继续短缺。依 QC01/04/25 的实际能力。 |
| **借来的护具** | 取回或经双方同意延长一件真实借物。 | 若器物归还时有实际损耗，双方决定维修或补偿；未解决争议可能影响之后合作；若完好归还则没有硬接第三幕。 | 借物者可能因家计困难而请求代工偿还，但须真实有工作、愿意接受且拥有所需能力。依 QC08/13/15/27。 |
| **一封没到的家书** | 送达获准口信，或确认收件人尚未获知。 | 若收到有来源的失联证据，才可能安排查访；若只是迁居，则协商转送；若亲人不愿联系，尊重其边界并结束。 | 不能自动告知远方生死，不让玩家一句“继续查”生成必有绑架案。依 QC06/16/22 的信息、许可与行动接线。 |
| **留给下一次的药谷** | 降低一次采收量并说明当前缺口。 | 若其他人也受短缺影响，可能形成真实的采收协调；执行后观察生态和生计结果；新供给出现时协调可以自然失去必要性。 | 不强制玩家成立组织、永久维护地区；未实现的采收协议先储备。依 QC02/25 和组织授权、真实生产能力。 |

这些链不按“完成三次同名日常必解锁”排列。可复用职业活动积累的是人物交往和世界条件；专属故事是否出现由明确作者条件与当前世界共同决定，不承诺每个普通委托背后都藏一条长篇秘密。

### 短单转长期合作与多单安排

D56 的定期供货/固定服务属于职业周期合作，与上文因真实问题延续的剧情长链分别编制。重复短单不会自动变成长约；双方同意后的合作周期按已同意条款履行和分期验收结算，不另加每期必须重新批准的步骤。D57 允许多单并行、顺路交付；以下仅复用现有种子，具体合作、暂停/终止清算和冲突提示统一见 [quest-system.md](quest-system.md)。

## 固定人物与固定活动的作者工作包

重点故事以作者编制的关键情节、动机和有效分歧为骨架，AI 可在合法已知事实内表达与编排，不现场补写一段必须生效的新史实。一个可实施的作者包至少包含以下内容：

| 作者交付物 | 需要回答的问题 |
| --- | --- |
| 来源与原创声明 | 哪些姓名、身份、关系来自小说；哪些当前状态是游戏假定；哪些故事全为原创候选？ |
| 不可任意换人的动机 | 为什么是此人提出、此人现在愿付出什么、最不能接受什么？泛职业需求应留在通用内容。 |
| 当前世界适配 | 所需人物是否活着、可达、知情且有意愿；资源是否存在；其既有经历已改变时如何承认？ |
| 协商与信息差材料 | 普通委托有哪些能实际接受或拒绝的报酬、期限和替代成果；公开悬赏哪些内容按公告固定？少量误报/隐瞒/灰色分支中的实际事实、动机、各方所知与对外说法分别有何依据，哪些线索可被核实？改立场后仍有哪些未结义务与财物需处理？具体生效和清算仍链接任务系统。 |
| 付款与异地交接材料 | 付款人为谁，接单前有哪些可知托管、担保或私人信用依据；缺资/拒付时有哪些已做、已付及未付证据？条款是否允许异地代交，实际执行目标者、运输者、收件/验收者各是谁，运输时间/费用/风险和可获知回执如何表达？托管清算、欠款/追偿与责任细则统一引用任务系统。 |
| 合作周期与并行安排 | 哪些短单可能在双方同意后转为定期供货/固定服务，哪些只是剧情续篇；合作周期内的分期成果、验收/结算及暂停/终止时已发生义务如何表达？多单有哪些真实顺路空间、资源冲突和本人已知期限，长途/闭关前可以向玩家提示什么？不另加每期审批，具体规则链接任务系统。 |
| 委托性质与收尾材料 | 哪些段落属于普通有偿工作、公开竞争、互助或主动目标；公开悬赏对应单一有效成果还是可拆贡献；撤单/主动放弃时，已做工作、实际投入、未用托付财物、归还、损失责任与已付事项有哪些证据？处理规则链接任务系统，不在作者包自定赔付、权重或信用扣分。 |
| 助手与承接关系 | 哪些工作可由愿意且有能力/时间的 NPC 协助，实际占用、物资和报酬从何而来；原承接人负责什么；若整单转包，委托人同意与角色/成果交接需要哪些证据？具体分成、助手退出责任及同意形式按任务系统后续细化。 |
| 场景与行动图 | 玩家能亲见/得知什么，可采取哪些有规则承载的行动；每条路径的实际代价与能力依赖是什么？ |
| 条款、进度与追踪材料 | 正式单的目标/报酬/期限/已确认进度从何生成；调查探索有哪些已知线索、最后核实位置和来源时点，哪些内容仍未知；手动追踪需要哪些合法材料？不在作者包发明实时全知标记或固定 UI 布局/数量。 |
| 选择与可辨认后果 | 选择前能理解的区别是什么，之后能通过什么合法经历辨认影响；不只换奖励数额或末句台词。 |
| 历史变体与不能成立的情况 | 人物迁居、死亡、拒绝、物资被他人取得、玩家提前完成相关行为时，故事哪些段落仍成立？缺少核心人物不默认抓另一个同职业者替补。 |
| 短任务联系 | 哪些职业/情境种子可以自然关联，哪些关键情节必须手写；不把长链接续概率藏在文案中。 |
| 依赖与实际就绪说明 | 要新增哪些底层动作、素材与公开表达；未就绪分支明确储备，作者故事完成不等于游戏可玩。 |

内容作者为任务标注主动作、决策结构、障碍、解法、参与者关系、场所拓扑、结果类型和叙事主题，用于比较体验。**模板 ID 不同不代表体验不同。** 例如“向甲买药交给乙”与“向丙买矿交给丁”若没有新的预算、资格、时效或取舍，归为同一种体验；“药已经被别人取得，核实后决定告知还是与持有人谈交换”则有不同的事实与决策。

后续验证应同时看三类材料：

1. **内容覆盖表**：有效候选数与上述标签分布、依赖未就绪数、各真实地区/身份下可成立的选择数量。全目录丰富而当前玩家长期只合格两种内容，需要继续调整内容条件与底层覆盖。
2. **实际接触序列**：记录玩家被告知、选择、拒绝和完成的任务体验签名及原因，区分“没投放其他类型”和“玩家主动偏好同一类型”。候选采样可比较连续 10–15 次接触中出现的不同主玩法、最长同结构连续段和最近一次相似体验的间隔；具体阈值留待实测，不预设为冻结参数。
3. **贯通体验样本**：分别以新建本地居民、采药/商旅相关身份、跨地区长期角色和恢复后的分支执行实际流程，检查是否能说明委托动因、解法差别与后续影响。仅离线抽样均匀、叙事新颖或静态目录检查不算真实体验丰富度证据。

重复原因要能区分：资格后仅剩少数内容、世界真实短缺导致需求相似、作者结构不足、投放节奏偏斜、玩家主动选择，以及已经结束的故事被错误重放。前两者不能通过随机生成不真实事件“修好”；应补充符合当下世界的结构，必要时允许暂时没有新委托。抽样与近期重复控制的实现继续归通用池，任务专属编排与长期结果归任务系统。

验收由执行者在实际实现时完成必要自查和相关验证；本文不建立独立审查、额外阶段批准或未完成工作的交接流程。本次已经正式实施；执行者继续以实际源码、必要自查与验证推进，完成证据和剩余限制记录于同一 Record。
