# 人物身体、伤势与行动能力

状态：2026-10-22 候选实施设计。本模块把“重伤、断腿、失去手臂”等创意落实为必须具备的状态、合法写入、行动影响、个人观察、表现与恢复路径；不声明这些机制已经实现。具体部位、伤病种类、数值、治疗条目和接口仍为候选，不能仅因旁白出现伤名就视为已完成规则。

## 唯一职责与范围

本模块是人物身体、伤病持续状态及能力影响的唯一详细设计。NPC 与玩家共享身体语义；NPC 后台冲突如何产生结果归 [npc-progression-conflict.md](npc-progression-conflict.md)，人物如何据此改策归 [npc-agency.md](npc-agency.md)，时间与临界事件归 [world-simulation.md](world-simulation.md)。

治疗供应、费用与照护分工使用 [world-systems.md](world-systems.md)，个人所知与关系反应使用 [social-graphs.md](social-graphs.md)。本模块不另造医疗经济、关系或时钟，也不把受伤自动等同于绑架成功、终身失能或必然复仇。

依据 D33，完整玩家战斗仍留待未来较大修改。当前可让玩家共享身体状态与查看能力，后台 NPC 冲突可依法写入部位伤势；不借本模块提前重做玩家战斗输入、公式或界面流程，不自动代玩家决定治疗、报复或赴约。

以下均为抽象游戏状态，不追求完整解剖或现实医疗模拟，不提供现实操作方法或医学建议。

## 有限粗粒度的身体部位

| 候选部位 | 对活动的主要关联 |
| --- | --- |
| 头部 | 意识、观察与沟通等条件；不进一步建立眼球、神经等完整解剖模型 |
| 躯干 | 全身承受、持续消耗与重要身体状态的粗粒度承载 |
| 左臂、右臂 | 持握、器物使用与需要相应手臂的施技、工作和照护 |
| 左腿、右腿 | 站立、移动、负重、逃离和需要相应下肢条件的活动 |
| 全身 | 疲惫、一般伤病、饥饿相关损害及暂不适合指定部位的效果 |

臂包含本轮需要的手部能力，腿包含相应足部能力；暂不细分每根手指、骨骼和器官。只有新玩法确需更细条件时才扩展，避免每句描写都新增一套身体结构。

部位完整性与当前伤病分开：完整、受损、缺失等候选状态回答“这个部位是否仍存在且具备结构条件”；疼痛、骨折、创伤等实例回答“发生了什么、目前怎样”。同一部位可以带多个有来源的伤病。

“断腿”必须消歧：腿仍存在但骨折，与腿部缺失不是同一状态。“断臂”也须区分骨折、暂时不能使用和实际缺失；未有明确合法结果时，叙事不得自行选择最严重解释。

总生命、斗气和伤势摘要可用于概览，但不是部位完整性的替代。补满生命、减少通用伤势或恢复斗气不会自动恢复缺失部位，亦不会自动证明一个骨折已经愈合。

如实际版本范围明确支持旧档，兼容方式须依据该版本已保存的事实确定；旧档只有总伤势时，无证据不得补造骨折、失明或肢体缺失。支持范围与处理方式在实际实现和验证后说明，本模块不自动承诺跨版本兼容。

## 有来源的伤病实例

| 概念职责 | 要回答的问题 |
| --- | --- |
| 稳定实例与所属人物 | 哪一处持续伤病正在演变，重试或再次观察是否仍是同一处 |
| 部位与类型 | 位于何处，属于一般创伤、骨折、缺失关联创口或全身状态等何种游戏类型 |
| 起因与来源事件 | 由哪次合法冲突、环境、缺粮或其它已声明效果产生；谁造成、本人是否知道分别处理 |
| 严重与阶段 | 当前程度、活动中/稳定/恢复中/留下后遗影响等阶段；具体等级与参数待校准 |
| 存续与时间边界 | 何时开始、上次结算到哪、下个临界事件、什么条件使其恶化、稳定或结束 |
| 治疗与投入 | 采用了什么可适用处置、由谁执行、资源和时间是否已实际支付、当前进度如何 |
| 可逆性与遗留 | 哪些效果可自然恢复或经治疗改善，哪些完整性变化需独立能力与规则才能改变 |

这些是概念职责，不是已存在的新字段。伤势来源引用实际事件，身份与保存沿用既有角色和世界路径，不为身体另建平行人物 ID 或日志真相。

持续出血等拟作为具体伤实例的声明效果，具有强度、持续条件与下一结算边界；不要求模拟现实血容量。相同伤势已结算的区间不能在日结和月结各扣一次。

伤势恶化、恢复与部位完整性变化均需可复述原因。已经稳定的创口不永久重复扣损，已经缺失的部位也不因其创口痊愈而重新出现。

## 行动能力由同一身体规则派生

拟由统一能力查询读取部位完整性、活动伤病、生命/斗气和已生效治疗效果，再给出可做、受限或不可做以及原因。具体行动补充其技能、物品、位置和时间条件，不在每处复制一组 `injury` 阈值。

| 能力维度 | 候选活动影响 |
| --- | --- |
| 意识与沟通 | 是否能主动决策、交涉、求助或需要他人照护；不会因台词生成而忽略当前失能 |
| 站立与移动 | 可用移动方式、负重与耗时范围；腿受伤不直接用“照常走完路程”掩盖 |
| 持握与器物使用 | 能否完成需要单手、双手或相应手臂的操作；已有装备不能自动绕过身体条件 |
| 运气与施技 | 是否满足该功法/斗技所需部位、身体承受和斗气条件；不统一判定所有功法都必须双臂 |
| 工作与采集 | 具体劳动需求与可用能力匹配，不能受伤后仍无条件获得整段满额收入 |
| 修炼与学习 | 区分能否静养修炼、练习某类动作及突破，保留各能力自身的前置条件 |
| 自理与照护 | 是否能进食、移动或照顾他人，是否需要协助与相应占用，不把病人自动当作完全无行动者 |

能力查询提供可解释限制，例如“左腿骨折，当前不满足负重赶路条件”或“双手持握条件不足”。计划器据此选择休养、替代工作、求助或交通安排；用户界面也读取同一原因。

限制不等于所有行动统一禁用。单臂人物仍可在已声明能力允许时沟通、使用单手器物或进行合适工作；具体补偿方式、辅助器物和特殊功法需有内容与规则，不能由模型临时补一个万能替代。

疼痛和行动受限可影响人物决策，但不改写用户意愿。若角色是玩家，系统显示真实限制与有效选择，由用户决定如何应对；NPC 则按人格、目标和所知选择后续活动。

## 临界时间、持续代价与恢复边界

危急伤势、持续消耗、活动恶化与治疗完成拟进入同一游戏时钟，按最近有意义边界检查，不能等月底第一次想起伤者。思考、输入与退出暂停仍依 D07，不采用现实等待扣损。

稳定恢复可按有效区间累计；临界恶化、死亡条件、功能变化和治疗中断必须截断区间再处理。具体速率与期限是游戏设计候选，不在文档伪造现实医疗数值。

严重伤者不能一边按受伤条件等待死亡，一边仍取得完整工作、旅行和修炼收益。先查当前能力与活动占用，再计算这段时间实际可获得的结果。

月度调度不得清空伤病实例、重置临界时间或让缺失肢体长回。降低 NPC 精度仅聚合可稳定累计部分；再次进入场所时应展开同一身体事实，而不是重掷健康状态。

受到新伤时重新评估已接受活动与未来边界；旧伤痊愈、治疗失败或失去照护也会改变下一步。取消后续计划不会撤销已经受伤、已消耗药物或已经走过的时间。

## 治疗条件与不同恢复结果

治疗拟检查适用伤类、执行者资格、人物状态、设施或渠道、真实资源、所需时间和双方安排。治疗意图、开始治疗与治疗完成分别表达，不能一次对话就宣布已经恢复。

| 候选恢复类别 | 应明确的结果 |
| --- | --- |
| 缓解或稳定 | 减少某种负担、停止相应持续恶化；不自动结束所有伤病或恢复部位完整性 |
| 普通恢复 | 满足休养和生活条件后逐步改善可逆损害；进度和中断影响真实可用能力 |
| 骨折等指定伤病治疗 | 类型与资格匹配后进入相应恢复过程；腿仍存在，愈合不能仅凭总生命已满判定 |
| 缺失或长期结构损失 | 保留完整性变化；普通疗伤只处理适用的创口或症状，不复原缺失肢体 |
| 特殊恢复能力 | 若后续采用小说中有依据的特殊能力，另核资格、材料、代价与效果；本轮不默认人人能再生 |

一份普通药可产生其规则声明的有限效果，不能因为降低了 `injury` 就同时治好骨折、永久损失和所有后遗状态。已经耗用或无效的药不因生成措辞不好看而退回；失败与拒绝仍按实际过程区分。

照护是能动活动：照护者必须有能力、时间与资源，受伤或离开可能中断安排。被照护者仍有可用能力、目标和社会联系，可请求替班、选择其它渠道或承担相应风险。

## 合法写入与个人观察的分离

后台冲突、已声明环境效果、伤病时间演变和治疗结算是候选合法写入来源。它们提出具体结果并经同一规则检查，写入伤实例、完整性及必要总量；模型、动画和自由旁白没有直接写入权。

NPC 冲突结算可以产生合法的重伤、骨折或缺失结果，但必须先有相应效果规则。尚未实现部位结果时只叙述已支持的结果，不为了表现戏剧性先说断臂、以后再找字段补上。

因果来源与知情分别保存：系统知道 A 造成 B 的伤，不等于 B 或家人已识别责任人。症状可以被观察、受害者可以误认、治疗者可以进一步判断；具体传播依世界信息规则。

自知也不等于全知诊断。本人能知道疼痛、活动受限和明显缺失；不能仅因拥有自己的角色投影就无条件知道所有隐藏伤因、准确类型或特效来源。

## 投影、人物详情与可见表现

| 信息位置 | 候选内容与授权边界 |
| --- | --- |
| 玩家自身状态与详情 | 身体概览、本人已知症状/诊断、部位完整性、活动限制、已接受治疗和相关时间状态 |
| 当前可观察 NPC | 实际可见的行动困难、明显外伤或缺失及观察时点；不直接公开全部伤病实例、隐藏效果或病因 |
| 已知人物档案 | 上次可靠观察或消息中的状态，标明来源与时效；离屏受伤后不自动刷新成实时医学报告 |
| 治疗与交互入口 | 已知需求、可执行处置、所需资源/能力与不能执行的原因；未知诊断不能被按钮无因剧透 |
| 场景与活动表现 | 动作、站位、移动方式或文字症状与已提交能力一致；动画不自行治愈、恶化或推动时钟 |

“观察到步履不稳”和“已诊断左腿骨折”是不同层次；未知时明确保留未知，不用一个绿色健康标记掩盖缺数据。对同一状态的 UI 摘要必须与行动合法性一致。

正式前端未完成时，后端仍须提供能检查这些事实的受限投影和必要本地验证入口；正式人物详情与场景接线按已有前后端分工推进。完整玩家战斗界面仍不属于本轮交付前置条件。

新增投影、详情语义和错误原因只有实现后才修订共用契约；当前 C2 的玩家 `injury` 及 NPC `observePerson` 不冒充上述字段已经可用，也不把 UI 方案图当成读写闭环证据。

## 长期后果、死亡与保存恢复

保存恢复覆盖部位完整性、伤实例、来源事件、已结算边界、治疗投入与进度、相关活动/占用和个人观察。能力由恢复后的同一事实重新派生，不能留下未来分支的已愈合状态或旁人诊断。

死亡按合法身体或其它世界条件结算，并与既有生死、遗产和家庭规则一致；重伤、失去肢体与死亡不混为一个状态。死者伤史可作为已有经历留存，不因死亡清除责任来源或无因生成治疗资源。

长期身体限制会影响谋生、学习、家庭照护、旅行和人际求助；不是只在战斗算式中扣一次数字。人物可在可用能力内重新安排生活，不强制所有受伤者退出世界或走同一复仇故事。

## 最小完整功能路径与候选样本

| 交付环节 | 最小可检验结果 |
| --- | --- |
| 状态 | 选定有限部位和至少一种可逆伤、缺失结果及对应伤实例，能够区分骨折与部位不存在 |
| 合法写入 | 已支持的 NPC 冲突或规则事件真正产生结果，治疗和时间演变可接续；不能手工改完数据就宣称行动链完成 |
| 能力影响 | 同一派生结果决定移动、持握及至少一种工作/修炼/照护活动，失败有具体原因 |
| 个人观察与表现 | 本人详情和授权 NPC 症状可见，诊断未知与上次所知可区分，活动文案不与能力矛盾 |
| 保存与接续 | 保存后继续恢复/恶化，再读回并推进，部位、实例、时间和治疗投入回到正确分支 |
| 必要小样本 | 对同一伤者完成产生、限制、求助或治疗、部分恢复及继续生活，另核缺失不会被普通药或过月抹去 |

候选例：B 左腿骨折但部位仍在，不能按原条件独行负重旅行，可休养、寻求协助或改活动；治疗后依实际过程恢复。另一分支若左腿缺失，创口稳定后仍保留移动限制，不能因血量回满恢复普通走路。

候选例：B 左臂缺失，要求双臂的器物或斗技不满足条件，但沟通及已声明的单手活动仍可能执行。A 或旁观者只获得其实际观察到的症状；B 是否求援、复仇或改换谋生依目标和用户/NPC控制边界决定。

这些环节构成本模块的最小闭环，不要求先完成全身解剖、全部伤类、完整玩家战斗或最终美术。未有合法状态和承载路径的伤名不作为首批正式效果；必要自查与样本归后续实施，本轮不新增测试或运行证明。
