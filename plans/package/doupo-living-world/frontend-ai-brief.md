## 1. 你在设计什么

Atria 是承载作品的宿主，本任务制作其中的一款《斗破苍穹》开放沙盒 RPG。设计对象是游戏的地图、场所、人物、文字行动与功能界面。Atria 的 Library、Studio、Runtime、模型配置、账户和全局导航不属于本任务的重构范围。

玩家使用自创角色，选择本土人或带有原著记忆的穿越者，以及多种社会出身，在小说开篇附近开始生活。首批围绕乌坦城、青山镇与部分魔兽山脉，优先做深 NPC 日常、长期关系、婚姻家庭、探索和机缘竞争，再扩大陆域。玩家可以改写原著命运，世界无需回到原著结局。

游戏采用世界地图加 2D 俯视地点场景；点击地面或对象移动，选择 NPC 自动接近。按钮和自由文字都能操作，包括战术回合或分段交锋。文字输入贯穿游戏，不能成为藏在某个对话弹窗里的附属入口。

NPC 有自己的谋生、修炼、休息、旅行、关系和目标，能够离开、拒绝、受伤或死亡。亲密、婚姻、共同生活、子女与家庭变故是首批长期玩法。持续游玩同一位主角，死亡后可读档，恢复相应时点的整个世界。

世界时间按有意义的行动推进，思考、输入、看面板与现实离线不推进世界。NPC 动态产生，存在可扩展的人口上限，通过有因果的世界事件平衡；人口上限具体数值尚待后端负载验证，前端不能自行决定或用隐藏删除人物来维持数量。

## 3. 视觉与布局起点

默认方向为国风手绘的 2D 俯视场景，轻微倾斜便于辨认建筑、人物与道路。小比例行走形象配重点人物的对话半身像；城镇、室内、林地、山石与洞窟有可复用的构件和统一尺度。乌坦城强调木石街巷、坊市和商贸生活，青山镇偏行旅、药材和佣兵活动，山脉突出路径、遮挡与可调查线索。这些是游戏美术推导，不声称小说提供了精确建筑图。

场景承担视觉主体。建议顶部放地点、游戏时间和当前活动，左侧为可折叠的已知地点与联系，右侧为当前对象及行动，底部放交流记录、明确指向对象的自由输入和功能入口。对话、战斗、家庭等活动可以改变主次，不要求固定三栏，也不把游戏做成数据仪表盘。

| 默认视觉材料 | 当前建议 |
| --- | --- |
| 基础色 | 玄青 `#172A30`、深石 `#263E44`，用于面板与层次 |
| 文字 | 石白 `#F1EBDD`、雾青 `#B5C9C8`；在场景背景上验证对比度 |
| 强调 | 古金 `#CBA568` 用于选择和重点，炎赤 `#E77C55` 用于斗气、危险与重要后果，配文字或图标 |
| 字体 | 标题可用中文宋体，正文/操作用中文黑体；正文约 16–18px、行高约 1.6；选择具体字库时说明授权与回落 |
| 动效 | 行走、选中、施技、受击和状态变化有原因；可减少运动，输入与操作不等待装饰动画结束 |

先以可操作灰盒确认场景、对象、路径、文字与功能关系，再深化一套有代表性的场景和人物。使用可追溯的原创或可用素材；占位美术明确标注，字体和图片无需外部 CDN 才能显示。候选颜色与版式可以调整，若改变已确认的俯视场景、点击移动或全程文字操作等体验，另列为产品变更建议。

电脑是主要目标。展示 1440×900 与 1920×1080，并验证 1280×720 和 200% 缩放的可操作性；空间不足时折叠面板，保留目标、行动与输入。移动端可以说明适配方向，不扩大为首轮手机全量验收。

## 4. 页面与功能覆盖

以下 ID 与 [共用契约](frontend-contract.md) 对齐。HTML 可挑选代表性场景做精细演示，交互文档须覆盖 F01–F12；HTML 中没画到的内容仍需有清楚入口与状态说明。

| ID | 页面或工作区 | 必须能说明的交互与状态 |
| --- | --- | --- |
| F01 | 开局与角色创建 | 自创角色、本土/穿越独立选择、出身与初始资源/联系预览；原著记忆不等于本局事实。四类出身为默认制作提案，可用代表样例，不编造原著年龄或开局日期 |
| F02 | 2D 场所、对象与移动 | 选中地面/设施/NPC、路径预览、自动接近、交互距离；目标改道/离场、路径受阻、途中中断与取消；场景对象对应可聚焦列表 |
| F03 | 对话与自由文字 | 始终明确对谁、在何处、做什么；草稿与已提交行动区分；按钮和文字进入同一规则；对话展开与回看、长文本、IME 与提交失败保稿 |
| F04 | 世界地图与旅行 | 已知地区、道路、目的地、耗时/准备/已知风险、同行与出发；旅行中断、路线不可用、未知或未制作地区；不能显示全大陆均已可玩 |
| F05 | 人物、成长与修炼 | 自身状态、伤势、资源、功法/斗技与学习条件、修炼/闭关进度及中断；区分能查看的设定、尚不可用的能力与实际已具备能力 |
| F06 | 行囊、交易与物资 | 持有者、数量、可用条件、商铺有限库存、价格/交换与结果；个人和家庭共用物资的区别；缺货、条件变化、已成交但说明生成失败 |
| F07 | 战术交锋 | 可见位置/距离、敌我状态、可选动作与自由战术；多步意图分段、当前结算、行动失效、逃离/投降/战败/死亡；思考期间世界暂停 |
| F08 | 关系、婚姻与家庭 | 已知关系与具体经历、约定/债务、相处与协商、成年亲密、成婚、住处/共同资源、照护、子女成长、亲属离去/死亡/分离；成员保有自己的目标，不能精确窥探私有好感或直接控制意愿 |
| F09 | 见闻、线索与机缘 | 来源与听闻时间、已知事实/传闻/原著记忆的区别；调查、普通采集、一次性机缘、竞争者可见行动、过期/被夺/归属变化；不泄露角色不知道的真相 |
| F10 | 保存、读档与死亡 | 手动/自动档、游戏时间与位置、保存中/失败/已完成；载入目标及其后果、恢复中/失败/成功；成功后全部可见状态和草稿上下文重新绑定，不显示未来信息 |
| F11 | 长时活动与人口变化 | 赶路、修炼和跨期推进的摘要与可解释中断；通过玩家可知事件表现出生、迁入、离开、死亡、继任和家庭变化；不把作者编制或底层预算冒充人口上限，不默认展示全知人口总表 |
| F12 | 宿主控制、等待与异常 | 游戏内加载、无可交互对象、不可执行、正在判断/生成、停止请求、失败与可重试边界；保留宿主退出/停止/保存/诊断/重载等既有通道，原型只示意边界，不仿造凭证或费用授权窗口 |

默认首批约 12 个场所单元、24–36 名持续具名人物、其中 8–12 名重点人物，是待验证的内容编制，人物数字包含关系，不相加；原型只需足够辨认的代表人物和地点。它们不是发布容量或动态人口上限。原著人物在场、年龄与具体机缘归属尚需资料核对，演示可用明确标注的原创人物和原创药材竞争线。

## 5. 必须画清楚的状态

| 场景 | 需要呈现的区别 |
| --- | --- |
| 文字与目标变化 | 编辑中的意图、提交时的目标、当前选中对象分开；目标已离开或切场景后不能悄悄改发给别人 |
| 移动与交互 | 选中、预览、提交、移动中、已到达、受阻与已取消分开；接近 NPC 不自动承诺交易、开战或泄密；取消不抹掉已发生的耗时和后果 |
| 规则与模型等待 | 提交/规则结算与生成表达分别表示；世界结果已提交而叙述失败时保留结果，不再给会重复交易或扣资源的按钮；没有真实进度时用不定状态，不伪造百分比 |
| 同时操作 | 等待时仍可编辑草稿、查看已知信息；会冲突的世界行动需明确何时可执行。点击“停止”是请求，不能承诺撤销已经提交的事实 |
| 知识与关系 | 未知不画成 0；传闻不画成确定事实；已知关系可展示，NPC 私有评价和秘密不因打开详情页泄露 |
| 家庭与人口 | 子女有出生与成长来源；人物死亡仍保留可知的亲属和历史；世界平衡事件以因果表达，玩家界面不出现“腾 NPC 槽位”式文案 |
| 保存与恢复 | 无存档、读取失败、保存失败、保存成功但列表刷新失败、恢复中、恢复失败、已恢复分开。成功后的刷新失败只重读，不重复写入；读档后旧对话/旧请求不能覆写新状态 |
| 冲突与失败 | 输入、目标和当前位置尽量保留，指出发生了什么与可用出路；原型中尚未接线的操作明确标注，不显示虚构成功 |

场景快捷键不在输入框或中文组合输入时触发；明确 Enter 与换行规则。焦点可见，打开层后可用键盘操作，关闭后回到触发器；地图和人物图形有列表等价路径，不能只靠悬停和小图标。颜色始终辅以文字、轮廓或图标；减少运动时仍能理解动作结果。长对话、关系历史、行囊与见闻需有可理解的滚动/检索，不能用固定高度截断必要内容。

普通选择与面板反馈约 100ms、基础画面朝 60fps 优化是当前候选目标，不是测量结果。原型可记录其实际设备上的操作表现；真实模型延迟、NPC 容量和世界追赶速度需后端测量，不能由演示计时器推导。

## 6. 原型与 Atria 集成边界

前端 AI 当前可直接推进离线的视觉和交互原型。用 HTML/CSS/少量脚本与静态演示数据展示界面；明显标注“演示数据/未接后端”。示例姓名、金额、耗时和人口事件只是展示状态的内容，不冻结成长公式、API 字段、人口阈值或世界规则。

| 工作 | 当前处理 |
| --- | --- |
| 地图、人物、面板、焦点、切页、文字草稿 | 可在离线原型实现并实际操作 |
| 场景等待、失败、恢复、家庭与人口事件 | 用可切换的演示状态覆盖；不声称已完成真实模拟或恢复 |
| 后端数据需求 | 以视图需要表达语义和已知范围，映射 [frontend-contract.md](frontend-contract.md)；缺少的契约列在交互文档“接线缺口”中，由后端落实后更新 |
| 新 HTTP 路径、状态字段、Host Bridge 方法 | 不自行约定为已实现；不将原型对象直接升级为后端合同，不造第二套世界写入或存档机制 |
| 模型和费用 | 原型不请求模型、不索取 API key、不操作真实账户、不外发用户内容；真实调用沿 Atria 既有受控通道 |
| 真实游戏前端 | 后续由用户选定集成者，将设计映射为实际 `.aui`、Controller、Canvas 与 Host Bridge 能力；依据当时源码和后端交付接线 |
| Atria 产品缺陷 | 记录明确阻断与样例，交由相应源码任务修补；不在视觉原型中改宿主、权限、关系或持久层来掩盖缺陷 |

当前 Atria 基于原生 ES modules/DOM/CSS 和原生作品前端机制，不是已存在的 React 组件库。视觉委托不决定产品换栈；若原型工具要求其他技术，须使设计、素材和交互说明仍可独立移交，不能要求真实产品沿用该工具运行时。

前后端可以同时推进。原型对字段缺失使用可解释的占位状态，后端提供已验证投影后再更新映射；不用等待每个细节确定才继续设计。后端完成不等于当前前端 AI自动获得正式集成任务，执行者仍由用户选择。

## 8. 交付时的自查依据

执行前端任务的 AI 自行完成直接相关验证并报告结果，不新增独立审查代理、多轮交叉审查或阶段审批。

- HTML 能离线打开，演示交互和未接线状态一致；素材失效仍能理解布局和操作。
- F01–F12 都映射到可发现入口与状态；HTML 覆盖范围、仅文档覆盖内容、尚未实现内容分别列明。
- 能演示“选中人物并接近 → 明确对象后输入 → 等待 → 已发生结果/失败”的连续操作；不会因切目标误发或在结算成功后重复提交。
- 至少能说明探索竞争改变线索/归属、家庭成员自主活动、长时推进的人口变化，以及保存后发生变化再恢复时全部可见状态如何更新；演示只证明交互设计。
- 在目标桌面尺寸、小窗口和缩放下保留场景、输入与主要行动；键盘、IME、焦点、长文与减少运动可用。
- 列出真实运行验证、仅本地模拟验证、未验证的性能或接线事项；不给未知能力画成完成状态。
