# 完整制作稿 — v0.15 世界自主运转、成长与后台冲突

状态：正式制作已获授权；确认项以 [decisions.md](decisions.md) 的 D01–D33 为准。be.2/C2 是已有后端基线，v0.15补充NPC自主成长和后台冲突，完整玩家战斗后续独立实施；新增机制尚未实现。具体规则、算法、数值与容量作为默认候选在实现/验证中校准，未逐项冻结不构成新的开工前置审批；前后端职责沿用 [分工](execution-split.md)，不替用户选择正式前端集成者或批准批量美术。

## 作品体验与首批交付

首要目标是世界整体自主运转。先证明玩家未参与时，首批三地的人物、家庭和组织也会围绕生计与长期目标生产、交换、出行、合作、竞争和传播信息，结果持续改变后续机会。玩家接触的是已经在运转的社会，进入场所或接取任务不会成为世界开始工作的必要条件。详细运行原则归 [世界模块](world-simulation.md)，人物和地区规则分别归 [npc-agency.md](npc-agency.md)、[world-systems.md](world-systems.md)。

连续因果与个人社交圈是这一目标的组成部分。人物可从一次失败形成持续动机，发现新线索后采取不同途径；途中相遇可使当前活动暂停或转向。每个角色包含玩家都有自己的社交圈与关系认知，详细规则归 [social-graphs.md](social-graphs.md)。玩家的控制方式不同，仍处于相同社会事实与行动条件中。

NPC成长和相互冲突也是当前世界循环的必要部分，详见 [npc-progression-conflict.md](npc-progression-conflict.md)。先实现自主修炼、突破准备与NPC/NPC后台战斗，按双方实际功法斗技、装备、可用道具及分类损耗结算，形成伤势、消耗、退让与后续动机。完整玩家战斗按D33留待后续大修改，既有be.2简单玩家交锋不因此删除，也不作为未来机制完成证据。

玩家以自创角色进入小说开篇附近的世界，在乌坦城建立生活与人际联系，因修炼、谋生或人物请求获得线索，经旅行抵达青山镇，再进入魔兽山脉部分区域探索。是否出发、同行对象、取得资源的方式与何时返回都可以改变；留在城中修炼、经营关系或处理家庭事务时，其他人物继续行动。

首批作品应能反复游玩这一循环，并在同一主角的长期游玩中展现婚姻家庭、人物换代与局势变化。短期原型只是实施中间结果，不能代替包含家庭与长期变化的首批交付。

| 内容 | 拟定首批可玩范围 | 后续扩展 |
| --- | --- | --- |
| 地理与生活 | 乌坦城、青山镇、山脉部分区域；具体场所见 [内容模块](content-and-runtime.md#首批场所与人物编制) | 其它城镇、学院、宗门与大陆区域 |
| 自创角色 | 四类社会出身，本土/穿越独立选择；见 [角色模块](player-and-combat.md#首批开局默认方案) | 新背景、其它开局地点与更多初始关系 |
| 社交与家庭 | 日常、同行、恩怨、师承接触、亲密、婚姻、共同生活、子女成长与家庭变故 | 更多地方礼俗、家业类型与跨区域社会内容 |
| 探索与竞争 | 药材、危险路线、遗留洞府、消息交易等机会；NPC 可先取得或改变它们 | 更深山域、特殊传承、异火与跨地区大争夺 |
| 成长与交锋 | 当前深化NPC自主修炼/突破与后台冲突，功法装备道具及分类损耗参与；玩家已有基础成长/交锋保留 | 完整玩家战斗机制单独大修改；高境界、完整丹方与高级炼药、更多特殊体质 |
| 组织与经济 | 成员身份、商铺/拍卖交易、委托、资源竞争、职位接替和势力衰败的基础结果 | 完整宗门经营、战争统御与大型产业管理 |
| 世界持续性 | NPC 自主计划、消息传播、长时推进、动态生成与人口事件平衡、完整世界读档 | 按已测运行规模扩大内容与人口容量 |

高境界设定可作为人物和世界资料存在，但只有规则、场景和内容都实际支持的能力才标为可玩。遇到首批之外的去向，地图说明内容范围，不假造已完成的目的地或用叙事代替未实现系统。远方压力与模拟边界见 [世界模块](world-simulation.md#远方世界与首批边界)。

人口上限是已确认的长期要求，首轮 24–36 人作者编制是内容起点。动态人物生成、计数、出生/迁入与死亡等事件的拟定平衡机制，统一见 [世界模块](world-simulation.md#动态-npc人口上限与事件平衡)；上限数值以目标世界规模与负载验证确定。

## 贯通体验样本

建议以一条非强制的药材竞争链作为首次贯通样本，内容为游戏原创设计，不声称是小说既有事件：

1. 玩家在城中通过交易、交谈或帮忙认识一位有实际生活目标的人物，得知其需要一种突破或治疗材料；接触方式随出身变化。
2. 玩家可以帮忙筹资、另找替代材料、交换线索，也可不参与。药铺库存、债务、承诺和相关人物的认知都进入状态。
3. 线索指向青山镇的采药与佣兵渠道。旅行显示耗时、准备和风险；玩家可独行、结伴或留在城中。竞争者无需等玩家接取任务才行动。
4. 山中出现可调查的足迹、采集点和危险；玩家可合作分配、交易、绕行、伏击或放弃。独特物品只有一个归属，普通资源按产出和消耗计算。
5. 返回后，分配、隐瞒、失约、救援或伤亡改变往来、家庭支出与下一次机会。关系变化可追溯到当事人知道的经历。
6. 玩家修炼或处理生活数日后，人物位置、修为、库存、关系与消息发生变化。分支存档可返回此前时点，核对没有未来记忆与物品串入。

此样本用于证明系统相连；自由游玩不要求玩家按上述顺序推进，也不保证获得材料。婚姻家庭与世代演化另有贯通样本，不能塞进首次短行程后宣称已验证。

在上述玩家体验之前，先跑同一世界的无参与样本：玩家只进行有补给的等待或修炼，药铺与家庭的需求仍引发采购、雇用与采运，佣兵和采药者真实备粮、出发、抵达、竞争、返程和交付。再从同一初始存档改变一笔库存、一条消息或一个参与者，核对后续因果随之变化。它是本轮新增制作依赖，不是新增的独立审查流程。

新增两条连续因果样本：药谷冲突的失败、宽恕与仇怨，可经实际尾随/观察发展为亲属受威胁和多方反应；炼丹完成后同时产生分享/访友目的，真实远行途中与狩猎者相遇，使后者考虑中断旧活动。人物动机、关系信息、动作条件与执行结果逐段成立，允许没有报复、跟丢、识破、劝退、反抗、求援、逃离或未相遇。完整设计见 NPC 模块；不为达成某种剧情预先锁定结果。

## 数据与生成职责

下表是语义职责划分，尚非最终 Domain 数量、文件名或新增服务列表。实施时优先映射到既有契约，避免为每类名词建立独立基础设施。

| 数据/行为 | 拟定承载与边界 |
| --- | --- |
| 小说设定与初始史 | 版本化 Package/Knowledge；保存时期、来源、冲突与游戏原创标记，不把后期状态灌入开局 |
| 人物、家庭与组织 | 既有 Actor/Subject 身份与 Session 内 Domain；动态人物不另造第二套 ID 或关系权威 |
| 位置、修为、物品、归属 | Session 权威状态；事务校验与 computation 结算；库存与唯一物品不能由模型随口增加 |
| 时钟、计划与到期活动 | Clock/Simulation 和游戏活动状态；计划有条件、耗时、占用与结束结果，按事件先后推进 |
| 人口与生成 | 复用身份与 Session 权威；人口规则、存活计数、生成/预留与事件结算同次提交检查，恢复到对应历史分支 |
| 关系事实与个人评价 | 婚约、亲属、债务等为已发生事实；信任、亲近、敬意与紧张为各自评价，保留来源，不强制双方同步 |
| 个人所知与记忆 | Information/Cognition/Memory 投影；人物只依据可取得的信息决策，历史摘要不替代生死与物品事实 |
| 个人社会图谱 | 复用真实人物身份、关系事实、个人信息和有向评价；每人具有自己的视角，稀疏存储，不复制全知图给每位角色；玩家行动由本人选择 |
| 连续因果与动机 | 事件/观察/主观归因/目标/活动保持可追溯联系；潜在仇怨、未解决承诺和多目的计划纳入保存，定期复盘不清空 |
| NPC成长与冲突 | 规则活动累计与条件突破；后台战斗读取双方真实能力和物品状态，策略只依本人所知；数量、次数/充能、耐久与维修分别入账，不由旁白或战斗力分数直接决定结果 |
| 文字意图与 NPC 判断 | 模型解析、评价与规划；只提出已声明规则可表达的行动，接纳后才改变状态 |
| 叙事与 UI | 读取已提交结果及玩家视角；对话可以欺骗，系统结果不能因生成措辞改变；Canvas 动画不自行推进时间 |
| 存档与历史分支 | 精确 Revision/SavePoint，覆盖所有本局持久化状态；新分支重绑定来源，隔离未来任务和记忆 |

首批默认不引入影响本局事实的跨 Session 外部记忆。若复用的 Atria 路径实际包含外部状态，必须纳入恢复或隔离验证，不能只因没有主动配置外部存储就假定读档完整。

## 框架验证与必要修补

后端先用最小内容验证最可能改变制作结构的能力。下列是执行代理的必要验证，无独立审查、交叉审查或额外审批流程；具体 BE/FE 验证归属见 [backend-task.md](backend-task.md#必须保持的权威与验证)。

| 顺序与问题 | 可执行验证样本 | 通过依据与失败后的处理 |
| --- | --- | --- |
| V1 动态人物 | 建立原始人物与动态 Subject，发生见面、援助、结仇；再加入出生/成长人物 | 双方个人信息可用、关系评价目标被接纳、来源授权正确、读档不串身份；若 manifest 目标限制阻断，修补既有身份/评价接纳路径 |
| V2 完整读档 | 保存后发生交易、死亡、婚姻变化、NPC 秘密获知和后台任务，再读回并继续 | 人物、物品、时钟、关系、任务、历史与个人所知恢复到对应分支；未来模型结果不能写入；修补实际遗漏或分支绑定 |
| V3 长时推进 | 同一初始世界分别逐日、跨月推进，包含两人争同一资源、到期约定、受伤和死亡 | 时间不倒退、资源不重复、到期事件不漏、冲突按因果顺序结算；先优化包内事件组织，再修补确实阻断的调度能力 |
| V4 长期增长 | 增长人物、关系、消息与记忆记录，同时测量投影、状态复制、追赶及保存 | 明确哪种数据先触及预算和开销；可聚合内容保持身份与必要证据；实际扫描或保留边界阻断时才改索引/投影/保留路径 |
| V5 场景与操作 | 路径阻断、目标移动、重复提交、缩放、场景切换、战斗与输入焦点 | 位置和结算一致、失败可理解、选中对象不误发；Canvas/Bridge 若有已复现阻碍，局部修补 |
| V6 真实模型 | 相同状态尝试求助、隐瞒、谈价、复合战术、越界意图与秘密问题 | 判断有个人依据、叙事不擅改事实、按钮与文字规则一致；记录实际等待和调用；先调内容/提示与规则，缺陷另定位 |
| V7 动态人口平衡 | 以候选上限构造接近满额、多项出生/迁入同时到期、人口损失与恢复、跨地区迁徙及读档样本 | 同一身份计数一次、不超额接纳、不重复释放；事件有因果且不过度震荡；人口计数/预留/历史随存档一致；阈值与总上限根据实际负载校准 |
| V8 世界自主运转 | 无玩家参与也完成生计、补给、协作采运、返程交付及地区反馈；与玩家改变资源/情报/路线的分支对照 | 需求与行动有来源、投入与产出连续，事件可被避免或改变；长期平稳或衰败有原因，不靠进入场所刷新；详细样本见世界模块 |
| V9 持续目标与社会能动性 | 同一人物保持长期目标，在缺钱/断路/竞争失败后改策；NPC之间及对玩家提出可拒绝的委托、邀约与同盟，检验隐瞒和利用 | 性格影响真实取舍、当前行动可执行、投入/承诺/利益分配可结算；人物只按所知判断，不用对话choice冒充实际行动 |
| V10 多尺度执行与成本 | 对齐事件依据后比较逐日/跨月、细算/聚合、途中保存/恢复；记录扫描、事务、序列化、历史增长和模型调用 | 关键事实/守恒一致，旧事件不重算，精度切换不重抽；测得的具体瓶颈指导包内优化或Atria通用补充，不能以声明预算推导容量 |
| V11 连续因果与机会改策 | 药谷失败后不同人物形成不同解释，后续观察提供新途径；携丹访友的多目的旅程途中触发潜在相遇，狩猎者比较新机会和旧计划 | 每段有动机/知情/时间/行动来源；所有受影响角色可反应，分支可中断；暂停/恢复旧活动与多目的部分成功成立，不能用预排剧情步骤代替自主选择 |
| V12 全角色个人图谱 | 人物互不相识到目击/介绍/误认/澄清，更新各自网络；包含玩家、第三者关系、秘密敌意、旧位置及死亡后历史，逐步/跨月与保存恢复对照 | 不读他人私图、不全员同步认知、有向评价不强制对称；玩家只见自己合法所知，不被自动接受邀约或选择报复；身份与历史不因视角切换复制 |
| V13 NPC自主成长与后台冲突 | NPC安排修炼/学习/准备突破；NPC/NPC因争夺/遭遇战斗，比较不同已学能力/装备状态/物品数量和损耗策略，贯通战后恢复/修理/改策 | 条件和资源实际约束成长及交锋，双方可退却/反抗；消耗物不复现，装备状态与归属连续，多阶段/跨月/恢复不重复扣损耗；不以完整玩家战斗作为本轮通过条件 |

源码边界与进一步验证要求见 [research.md](research.md)。只看到声明限额或阅读代码不能算复现缺陷；也不能为绕过缺陷建立平行的身份、存档、记忆或关系系统。

必要产品修补进入独立源码工作树和有语义的产品任务，引用本项目的具体失败样本与验收结果；包资产仍归 `package`，调查与实施事实留在对应 Record。按实际缺陷修补并验证，不预设全面重写框架。

## 实施顺序与完成依据

当前优先补齐下表的世界运行依赖，再把结果贯通到既有 P0–P5 交付。W0–W5 是新增工作拆解，不表示 be.2 已实现这些能力，也不是阶段审批。世界运动先有可运行的最小跨系统循环，再增加复杂人物谋划与内容变体；不先堆台词、事件数量或美术来代替运行。

| 顺序 | 工作 | 可检验结果 |

连续因果分三类验证：先验证活动、感知和关系边界；再设置有合理动机与条件的起点，观察自主选择能否贯通或合理中断；最后在自然世界推进中记录类似链条的起因、频率与失败点。不能预填每一步计划再称其自然涌现，也不要求每个普通世界窗口都出现同一戏剧性结局。

## 实施中保留的拟定项

已确认方向无需重选。以下内容沿用默认建议推进，按资料、原型或真实负载校准；用户可在独立前端对话中迭代视觉方案：

- 首批可进入场所、四类出身与人物规模是否足够支撑生活，而没有把首批变成全大陆制作。
- 原著人物与原创生活人物的比例，是否能同时满足小说代入与自主社会生活。
- 婚姻、子女和家庭变故的具体深度，是否与长期主角体验一致。
- 2D 国风手绘、场景为主的桌面布局，以及分段战术交锋的展开是否合适。
- 高级炼药、异火、高境界可玩内容和完整势力经营的扩展顺序。
- 人口上限的具体计数口径、事件种类与平衡方式；动态生成、存在上限与通过事件平衡的方向已确认，不重复提问。

精确公式、单条动作时长、经营周期、计划算法、最终容量与模型选择通过资料核实、原型和负载确定，不逐项制造审批。正式制作已获启动确认，当前可按 W0–W5 继续世界运行实现；按 [execution-split.md](execution-split.md) 分别推进，不提前指定前端集成执行者。后续出现实质用户反馈时先更新受影响方案，普通工程选择不重新启动多轮讨论。
