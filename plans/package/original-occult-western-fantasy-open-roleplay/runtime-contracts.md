# 运行契约与状态权威

## 状态

本模块描述目标和核对问题，不声称当前 Core 已有这些能力。Phase 1产出可审阅的实际映射与缺口；只为确认的产品需要补最小 Core 支持。复用原有 Session、authority、模型调用、保存和安全投影，不建立第二套世界数据库、调度器或提交权威。

## Phase 1 契约核对清单

| 领域 | 查明的问题与产出 |
| --- | --- |
| 开局 | 无额外模型调用的问答组合如何绑定合法背景、实体及入口；正式提交点 |
| 自由意图 | 当前 resolver 如何处理非预声明调查动作；可复用的通用原语、受支持组合、拒绝与后续扩展 |
| 结果 | 能力／条件／随机权威、回执及模型叙述如何共用事实；文本不能替代提交 |
| 动态内容 | 固定数据和安全视图边界，动态对象稳定 ID／来源／版本，合法扩展的声明与落地 |
| 演化 | 轮次 authority、预算、重要度、触发队列、合并、失败重试与持久化 |
| 终局与保存 | 普通／铁人区分，死亡已提交状态，续玩检查，删档拥有范围与中断恢复 |
| 前端 | 现有 Native 模板、控制器、Host Composer、抽屉与语义／焦点的支持范围 |

直接相关定位入口：Package 的 runtime/INTERACTION.md、runtime/authority.json、runtime/logic.json、runtime/tasks.json、tools/opening-compile.mjs、tools/long-horizon-compile.mjs、tools/frontend-compile.mjs；Core 的 src/native/model-prompt-runtime/、src/native/session-core.js（存在性与实际入口以搜索核对）、public/scripts/native/frontend/ 和保存相关现有权威。只加载命中的必要模块，不能为审计扫完整所有代码／文档。

## 意图、判定与叙述

输入转为受校验的意图／参数，结合权限、能力、物品、环境与他人意愿判定。新意图不能都回落到调查白名单，亦不能把模型生成的任意 JSON视为合法 App Command。

稳定因果决定普通结果；有抵抗或超凡风险时允许规则约束的随机。RNG按现有权威处理，网络重试、重复点击不能重掷或重复发布。详细随机规则由 Phase 1定案，UI不揭露隐藏成功率／种子。

模型解释和叙述基于可访问上下文与确认结果。若现有协议需要先模型选择再提交，必须明确草案与事实界线、拒绝／未知状态，以及叙述失败后的恢复；不因模型中断就虚构成功或终局。

## 轮次与世界更新

“有效游玩轮次”以完成的实际游戏推进为准；打开资料、筛选、切页、生成失败与同一操作重试不新增轮次。一次模型请求不等于一轮，多意图的计数方案明确说明。

重要度／更新间隔／预算需要唯一持久权威；刷新与重新进入不触发重复演化。失败保留必要的原调用身份与待处理状态，不能借不断重试绕过调用次数。只在需要创作变化时使用模型，其余规则更新不伪装为 AI任务。

## 普通与铁人

普通模式可保存、恢复先前状态并另作选择。铁人模式可持久续玩，不能提供回退读档；死亡必须是权威确认、已提交的真实结果。

铁人删除范围是该局由产品管理的存档，不删除其它局、用户原始 Package或任意文件。若先记录不可恢复终局再清理保存，必须使中断期间残留文件也不能被当成可续玩局；若现有系统支持原子删除则复用。不通过前端 alert／隐藏按钮实现防回退，不允许 AI文本直接删档。

后续需要验证该局的常规保存、自动保存及可恢复衍生状态索引，保证没有可回退入口，同时保护无关数据。不承诺防止用户操作系统级外部拷贝，不扩展成 DRM或反作弊工程。

生成失败、断线、进程中断不等于死亡，恢复只核对已提交事实，不能自动重放未知操作。既有旧版本存档保护；新版本迁移是否支持要单独证明，不能默认为无损可用。

## 版本与实现所有权

Package改动在主任务分支。Core有确认缺口才从当前 main建辅助产品分支（建议 refactor/open-roleplay-core），同 Task ID / 同 Record记录精确 HEAD；不复制两份实施记录。

旧 .atria发布保留；新能力使用明确版本与 feature gate／兼容要求，具体方法以真实工程结构决定，不先发明通用兼容层。Core新增支持不能要求其它游戏都切换成开放文字角色扮演。
