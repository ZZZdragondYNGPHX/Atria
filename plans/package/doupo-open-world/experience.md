# 开放世界交互体验（讨论草案）

## 已确认的体验锚点

玩家以自创角色进入客栈，点击掌柜，自由打字交谈。世界中的对象是交互入口；自由文字同时服务人物表达、意图和具体功能。

用户进一步确认类似《这是我的战争》的 2D 场景与行动推进时间。以下建议采用横向／剖面场景、可交互角色和物件；参考的是空间表达，具体美术、玩法和时间细则由本作品定义。

## 建议的空间结构与时间细则

- 地区地图连接城镇、山脉、宗门和遗迹；地点内部展开为可移动的 2D 场景。客栈、坊市、炼药房等可以有房间、楼层和出入口。地图层级与具体移动方式尚未冻结。
- 选择人物时展开属于此人的局部交谈区域；选择药鼎、柜台、柜门或采集点时展开相应功能。文字与操作附着于对象和当前情境，场景应保持可辨认。
- 建议读文字、编辑输入、查看背包／地图不消耗世界时间；已接受的行走、交易、交谈、采集、炼药和修炼按其意义推进相应时间。具体哪些动作耗时、按什么粒度结算仍需细化。
- 建议将输入耗费的现实时间与世界内交谈耗时分开；玩家打字慢不造成世界惩罚，角色真正交谈仍可以消耗游戏时间。
- 玩家进行耗时行动时，其他主体和远方事项按同一游戏时钟结算；跨越截止点须处理到达、袭击、约定、炼药阶段等实际事件，不能跳过因果。
- 建议画面中的呼吸、光照、烟雾和姿态等表现动画可以持续播放，但不得因此自行推进世界业务时钟。

## 建议的贯通场景

以下是用于讨论的展开示例，不代表已确认的具体玩法或已实现能力。

1. 玩家来到城镇中的客栈，能够辨认入口、掌柜、住客、桌面物品和其他可交互对象。
2. 选择掌柜后，与这个具体人物交谈；谈话引用双方所在场景、当时事件、过往关系和掌柜实际知道的信息。
3. 输入“住一晚，能便宜一点吗”，可进入问价／议价／入住流程；真实价格、房间、付款和时间由作品规则决定。
4. 输入“有人见过这个人吗”，掌柜依据见闻、动机和信任选择回答，不因模型知道原著便自动知道世界秘密。
5. 玩家可以结束交流、查看住店条件、购买可售物品、转向其他人或离开。对方承诺、已达成交易和消息传播产生相应持续后果。
6. 再次到来时，同一掌柜的身份、记忆、库存、营业状态和有关后果保持连续；人物死亡、迁居或客栈易主应按同一历史变化。

## 待讨论的跨功能原则

- 建议提供可发现的常用操作和自由输入：购买、修炼、炼药、探索、交涉等都有明确入口，也允许表达复杂意图。
- 建议将交谈中的提议、报价、谎言、承诺和已完成操作区分清楚；界面显示当前实际结果，不能因一句模型叙述就凭空增加资产或完成任务。
- 建议使用原 Atria 正式事务、受众投影、任务和存档权威。自由输入可以提出当前规则支持的行动；超出支持范围时给出符合情境的真实反馈。
- 建议按人物获知渠道解释消息传播；重要角色有独立目标，其他人物和远方地区按游戏时间、事件和分层结算继续演化。
- 渲染大方向与行动推进时间已定；移动粒度、交谈耗时、战斗节奏及退出后的世界行为仍待细化。
