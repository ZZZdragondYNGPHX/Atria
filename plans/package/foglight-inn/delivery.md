## 3. 正式制作的开工阅读顺序

1. **入口与整合权威**：[index.md](index.md) → [frontend-integration.md](frontend-integration.md)。先理解制作基线、采纳范围、必须补齐项及原件不能直接执行的建议。
2. **三项审美参考**：读取 [功能表现原件](frontend-reference/feature-presentation.md) 和 [整体指导原件](frontend-reference/frontend-guidelines.md)，在真实浏览器实际打开 [HTML 原件](frontend-reference/foglight-inn-concept.html)，查看代表布局并操作其已有流程。只读源码不能替代查看画面；原件中未实现的流程不因此被判为已验收。
3. **规则与运行边界**：读 [gameplay.md](gameplay.md) → [media-and-runtime.md](media-and-runtime.md)。以实际 Git 和 Native 合同复核状态、事务、任务、存档、媒体及需补齐的产品能力；不从样稿反推或重写规则。
4. **完整功能对照**：读 [interface-requirements.md](frontend-design-package/interface-requirements.md)，建立 S/A/ST → 正式界面与状态 → 实现/验收证据的映射，覆盖 HTML 与外部文档都没有画出的功能。
5. **内容制作**：涉及人物、事件、线索与披露时再读 [story.md](story.md)，保留有限视角与作者秘密；不把作者全文直接灌入玩家展示或每个角色上下文。
6. **实施与验收**：按 [implementation-prompt.md](implementation-prompt.md) 开始制作，执行本文件 §5 阶段与 §6 验收。后续发现新的适配差异，集中更新整合决策，避免在原件、玩法和多个说明中重复维护。

浏览器查看原件用于理解与评估参考，不能代替正式游戏在同场景、同密度下的实现对照。外部样稿中的演示数据、存储、音频播放或模拟生成逻辑不具有正式状态权威。

## 4. 工作空间与资产职责

- `docs`：本 Plan Bundle、外部设计输入、原样参考、整合决策与制作启动请求；不存正式图片、音频或产品实现。
- `package`：未来 `foglight-inn/` 游戏资产、逻辑、前端源码与媒体、构建工具，以及 `releases/` 历代 `.atria` 成品。旧版本保留。
- 产品源码：只为已核实的能力缺口在适当语义分支实施，优先为 [媒体模块](media-and-runtime.md) 的受限音频控制；复用原状态、存储与 Host。
- 外部参考：用户带回的 HTML/文档保留来源与版本。构图、样式和交互转译到游戏前端，避免任意脚本进入 Host 或另建持久规则。

正式实施先核对实际 Git 状态和项目规则，保护其他活跃修改。此前核查的 `main@9241325a7` 只用于说明企划依据，不假设新对话中的仓库仍未变化。通用生命周期、测试和 API 限额只归 [Governance](../../../README.md)。

## 5. 正式实施阶段

| 阶段 | 可审阅成果 | 完成依据 |
| --- | --- | --- |
| M0 — 合同与媒体准备 | 终稿对应的状态/动作/披露合同，图片风格小样、声音小样，模型路由和资产清单 | 样例能对应规则与设计参考；真实连接按需验证 |
| M1 — 一段完整流程 | 开局 → 一个地点 → 交谈/行动预览 → 正式结算 → 新场景/日志 → 存档恢复 | 真实规则有后果，失败无半提交，媒体和读取一致 |
| M2 — 必需音频能力 | 有界播放、环境/效果音量、首次手势、淡变与事件去重 | 不越权，退出/读档不残留或重播事件 |
| M3 — 三日完整游戏 | 人物主动事件、两条离岛路线与安全留守、三条结局及后记 | 计划可达性在运行时成立，无软锁，无隐藏免费改规则 |
| M4 — 表现打磨与作品交付 | 完整媒体、参考风格、响应式、恢复、`.atria` | 对应下方验收矩阵和最小相关检查 |

阶段组织依赖与验证，不新增逐阶段许可。P2/P3 文档与参考整合完成不表示 M0—M4 已实施；正式制作在用户新建的后续对话启动，媒体与音频能力等准备仍需实际完成。

## 6. 验收矩阵

| 领域 | 核心行为 | 必须覆盖的边界 |
| --- | --- | --- |
| 开局/规则 | 固定身份边界、正确初态、24 AP 与夜间维护 | 无重复开局/扣费；无半生成角色 |
| 自由输入 | 识别合理意图、显示候选与已知代价、确认后执行 | 不支持/含糊/多意图可恢复，不能任意造物或泄密 |
| 行动事务 | 资源、设施、承诺、时间与结果一致 | 双击/过期状态/取消/网络重试不重复提交；结果未知先对账 |
| 人物/记忆 | 记住相关帮助与承诺、NPC 有主动行动和边界 | 私密事实不串人；说法与事实不同；旧历史不等于当前同意 |
| 时间/事件 | 显式进段、可察觉的维护与天气、协助依约完成 | 读日志不耗 AP；行动与入夜配给独立确认，未完成配给可保存并恢复继续；事件幂等，不挂机无限思考 |
| 结局可达性 | 每条主要路线均能在合法预算下完成 | 无线电失修有替代联络；零谜团线索仍能完成；0 AP 仍能最终决策 |
| 安全与后记 | 留守完整，过去不可逆，个人回应有来源 | 不随机全灭、不靠异常造资源；差异有叙事意义 |
| 图片 | 资产闭包与 exact 选择、日夜/天气/设施变化 | 无遗漏/剧透；加载失败可读；读档不跨路线错图 |
| 音效 | 解锁、环境切换、短音、静音/分组音量 | 自动播放拒绝可恢复；事件不重播；静音可取得必要信息 |
| 前端 | 完整 S/A/ST 覆盖、整合后的参考风格、清晰操作与阅读 | 以同场景/同内容密度对照正式实现与原件，检查长段与多事件；桌面/窄屏、中文输入法、键盘/焦点及返回、减少动态效果、空/错/忙均有实际证据，不以原件局部演示替代 |
| 存档/恢复 | 普通模式精确保存、恢复和派生路线、可移植导出 | 精确版本依赖、历史只读、恢复后旧异步结果不污染 |
| 模型与性能 | 真实旁白、角色自然度、记忆消费、等待反馈 | 真实连接证据；取消/失败/延迟不伪装成功，不靠 mock 推断质量 |
| 作品包 | 构建、安装、开局、继续、三路线、导出/导入 | `.atria`/`.atriasave` 完整，必要媒体随包，凭据不随包 |

按变更先执行针对性检查，只有新变化或未解决问题再扩大。先前审查发现数据库依赖/服务缺失、旧接口测试、旧清理预期、Windows 路径和部分未定位断言；正式制作遇到相关路径时诊断并复验，不把它们全部归为游戏损坏或全部忽略。

## 7. 新对话启动请求与制作边界

正式制作入口为 [implementation-prompt.md](implementation-prompt.md)，由用户复制到自行新建的对话。启动请求应明确以下关联信息；详细规则只引用权威模块，不重新维护：

- v1.0 Plan entrypoint、本文件 §3 的必读顺序、三项原样参考、整合决策与完整语义清单。
- 已定方向、制作范围、状态权威、重要规则/信息/媒体约束。
- 实际源码与资产基线、工作空间职责、待补音频能力及其他已证实差异。
- 媒体 Target/预算等真实准备情况与尚缺资料；不含秘密值。
- 实施起点、依赖顺序、按模块的相关验证和交付范围。

启动请求是正式制作的任务说明，不是将失败或阶段边界转移给用户的 HANDOFF。本轮不自动创建新对话、不启动产品实现，也不把尚未生成的媒体、未补齐的音频能力或未执行的验收写成已完成；正式制作对话按实际 Git 与上述入口开始工作。
