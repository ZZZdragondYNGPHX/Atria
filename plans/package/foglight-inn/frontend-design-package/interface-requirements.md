# 《雾灯旅舍》前端界面与交互需求

本文件供外部前端设计 AI 独立阅读，与 `README.md`、`design-brief.md` 一同构成输入包。请据此设计精致 HTML、完整功能表现说明和整体前端指导；三项产物的交付格式见 `README.md`。

## 1. 体验目标与设计自由

《雾灯旅舍》是一部温暖、克制、带轻悬疑的旧式海岛群像冒险。玩家临时代管旅舍，协调滞留客人，在风暴前安排可执行的出路。少量真实异常藏在生活中，结尾允许遗憾，最终留下温暖与希望。

玩家应同时感到“我身在此处”和“我知道眼前可以做什么”。场景图、天气声、自然对话营造生活；清楚的代价、承诺和结果帮助判断。避免把主游戏做成管理后台，也避免让装饰遮蔽阅读和行动。

本文件定义信息、操作语义和状态，不指定栏数、导航形状、抽屉位置、字体或配色。`S` 是界面职责，可以合并为区域、页签、弹层或面板；不要求每个 `S` 都独立成页。`A` 是操作语义，不要求每个 `A` 都成为常驻按钮。

优先级：**P0** 为正常游玩中应直接发现的入口；**P1** 为上下文出现或一步可达的次级入口；**P2** 为菜单内的设置、恢复与管理入口。优先级不等于视觉尺寸；当前情境可以提升相关操作的显著性。

公开规则、行动成本与设施状态名称以 `design-brief.md` 的规则摘要为准。本文件不重新定义数值、配方、任务条件或结局判定。设计需要展示资源与成本的真实示例，不另造与摘要冲突的系统。

## 2. 所有界面共同遵守的信息边界

- 展示当前地点、日期／时段、天气阶段、当期行动余量和共同目标；期限在相关决策处可回看，不用真实倒计时催促阅读。
- 储粮、燃料、零件公开精确数量。设施显示可理解的状态和已知修复条件，不能只靠颜色或抽象百分比表达。
- 客人以姓名、在场／已知去向、公开身份、已知言行、承诺和可协助事项呈现；不显示隐藏信任、好感、秘密条件或内心独白。
- 日志分清亲眼所见、人物说法、待核实推测；保留来源和获知时点。未知事实不预填，未发现线索不用剪影清单泄露数量。
- 普通查看、回看、看图、查看日志和常规移动不消耗行动余量；会结算的行为必须先展示已知成本、对象、条件和风险，再确认。
- 自由输入表达意图。关键行为经过“理解意图 → 可执行方案 → 预览确认 → 正式结果”；输入回车不能跳过确认直接改变关键状态。
- 普通闲聊可以自然回应，但不能伪装成完成维修、正式承诺、交换物资或推进时段。关键对话选项也复用行动预览。
- 风暴、船期和人物事件随正式游戏进程推进。不要用网页真实时间、离开页面时间或动画播放时长偷偷推进世界。
- 画面和声音依据当前正式状态切换；已加载的画面不是额外世界状态。读档恢复后不得保留另一条进程的天气、人物或资源。
- 保留清楚的系统状态语言。无线电里的故事异样与网络错误、请求失败、数据恢复必须容易区分。

## 4. 必要操作语义

同一操作可以有上下文按钮、文字选项、键盘入口等多种入口，结果必须一致。按钮文字可以润色，但功能说明必须逐项映射下列 ID。

| ID／优先级 | 操作与条件 | 反馈、代价和焦点要求 |
| --- | --- | --- |
| A01／P0 | 开始新局；入口与结局后可达。 | 进入 S02；已有进度时说明创建方式，避免无提示覆盖。 |
| A02／P0 | 继续；仅存在有效当前进度时出现。 | 显示将继续哪天／何地，完成恢复后进入 S03；失败保留其他存档入口。 |
| A03／P0 | 设置称呼与允许的角色表达偏好；开局可用。 | 字段错误贴近字段，保留已填内容；不能设定破坏代管前提的能力与身份。 |
| A04／P0 | 首次启用声音／静音开始；由真实用户手势触发。 | 不因拒绝声音阻止开局；可预览音量并撤销，音频未解锁时给清楚状态。 |
| A05／P0 | 确认开局。 | 进入首场景，首次目标与操作提示简短出现；不要求读长篇操作手册。 |
| A06／P0 | 观察当前场景、放大已知图片或查看显著物件。 | 普通查看不耗行动；若选择正式调查则进入 S09，不能把查看暗中计费。 |
| A07／P0 | 打开简图／选择可达地点／返回。 | 常规移动无成本；特殊行动单独预览。到达后更新人物与画面，关闭简图回触发点。 |
| A08／P0 | 找在场人物交谈／打开人物记事。 | 明确正在与谁交谈；人物不在时呈现已知去向，不能远程变出现场对话。 |
| A09／P1 | 选择话题、普通闲聊、回看或结束交谈。 | 普通闲聊不结算关键变化；关键请求转 S09。结束后回人物入口和原阅读位置。 |
| A10／P1 | 请求协助／查看或取消未完成的协助；仅在对应人物与情境提供。 | 说明对象、条件、完成时机、资源预留及人物占用；取消免费并释放尚未消耗的预留物资，已用行动不退还。与取消预览、停止请求区分；明确进行中／已完成，拒绝用可知理由表达，不暴露隐藏关系门槛。 |
| A11／P1 | 答应、婉拒、兑现或调整正式承诺。 | 涉及状态变化先 S09；显示期限／对象与已知后果，承诺建立后可在 S07 回看。 |
| A12／P0（情境） | 执行当前地点提供的经营、维修或准备活动。 | 显示动词和对象，预览资源／行动成本；设施缺件时给原因和已知可尝试方向。 |
| A13／P1 | 查看并选择有限补给／资源整理方案；仅在实际支持的情境出现。 | 同屏显示付出、得到、数量与完成后余量，限次状态清楚；不引入金钱、无限商店或额外交易系统。 |
| A14／P1 | 调查已发现的对象或线索。 | 区分“回看已有记录”与“花行动进一步调查”；未了解的结果保持不确定。 |
| A15／P1 | 查看物品来源、已知用途与当前可做的事。 | 使用、交付等正式操作转 S09；无用途线索不随意提供“合成所有物品”等通用按钮。 |
| A16／P0 | 输入自由意图并提交理解；主游戏可用。 | 提供简短示例和输入提示；解释中保留原文，不先扣资源。未识别时给澄清或支持方向。 |
| A17／P0（预览） | 修改意图、对象或方案。 | 回到可编辑输入／候选方案，保留原文；再次确认前刷新代价，不能静默改写行动。 |
| A18／P0（预览） | 确认执行受支持行动。 | 唯一正式结算入口之一；执行中防重复提交，按已提交结果更新，结束后进入 S10。 |
| A19／P0（预览） | 取消未提交预览。 | 不耗资源／时间，恢复触发处的焦点与输入；与执行后的“停止请求”区别明显。 |
| A20／P1 | 等候／休息，按既定规则推进一次行动。 | S09 展示时间成本、当期余量与可能错过的已知事项；不提供无代价跳时段捷径，不对正在阅读的人自动跳时段。 |
| A21／P0（结果） | 读完结果／交接并回到可行动状态。 | 重要变化可再次回看；非关键反馈不要求层层确认，焦点回合理的下一行动入口。 |
| A22／P1 | 打开记事、切换分类、筛选进行中／历史。 | 保持事实类型和来源可见；无匹配时提示清除筛选，不把空白当加载错误。 |
| A23／P1 | 打开线索、广播、人物说法或相关记录详情。 | 允许跨条目跳转及返回；回原条目／阅读位置，引用不变成未经确认的事实。 |
| A24／P1 | 回看或关注承诺／目标。 | 关注只改变阅读便利，不改变期限和世界；不制造一套独立任务奖励或打勾结算。 |
| A25／P2 | 请求逐层提示、调整提示强度。 | 先回顾已知目标，再给可尝试方向；进一步提示需玩家选择，不默认泄露秘密和最优路径。 |
| A26／P1 | 查看广播／操作当前可用联络。 | 回看不耗行动；实际发信、调试等正式操作转 S09，不能因装饰旋钮变化直接改世界。 |
| A27／P2 | 保存当前进度。 | 显示保存中、成功或失败；忙碌时解释不可保存的原因／安全时点，失败不假装成功。 |
| A28／P2 | 选择并恢复存档。 | 预览将恢复的进度、确认对当前进度的影响；取消保留现场；成功后清除未提交草稿／旧预览，重建 S03 与环境声。尚未确认的当夜配给是持久待办，恢复后须继续单独确认，并暂不可提交下一耗时行动。 |
| A29／P2 | 前往宿主管理导出／导入存档。 | 清楚说明回到 Atria 的 Play／Library 存档管理办理；游戏内不假定已有直接文件操作接口。宿主流程区分文件选择、校验与恢复，损坏／版本不兼容可解释并保留有效进度。 |
| A30／P1 | 回看当前进程历史。 | 明示历史日期与只读状态；回到当前后恢复实时地点。历史没有“在此任意分叉／重写／重生成”入口。 |
| A31／P2 | 设置总静音、环境／效果音量、文字大小／行距、提示、减少动态效果。 | 更改即时可感知并可恢复；文字设置不截断内容，声音设置不改变剧情状态。 |
| A32／P1（忙碌） | 停止当前请求；由宿主能力承接。 | 明示停止不等于撤销已提交行为；核对结果后给出已完成／未执行／需恢复的真实状态。 |
| A33／P1（失败） | 安全重试未提交请求／查看已提交结果／恢复。 | 根据真实执行状态提供正确操作；防止重复结算，不给一个含义不明的通用“再来一次”。 |
| A34／P0（临近收束） | 查看最终准备；行动窗口结束后确认最终方案。 | 区分仍可行动和免费最终决策；可见方案说明已知条件，安全留守始终可达。提前说明不可逆节点，决定需 S09，不能把查看误当结束。 |
| A35／P0（结局） | 阅读结局及人物后记／回看本局重要经历。 | 留出完整阅读与媒体停留，支持返回段落；不自动开启新局，不展示后台判定公式。 |
| A36／P1（结局） | 另开新局。 | 明示新局与本局保存关系；不默认跨局继承秘密、资源或关系。 |
| A37／P2 | 退出作品。 | 说明未保存进度处理并停止当前声音；可取消返回。已执行行为不因退出而被假定撤销。 |

## 5. 跨功能流程

1. **首次进入：** S01 → S02；完成有限玩家设定，选择声音 → 确认开局 → S03。第一屏提供共同目标、当前处境和少量眼前行动，设置与教程可稍后回看。
2. **常规行动：** S03／S05／S06 → 明确对象与行为 → S09 → 确认 → S10 → S03。资源、时间、人物安排变化应在结果中有稳定位置，不必反复翻日志猜测。
3. **自由表达：** 输入意图 → 解释／必要澄清 → 一个或少量可比较方案 → S09 → 确认。用户取消、换对象或提出不支持的办法均能回到当前场景，保留输入。
4. **获知线索：** 场景／人物／广播 → 新记录简短提示 → S07 具体条目 → 来源／关联记录 → 返回原上下文。线索重要性不依赖短暂弹出消息或声音。
5. **时段与日终：** 正式行动推进到时段边界 → S10 汇总 → 必要事件决定 → 下一时段。入夜配给一次预览一次扣减，不与共同用餐重复扣；日终回顾完成、遗留与已知次日安排，世界变化与系统保存分别表达。
6. **恢复：** S11 选择有效存档 → 预览影响 → 确认 → 恢复中 → S03。清除旧草稿与预览，更新数字、文本、人物在场、图片和环境声；不重放历史事件短音或已消费提示。若存档有尚未确认的当夜配给，继续 S10 中的独立决定，允许阅读/保存，未处理前禁止下一耗时行动；它不是可丢弃的旧弹窗。
7. **收束：** 临近期限给准备回看 → 明确最后可操作机会 → 最后安排 → S12 结局及后记 → 保存／导出／新局／退出。各种主要结果均有完整阅读路径。

## 6. 必须覆盖的状态

| ID | 状态 | 表现与恢复要求 |
| --- | --- | --- |
| ST01 | 正常可行动 | 当前事实、入口与可执行对象可读；焦点顺序稳定，单一主任务不会淹没其他合理选择。 |
| ST02 | 空内容 | 尚无记录／此处无人／筛选无匹配分别说明；提供合理返回或清除筛选，不伪造任务占位。 |
| ST03 | 条件不可用 | 已发现但缺资源／缺件／人物不在／时段不符，显示已知原因；未知行动不提前列出秘密条件。开局模型未就绪单列配置引导，交给宿主修复，不伪装成剧情里的困难。 |
| ST04 | 意图理解／澄清 | 保留原文和编辑入口；显示正在理解／需要明确对象；不扣资源，不把等待做成游戏时间流逝。 |
| ST05 | 待确认预览 | 已知成本、对象、条件、风险与时间推进可比较；确认／修改／取消语义清楚，默认焦点避免误提交。 |
| ST06 | 正式执行中 | 诚实的阶段文案与停止入口；锁住会产生冲突的再次提交，仍允许安全阅读；不能伪造进度百分比。 |
| ST07 | 结果与变更 | 区分成功、部分达成、规则拒绝；展示实际结算与下一步，拒绝不自动等于网络失败或消耗成本。 |
| ST08 | 时段／日终／广播事件 | 突发事件可被注意到并回看；正在编辑的输入不丢失；需要回应时停在明确决定，不自动替玩家选。 |
| ST09 | 请求失败 | 简短说明影响范围与是否已提交；保留输入及当前有效状态，提供匹配的重试／查结果／恢复入口。 |
| ST10 | 停止后核对 | 显示“正在核对结果”等真实状态，完成后说明行为是否生效；不承诺停止能撤回已提交行动。 |
| ST11 | 预览已过期／状态不再匹配 | 说明条件已变化，刷新方案与成本后重新确认；不沿用陈旧预览盲目执行。 |
| ST12 | 保存／恢复／文件校验 | 进度受保护，展示真实成功或错误；恢复中阻止冲突操作；失败后仍可回当前有效进度。已持久化的未确认配给等必要决定恢复后继续，只有未提交草稿/陈旧预览被清理。 |
| ST13 | 历史只读 | 时间、只读标识和“回到当前”清楚；不提供改变历史状态的行动；与恢复存档入口区分。 |
| ST14 | 最后机会／结局 | 收束前后边界明确；未完成事项以事实表达，结局内容可回看；没有催促离开的自动倒计时。 |
| ST15 | 图片／声音缺失或受限 | 图像失败时保留场景文字和操作；声音未解锁／静音／失败可识别，核心线索有文字对应；不阻塞通关。 |
| ST16 | 窄屏／大字／减少动态效果 | 所有关键入口仍可达，文字不裁切，层与页可返回；减少动态效果后切换立即或轻淡变，信息同样完整。 |

## 7. 图片、声音、阅读与导航

- 插画主要在制作期通过生图接口生成，游玩按地点、天气、时段与正式事件切换。外部 HTML 可以使用清楚标注的占位图／样图；请说明构图、裁切、安全区和所需变体，不调用游戏生图接口。
- 场景是空间与气氛的载体，人物形象不能挡住关键正文；正文、选择与资源不是必须烘焙进图片的内容。重要人物状态不能只靠一张表情图表达。
- 首次声音启用有明确选择；总静音、环境音量、效果音量随时可达。环境声随地点／风暴状态变化，短音对应已发生事件，音频不能承担唯一线索。
- 音效采用本地随包环境与事件素材；自动混音与平滑切换需要 Atria 最小宿主配套。HTML 若模拟此能力必须标为“交互示意”，不能宣称现有宿主已完整支持。
- 本作不要求角色配音或自动朗读。不要额外发明强制语音、麦克风输入、动态生成音效或背景音乐系统；环境与事件声音须给阅读让路。
- 自由输入明确 Enter／换行约定，兼容中文输入法组合输入；发送、预览确认、正式执行分别有明确语义，避免 Enter 连按连续提交。
- 模态层开启时焦点进入层，关闭回触发点；Escape 关闭可取消层，执行中不能用 Escape 暗中取消已提交行为。键盘可完成导航、选择、输入和返回。
- 触控有足够点击区域，信息不依赖悬浮；焦点状态清楚，颜色并配文字／形状传达状态。长文本支持滚动与恢复阅读位置，避免大量嵌套滚动。
- 新结果不会把正在阅读历史的人强拉到底；提供“回到最新”或等价入口。打开记事后回游戏，保持当前正文位置和未提交输入。
- 无需把 `exit`、`stop`、`save`、Persona、诊断、重新加载全部铺在主屏。日常入口和宿主恢复入口层级清楚，系统故障时仍能找到退出与恢复。

## 8. 信息层级、窄屏与事件并存

以下为必须解决的问题，不指定解决它们的视觉布局。功能表现说明应写明桌面与窄屏各自的安排。

| 情境 | 必须保留的层级 | 窄屏与返回要求 |
| --- | --- | --- |
| 长段阅读 | 正文与当前发言人优先；场景、当前处境与下一步仍可找。 | 允许场景收起或压缩，但不能以整屏固定大图挤走文字；回看不丢阅读位置。 |
| 查看人物 | 当前人物、在场／去向、谈话与承诺各有清楚用途。 | 退出人物层回原场景与原入口；切换人物不能把上一人的输入或预览误带给下一人。 |
| 查看物资设施 | 当前资源、所选设施状态、可行方案与下一步条件有清楚关系。 | 精确数量不能被工具提示藏住；大字状态下不出现横向裁切的成本表。 |
| 预览与确认 | 将做的事、对象、付出与预计时间推进比装饰更突出。 | 关键代价和确认能在同一阅读流程看到；按钮不遮正文，长说明仍可完整查看。 |
| 结果后再行动 | 实际结果先于新候选操作，新增线索／承诺可以直达。 | 先看到结算，再选择是否看详情；返回后仍能找到刚刚发生的结果。 |
| 地图与去向 | 当前地点、可达地点、人物已知位置与事项区分。 | 不要求精密拖动或微小热点；提供可读地点列表或等效触控替代。 |
| 设置与恢复 | 日常设置和技术恢复层级清楚，退出与停止能被找到。 | 窄屏仍有稳定菜单入口；故障状态不把恢复按钮藏在不可关闭的遮罩下面。 |

多件事同时发生时，按以下约束编排：

- 行动确认只针对一个明确方案；关联广播、人物来访或配给随后以独立事件呈现，不能借一次确认替玩家决定多件事。
- 相继发生的消息可以合并为一个可回看的时段摘要；需要选择的事件保留自己的上下文和确认边界。
- 新线索、承诺变化、设施变化等非阻断通知不要层层弹窗；需要阻断时说明下一步为何暂不可进行。
- 当前人物交谈与其他客人的新动向能够并存；设计要说明玩家怎样先读完当前段落，再查看新消息。
- 请求中允许的安全查看只读取当前已提交状态，不提供可同时结算的第二项关键操作。
- 用户已在记事或历史中时，新的正式结果标明“有新内容”并允许主动返回；不能替换当前正在阅读的条目。
- 完成协助时要区分“协助任务完成”和“人物仍在场可对话”；不要用同一个图标暗示人物无条件随时可用。
- 条件不足时只禁用必要动作，仍允许查看条件、移动、交谈或采用其他公开路径；整个页面不因一件设施缺零件而失效。
- 已知风险与系统警报使用不同文案语气：风暴预警属于故事，连接中断属于系统；两者都不能只用颜色区分。
- 同一时间不堆叠多个模态层。细节引用可在层内切换并保留返回链，避免关闭后不知道身处哪里。
- 输入中、预览中、执行中、结果已提交各有不同的退出处理；功能说明应逐一交代保留／丢弃／恢复语义。
- 所有图标操作有可读名称，关键状态变化对辅助阅读工具可感知；自动更新不反复打断正在阅读的长文本。

## 9. HTML 代表范围与完整覆盖验收

建议只精修三个代表画面及一个窄屏版本：① S03 的雨夜旅舍主游戏；② S07／S05 的记事与人物信息层；③ S09 的行动预览，并能切换执行中／不可用／请求失败示例。它们可以共享一个 HTML 中的少量真实交互。无需将所有 S 做成精致页面。

HTML 应让评审者实际看到阅读、场景、人物、资源与操作如何相处，并体验至少一次“发起 → 预览 → 取消／确认 → 结果”的模拟。示例数据必须固定且无剧透；模拟不得连接真实账户、模型或生图服务。
