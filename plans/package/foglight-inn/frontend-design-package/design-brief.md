# 《雾灯旅舍》设计背景、体验目标与示例内容

本文件与 [任务说明](README.md)、[完整界面需求](interface-requirements.md) 一起使用。这里提供无需读取作者剧本的公开内容，帮助设计者做出具体、可信的游戏画面。

## 1. 游戏是什么

《雾灯旅舍》是一部小型海岛群像冒险。你临时替人照看灯岬岛上的旅舍，风暴与最后一班船将在三天内到来。几位客人各有离开、留下或尚未完成的事。你安排时间、物资与维修，也逐渐认识他们，和他们一起准备接下来的路。

整体温暖、克制，略带孤独与轻悬疑。世界中有少量真实却不直接解释的异常。有些旧事不会被重新改写，但眼前的人可以互相照应，结尾留下希望。

玩家应感觉自己住在这里、认识这些人，也能理解眼前可以做什么。图像、声音和简洁叙述共同建立场所感；交谈、观察、安排和行动都产生体验。

## 2. 已定方向与设计者的空间

**已定体验：**

- 尚未普及个人随身联网的架空近现代海岛，日常依靠无线电、固定通信、渡船、机械设备和纸面记录。
- 有明确职责的普通临时代管者；姓名、性格与合理处事方式可表达。贴近主角的有限视角，不直接看透他人内心。
- 有时间窗口、过程由玩家安排。客人会主动协助、改变计划或拒绝安排，关系通过言行、承诺和共同经历体现。
- 图片主要制作期生图后随包，游玩按状态切换；随包环境声与短事件声建立地点与天气感。
- 已知代价、系统等待和真实结果清楚；人物秘密、未知信息和谜团保持发现空间。
- 单次完整故事，允许不同的离岛/留守与人物后记；结局不评判玩家人格，也不要求穷尽全部内容。

**设计空间：**

你决定具体构图、字体、配色、留白、材质、导航结构、组件和动效语言。下面的“暖灯、冷海、木屋、纸张”是世界线索，可以提炼成自己的视觉观点，不要求复刻某个既有游戏或固定三栏布局。

作品有阅读和行动两种需求。界面需要让场景、人物、正文、当前局面与可执行操作相处得当。设置、历史与细节可分层，不需要一屏显示所有功能。

## 3. 可用世界与人物素材

### 五个地点

| 地点 | 可见内容与感觉 | 常见事情 |
| --- | --- | --- |
| 旅舍公共厅 | 木桌、炉火、晾着的外衣、窗外雨雾；大家短暂停留的共同空间 | 交谈、用餐、承诺、查看共同安排 |
| 厨房与储物间 | 食材、燃料、零件与可修补的日常器具 | 看物资、整理、准备与经营活动 |
| 旧无线电室 | 现用报务台、纸面记录和旧器物；安静、需要专注 | 查看消息、维修、联络、回看记录 |
| 灯塔 | 上塔的路、旧机械、灯组与开阔的海面；风更明显 | 观察、修复、试亮、请求熟悉设备的人协助 |
| 避风码头 | 系船桩、候船处、潮水、纸面船务登记 | 看海况、准备接应、登记、有限补给 |

| 人物 | 公开身份 | 可用于画面与文案的印象 |
| --- | --- | --- |
| 周守川，61 岁 | 退休灯塔管理员 | 话不多，熟悉旧设备与路况，习惯先看一眼窗外再回答 |

## 4. 公开玩法摘要

以下用于理解 UI，不要求 HTML 实现完整规则引擎。正式数值由游戏企划维护，这里的样例需要保持基本一致。

- 三天，每天晨/午/暮/夜四个时段，每时段两次行动，共 24 次关键行动预算。界面可以用“还可行动 1 次”等自然语言，不必使用开发术语。
- 看场景、常规移动、看人物信息、读记事与历史不消耗行动；维修、正式调查、实质请求与等候会消耗行动。普通闲聊不直接改变关键状态。
- 三种公开资源为储粮、燃料、零件，初态分别 6/4/3。储粮是一批共用食物单位，非每位客人的单独饥饿值。
- 入夜有一次独立的舒适配给选择；先前行动先结算，配给另行确认与扣账。未确认配给随存档保留，处理前可阅读/保存但不能提交下一耗时行动。旅舍有固定三晚应急底线，资源不足仍可安全留守，日常舒适与可选活动会受影响。
- 协助会占用人物和预留物资，有预计完成时机；可免费取消未完成协助并释放预留物资，已用行动不返还。已知拒绝原因通过人物表达，隐藏关系值不做进度条。
- 常用操作与自由输入并存。自由表达先被理解为受支持方案，展示对象、已知成本与条件，再由玩家确认结算；理解失败可以澄清、修改或换已知操作。
- 已提交行为才改变资源/时间/设施。取消预览不花费；
- 最后一次行动用完后仍有明确、免费的最终安排选择。看清准备、决定离岛方案或留守后进入完整结尾；不能因为回看记录就突然错过最后按钮。
- 普通模式可保存、恢复和回看历史，导入导出通过 Atria 宿主管理。恢复会重建当前状态，清理旧预览和输入，继续未完成的必要决定；历史是只读的。

不需要给玩家展示所有内部数字。人物内心、真实关系值、隐藏线索和未发生的结局演出保留在故事发现中。不要提前展示其他结局标题或人物后记，也不要把实际准备要求藏成秘密解锁表。

## 5. 代表性 HTML 情境

精修下面三个情境即可，其余功能由完整说明覆盖。可以在同一个 HTML 内通过模拟交互切换，不要求分别制作完整页面。

### V1 — 第一天暮色中的旅舍

公开演示快照：

| 字段 | 显示内容 |
| --- | --- |
| 当前地点 | 旅舍公共厅 |
| 时间与天气 | 第 1 日 · 暮 / 海雾渐浓，开始落雨 |
| 本时段余量 | 还可行动 1 次 |
| 物资 | 储粮 6 / 燃料 4 / 零件 3 |
| 在场人物 | 林岚、周守川 |
| 共同目标 | 为第三夜的船务窗口做好准备 |
| 当前可知事项 | 报务台接收不稳；码头仍可通行|

正文可直接使用：

> 雨水沿着窗框往下走。林岚把工具包挪到炉边，腾出一小块空地，让你放下刚搬来的木箱。
>
> “楼上的报务台，还想试试吗？”她抹去手背上的水，“零件够的话，今晚就能让它安静些。”
>
> 周守川端着杯子，朝门口看了一眼：“码头那边风小些。真要过去，我带路。”

可见动作示例：与林岚谈谈、查看无线电室、打开旅舍记事、看看码头。自由输入提示例：“说说你想做什么，例如：请林岚看看报务台。”其中普通查看与涉及结算的行动需要有清楚区别。

最近结果示例：“你把干燥的纸张收到高处。沈遥说，之后若有新的船务消息，会替你记下来。”这是一条已发生的叙述示意，不要求设计 HTML 推导资源结果。

### V2 — 记事与人物信息

可以直接使用这些互不混淆的条目：

| 类型 | 内容 | 来源/时点 |
| --- | --- | --- |
| 亲眼所见 | 报务台的接收指示不稳定，完整通话尚未建立 | 第 1 日 · 午，无线电室 |
| 人物说法 | 林岚说，接点清理后还需要更换一只小部件 | 第 1 日 · 暮，与林岚交谈 |
| 待核实推测 | 潮气可能让旧设备的状态变差 ||
| 已有承诺 | 准备去码头时先告诉周守川 | 第 1 日 · 暮，口头约定 |
| 当前事项 | 了解报务台修复条件；查看码头登记 | 尚未完成 |

人物侧可展示“林岚 · 修理技师”“目前在公共厅”“愿意先看看设备”“正在处理的事：无”。不显示真实好感值、秘密标签或未见过的去向。

记事层返回后应恢复原场景、阅读位置与未提交文字。设计者可以选择自己的分层方式，不要求左右固定面板。

### V3 — 行动预览、结果和恢复状态

选择“检修现用报务台”，此时已看过公开故障说明，人在无线电室：

- 将做的事：清理接点并更换损坏部件，恢复现用报务台的基本通信。
- 已知代价：行动 1 次、零件 1；燃料与储粮不变化。
- 预计余量：本时段行动 0 次、零件 2；本次后进入夜间交接。
- 已知说明：现场条件允许检修；恢复现实通信不等于解开所有旧记录。
- 操作语义：确认检修、修改打算、先不修。

结果示例：

> 你把最后一只接头拧紧。底噪降下来，一段清楚的船务播报终于从扬声器里传出。

变更说明：“报务台恢复基本通信。零件 −1，剩余 2。本时段行动已用完。”随后夜间配给是独立决定，HTML 可只展示交接提示，不假装确认检修同时替玩家选择了晚餐。

另提供可切换示例：

- 条件不足：“还缺 1 份零件。你可以查看已知的补给方式，或先处理其他事情。”
- 理解中：“正在整理你的打算……”保留原输入，可取消未提交的理解请求。
- 正式执行中：“正在处理这次行动……”锁住重复确认，保留安全阅读与停止入口。
- 请求失败且结果未知：“暂时未能确认结果。

以上是可独立切换的公开设计快照，不是完整存档或自动推演脚本。示例未发现作者谜底；请不要自行补出广播真相、神秘人物身份或未发生的结局演出。现实路线的已知准备条件仍需清楚可查。

## 6. 图片与声音如何参与

场景图主要承载空间、天气和光照，人物图帮助识别人和在场状态，物件图用于已知记录/物品。重要文字和按钮仍由界面提供，避免烘焙进图；须说明桌面/窄屏裁切和安全区域。

声音意图：室内近处炉火、较轻的窗上雨声；室外海风与浪；设施运转声随状态变化；门铃、工具、无线电提示和船笛来自事件。语音不是首版必需，不能用纯听觉传递唯一关键线索。

首次交互允许启用声音或静音开始；总静音与环境/效果音量有清楚状态。音效在正式产品需要有界宿主能力，外部 HTML 的自动播放/混音只是设计示意。

## 7. 外部设计必须知道的边界

- Atria 是宿主，负责安装、模型配置、账户和基本恢复。不要替它重新设计整个应用壳或把作者工具放进旅舍。
- 游戏会使用原生组件、声明状态、受限脚本与精确媒体资源；外部 HTML 是视觉参考，正式实现会转译。你可以先做精致的普通 HTML，不必学习底层协议。
- 日常保存/声音/退出与宿主的停止、Persona、诊断、重载需要合理层级。其存在与入口需求见完整清单，不必把所有功能都铺在主屏。
- 不展示真实 API 密钥、供应商配置、内部 JSON 或模型推理过程。系统失败与故事异常使用能区分的语言。
- 提示、记事和空态帮助玩家理解当前处境；不把信息全部换成神秘符号，也不把所有人的秘密做成收集进度条。
