# 雾灯旅舍 — 媒体与 Atria 运行边界

> 先读 [index.md](index.md)。故事事实归 [story.md](story.md)，玩法规则归 [gameplay.md](gameplay.md)。本模块定义媒体资产和运行集成，当前是设计基线，不代表资产已生成或能力已补齐。

## 1. 图片制作与展示

正式图片主要在制作期调用生图接口，筛选、统一身份和风格后作为精确资产随作品交付。玩家通关不需要生图连接；游玩时根据当前地点、时间、天气、人物与事件阶段选择已有图。

具体供应商、模型、Workflow、输出尺寸与调用费用配置属于制作准备。复用 Atria Native 图片资源/资产工具；不在作品包中携带密钥，不由 Package Script 私建供应商客户端。

外部三项参考已回归，原稿保存在 [HTML 样稿](frontend-reference/foglight-inn-concept.html)、[功能表现说明](frontend-reference/feature-presentation.md) 和 [前端指导](frontend-reference/frontend-guidelines.md)；采用、补足与覆盖决策归 [前端整合说明](frontend-integration.md)。采用大场景、稳定透明人物主立绘与浅色半透明底部 ADV 阅读区，保持旧式海岛的温暖与轻悬疑。

正式美术采用柔和叙事插画；人物风格按用户制作期明确要求及 [前端整合说明](frontend-integration.md) 执行。场景通过木材、织物、纸张与旧设备等生活材质建立场所感。样稿中的 Unsplash 照片、海上背景和现代摄影人物仅供布局示意，不作为最终美术资产或人物外貌依据。

当前正式图片尚未生成。正式制作按整合后的美术规则批量产出。

可复用构图和局部裁切优先于大量重复生成。人物外貌、服饰和随身物建立参考，地点几何与设备保持稳定；天气和照明变化不能任意改变可交互物件的事实。四张主立绘必须具有真正透明的背景和可合成的边缘；底部渐变遮罩只可用于表现，不替代透明资产制作。透明处理纳入原四张立绘的制作，不增加大量表情或姿态差分。

场景构图给底部阅读区和行动入口留出低干扰空间，并为窄屏与大字状态保留裁切安全区；关键人物、设备和线索不能被阅读区遮住或放在易被裁掉的边缘。文字、按钮、实时数值与重要线索原文由前端渲染，避免烘焙进图片。人物主立绘不把未知动机或身份画成显眼符号。

## 3. 图片状态与失败

- Package 将规则快照投影为 exact 图片引用；读档重新计算选择，不维护另一套竞争的视觉事实。
- 懒加载时保留已有图与可读信息，错误时提供同场景基础版本/文本替代和重试。
- 展示过渡保持克制，尊重减少动态效果；排版与动效采用范围归 [前端整合说明](frontend-integration.md)，不将原稿中的持续动画直接视为强制实现。
- 图片只能展示当前玩家可知内容。作者秘密、其他路线内容和未目击的异常不进入当前图像或替代文本。
- 若后续增加运行期生图，应单列功能并复用 Native Image 作业、预算、来源、ImageVersion 和存档引用；不是本版通关依赖。

- [Kenney Interface Sounds](https://kenney.nl/assets/interface-sounds)：CC0，轻界面反馈。
- [Beach Ocean Waves / jasinski](https://opengameart.org/content/beach-ocean-waves)：CC0，海浪素材。

## 5. 首版产品配套：受限 Host 音频控制

基线代码支持音频资产和原生手动控件，尚不足以直接实现随场景自动播放、短音和分组混音：

- `main:public/scripts/native/frontend/runtime.js:299` 为 audio/video 强制原生 controls，`:439` 的绑定主要切换媒体资源；Script NodeRef 不开放 `play/pause`。
- `main:public/shared/native-frontend-host.js:32` 的固定媒体目标只做 resolve；没有现成播放/音量目标。
- `main:public/scripts/native/presentation-client.js:105` 的 SceneCue 有 loop/volume，但仍是手动媒体；其 fade 是画面 opacity，不是音量淡变。

正式制作在既有 `host.media` / Presentation 内补有界控制，不开放任意 DOM/WebAudio，也不另建音频世界状态。接口名称与具体代码在正式实施重查源码后定义。

所需行为：

1. 声明 exact 资产、环境/效果分组、循环、增益、过渡参数；Host 管理资源和并发上限。
2. 首次真实点击后解锁声音；拒绝播放时显示可恢复的启用入口，不阻挡游玩。
3. 提供总静音、环境/效果音量与即时反馈；按设置协调可选朗读，不假称已有自动 ducking。
4. 地点/天气/设施变化时切换环境并平滑增益；根据正式规则状态重建。
5. 短音只消费已提交、当前分支的新事件并去重；渲染刷新、读档、切换历史不重播过去门铃/船笛。
6. 隐藏、暂停、退出和恢复时正确停止或重建；读档恢复当前环境，不要求恢复到录音原来的秒数。

回归 HTML 中的波形只是 CSS 动画，没有实际音频播放、首次手势解锁、音量或淡变实现，不能视为音频能力已完成，也不能表示正在配音。正式声音仍依赖本节的 Host 配套；后续小样中的本地音频示意也不直接复制为正式 Host 权威实现。阅读输出指示与真实音频状态的表现区分归 [前端整合说明](frontend-integration.md)。

## 6. Atria 能力映射与实现边界

| 游戏需求 | 复用权威 | 游戏侧内容/配置 | 必要产品配套 |
| --- | --- | --- | --- |
| 行动、资源、修复、门槛 | Authority Transaction / Computation | 类型化状态与闭合动作 ||
| 自由表达到行动预览 | 声明 Task / Processing / Host Bridge | 受支持行动的识别与候选；确认后提交 | 不另开任意工具执行通道 |
| 时间、事件、客人协助 | Lifecycle / Simulation / Tasks | 有界事件、出勤与协助表 | 依正式时钟，不做无界后台思考 |
| 人物所知、记忆、关系 | Information / Knowledge / Memory / Cognition | 证据、承诺、披露与有界反应 ||
| 图片和专属 UI | Native Frontend v3 / exact media | AUI/CSS/Script、资源映射 | HTML 转译，不直接嵌入任意网页 |
| 场景音与短音 | 既有媒体/Presentation | 音频引用、场景与事件映射 | §5 的音频 Host 控制 |
| 开局、存档、历史 | Package / Session / Run / Save | 入口与普通模式配置 | 走现行 SavePoint 恢复，不复活旧 retry/fork API |

角色演绎/记忆反应、行动解释、旁白按需要分离 Task 与上下文，不把所有旧编排模式叠加到正式 Turn。关键规则、输赢、NPC 能力与披露不由旁白临时改写。外部请求数量和延迟通过有限角色与事件、按需触发、缓存确定内容控制。

Library 安装、Runtime 的模型配置、账户、作者 Studio 和开发诊断属于宿主。游戏可清楚引导就绪问题并保留退出/停止/保存/Persona/诊断/重载等宿主恢复入口，主画面不复制整套产品控制台。

存档创建/列表/恢复、Persona 选择和退出可沿现行固定 Host 目标接线；导入导出由 Atria 的 Play/Library 管理，游戏说明返回路径，不假定当前固定 Host 目录存在直接导入/导出/删除/覆盖 SavePoint 方法。

### 6.1 模型用途与就绪

- 直接选择已知行动可跳过意图识别；自由输入使用声明的解释任务，只产出受支持行动及参数候选，不能写入结果。
- 旁白消费已提交或受规则约束的事实、当前玩家可知信息和相关记忆，输出有限视角叙述。
- 人物的认知/关系反应只在相关承诺、信息与事件后按既有契约触发；公共安全消息和确定性工作不必为每个 NPC 每个时段额外调用模型。
- 上述用途可共享现有 Connection/Model/Route，不要求玩家拥有三个不同模型。具体 Task 槽位、提示资源与 schema 在 M0 按当时产品合同定义。
- 缺少配置时由宿主解释与引导修复。正式图像已随包，不把缺少生图连接误判为玩家无法游玩。
