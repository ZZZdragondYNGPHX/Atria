# Native Agent Plans and Runs

Open **Agents → Plans** to create a graph. Edit nodes and typed ports in the canvas or list and Inspector. Save the draft, validate it on the Host, and publish an immutable revision. Choose the exact Session, Project task or chat under Revisions to bind that revision. A Binding does not start work or grant execution permissions.

Open **Agents → Runs** to select a source and follow its Runs. Chat starts require an explicit preflight and paid start. Project trusted commits require a current reviewed task, an exact published commit Plan, preparation, a separate trusted Review window and explicit dispatch. The browser reads the review hash from the original Task authority.

The Timeline and Graph show the same Host projection. Costs distinguish known usage, unknown usage and reserved limits. Cancel does not undo work already sent or refund unknown fees. An interrupted mutation remains unknown until the same command and body are checked again. Closing a page does not cancel the Host operation.

Desktop uses a canvas and Inspector; mobile offers an equivalent node/edge list and sheet. Memory keeps its own scoped read and maintenance surface. External tools cannot register executable authority through a Browser capability registry.

RP, Game and Project main graphs and delegated child graphs implement combinations of published Agent, Planner, Review and Judge tasks: DAG dependencies, bounded return edges, dynamically added owned Agents, and safe local Review redo of pure-model Planner work. Each domain consumer still checks the actual graph, resource pins and permissions. A saved or published graph alone does not prove that every combination can execute.

Independent-Actor collaboration in main RP graphs has existing FS, SQLite and SQL execution evidence. Delegated child Actor contexts now use owned Actor pins, authorized Information and recipient-specific Result visibility; that new wiring has only static evidence and has not yet been run. Judge-to-successor-Agent work inside frozen Fanout scopes is also being integrated: Game and Project wiring is present, while RP integration is in progress. These additions are not runtime PASS claims.

The sole Narrator output boundary and Project's formal tool and human Review requirements remain in force. Review redo across completed Fanout/Join work, changes to scope topology and nested delegation remain restricted. Cancellation of work not yet executed and explicit blocked outcomes are still being completed across the three domains. Original budgets and known/unknown cost accounting remain authoritative; neither arbitrary graph support nor complete product acceptance is claimed.

The retired Browser execution modes, preset settings and checkpoint protocol have no execution or migration path. Historical files outside the active protocol remain inert; current domain data, receipts and unknown costs are retained.
