# Phase 6 — Director ownership and native delegate policies

The default main-agent and child-agent loops now use serializable Runtime policy controllers. The existing generators are retained as single admitted model/tool transport adapters (retry, streaming, prompt formatting, trace); the old coordinator is selectable only for explicit compatibility execution.

Main Runtime stores history references, round/tool cursor, plan identity, output envelope and dispatcher descriptions/results. Child runs have deterministic delegate IDs and their own checkpoints. Dynamic dispatch groups share Runtime ParallelExecutor concurrency admission. Dispatch remains nonblocking, await preserves handle order, cancellation reaches active and queued workers, and finalization closes remaining workers. Handoff is no longer emitted for Director delegation.

Every tool is checked against its effective allowlist before execution. Only the owner can finalize. Existing explicit worker write/patch flags remain supported; ordinary workers cannot write, finalize or recursively dispatch by inventing tool names. Memory OS feedback is transient and source guarded, never copied into checkpoint conversation history. Recovery with missing feedback fails closed; unacknowledged side effects are not replayed. Director exposes explicit engineRunId/engineResume host injection; it does not silently resume into a newly opened draft.

Validation: Runtime/orchestrator run passed 1395/1396 assertions; the sole new-test failure was its incorrect assumption that write_message replaces rather than appends. Corrected that expectation, then Director + parallel tests passed **24 suites / 298 tests**. The preceding main-only Director run passed 23 suites / 276 tests. New coverage checks unauthorized owner writes, worker write grants versus finalize/delegate denial, completed-handle restore without replay, and cancellation of queued dynamic groups. Full regression and browser verification follow in Phase 9.

Compatibility fixtures that formerly invoked undefined custom tools now register their schemas; this prevents those tests from bypassing the new authorization boundary. Source extraction preserves existing draft, streaming, context digest, notes, skills, custom-tool prototype and plugin-regex behavior.
