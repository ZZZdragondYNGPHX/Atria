# 找到此刻用得上的记忆

目标是给续写找到具体的来处：上次答应了什么、两个人为什么生分、这件物品如何到了这里。先用已经给出的记忆，再围绕缺少的内容读取，不为了完成流程而遍历全部历史。

## 先分清记忆的种类

剧情记忆图中的事件摘要描述已记录的故事，人物卡和地点状态描述相对稳定的信息；Native 世界中某个 Actor 的 memory 则可能是这个人物自己的回忆。它可以模糊、重构，或因不愿触及而暂不使用，不能一律当作全知事实。

本次提供了哪些记录、字段和读取能力，就按那些内容工作。当前节点的工具定义和输入范围决定怎样读取。

## 从问题出发

- 找人或物：使用名字、真实别名和关联事件，先确定同名项是否确实是同一个实体。
- 找承诺：比起“关系很好”，更需要承诺内容、条件、期限和后来是否兑现。
- 找一段往事：先看概括，确需具体措辞或细节时再向原始事件或原文读下去。
- 找现状：区分历史状态与最新变化，别把曾经的联盟当作仍然成立。

检索返回的相关度、图中度数和近期排序能帮助定位，最终是否有用取决于内容与当前问题的关系。一个孤立的承诺也可能比连接很多的背景事件更重要。

## 记忆图的层级

返回数据含 semanticDepth、parentId、childCount 时，可以用来判断信息粒度：depth=0 是叶事件，较高层 rollup 概括更长时段。需要整体背景时读概括；需要知道具体条件、当事人或转折时，读取相关子事件。

角色和地点节点也能通过相关事件提供线索，不必等它们有 children。已给出的关联信息足够时直接使用，需要更多才扩展到邻居。

同一往事的父摘要与子事件会重叠。返回时选最合用的粒度，或明确子项补充了父项省略的哪条信息。alwaysInject 等标记说明注入安排，不保证当前上下文已经包含全部细节；结合实际可见材料判断是否还需补充。

floorRange 若存在，可以作为回读原文的定位；seqTo 只是序列位置，不据此猜出整段历史范围。没有原文读取能力时，如实使用摘要，不伪称已核对原话。

## 返回什么

每项给简短内容、实际记忆 ID 或来源、与当前场景的关系。若是人物的信念或回忆，保留归属与确定程度；若两个来源不同，说明差异，不悄悄合并成唯一真相。

只返回本次有价值的内容。没有相关命中时说明检索范围和结果即可，不把最近几条无关记忆当作填充，也不替作者编出缺失的往事。
