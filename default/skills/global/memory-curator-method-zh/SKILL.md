# 整理剧情记忆

让后来续写的人知道故事走到了哪里。根据本次新发生的事件更新真正变化的内容，沿用已有实体与线索，不把每次心情、每个动作都变成长期设定。

## 先确认正在整理哪种记忆

记忆图中的 event、character_sheet、location_state、thread 是剧情整理模型；Native 世界中的 Actor memory 则是人物持有的认知记录，两者用途不同。人物回忆可能有清晰度、来源和适用条件，不要把剧情概括直接覆盖成人物知道的事实。

使用本次提供的 schema、现有记录和操作能力。任务要求结构化抽取时返回其规定的结果；提供写入工具时按真实字段操作；只读任务则给出整理建议。

## 事件与长期状态

**事件**记录本次发生的行动、选择与后果。抽取任务要求连续事件流时，平常的休整或过场也用短摘要接上时间线；同一批对话中的独立转折都要照顾到，prior context 只用于理解，不重复当成新事件。

事件摘要的写法见可用的 event-summary-rules-zh；它关注因果、决策内容、持续后果和未结事项。叶事件用自然段，高层 rollup 按当前压缩请求采用概括条目。

**人物**记录稳定身份、习惯、能力、持有物和长期目标。一次生气不改性格，一时客串不变长期身份；真正发生的立场转变、获得物品或关系破裂则应及时反映。

**地点**记录持续用途、资源、危险和实际控制者。临时访客、散落物品和单次活动的痕迹通常属于事件；火灾后建筑毁坏、据点易主等会影响再访的变化进入地点状态。

判断是否长期，不必机械计算二十四小时或重复次数。看这项信息是否已经成为后续场景的真实条件，以及当前 schema 将它放在哪里。

## 复用已经存在的记录

先利用已提供的记录、ID、别名和关系判断身份，材料不足时再检索相关实体。同一个人换称呼不另建人物；不同人物同名也不强行合并。

已有字段不必整份重写。只改本次确实变化的部分，保留仍成立的背景。可写字段、必填项、可编辑类型和关系词表以当前 schema 为准，不额外创造不被接纳的属性。

别名来自真实使用的称呼。一次戏称是否值得留下，看它有没有成为可识别的称呼，不把所有临时比喻都收进 aliases。language_sample 若被支持，挑有代表性的场景声音，人物根本转变时再相应调整，避免每段语气波动都改写样本。

关系可以并存：盟友也可能互相欺骗。只有关系确实不再成立时才删除它；使用实际实体 ID 与当前词表记录关系，层级父子关系留给现有压缩机制处理。

## 未结事项

thread 适合需要后文接续的具体问题：未送达的信、调查目标、跨场景的委托、有条件的承诺。眼前一个小动作或笼统的“成长线”通常留在事件里即可。

标题让人认得出这件事；note 写清当事人、现有进展和何时算解决。无需为了短标题省掉关键目标。

采用默认 thread schema 时：
- active：仍在进行或等待条件。
- resolved：目标确实达成，或问题已经解决。
- abandoned：明确放弃或已不再可能继续。

根据本次事件更新受影响的开放事项。有人接受了调查，不等于调查完成；已经找到了失踪者，也不要继续把“寻找失踪者”留作未解决。没有触及的事项保持原样，无需逐条输出“无变化”。

已结束的事情后来出现新问题时，区分新一轮任务与原事项的补充，按当前记录模型处理，不擅自改写已发生的结局。

## 压缩已有事件

压缩处理任务给定的来源组和层级。先读清每条的核心变化，按主体、关系或行动线归并，把连续的小事件概括成阶段性结果。

- 叶事件保留关键情节的具体条件；高层概括保留更长时间的转折和结束状态。
- 多条来源指向同一个事件时只记一次，不能因相邻就把不同事件混为一件。
- 重要后果、尚未兑现的条件和未解事项继续保留；过程细节随层级提高逐渐省略。
- 时间范围覆盖整组来源；消息范围与故事日期分别沿用实际数据。

semanticDepth、childCount 和 rollup_depth 等信息若由当前输入提供，用它们理解层级。分组、父子边与写入方式沿用当前机制，处理本次指定的来源。

## 返回结果

完成后简短说明新增、更新或压缩了什么；只提出建议时明确仍是建议。无需把全部实体逐个点名，也不用把初稿、判断表和完整思考过程写进响应。

整理结果使用当次的 schema、范围和输出约定。
