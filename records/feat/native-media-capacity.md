## 实现与边界

用户在斗破地图/补图任务之后授权依据真实游戏需求优化 Atria。先建 Plan，再在独立 feat/native-media-capacity 工作树实现。媒体库和前端结构预算分离，作者编译、安装和浏览器共享契约；按使用租约和闲置 LRU 管理本地媒体，防止访问过的图片永久常驻。显式隐藏图片（跨组件 Shadow Root）、换图、卸载和迟到结果释放；CSS 资源持有至前端卸载。远程失败/解码回退复用本地租约。没有扩大浏览器脚本、DOM、状态或权限预算；服务端规则阶段时间的后续调整及诊断见下文。

作品导入及存档依赖恢复改用二进制 Blob，消除客户端 base64/JSON 扩张；认证后才解析专属二进制入口，安装选项保留权限、精确依赖和 base-version 校验。旧 JSON、MCP 临时上传、存档和 Resource Bundle 使用各自预算。容器、结构、媒体和缓存的详细限额集中产品文档 `main:docs/development/native-media-capacity.md`；不在记录复制第二份规范。服务端解析缓存独立扩容，每次仍验证用户持有原包、隔离返回 Buffer 和元数据。

## 已执行验证

- 真实编译/图谱验证：300 个媒体、40.375 MiB 总媒体及单个 3 MiB 媒体通过，跨越旧 256 条/32 MiB/2 MiB 限制；结构、媒体字节和数量超限、类型伪造与哈希破坏拒绝。
- 实际编码 Buffer/Blob：并发去重、64 MiB 预留、闲置 LRU 淘汰重载、活跃保护、重复释放、哈希失败重试、加载未结束即卸载、CSS 持有至卸载通过。随机媒体样本用于资源管理测试，不声称图片解码。
- 实际 HTTP router：129 MiB 二进制预检、安装选项传递、未认证拒绝、空包/坏选项拒绝、旧 JSON 路径通过；浏览器客户端传 Blob，无 base64 拷贝。
- 远程无权限、并发离线回退共享、再次尝试、解码回退的本地租约释放通过。真实 Chromium + renderer 的直接/嵌套 Shadow Root 图片隐藏与三次重显、Blob 去重和最终销毁通过。
- 最终斗破包重复打开：旧缓存策略 839/807/789 ms，新策略 857/162/149 ms；调用方修改字节不能污染缓存，元数据不可变，缓存命中时原包篡改仍拒绝。这是本机单次对照，不代表通用性能保证。
- 大包实际构建/检查：307993226 bytes 加密包，解压内容309029128 bytes；完整性/字节相等与认证标签篡改拒绝通过。用时约8.7秒，同进程构建及检查峰值RSS3795680 KiB（约3.62 GiB）。样本跨越旧128 MiB容器/256 MiB解压上限；没有验证512 MiB极限，更未证明1 GiB作品舒适运行。
- 修改 JS 的 ESLint 与 `git diff --check` 通过。脚本、随机大样本、临时配置和截图在仓库外，未加入产品提交。
- 收尾浏览器回归两次创建返回`bridge_target_invalid`，公开回执未保留原异常；加入本地adapter异常记录后，完整流程通过，未复现原始异常。检查发现独立的性能缺陷：规则artifact缓存键把全部图片解码成UTF-8再JSON哈希。改为原始字节SHA-256，仍覆盖全文件且不缓存输入/结果。同一真实高画质文件集合的小规则调用从1680/1634/1588 ms降为42/36/36 ms，输入变化与被import模块修改的缓存失效通过。此测量证明消除了媒体文本转换成本，不能据此断言已证明两次拒绝的根因；保留40 ms客体执行预算。

后续重现取得准确诊断：`rules/engine.js precondition`在输入`freeze`阶段收到QuickJS `InternalError: interrupted`，发生在40ms服务端客体预算内。单纯优化冻结（跳过原始值的递归调用）在20次独立样本通过，但真实浏览器新局仍出现同类拒绝。按用户对真实框架限制的授权更新Plan：服务端单阶段使用独立100ms wall-clock限额，浏览器仍40ms；没有放大堆、输入输出或总工作预算。无限循环在约127ms（含模块准备）终止，深层对象和数组仍冻结；本地诊断代码已从产品移除。上述精确诊断补足前一条尚未确认的根因。
