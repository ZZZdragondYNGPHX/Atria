## 大包与浏览器实测

- 上传从 Express 整包 Buffer 改为有界流写临时文件。预检只读取小头部，安装和冷打开直接流式解密；ZIP 大条目边解压边校验 CRC/SHA256 并写 backing。Blob 直接从已接纳文件流持久化。小元数据仍有独立大小限制，图片与音视频预算分离。
- 新增使用相同容器 v2/inventory 权威的文件构建入口；流式包上限 16 GiB、总展开 64 GiB、单音视频/条目 2 GiB。旧 Buffer 构建/读取路径保留 512 MiB 容器、32 MiB 条目限制，不把其容量谎报成流式能力。Studio/MCP 旧 Buffer 构建与导出链仍有各自边界，不能据此宣称全部编辑/导出入口已经支持大包。
- 现有真实游戏包内追加合成媒体测试（不是可播放视频）：32 MiB / 256 MiB / 1 GiB 均成功构建、安装、冷打开、验证图谱和末尾 1 KiB Range；禁止整包 readBlob 后仍通过。1 GiB 资源形成 1,180,505,767 字节包：构建 4,464 ms、安装 7,602 ms、冷打开 5,589 ms。256 MiB 场景峰值 RSS 444 MiB，1 GiB 场景 450 MiB（进程起始约 134 MiB，包含旧游戏声明与资源），未随媒体尺寸线性放大。
- 范围流测试发现共享 FD 被 destroy 关闭问题，改为由 payload 所有者关闭句柄、范围消费者通过显式位置读取；重测 256 MiB / 1 GiB、提前停止一个范围后再次读取均通过。HTTP 实际 Router 验证流式 body、options 解析、响应后关闭、上传限额和破坏 GCM 的拒绝。
- Chrome 156 / Windows 真实浏览器：600 秒 PCM WAV（115,200,044 字节）加载元数据并 seek 至 550 秒。网络先 bytes=0- 传约 917,504 字节，再 bytes=105578496-115200043 传约 720,896 字节，均关闭。前端 loadBytes 只加载 index，没有下载媒体 Blob。
- 实际生产构建的 QuickJS Worker + supervisor：102 次调用、仅 2 次快照，约 133,187 字节；初始单快照消息 60,177 字节，最终状态 hp=20，无诊断。Canvas 同尺寸第二帧尺寸 setter 调用 0 次；像素 [0,255,0,255] 验证透明度/变换已重置。
- 浏览器使用隔离测试页和真实运行时模块，没有改造 UI 外观；不是完整游戏 FPS 或低端实机证据。此次前端验证应用 animation-performance 技能的实际浏览器/主线程诊断要求。

- 修复内部读取包字节也会破坏准入身份的问题：内部读取返回自有副本，外部可变 Map/Buffer 暴露仍会撤销身份。真实游戏包首次图谱和逻辑解析约 182.68 ms；100 次热读取合计 0.149 ms。调用方修改副本不污染缓存；通过公开 Map 修改内容会撤销身份并重新解析，损坏逻辑被拒绝。
- 新增绑定安装版本及内容哈希的流式归档下载。1,180,505,767 字节归档的末尾 1 KiB 实际只传输 1,024 字节；首次约 689.79 ms 包含冷 SHA 校验，后续 HEAD/304 不流读。错误 pin、跨账号访问被拒绝，旧 Buffer 导出超过 128 MiB 在分配前拒绝。归档下载已可流式；Studio 文本编辑与便携 Save/MCP 入口仍是独立容量合同。
- 生命周期状态缓存只共享由宿主接纳并深冻结的记录值；记录信封、可写状态容器和候选保持隔离。成功类型校验只按不可变值身份复用，外部浅冻结对象不能获得信任。50,000 条记录、每条 32 个数值（160 万标量）：公共可变读取约 183.84 ms，内部共享读取约 14.36 ms；首次类型校验 91.13 ms，热校验 10.69 ms；候选准备 25.88 ms。跨 revision 的未变值保持身份，公共读取修改不影响存储，非法新值仍拒绝。
- 模拟追赶内缓存具备完整依赖签名的静态任务求值；记录值、scope 身份/状态/epoch、目标和请求时钟变化即失效，引用当前时钟的表达式加入当前 tick。集合和 Subject 任务仍走完整求值。100 个任务、40 轮、每次读取 5,000 数值：完整求值 4,000 次约 254 ms，复用后 100 次约 7.67 ms；替换/删除值、scope 和时钟变化的失效检查通过。真实声明验证允许 4,096 jobs / 65,536 steps，4,097 jobs 拒绝；这不是 4,096 个复杂任务的整场游戏跑分。
- 文件存储增加 4,096 项 / 64 MiB 的已解码文档缓存，单项最大 16 MiB；命中前仍通过打开文件的完整 fstat 身份核对，修改、删除、损坏时失效。FS journal 的压缩/解压改用异步 zlib，保持原存储字节格式；JSON 解析和字符串化的冷成本仍存在。实际测试覆盖原地修改、删除、损坏、公共可变读取隔离，以及 publish 后故障的新引擎恢复。

## 交付边界与后续性能判据

本次完成的是计算、状态、存储、资产和前端传输的底层路径改造。P0 基线、P1 资产准入/图像线程、P2 不可变状态/索引、P3 分片多核/取消、P4 锁外计算/查询/历史、P5 媒体/脚本/Canvas、P6 真实调用与文档均有实现和证据。原有权限、沙箱、类型准入、预算、CAS 和 journal 耐久边界保留。

仍需按实际项目负载判断的成本：冷完整快照读取全历史；新状态内容哈希和某些集合统计为 O(namespace/collection)；首次 JSON 解析仍占宿主线程；字段筛选、集合/Subject 模拟任务仍按扫描工作量执行。分片需要程序声明可独立部分，不能自动并行有依赖的任意脚本。IPC/沙箱有序列化复制，没有宣称零拷贝、原生 SIMD 或 GPU 计算已经落地。后续若实际负载由这些部分主导，应以该负载的剖析数据推进，不以放宽预算代替改造。

流式容量是 16 GiB 包 / 64 GiB 展开 / 2 GiB 单资源的实现预算；已实测最大为 1 GiB 合成单资源，不把上限数值当成全尺寸压力测试。完整游戏帧率、全部作者工具及所有数据库平台不在现有证据覆盖内。

实现合同位于 main 的 `docs/development/native-transactions.md` 和 `docs/development/native-media-capacity.md`。调研采用 [Node Worker 官方文档](https://nodejs.org/docs/latest-v24.x/api/worker_threads.html)、[isolated-vm 官方 README](https://github.com/laverdet/isolated-vm/blob/main/README.md)、[SQLite 查询规划说明](https://www.sqlite.org/queryplanner.html)；官方能力说明与本机实测分开记录。
