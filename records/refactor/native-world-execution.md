# Native 世界执行性能

Task ID: `perf/native-world-execution`。Plan: [目标与边界](../../plans/refactor/native-world-execution.md)。2026-10-25 从 `95d3f5ff` 开始；用户在众生行秘境／现场交互开发中明确追加全面性能检查，重点担心重复防御代码与百人至千人的世界及智能负载。新产品工作树与未完成的其它任务隔离，主线尚无本任务修改。

开始事实：游戏规则在独立 cold probe 中约几十毫秒，但实际 Native 操作约数秒，新局约 200 个主体的顺序初始化很慢；此前围绕包内账本的优化不足以证明整体可扩展。正在采样完整宿主执行链，不先假定瓶颈或增加限额。

首次实测：同一存档 3 次读取与 3 次行动的约 12 秒 CPU 采样中，PackageInstaller.open 包含约 9.9 秒，inspectAtriaPackageContainer 约 8.2 秒；反复哈希、解包、CRC 与分配主导成本。约 252 MB 发行包的 archive、source、编译媒体、asset 重复计入 256 MiB 缓存，导致每次操作重新解包。修改后只保留按已验证摘要共享的唯一 payload，读取从 1709–1879 ms 降至 54–80 ms，预热行动从 1919–2612 ms 降至 237–252 ms；首次行动另有约 447 ms 冷编译。尚未完成超缓存容量包的解耦、全面规模验证和最终集成。

用户补充综合游戏平台定位，明确授权修改 Atria 架构。正在拆分服务端世界计算与前端控制器预算、检查主线程计算阻塞及大资产按需读取。数字是本机隔离存档样本，不代表千人智能或所有设备表现。

随后实现了世界计算工作线程池，每次调用仍建立独立 guest；并发及堆默认值根据可用核心、总内存／容器约束计算，`native.computation` 提供宿主配置。前端控制器预算独立。千万次循环、四个并行计算、死循环中断及中断后再次调用通过；主事件循环在该样本中继续处理定时器。该证据证明隔离与响应，不证明所有计算都已达到原生吞吐。

大 payload 现在溢写至私有临时 backing，按访问复制单个资源，常驻素材每包 32 MiB；LRU 淘汰后已经返回的资源 map 继续持有 backing，GC／进程退出回收。真实约 252 MB 候选包的 warm open 不再读取 archive；调用者 buffer 修改隔离、跨 owner 缓存隔离、导出一致、变更／丢失 blob 拒绝均完成定向检查。冷导入仍为整包处理，发行格式的 512 MiB／1 GiB 限制尚未改为流式大包支持。

构建校验与执行共享精确代码编译缓存，manifest 深冻结后直接共享，schema 编译只在根复制一次。JSON declaration 合并检查与不可变复制，只有自身确认并冻结的对象可复用验证结果；恶意字段、getter、隐藏字段、非 JSON、稀疏数组、字节限制及调用者修改隔离已检查。1000 条普通对象的声明样本首次约 1.83 ms，原样重用 1000 次约 0.13 ms，不是人物智能基准。

游戏完整 Native 新局（200 主体）、入境／离境、幂等重复提交、四域存档精确恢复通过；桌面与 390×844 模拟手机的现场接近／入境／机关观察／江湖录只读／行囊图片／键盘退出／空闲诊断流程通过。手机视口发现人物遮住机关点击及顶部挤压，已修正；最新顶部按钮位置微调仍需刷新检查。真机移动性能未验证。

## 原生计算与硬件适配推进

同一份真实游戏输入比较（每次新建隔离环境、输出深比较一致）：QuickJS 预热约 55–57 ms，独立 V8 约 18–21 ms。随后将服务端实现升级为 `isolated-vm@6.2.0` 的原生 V8 隔离上下文，运行在可回收子进程池；故障／超时不会运行在宿主事件循环。精确程序在进程内复用编译结果，调用仍创建独立上下文。模块拒绝异步世界程序，前端异步控制器保持允许。依赖 ISC 许可，最低 Node 22，Docker 固定 Node 24；本机 Node 24.18.0 实测。参考：[官方项目与兼容说明](https://github.com/laverdet/isolated-vm)。

一亿次循环样本（含首次调用准备）约 180 ms；并行、死循环中断、上下文原型隔离、异步／宿主能力拒绝、16 MiB 预算下内存异常与后续恢复、队列背压均通过。队列测试 65 个接纳任务完成、5 个明确 busy，之后仍可执行。实际 Native 新局与精确恢复再次通过；预热移动样本约 189–195 ms。多核心并发并不改变同一事务的提交顺序。

浏览器控制器按 hardwareConcurrency/deviceMemory 提示调整总体 CPU 和堆预算，初始化与常规回调分开计时；1 GiB／2 核与 8 GiB／16 核策略，以及原 8 MiB 无法执行而 32 MiB 可执行的百万数组样本通过。未知设备使用默认值；这不是手机真机性能结论。

已将 artifact 中转改为私有磁盘分块暂存，移除整包 Buffer 预分配，默认容量与合法 Package 大小一致。真实 251,680,090 字节候选包的分块上传、增量摘要、导出暂存、owner／引用隔离、调用者修改隔离、过期与在用保护、错误分块回收全部通过。开始暂存的 ArrayBuffer 增量小于 4 MiB。安装消费阶段仍会读入整包，后续需要继续处理冷导入与大包流式路径。

尝试对 State Delta 差分做单遍重写，100／1000／10000 条记录的实际持久化往返没有显示收益（万条约 23 ms，对照约 22 ms），已撤回该改动。未把无收益实验留在产品代码。

## 现场移动与空闲开销

走路原来可在一次请求直接结算到路径终点，现按实际格点推进，途中可以停止与响应占位变化。人物同地图位置通过 160 ms linear transform 过渡，地图切换重建人物节点，减少动效时不平移；这是空间运动反馈。没有动画父级坐标变量或 left/top 过渡。四秘境进出／重入、准确崩解边界及完整试炼通过；最新试炼样本 184 分钟、余量 60 分钟。

前端由操作直接启动串行延续，不再每 500 ms 空转检查。真实 Native + Chrome 延迟响应测试中，发起移动、一个 continue 已提交后暂扣响应、玩家暂停并重复按方向键，释放响应后在 x=5,y=7 停下；仅 3 次写入，没有续跑或重复提交。16 秒空闲只有 4 次 Worker 消息、0 次新写入、无诊断错误。此测试使用最新重建的前端 Worker bundle。

产品尚未集成／发布。测试新依赖通过临时解析入口指向同版本已安装库，未改变共享 node_modules；重建依赖目录链接的命令曾被自动审批拒绝（无具体原因），已改用只更新依赖清单的安全方式。最终集成后需要验证正常依赖安装路径。
## 冷加载、规模与集成结果（2026-10-25）

最终实现为 `.atria` v2 分块认证解密到私有临时 ZIP、逐文件异步解压与 CRC／inventory 接纳，大资源直接落磁盘缓存；同步构建与异步安装／读取共用同一个接纳生成器，没有两套校验规则。安装以惰性资源迭代器取得 Blob publication leases，避免为取得锁先同时读入全部素材。并发冷读取共享同一接纳结果，缓存计数不会重复增加。旧的整包解压后再 spill 实现已移除。

真实 251,680,090 字节包：异步冷检查约 1,489 ms，10 ms 心跳期间执行 123 次，最大间隔约 227 ms；观察到 ArrayBuffer 峰值增量约 98.4 MB（不含调用者已经持有的密文包）。160 个 Asset 内容、521 个 source 文件、认证损坏、ZIP CRC 错误、失败临时文件回收与并发缓存隔离通过。仍有编译／图检查同步段；上传中转与解压已磁盘化，但 HTTP／Blob 消费的密文输入仍整包驻留。v2 的 512 MiB 包、32 MiB 单文件等导入边界没有被本轮虚称无限容量。

游戏名册调度改为选择最早八个主体，普通更新保留既有稳定 ID 顺序，只在新增主体时重排；最早时点用单遍循环，避免巨大数组 spread。与原算法结果逐项一致，100／1,000／10,000 条分散地域名册的选择加下一时点计算分别由约 0.017／0.110／1.217 ms 降至 0.011／0.033／0.174 ms。包含同时间排序、出生／死亡／更新与空名册。这是调度数据规模样本，不代表万名完整智能人物世界；单次人物窗口 100、当前居民／兽类编制及 Authority 值预算仍是后续世界扩充需要处理的边界。

新依赖已通过正常 Node 模块解析安装及运行，不再依赖临时解析钩子；未更改或删除原共享 node_modules 链接。最终最低 Node 为 22.2.0（使用原生 CRC），Docker Node 24；本机 Node 24.18.0。新版最终候选再次通过真实 Native 安装、200 主体初始化、实际秘境进出、幂等与四 Domain 精确恢复。全部修改 JS 的定向 ESLint 和 git diff whitespace 检查通过。

产品提交 `40cefca4` 已本地快进集成 main 并同步 origin/main，正常依赖路径下主线一亿循环、并行、中断与后续恢复检查通过。未新增测试资产到仓库，未修改无关任务。硬件自适应并发有助于独立工作同时运行；同一世界的顺序事务没有被错误宣称自动拆成全核并行。

## 月度推演第二轮实现（2026-10-25，本地待发行）

复用历史 `world.2` 的同一份 96 NPC 加玩家、起点 4320 分钟的真实存档进行完整 30 天推演。历史记录 416,742 ms；`40cefca4` 作为本轮基线 210,100 ms。第一轮去重复制／不变量复用后 176,696 ms；把所有子对象都登记接纳证明的实验为 178,400 ms，没有收益，因此撤去子对象普遍登记，仅保留实际接纳根对象的节点数、深度和字节证明。根证明及无诊断 Schema 路径优化后初测 163,872 ms，但前段存在短暂并行测试，最终单独计时另记。各次均为 2,327 个逻辑事务、规则序号增加 5,527，结束时间 47,520 分钟，幂等和完整读档通过。外层请求数会随 250 ms 连续提交预算变化，不能作为执行内容变化的依据。

实现继续复用原权威：已接纳 JSON 使用专用复制；私有读取保留接纳过程已经产生的不可变副本；深冻结契约可按身份命中原声明缓存；不读取候选状态的纯不变量免除发布前相同输入的第二次运行；发布阶段复制记账与记录外壳，记忆取得写入替换 value/basis 路径。读取候选状态的不变量仍二次运行。Schema 保留默认诊断路径，仅内部只问是否合法时不构造成功节点路径。哈希只缓存有界字段名编码，不缓存可变文档哈希，不改变规范字节。

定向检查包括嵌套根证明的深度／节点／字节上限、重叠私有字段读取隔离、记忆发布源对象不变、候选状态变化后的不变量拒绝、254 个 Schema 样本和 1,410 个规范 JSON 字节样本。JS 定向 ESLint、whitespace 检查通过。测试和采样保留本机临时目录，未提交测试资产。

游戏被动推进发现身体行动时间被误当作批处理外部边界。直接放开会改变近邻读取和行动分组，八天对照实际出现见闻与秘境动作差异，未采用。最终仅在下一组行动完整落在累计写入预算内、五个身体读取分块／认知／关系窗口全部不变、没有更早未加载主体或世界边界时复用加载结果。八天完整对照的总规则调用从 7,693 降为 5,487；313 个最终主体、全世界状态、规则序号 14,316、关系、个人记忆与因果记录一致（关系证据中的调用 ID／前值哈希随提交边界变化而单独排除比较）。四秘境进出、重入、同行等候／继续和准确截止死亡检查通过。此数字是纯规则对照，不冒充 Native 月度端到端时间，也不代表千名深度智能人物吞吐。
